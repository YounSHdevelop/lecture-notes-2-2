장면 1

10만 원씩 두 번 넣었는데, 왜 통장엔 10만 원뿐일까?

공유 자원 · 경쟁 상태(race condition) · 임계구역(critical section) ★ 밑줄 · 동기화 · 생산자-소비자 문제

나랑 동생이 같은 통장에 동시에 10만 원씩 입금

통장엔 0원이 있었어요. 둘 다 넣었으니 20만 원이어야 하는데, 찍힌 건 10만 원. 교수님: "참을 수 있어요? 못 참죠."

스레드 여러 개는 각자 돌아가지만, 가끔 변수 · 파일 · 주변장치 같은 공유 자원(shared resource)을 같이 써요. 예금이 바로 그 공유 변수예요. 문제는 "예금에 10만 원 더하기"가 사실 세 단계라는 거예요. 예금을 읽고, 10만 원을 더하고, 다시 저장하죠. 이 세 단계 사이에 다른 스레드가 끼어들 수 있어요.

이렇게 둘 이상의 스레드가 같은 공유 자원에 동시에 접근해서, 누가 언제 읽고 쓰느냐에 따라 결과가 달라지는 상황을 경쟁 상태(race condition)라고 해요. 각자 다른 데이터를 만질 때는 아무 문제가 없어요. 예금처럼 데이터 하나를 둘이 같이 만질 때만 생기는 문제예요.

해결책은 "읽고 → 더하고 → 저장"하는 부분을 한 번에 한 스레드만 들어갈 수 있는 구역으로 묶는 거예요. 그 구역이 임계구역(critical section)이에요. 결과에 중대한(critical) 영향을 주는 곳이라 이런 이름이 붙었어요. T1이 임계구역에서 일하는 동안 T2는 밖에서 기다리고, T1이 끝나면 "들어와도 돼" 하고 알려 줘요. 그러면 T2는 10만 원을 읽어서 20만 원을 저장하죠(그림 6-2). 이렇게 임계구역에 들어가는 순서를 조절하는 걸 동기화(synchronization)라고 해요. 그래서 임계구역 문제는 곧 동기화 문제예요.

교수
우리가 작업을 하다가, 어떤 영역은 내가 작업하는 동안에 남이 진입하면 안 되는 영역이 있습니다. 그걸 이 장의 주제인 크리티컬 섹션, 임계구역이라고 합니다.10/19 강의 중 (말을 조금 다듬음)

다른 책의 단골 예시 — 생산자-소비자 문제

다른 책들은 보통 이 예시로 설명한대요. 생산자(producer)는 원형 버퍼에 데이터를 넣고 sum = sum + 1, 소비자(consumer)는 데이터를 빼고 sum = sum - 1을 해요. sum이 3일 때 하나 넣고 하나 빼면 여전히 3이어야 하죠. 그런데 sum을 고치는 두 줄이 서로 끼어들면, 소비자가 나중에 저장되면 2, 생산자가 나중에 저장되면 4가 돼요(그림 6-4). 둘 다 틀린 값이에요. 해결은 똑같아요. input(buf)와 sum = sum + 1을 한 임계구역으로 묶고, output(buf)와 sum = sum - 1도 한 임계구역으로 묶어요.

시험엔 이렇게

경쟁 상태(race condition)는 둘 이상의 스레드가 동일한 공유 자원에 동시에 접근해 실행 결과를 예측할 수 없게 되는 상황이다. 이를 막으려면 임계구역을 지정해야 하며, 임계구역(critical section)은 둘 이상의 스레드가 동시에 접근해서는 안 되는 공유 영역을 가리킨다. 임계구역에 대한 접근을 제어하는 과정을 동기화(synchronization)라 한다.

외우는 법: 동시에 건드리면 경쟁 상태 → 한 명씩만 들어가는 방이 임계구역 → 순서 정리가 동기화
바로 확인
sum = 3인 상태에서 생산자는 sum = sum + 1, 소비자는 sum = sum − 1을 하는데 두 코드가 서로 끼어들었다. 나올 수 없는 결과는?
둘 다 3을 읽은 뒤 끼어들면, 나중에 저장한 쪽의 값이 남아요. 소비자가 나중이면 2, 생산자가 나중이면 4예요(그림 6-4). +1과 −1밖에 없으니 5는 나올 수 없어요. 올바른 값은 3이에요.

화장실 문을 잠그기만 하면 끝일까?

잠금(lock) · 잠금 해제(unlock) · 해결 조건 3개 ★ : 상호 배제 ★ · 한정 대기 · 진행의 융통성

임계구역 = 화장실

"둘이 같이 쓰면 안 돼요. 아무리 친해도." 그래서 들어갈 때 문을 잠그고(lock), 나올 때 잠금을 풀어요(unlock). 잠금을 풀면 기다리던 사람에게 "비었어요" 신호를 보내는 거고, 이게 곧 동기화예요(교재 옆 "비유" 손글씨).

임계구역을 지키는 가장 기본적인 방법은 잠금(lock)과 잠금 해제(unlock)예요. 그런데 교수님 말로는 "락을 쓴다고 해서 문제가 무조건 다 해결되는 건 아니에요". 어떤 방법은 해결했다고 주장하지만 실제로는 아닌 경우가 있어요. 그래서 어떤 방법이든 다음 3가지를 무조건 만족해야 제대로 된 해결이에요.

조건교재 정의화장실로 말하면
상호 배제 ★
mutual exclusion		한 스레드가 임계구역에 들어가면 다른 스레드는 임계구역에 들어갈 수 없다. 이게 안 지켜지면 임계구역을 설정한 의미가 없다.내가 쓰는 동안 남은 끼어들 수 없어요. 같이 쓸 수는 없어요.
한정 대기
bounded waiting		임계구역에 진입하려는 스레드 중 무한히 기다리는 스레드가 있어서는 안 된다.누구는 계속 들어가고 누구는 계속 밀리면 안 돼요. 일정 시간 안에는 내 차례가 와야 해요.
진행의 융통성
progress flexibility		한 스레드의 작업이 임계구역에 진입하려는 다른 스레드의 진행을 방해해서는 안 된다.내가 화장실에 들어가는 게 다른 사람 때문에 막히면 안 돼요.
교수
첫 번째 조건이 뭡니까? Mutual exclusion. 별표해 주세요. 뒤에 또 나올 겁니다. 상호 배제. 내가 화장실을 쓰는 동안에는 다른 사람이 그 자원을 쓰면 안 된다.10/19 강의 중 (말을 조금 다듬음)

시험엔 이렇게

임계구역을 보호하는 대표적인 방법은 잠금(lock)과 잠금 해제(unlock)이며, 어떤 방법이든 다음 세 조건을 반드시 충족해야 한다. 상호 배제: 한 스레드가 임계구역에 들어가면 다른 스레드는 들어갈 수 없다. 한정 대기: 임계구역에 진입하려는 스레드 중 무한히 기다리는 스레드가 있어서는 안 된다. 진행의 융통성: 한 스레드의 작업이 다른 스레드의 진행을 방해해서는 안 된다.

외우는 법: 상 · 한 · 진 — 혼자 쓰고(상호 배제), 언젠간 들어가고(한정 대기), 남 때문에 막히지 않게(진행의 융통성)
바로 확인
"임계구역에 진입하려는 스레드 중 무한히 기다리는 스레드가 있어서는 안 된다"는 어떤 조건일까?
"무한히 기다리면 안 된다" = 기다림에 한도가 있어야 한다 = 한정 대기(bounded waiting)예요.

잠금 코드 세 개, 각각 어떤 조건을 어겼을까?

그림 6-6 상호 배제 위반 · 6-7 한정 대기 위반 · 6-8 진행의 융통성 위반 · 타임 슬라이스 아웃 · 경직된 동기화

세 코드 모두 T1과 T2가 같은 모양의 코드를 갖고 경쟁해요(그래서 경쟁 상태죠). 겉보기엔 멀쩡한데, 딱 안 좋은 순간에 타임 슬라이스 아웃이 걸리면 문제가 터져요. 시험에선 "이 코드는 어떤 조건을 위반하나?"로 묻기 좋으니 짝을 꼭 맞춰 두세요.

① 잠금 1개 — 둘 다 들어가 버림 → 상호 배제 위반

그림 6-6 · lock = false (초기값, 문이 열려 있음)while(lock == true);   // ① 누가 쓰고 있으면 여기서 계속 돈다(바쁜 대기)
lock = true;            // ② 비었으면 문 잠그고
임계구역
lock = false;           // 나오면서 문 열기

T1이 ①을 통과(아직 false)했는데 ②로 잠그기 직전에 타임 슬라이스 아웃. 이제 T2가 실행돼요. 잠금은 아직 false니까 T2도 ①을 통과하고, 잠그고 들어가요. 그다음 T1이 돌아와 ②를 실행하고 들어가요. 화장실 하나에 둘이 들어간 거예요. 원인은 ①(검사)과 ②(잠금) 사이가 잘렸다는 것. 이건 장면 4의 검사와 지정으로 해결해요.

② 잠금 2개 — 둘 다 영원히 못 들어감 → 한정 대기 위반

그림 6-7 · lock1 = false; lock2 = false;// 스레드 T1                     // 스레드 T2
lock1 = true;              lock2 = true;            // 일단 내 잠금부터 걸고
while(lock2 == true);      while(lock1 == true);    // 상대가 안에 있으면 기다림
임계구역                    임계구역
lock1 = false;             lock2 = false;

이번엔 먼저 잠그고 나서 상대를 확인하니까 둘 다 들어가는 일은 없어요. 그런데 T1이 lock1 = true 직후 타임 슬라이스 아웃, T2도 lock2 = true 직후 타임 슬라이스 아웃. 이제 서로 "저쪽이 잠갔네" 하며 기다려요. 둘 다 영원히 화장실에 못 들어가요. 무한 대기니까 한정 대기 위반이에요. (교재 하이퍼링크: 이렇게 잠금 때문에 작업이 더 진행되지 않는 상태가 7장의 교착상태예요.)

③ lock = 1/2 번갈아 — 혼자 두 번은 못 감 → 진행의 융통성 위반

그림 6-8 · lock = 1 (T1이 먼저)// 스레드 T1                     // 스레드 T2
while(lock == 2);          while(lock == 1);
임계구역                    임계구역
lock = 2;                  lock = 1;                // 다음은 상대 차례라고 넘겨줌

제일 단순한데 둘이 같이 들어가지도 않고(상호 배제 ○) 영원히 기다리지도 않아요(한정 대기 ○). 그런데 반드시 번갈아 들어가야 해요. T1이 화장실 다녀오면 lock이 2가 되니까, T1이 배탈 나서 또 가려면 T2가 한 번 다녀와야 해요. 교수님 말로 "제발 화장실 좀 들어갔다 나와라, 너 안 다녀오면 난 오늘 죽는다". 상대가 나의 진행을 방해하니 진행의 융통성 위반이고, 이렇게 서로 진행을 방해하는 현상을 경직된 동기화(lockstep synchronization)라고 해요.

잠금 2개 (6-7)둘 다 잠그고 서로 기다리다 무한 대기한정 대기
lock 1/2 번갈아 (6-8)무조건 번갈아야 해서 연달아 못 들어감진행의 융통성 (경직된 동기화)

교수님 정리: "이게 생각보다 간단하지 않다는 거야. 그 문제를 해결하는 방법 자체가 생각만큼 간단하지 않다."

시험엔 이렇게

잠금 변수 하나로 검사 후 잠그는 코드는 검사와 잠금 사이에 타임 슬라이스 아웃이 발생하면 두 스레드가 모두 임계구역에 진입해 상호 배제를 위반한다. 각자 잠금을 건 뒤 상대의 잠금을 확인하는 코드는 두 스레드가 모두 무한 대기에 빠질 수 있어 한정 대기를 위반한다. lock 값으로 차례를 정해 번갈아 들어가는 코드는 한 스레드가 연달아 진입할 수 없어 진행의 융통성을 위반하며, 이를 경직된 동기화라 한다.

외우는 법: 잠금 1개 = 둘 다 들어감(상호) · 2개 = 둘 다 못 들어감(한정) · 번갈아 = 혼자 두 번 못 감(진행)
바로 확인
T1은 while(lock == 2), T2는 while(lock == 1)로 기다리고, 나올 때 상대 번호를 lock에 넣는 코드. T2가 한동안 임계구역을 쓰지 않으면 T1은 어떻게 될까?
T1이 나오면서 lock = 2로 바꿨으니, T2가 들어갔다 나와서 1로 바꿔 줘야 T1이 다시 들어가요. 상대가 내 진행을 방해 = 진행의 융통성 위반(경직된 동기화).

장면 4

검사하고 잠그는 두 줄, 잘리지 않게 한 줄로 만들 수 없을까?

검사와 지정(test-and-set) ★ 밑줄 · 원자적 연산 · 하드웨어 지원 · 동기화 도구 · 뮤텍스(mutex)

장면 3의 첫 번째 코드는 while(lock == true)(검사)와 lock = true(잠금) 사이가 잘려서 망했어요. 그럼 두 줄을 한 줄로 합쳐서 중간에 못 자르게 하면 되죠. 그게 검사와 지정(test-and-set)이에요.

그림 6-9 · 검사와 지정 코드while(test_and_set(lock) == true);   // 검사 + 잠금을 한 번에
임계구역
lock = false;

두 연산이 떨어지지 않고 하나처럼 실행되는 걸 원자적(atomic)이라고 해요. 중요한 점: 이건 소프트웨어로 "나 안 잘릴게" 한다고 되는 게 아니라, CPU 명령어 안에 마련되어 있어야 해요. 즉 하드웨어의 도움을 받아요. 실행되는 동안 문맥 교환이 안 일어나니 T1, T2가 동시에 불러도 차례로 실행돼서, 둘이 같이 들어가는 문제가 사라져요.

그런데 하드웨어에 의존하니 저수준 언어로 짜야 하고 시스템마다 구현이 달라요. 그래서 운영체제는 고수준 언어에서 쓸 수 있는 동기화 도구를 제공해요. 바로 뮤텍스, 세마포어, 모니터예요. 교수님 표현으로 동기화 도구는 "누구 있어요? 네. 그러면 화장실 들어가면 안 되잖아. 그게 동기화 도구예요".

첫 번째 도구 — 뮤텍스

뮤텍스(mutex)는 'MUTual EXclusion(상호 배제)'의 약자예요. 가장 오래된 기본 도구로, 들어가기 전에 mutex_lock()으로 잠그고, 나오면서 mutex_unlock()으로 풀어요. 화장실 들어갈 때 잠그고 나올 때 푸는 것 그대로예요. 내부는 앞의 검사와 지정 같은 기본 코드로 구현되어 있어요. 잠긴 상태에서 기다리는 스레드는 CPU를 양보하고 대기 상태로 가서, 기다리는 동안 CPU를 쓰지 않아요.

한계는 하나의 공유 자원에 대해서만 동기화할 수 있다는 거예요. 교수님 비유로 화장실 안에 좌변기가 1개면 잘 돌아가지만, 좌변기가 3개인데 쓰려는 사람이 4명이면 쓸 수 없어요. 교재는 한 가지 더 짚어요. 뮤텍스는 칸마다 따로 줄을 서는 것과 같아서, 앞사람이 오래 걸리는 줄에 서면 먼저 온 사람이 오히려 늦게 들어갈 수 있어요. 스레드를 한 줄로 세우는 기능이 없거든요.

시험엔 이렇게

검사와 지정(test-and-set)은 잠금을 확인하는 연산과 잠금을 거는 연산을 하드웨어의 도움을 받아 원자적으로 실행해, 그 사이에 문맥 교환이 일어나지 않게 하는 하드웨어적 해결 방식이다. 뮤텍스(mutex)는 MUTual EXclusion의 약자로, 임계구역 진입 전 mutex_lock()으로 잠그고 작업 후 mutex_unlock()으로 해제해 상호 배제를 보장하는 기본 동기화 도구이며, 하나의 공유 자원에 대해서만 동기화할 수 있다.

외우는 법: 검사 + 잠금 = 한 줄(원자적) = 하드웨어 · 뮤텍스 = 좌변기 1개용

화장실이 두 칸이면? 숫자 하나(S)로 줄 세우기

세마포어(semaphore) ★ 오늘의 핵심 · 데이크스트라 · init(n) · wait() · post() · S = 사용 가능한 자원 수 · 이진 세마포어 · p() / v()

미국은 우주용 볼펜을 몇억 들여 개발했고, 소련은 연필을 깎아 갔다

교수님이 세마포어를 소개하며 든 이야기예요. 앞의 복잡한 문제들을 아주 단순한 방법으로 처리했다는 뜻이에요. "세상에 참 머리 좋은 사람들이 많은 것 같아."

세마포어(semaphore)는 데이크스트라(Edsger Dijkstra)가 제안했어요. 화장실이 여러 칸이어도 사람들을 도착한 순서대로 한 줄로 세워서, 빈 칸이 생기면 맨 앞사람이 들어가게 해요. 그래서 뮤텍스와 달리 여러 개의 자원을 동시에 관리할 수 있고 진입 순서까지 제어할 수 있어요. 교수님: "오늘 내용의 가장 핵심이 되는 내용이 바로 세마포어라고 하는 거야."

쓰는 법은 세 줄, 속은 몇 줄 (그림 6-12, 6-13)

세마포어 사용법 → 내부 코드init(n);   // S = n;   사용 가능한 자원 개수로 초기화 (화장실 1칸이면 1, 2칸이면 2)
wait();    // if S <= 0 then pause();   자원이 없으면 일시정지(대기)
           // S = S - 1;                들어가면서 하나 쓴다고 빼기
임계구역
post();    // S = S + 1;   나오면서 하나 돌려놓고
           // wake_up();   기다리는 스레드가 있으면 깨운다

핵심은 S = 현재 사용할 수 있는 자원의 수예요. wait()는 뮤텍스의 lock(), post()는 unlock()에 해당해요. S가 0 이하면 남은 칸이 없으니 pause()로 멈춰서 세마포어 큐에서 기다리고, 누가 post()로 wake_up() 신호를 보내면 깨어나서 S를 1 빼고 들어가요.

  • 이진 세마포어(binary): init(1)인 경우. 자원 상태가 '비어 있음'과 '사용 중' 둘 중 하나라서 이렇게 불러요. 뮤텍스와 같아요.
  • 함수 이름: 처음엔 잠금에 p(), 해제에 v()를 썼는데 직관적이지 않아서 지금은 wait() · post()를 써요. post()는 signal()이라고도 해요.
  • wait() · post() 내부 코드도 도중에 문맥 교환이 일어나면 안 되니, 검사와 지정처럼 하드웨어 도움을 받아 분리 실행되지 않게 되어 있어요.

예금 예제를 세마포어로 (그림 6-14, init(1))

시험엔 이렇게

세마포어(semaphore)는 자원을 사용하려는 스레드가 세마포어 큐에 순서대로 대기하도록 하여 자원의 접근을 제어하는 동기화 도구로, 하나의 자원만 보호하는 뮤텍스와 달리 여러 개의 자원을 동시에 관리하고 진입 순서까지 제어할 수 있다. init(n)은 세마포어 변수 S(현재 사용할 수 있는 자원의 수)를 n으로 초기화하고, wait()는 S가 0 이하이면 pause()로 대기한 뒤 S를 1 감소시키고 진입하며, post()는 S를 1 증가시키고 wake_up()으로 대기 중인 스레드를 깨운다. init(1)인 경우를 이진 세마포어라 한다.

외우는 법: S = 빈 칸 수 · wait = 0 이하면 멈춤, 아니면 −1 · post = +1 하고 깨우기
바로 확인
init(3)으로 시작한 세마포어에 스레드 4개가 차례로 wait()를 호출했다. 네 번째 스레드는 어떻게 되고, 그때 S는?
3 → 2 → 1 → 0으로 세 스레드가 진입하고, 네 번째는 S가 0이라 pause(). 교재 코드에서는 pause 다음에 빼니까 S는 0에 머물러요. 누가 post()하면 1이 되고, 깨어나서 다시 0으로 만들고 들어가요.

세마포어를 사람이 잘못 쓰면? 그리고 1등이 꼴찌로 끝나는 이상한 일

세마포어 잘못 쓰는 사례 · 모니터(monitor) · synchronized(lock) ★ 밑줄 · 우선순위 역전 · 우선순위 상속 · 우선순위 상한

세마포어는 멀쩡한데, 쓰는 사람이 틀린다

세마포어 자체엔 문제가 없어요. 그런데 프로그래머가 실수하면 임계구역이 또 무너져요(그림 6-16).

  • 세마포어 없이 그냥 임계구역에 들어가는 경우
  • wait()와 post()를 뒤바꿔 쓰는 경우
  • wait()를 2번 쓰거나, post()를 2번 쓰는 경우

그래서 모니터 — 은행원에게 맡기기

교수님 비유: 은행원
두 사람이 예금에 직접 손대면 세마포어를 무조건 써야 하는데, 잘못 쓸 수가 있어요. 그러니까 은행원 한 명을 두고 "입금 좀 해 주세요" 하고 부탁해요. 은행원이 도착한 순서대로 큐에서 하나씩 처리해 주면 문제가 없죠. 그게 모니터예요.

모니터(monitor)는 공유 자원을 안전하게 보호하고 임계구역에 대한 동기화를 자동으로 처리하는 고수준 동기화 도구예요. 스레드는 직접 동기화 연산(lock/unlock, wait/post)을 하지 않고, 모니터를 통해서만 임계구역에 접근해요. 요청은 모니터 큐에 저장되어 순서대로 처리되고, 끝나면 결과를 알려 줘요.

코드 6-1 · 자바로 구현한 모니터 코드class MonitorCode {
    private int dep = 0;                      // 예금
    private Object lock = new Object();

    public void increase(int amt) {
        synchronized(lock) {                  // 임계구역 시작 ← 밑줄!
            dep = dep + amt;
            System.out.println(dep);
        }                                     // 임계구역 끝
    }
}
// 사용: 스레드 T1도 increase(10);  스레드 T2도 increase(10);  → 끝

synchronized(lock) { }으로 둘러싼 부분이 임계구역으로 보호돼요. 진입과 탈출을 이 한 줄이 알아서 처리하니까, 스레드는 그냥 increase(10)만 부르면 돼요. C로 짤 때처럼 우리가 직접 잠그고 풀 필요가 아예 없어요.

교수
synchronized(lock) 밑줄 쳐 놓으세요. 그게 뭐야, 임계구역을 시작하는 놈을 알려 주는 거야. 나중에 자바 책을 보다가 synchronized를 보시게 되면, 아 이게 운영체제의 모니터라고 하는 거구나 하고 이해하시면 될 것 같습니다.10/19 강의 중 (말을 조금 다듬음)

우선순위 역전 — 우선순위 1인 T1이 제일 늦게 끝난다

보통은 우선순위가 높은 스레드가 먼저 실행돼요. 그런데 임계구역이 끼면, 우선순위 낮은 스레드 때문에 높은 스레드가 늦어지는 일이 생겨요. 이게 우선순위 역전(priority inversion)이에요. 여기선 숫자가 작을수록 우선순위가 높아요(T1 > T5 > T9).

  1. 우선순위 9인 T9가 먼저 임계구역에 들어가 작업해요.
  2. 우선순위 1인 T1이 와서 임계구역에 들어가려 하지만, T9가 쓰고 있어 pause() 상태로 기다려요.
  3. 그 사이 우선순위 5인 T5가 생겨요. T5는 임계구역을 쓰지 않지만 T9보다 높으니 먼저 실행돼요. T9가 밀리니 T9를 기다리는 T1도 같이 밀려요.
  4. 결국 우선순위가 가장 높은 T1이 가장 늦게 실행돼요.

해결 방법은 두 가지예요.

  • 우선순위 상속(priority inheritance): T1이 공유 자원을 기다릴 때 T1의 우선순위를 T9에 물려줘요. T9가 우선순위 1로 작업하니 T5가 끼어들지 못하고, T9가 끝나면 T1이 바로 실행돼요. 교수님 설명도 이거예요. "T9의 우선순위를 T1까지 확 높여 주면" 해결된다고.
  • 우선순위 상한(priority ceiling): 임계구역을 쓰는 모든 스레드의 우선순위를 일정 수준까지 높여요. 그런데 얼마나 올릴지 계산하기 어렵고, 역전이 안 생기는 상황에서도 무조건 높이는 문제가 있어서, 보통은 단순하고 구현이 쉬운 우선순위 상속을 써요.

교수님 덧붙임: "이렇게 극단적인 예는 거의 없어요. 이론적으로 그렇다."

시험엔 이렇게

세마포어를 사용하지 않거나 wait()와 post()를 바꾸어 쓰거나 한쪽을 2번 쓰면 임계구역을 보호할 수 없다. 모니터(monitor)는 공유 자원을 안전하게 보호하고 임계구역에 대한 동기화를 자동으로 처리하는 고수준 동기화 도구로, 스레드는 모니터를 통해서만 임계구역에 접근하며 자바에서는 synchronized(lock){ }으로 둘러싼 코드가 임계구역으로 보호된다. 우선순위 역전(priority inversion)은 임계구역 때문에 우선순위가 높은 프로세스가 낮은 프로세스에 의해 지연되는 현상으로, 우선순위 상속이나 우선순위 상한으로 해결한다.

외우는 법: 모니터 = 은행원 = synchronized · 역전 = 1등이 꼴찌 → 9한테 1을 물려준다(상속)
바로 확인
T9(우선순위 9)가 임계구역을 쓰는 중이고, T1(우선순위 1)이 그걸 기다리고 있다. 우선순위 상속을 적용하면?
상속 = 기다리는 높은 놈(T1)의 우선순위를 자원을 쥔 낮은 놈(T9)에게 물려주는 것. 세 번째 보기는 우선순위 상한이에요.

★ 교재 별표 · 밑줄 · 시험 언급

① 문제 — 경쟁 상태와 임계구역 ★ 밑줄

  • 경쟁 상태 : 둘 이상의 스레드가 같은 공유 자원에 동시에 접근해 결과를 예측할 수 없게 되는 상황
  • 임계구역 : 둘 이상의 스레드가 동시에 접근해서는 안 되는 공유 영역
  • 동기화 : 임계구역에 대한 접근을 제어하는 과정
  • 예금 예시 : 10만 원씩 두 번 넣었는데 10만 원 · 생산자-소비자 : sum이 3이어야 하는데 2 또는 4

② 해결 조건 3개 ★ 별표

  • 상호 배제 : 한 스레드가 임계구역에 들어가면 다른 스레드는 들어갈 수 없다
  • 한정 대기 : 진입하려는 스레드 중 무한히 기다리는 스레드가 있으면 안 된다
  • 진행의 융통성 : 한 스레드의 작업이 다른 스레드의 진행을 방해하면 안 된다

③ 틀린 코드 → 위반 조건 1개 · 2개 · 번갈아

  • 잠금 1개 (6-6) : 검사와 잠금 사이에 잘려 둘 다 진입 → 상호 배제 위반
  • 잠금 2개 (6-7) : 둘 다 잠그고 서로 기다림 → 한정 대기 위반
  • lock 1/2 (6-8) : 반드시 번갈아 → 진행의 융통성 위반 = 경직된 동기화

④ 검사와 지정 · 뮤텍스 ★ 밑줄

  • 검사와 지정 : 검사와 잠금을 하드웨어 도움으로 원자적으로 실행 (test-and-set)
  • 뮤텍스 : MUTual EXclusion. mutex_lock()으로 잠그고 mutex_unlock()으로 해제. 자원 1개만 가능

⑤ 세마포어 ★ 오늘의 핵심

  • 세마포어 : 세마포어 큐에 순서대로 대기시켜 여러 자원을 관리하고 진입 순서까지 제어 (데이크스트라)
  • S : 현재 사용할 수 있는 자원의 수. init(n) → S = n
  • wait() : S ≤ 0이면 pause(), 아니면 S = S − 1 후 진입 · post() : S = S + 1, wake_up()
  • 이진 세마포어 : init(1). 뮤텍스와 같음 · 옛 이름 p() = wait(), v() = post() (= signal())

⑥ 모니터 · 우선순위 역전 ★ synchronized

  • 모니터 : 동기화를 자동으로 처리하는 고수준 도구. 모니터 큐로 순서대로 처리 (은행원)
  • synchronized(lock) : 자바 모니터의 핵심. 중괄호 안이 임계구역
  • 우선순위 역전 : 임계구역 때문에 높은 우선순위가 낮은 우선순위에 의해 지연 (T1이 가장 늦게)
  • 우선순위 상속 : 기다리는 높은 우선순위를 자원을 쥔 스레드에 물려줌 · 상한 : 임계구역 쓰는 모든 스레드를 일정 수준까지 올림

빈칸 채우기 눌러서 정답 확인

둘 이상의 스레드가 같은 공유 자원에 동시에 접근해 결과를 예측할 수 없는 상황을 경쟁 상태라 하고, 동시에 접근하면 안 되는 공유 영역을 임계구역이라 한다. 임계구역 해결 조건은 상호 배제 · 한정 대기 · 진행의 융통성이며, lock 값으로 번갈아 들어가는 코드는 진행의 융통성을 위반한다. 검사와 잠금을 하드웨어 도움으로 원자적으로 실행하는 것을 검사와 지정이라 한다. 세마포어의 S는 현재 사용할 수 있는 자원의 수이며, wait()는 S가 0 이하면 pause()로 대기하고, post()는 S를 1 증가시키고 wake_up()을 보낸다. init(1)인 세마포어를 이진 세마포어라 한다. 자바 모니터에서 임계구역은 synchronized(lock)으로 둘러싸고, 낮은 우선순위 스레드에 높은 우선순위를 물려주는 해결법은 우선순위 상속이다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
경쟁 상태란?
둘 이상의 스레드가 동일한 공유 자원에 동시에 접근하여 실행 결과를 예측할 수 없게 되는 상황.
임계구역이란?
둘 이상의 스레드가 동시에 접근해서는 안 되는 공유 영역. 결과에 중대한(critical) 영향을 미쳐서 이렇게 부른다.
동기화란?
임계구역에 대한 접근을 제어하는 과정. 그래서 임계구역 문제는 곧 동기화 문제.
임계구역 해결 조건 3개는?
상호 배제(한 명만), 한정 대기(무한 대기 금지), 진행의 융통성(다른 스레드의 진행을 방해하면 안 됨).
잠금 1개 · 잠금 2개 · lock 1/2 번갈아 코드는 각각 어떤 조건을 위반?
상호 배제 위반 · 한정 대기 위반 · 진행의 융통성 위반(경직된 동기화).
경직된 동기화란?
스레드가 반드시 번갈아 실행되어 서로의 진행을 방해하는 현상 (lockstep synchronization).
검사와 지정(test-and-set)이란?
잠금 확인(test)과 잠금 설정(set)을 하드웨어의 도움으로 원자적으로 실행해, 그 사이에 문맥 교환이 일어나지 않게 하는 방식.
뮤텍스란? 한계는?
MUTual EXclusion의 약자. mutex_lock()으로 잠그고 mutex_unlock()으로 해제하는 기본 동기화 도구. 하나의 공유 자원에 대해서만 동기화할 수 있다.
세마포어가 뮤텍스보다 나은 점 2가지는?
여러 개의 자원을 동시에 관리할 수 있고, 세마포어 큐로 스레드의 진입 순서까지 제어할 수 있다.
세마포어 wait()와 post()의 내부 코드는?
wait(): if S <= 0 then pause(); S = S − 1; · post(): S = S + 1; wake_up();
init(2), 스레드 3개가 차례로 wait()하면?
T1 진입(S = 1), T2 진입(S = 0), T3 pause(). 누가 post()하면 T3가 깨어나 진입하고, 모두 끝나면 S = 2로 복원.
모니터란?
공유 자원을 안전하게 보호하고 임계구역 동기화를 자동으로 처리하는 고수준 동기화 도구. 스레드는 모니터를 통해서만 임계구역에 접근. 자바 synchronized.
우선순위 역전이란? 해결법은?
임계구역 때문에 높은 우선순위 프로세스가 낮은 우선순위 프로세스에 의해 지연되는 현상. 우선순위 상속, 우선순위 상한.
