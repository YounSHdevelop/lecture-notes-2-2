프로세스는 혼자 생기지 않고 부모가 자식을 낳으며 생겨요. 그 "낳는" 시스템 콜이 fork, 남의 집에 들어가 내 코드로 바꿔치기하는 게 exec예요. 짧은 C 코드가 실제로 몇 번, 어떤 순서로 출력되는지 따라가 보는 날이에요.

컴퓨터를 껐다 켜면 왜 빨라질까?

가비지 컬렉션 · 부모-자식 관계 · init(PID 1)

프로세스가 끝나면 그 자리를 누가 치워 줘야 해요. 식당에서 손님이 나가면 그릇을 치워야 다음 손님이 앉는 것처럼요. 이걸 가비지 컬렉션(쓰레기 치우기)이라고 해요. 그런데 프로세스가 수백 개씩 생겼다 사라지니까 OS가 다 못 치우면 메모리 여유 공간이 줄어서 느려져요. 껐다 켜면 메모리가 리셋되니까 다시 빨라지는 거예요.

그래서 모든 프로세스는 혼자 생기지 않고 부모-자식 관계를 가져요. 자식이 끝날 때 부모에게 "저 이제 갈게요" 하고 알리면, 부모가 자식이 쓰던 자원을 치우거나 OS에게 치워 달라고 알릴 수 있죠. OS가 전부 지켜보지 않아도 뒷정리가 잘 돼요.

계속 거슬러 올라가면 모든 프로세스의 조상이 나와요. 유닉스에서는 init, PID가 1번이에요. 컴퓨터를 켜면 init부터 생기고, 끌 때는 맨 아래 자식부터 차례로 죽어 올라가서 마지막에 init이 끝나면 전원이 꺼져요.

시험엔 이렇게

모든 프로세스는 부모-자식 관계를 가지며, 자식이 종료를 부모에게 알려 부모가 자원을 정리(가비지 컬렉션)할 수 있게 한다. 유닉스의 최상위 프로세스는 PID 1인 init이다.

바로 확인

자식이 끝나면 부모에게 알리고, 부모가 자원을 치우거나 OS에 알려서 가비지 컬렉션이 원활해져요.

손님 100명이 동시에 로그인하면, 로그인 프로그램은 어떻게 다 받을까?

fork 시스템 콜 · 메모리 안에서 복사 · PID · PPID · CPID

크롬을 처음 켤 땐 하드디스크에서 코드와 데이터를 가져오고 PCB도 만들어야 해서 살짝 느려요. 그런데 새 창은 하드디스크에서 안 가져오고 메모리 안에서 그대로 복사해요. 그래서 빨라요. 이때 쓰는 시스템 콜이 fork예요.

교수님 비유 — 손님이 너무 많은 중국집 주방장이 꾀를 부려요. 짜장면 하나를 만들어 놓고 "포크!" 하면 똑같은 짜장면이 하나 더 생겨요. 안 만들어도 되니 빨라요. 원본은 부모, 새로 생긴 건 자식. fork는 아이를 낳는 것과 같아요.

왜 중요할까요? 로그인 프로그램을 생각해 봐요. 우리가 짠 코드는 위에서 아래로 한 줄씩 돌아서, 한 명 처리가 끝나야 다음 사람을 받아요. 네이버에 100명이 동시에 로그인하는데 "줄 서세요" 할 순 없죠. 그래서 새 사람이 올 때마다 fork로 로그인 자식을 하나씩 낳아서 맡겨요. 100명이면 자식 100개가 동시에 처리하죠. 그래서 fork가 병렬 처리의 핵심이에요.

복사하면 똑같은데, 딱 하나 다른 것

fork하면 코드 영역, 데이터 영역, PCB가 거의 그대로 복사돼요. 단, PID는 달라요. 아버지와 내 주민등록번호가 다른 것처럼요. 그리고 PCB에는 부모 번호 PPID와 자식 번호 CPID도 적혀 있어요.

시험엔 이렇게

fork는 실행 중인 프로세스를 메모리 안에서 그대로 복사해 자식 프로세스를 만드는 시스템 콜이다. 하드디스크에서 가져오지 않아 빠르고, 코드·데이터·PCB가 복사되지만 PID는 다르며 PPID·CPID로 부모-자식 관계가 기록된다. 병렬 처리의 핵심이다.

외우는 법: 포크 = 짜장면 복사 = 아이 낳기, 다른 건 PID 하나
바로 확인

fork는 코드·데이터·PCB를 그대로 복사하지만 PID는 새로 받아요. 그리고 부모 PCB의 CPID, 자식 PCB의 PPID로 서로를 기록해요.

장면 3

printf가 if와 else에 하나씩인데, 왜 둘 다 찍힐까?

fork의 반환값(0 / 양수 / −1) · wait와 출력 순서

교수님이 "오른쪽 코드는 손으로 가리고 왼쪽만 읽어 보라"고 한 코드예요.

교재 fork 예제 (요지)int main() {
    int pid;
    pid = fork();                 // 이 순간 프로세스가 2개가 된다
    if (pid == 0)                 // 자식은 0을 받음
        printf("Child\n");
    else if (pid > 0) {           // 부모는 양수(자식의 PID)를 받음
        wait(NULL);               // 자식이 끝날 때까지 기다림
        printf("Parent\n");
    }
    else                          // −1: fork 실패
        printf("fork failed\n");
    return 0;
}

if 문만 보면 printf는 한 번만 찍혀야 정상이죠. 그런데 fork()를 만나는 순간 똑같은 코드가 옆에 하나 더 생겨서 프로세스가 2개가 돼요. fork는 부모에게는 양수(자식의 PID), 자식에게는 0을 돌려줘요. 실패하면 −1.

  • 자식은 pid == 0 → Child를 찍어요.
  • 부모는 pid > 0 → 그래서 코드는 하나지만 출력은 2줄이에요.

누가 먼저 찍힐까?

부모와 자식은 독립된 프로세스라서 원래는 누가 먼저 실행될지 아무도 몰라요(대부분 부모가 먼저지만 가끔 자식이 먼저). 그런데 위 코드는 부모가 wait로 자식이 끝날 때까지 기다린 뒤 찍어요. 그래서 이 코드는 항상 Child → Parent 순서예요.

경우출력 줄 수순서
wait 있음 (위 코드)2줄Child → Parent 고정
wait 없음2줄보장 안 됨 (누가 먼저일지 모름)
시험엔 이렇게

fork는 부모 프로세스에게 자식의 PID(양수)를, 자식 프로세스에게 0을 반환하고 실패하면 −1을 반환한다. 부모와 자식은 독립적으로 실행되어 순서가 보장되지 않으며, 부모가 wait를 호출하면 자식이 끝난 뒤 부모가 진행된다.

외우는 법: 자식은 0(갓난아기), 부모는 양수 · wait = 자식 먼저
바로 확인
위 코드에서 wait(NULL); 줄을 지우면 출력은?
fork 뒤엔 여전히 프로세스 2개라 2줄. wait가 없으니 독립적으로 돌아서 순서는 모른다예요.

부모가 기다려 주지 않고 먼저 끝나 버리면?

return 0 · wait · 고아 프로세스 · 좀비 프로세스

C에서 main 끝에 return 0;을 쓰라고만 배웠죠? 이제 이유가 보여요. 우리 C 프로그램도 누군가의 자식이에요. 다 끝났으면 부모에게 "나 정상적으로 끝나고 돌아가요"라고 알려야 하는데, 그게 return 0(정상 종료)이에요. (안 써도 동작하는 건 컴파일러가 강제로 넣어 주기 때문이에요.)

부모는 자식이 돌아올 때까지 기다려 줘야 해요. 그 장치가 wait예요. wait는 자식의 return 0을 받아 주는 자리죠.

  • 부모가 기다리지 않고 먼저 종료하면, 나중에 자식이 신호를 보내도 받을 부모가 없어요. 부모 없는 자식 = 고아 프로세스.
  • OS가 고아를 발견해 정리하면 괜찮은데, 놓치면 일은 안 하는데 계속 살아 있는 좀비 프로세스가 돼요.
  • 좀비가 쌓였다 = 가비지 컬렉션이 제대로 안 됐다 → 컴퓨터가 느려져요.
시험엔 이렇게

자식은 return(exit)으로 종료를 부모에게 알리고 부모는 wait로 이를 받는다. 부모가 먼저 종료되면 자식은 고아 프로세스가 되고, 정리되지 못한 채 남으면 좀비 프로세스가 되어 자원을 낭비한다.

외우는 법: 부모가 먼저 가면 고아, 아무도 안 치우면 좀비
바로 확인
작업은 끝났는데 아무도 정리해 주지 않아 시스템에 계속 남아 있는 프로세스는?
부모가 먼저 끝나서 부모 없는 상태가 고아, 그 고아가 정리되지 않고 남아 버린 게 좀비예요.

짜장면만 복사하던 주방에 "짬뽕 주세요"가 들어오면?

exec 시스템 콜 · 코드 교체 · 셸 · fork + exec
교수님 비유 — 짜장면을 포크로 하나 복사해 놓고, 그 짜장면한테 "넌 짬뽕이야, 넌 짬뽕이야" 하고 우기는 거예요. 그러면 짬뽕이 돼요. 이렇게 원래 있던 코드를 새 코드로 바꿔치기하는 시스템 콜이 exec예요.

왜 필요할까요? 로그인에 성공하면 이제 명령어를 받아 처리할 셸이 필요해요. 원래대로라면 ① 로그인 프로세스를 종료하고 메모리·PCB를 치운 뒤 ② 셸을 하드디스크에서 가져와 새 PCB를 만들어야 해요. 두 번 일이죠. 대신 로그인이 쓰던 메모리 영역과 PCB를 그대로 두고 코드만 셸로 바꿔치기하면, 남이 살던 집에 그대로 들어가 사는 셈이에요. 메모리 관리도 편하고 부모-자식 관계도 그대로 유지돼요.

forkexec
하는 일프로세스를 복사해 새 자식을 만든다코드를 새 프로그램으로 바꿔치기
PCB복사(PID는 새로)그대로(PID 안 바뀜)
코드 영역그대로 복사새 코드로 교체
데이터 영역그대로 복사리셋
exec 예제printf("Before exec\n");
execlp("ls", "ls", NULL);     // 이 순간 코드가 ls로 통째로 바뀜
printf("After exec\n");       // 찍히지 않는다 — 이 줄은 이미 사라진 코드

출력은 Before exec, 그다음 ls가 찍어 주는 파일 이름(예: a.c)뿐이에요. exec 아래 코드는 ls 코드로 다 덮여서 After exec은 안 찍혀요.

내 C 프로그램이 실행되는 진짜 과정

  1. 컴퓨터를 켜면 init이 생기고, fork + exec로 OS 관련 프로세스들을 만들어요.
  2. 로그인 프로세스가 생기고, 통과하면 exec로 셸이 돼요.
  3. 내가 my.c를 실행하면 셸이 fork로 자식 셸을 낳고, 그 자식을 exec로 내 코드로 바꿔요.
  4. 내 코드가 return 0을 하면 부모 셸로 돌아가요. 그래서 return 0을 쓰라고 한 거예요.

fork와 exec를 섞은 교재 마지막 코드도 같은 원리예요. 자식은 exec로 ls가 되어 파일 목록을 찍고, 부모는 wait로 기다렸다가 자식이 끝난 뒤에 마지막 줄을 찍어요.

시험엔 이렇게

exec는 기존 프로세스의 코드 영역을 새 프로그램으로 교체하는 시스템 콜이다. PCB(PID)는 그대로 유지되고 코드는 교체, 데이터 영역은 초기화되며, 새 프로세스를 만들지 않으므로 부모-자식 관계가 유지된다. exec 이후의 원래 코드는 실행되지 않는다.

외우는 법: fork는 복사, exec는 바꿔치기 · 셸은 fork 하고 exec
바로 확인
exec를 호출한 뒤에도 바뀌지 않는 것은?
exec는 새 프로세스를 만들지 않고 집(PCB)은 그대로 둔 채 코드만 바꿔요. 데이터 영역은 새 코드용으로 리셋돼요.

  • exec 뒤 원래 코드는 실행 X · 셸 = fork + exec

빈칸 채우기 눌러서 정답 확인

유닉스에서 모든 프로세스의 조상은 PID 1인 init이다. 실행 중인 프로세스를 그대로 복사해 자식을 만드는 시스템 콜은 fork이며, 이 함수는 자식에게 0을, 부모에게는 자식의 PID(양수)를 반환한다. 부모가 자식이 끝날 때까지 기다리게 하는 것은 wait다. 부모가 먼저 종료된 자식은 고아 프로세스가 되고, 정리되지 못하고 남으면 좀비 프로세스가 된다. 코드 영역을 새 프로그램으로 바꿔치기하는 시스템 콜은 exec이다.

컴퓨터를 껐다 켜면 빨라지는 이유는?
끝난 프로세스 자리를 다 못 치워(가비지 컬렉션 부족) 줄었던 메모리 여유 공간이 리셋되기 때문.
부모-자식 관계를 만드는 이유는?
자식이 끝날 때 부모에게 알려 부모가 자원을 정리(또는 OS에 요청)할 수 있게 하려고.
유닉스 최상위 프로세스와 PID는?
init, PID 1.
fork란?
실행 중인 프로세스를 메모리 안에서 복사해 자식 프로세스를 만드는 시스템 콜. 병렬 처리의 핵심.
fork의 반환값은?
자식에게 0, 부모에게 자식의 PID(양수), 실패하면 −1.
fork 후 부모와 자식이 다른 것은?
PID. (PCB에 PPID·CPID로 서로 기록)
wait의 역할은?
부모가 자식이 종료(return)할 때까지 기다리게 한다. 그래서 자식 출력이 먼저 나온다.
고아 프로세스와 좀비 프로세스는?
고아 = 부모가 먼저 종료된 자식. 좀비 = 정리되지 못하고 시스템에 남은 프로세스.
return 0의 의미는?
부모에게 정상 종료를 알리는 것.
exec란?
프로세스의 코드를 새 프로그램으로 교체하는 시스템 콜. PCB 그대로, 코드 교체, 데이터 리셋.
exec를 쓰는 이점은?
프로세스를 종료·새로 생성하지 않아 메모리 관리가 편하고 부모-자식 관계가 유지된다.

    퀴즈 다 풀고 채점하기

    Q1다음 코드의 출력 줄 수는? int main(){ fork(); printf("A\n"); return 0; }

    fork 이후 부모와 자식 둘 다 printf를 실행해요. A가 2번 찍혀요.

    Q2fork 직후 자식 프로세스의 pid 변수 값은?

    fork는 자식에게 0, 부모에게 자식의 PID(양수)를 돌려줘요. −1은 실패.

    Q3장면 3 코드(부모가 wait 후 출력)의 출력 순서는?

    부모가 wait로 자식이 끝날 때까지 기다린 뒤 찍으니까 항상 자식이 먼저예요.

    Q4다음 코드의 출력은? printf("1\n"); execlp("ls","ls",NULL); printf("2\n"); (현재 폴더에 a.c만 있음)

    exec 순간 코드가 ls로 바뀌어서 그 아래 printf("2")는 사라져요. 1과 ls 결과(a.c)만 나와요.

    Q5로그인 성공 후 셸을 만들 때 "로그인을 종료하고 셸을 새로 만드는" 대신 exec를 쓰는 이유가 아닌 것은?

    exec는 PCB를 그대로 쓰니까 PID도 그대로예요. 새 PID를 주는 건 fork.

    Q6부모가 wait 없이 먼저 종료됐고, OS도 그 자식을 놓쳐 계속 남아 있다. 이 자식은?

    부모 없는 고아가 정리되지 못하고 남으면 좀비. 쌓이면 컴퓨터가 느려져요.

    내 말로 설명하기 친구한테 말하듯이

    셸에서 내 C 프로그램을 실행하면 fork와 exec가 어떻게 쓰이는지, return 0이 왜 필요한지까지 설명해 보세요.

    셸은 내 프로그램을 실행할 때 먼저 fork로 자기 자신을 복사해 자식 셸을 낳아요. 그다음 그 자식에게 exec를 해서 코드만 내 C 프로그램으로 바꿔치기해요. 그래서 내 프로그램은 자식 셸의 PCB와 메모리 영역 안에서 돌고, 셸과 부모-자식 관계를 가져요. 다 끝나면 return 0으로 부모 셸에게 정상 종료를 알리고, 부모는 wait로 그걸 받아 뒷정리를 해요. 알리지 않으면 정리가 안 돼서 좀비가 남을 수 있어요.
    더 알아두면 좋은 것 시험 비중 낮음

    시그널

    자식이 return하면 부모의 wait에게 신호가 가는데, 이걸 시그널이라고 해요. 상대를 죽이는 SIGKILL 같은 종류도 있어요. 예전엔 3학년 시스템 프로그래밍 과목에서 직접 실습했다는 얘기였어요.

    PID 0

    사실 0번(스와퍼)도 있지만 보이지 않아서, 보이는 프로세스는 1번 init부터예요. 우리가 만드는 프로세스는 보통 만 번대 번호를 받아요.
