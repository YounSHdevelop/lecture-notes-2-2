시험엔 이렇게

고수준 스케줄링(장기·작업 스케줄링)은 작업의 승인·거부를, 중간 수준 스케줄링은 보류·활성화로 활성 프로세스 수를 조절한다. 저수준 스케줄링(단기 스케줄링)은 준비 상태의 프로세스 중 하나를 선택(디스패치)해 실행 상태로 전환하는 단계이며, CPU 스케줄링은 일반적으로 저수준 스케줄링을 의미한다.

작업 중인 프로세스한테서 CPU를 뺏을 수 있을까, 없을까?

선점형(preemptive) · 비선점형(non-preemptive) ★★★★★

스케줄링에서 가장 중요한 단어 두 개예요.

  • 선점형 스케줄링 — 스케줄러가 실행 중인 프로세스의 CPU를 강제로 빼앗아 다른 프로세스에 줄 수 있어요. 대표 예가 시분할 시스템이에요. 각 프로세스는 CPU를 일정 시간(타임 슬라이스)만 쓰고 다음 프로세스에 양보하죠. 인터럽트가 생겨도 현재 작업을 멈추고 인터럽트를 처리한 뒤 원래 작업으로 돌아가요.
  • 비선점형 스케줄링 — 프로세스가 CPU를 잡으면 작업이 끝날 때까지 빼앗을 수 없어요. 9/9에 "꼭 기억하라"던 과거 일괄 작업(배치) 시스템에서 주로 쓰였어요.
선점형비선점형
CPU 빼앗기가능불가능 (끝날 때까지)
단점문맥 교환 같은 부가적인 작업으로 낭비가 생김실행 시간이 긴 프로세스가 있으면 짧은 프로세스들이 오래 기다려야 해서 처리율이 떨어짐
장점한 프로세스가 CPU를 독점하지 않아 빠른 응답문맥 교환이 적어 오버헤드가 작음
어디에대화형·시분할 시스템, 대부분의 저수준 스케줄러과거 일괄 작업 시스템

"요즘 일괄 작업 시스템은 거의 없다던데요?" — 거의 없다는 거지 안 쓴다는 건 아니에요. 교재 예: 선점형 시스템에서도 시스템 백업 프로세스는 중단 없이 실행돼야 하니까 비선점형으로 처리해요. 대신 우선순위를 낮게 잡아 시스템 성능에 주는 영향을 줄여요.

그래서 알고리즘도 이 순서로 나와요. 비선점형이 먼저(옛날, 배치 시절), 선점형이 나중(시분할 시절). 앞의 것의 단점을 뒤의 것이 고치는 흐름이라, 교수님은 "하나의 이야기로 엮어서 외우라"고 했어요.

짝으로 보면 이야기가 돼요. 선점형의 기본은 라운드 로빈(도착 순서대로 받지만 타임 슬라이스를 다 쓰면 큐 맨 뒤로)이고, SJF를 선점형으로 바꾼 게 SRT, 고정형 우선순위를 쓰는 다단계 큐의 단점을 고친 게 다단계 피드백 큐예요.

시험엔 이렇게

선점형 스케줄링은 스케줄러가 실행 중인 프로세스의 CPU를 강제로 빼앗아 다른 프로세스에 할당할 수 있는 방식으로, 문맥 교환 같은 부가 작업의 낭비가 있지만 CPU 독점이 없어 빠른 응답이 필요한 대화형·시분할 시스템에 적합하다. 비선점형 스케줄링은 프로세스가 CPU를 사용하면 작업이 끝날 때까지 빼앗을 수 없는 방식으로, 오버헤드는 작지만 실행 시간이 긴 프로세스 때문에 짧은 프로세스가 오래 기다리는 문제가 있으며 과거 일괄 작업 시스템에서 사용되었다.

수학 계산만 하는 프로그램과 파일 복사만 하는 프로그램, 누구를 먼저?

우선순위의 개념과 필요성 ★ · CPU 집중 vs I/O 집중 · 전면 vs 후면 · 변동 우선순위

우선순위가 없다는 건 모든 프로세스의 중요도가 같다는 뜻이에요. 그러면 다들 한 줄로 서서 순서대로 실행되는데, 커널 프로세스와 사용자 프로세스를 같은 순위로 처리하면 중요한 커널 작업이 제때 실행되지 않아 시스템이 불안정해질 수 있어요. 그래서 CPU 스케줄러는 우선순위를 기반으로 스케줄링해요. 우선순위가 높은 프로세스가 먼저 실행되고 더 오래 CPU를 차지해요.

커널 프로세스가 사용자 프로세스보다 높고, 사용자 프로세스끼리도 달라요. 교재 예: 문서 편집기와 비디오 플레이어 중엔 비디오 플레이어가 더 높아요. 사람의 입력 속도는 CPU보다 훨씬 느려서 문서 편집기는 조금 느려져도 괜찮지만, 비디오 플레이어는 실시간으로 데이터를 가져와 영상과 소리를 내야 해서 자주 실행되지 않으면 화면이 끊기거든요. 윈도우에서는 작업 관리자에서 사용자가 직접 우선순위를 바꿀 수 있어요. 비디오를 "매우 높음"으로 올리면 영상은 안 끊기지만 카톡·한글은 반응이 느려지죠.

CPU 집중 vs I/O 집중 — 누구에게 줄까?

수학 연산처럼 CPU를 많이 쓰는 CPU 집중 프로세스(CPU-bound)는 입출력이 거의 없어서 자기 타임 슬라이스 동안 계속 실행 상태에 머물 확률이 높아요. 저장장치에서 데이터를 복사하는 것처럼 입출력이 많은 I/O 집중 프로세스(I/O-bound)는 대기 상태로 옮겨 갈 가능성이 높고요(C 드라이브 → D 드라이브로 큰 파일 옮기기).

  • CPU 집중을 먼저 주면 → 타임아웃까지 CPU만 쭉 써요. I/O 집중은 그게 끝날 때까지 기다려야 해요.
  • I/O 집중을 먼저 주면 → CPU를 잡자마자 I/O를 요청하고 대기 상태로 빠져요. 그럼 CPU 집중이 거의 바로 이어서 CPU를 써요. I/O와 계산이 겹쳐서 진행되니 효율이 올라가요.

그래서 I/O 집중 프로세스에 우선순위를 더 주는 게 시스템 효율에 좋아요.

시험엔 이렇게

I/O 집중 프로세스에 높은 우선순위를 주면, I/O를 요청해 대기 상태로 간 사이 CPU 집중 프로세스가 CPU를 사용하므로 시스템 효율이 향상된다. 커널 > 일반, 전면 > 후면, 대화형 > 일괄 작업, I/O 집중 > CPU 집중 순으로 우선순위를 준다.

준비 상태의 PCB들은 그냥 한 줄로 서 있을까?

우선순위별 준비 큐 · 장치별 대기 큐 · 큐를 포함한 상태 전이 흐름(그림 5-10) ★ · 링크드 리스트

9/28엔 준비 상태를 그냥 "기다리는 곳"이라고만 했죠. 실제로는 커널·일반, 높고 낮은 우선순위가 뒤섞여 있어서 한 줄로 서 있으면 매번 누가 제일 높은지 찾아야 해요. 그래서 우선순위별로 줄을 따로 세워요. 0번 줄에 PCB들을 엮고, 1번 줄에 엮고… 0번 줄부터 하나씩 꺼내 CPU를 주고, 다 처리되면 1번 줄로 내려가요. 작업이 안 끝나면 자기 줄 맨 뒤로 다시 가고요. 이게 준비 큐(우선순위 큐)예요.

대기 큐도 마찬가지예요. I/O는 하드디스크·네트워크·키보드·사운드카드처럼 종류가 많죠. 뒤섞여 있으면 "네트워크 I/O가 끝났다"는 신호가 왔을 때 누구 건지 일일이 찾아야 해요. 그래서 장치(디바이스)별로 요청한 순서대로 줄을 서요. 하드디스크가 끝나면 하드디스크 줄만 보면 되죠.

교재 그림 5-8·5-9를 보면 각 큐는 head와 tail을 갖고, PCB의 pointer가 다음 PCB를 가리키다가 마지막은 null로 끝나요. 교재 그림 5-10처럼 PCB는 준비 상태의 다중 큐에 들어갔다가 CPU 스케줄러가 실행 상태로 옮기고, 입출력을 요청하면 대기 상태의 다중 큐로, 입출력이 끝나면 다시 준비 상태의 다중 큐로 돌아가요. 이 과정 전체를 CPU 스케줄러가 관리해요.

이 줄들은 전부 포인터로 엮은 링크드 리스트예요. OS 자료구조는 거의 다 링크드 리스트라, C에서 포인터를 그렇게 강조한 거예요. (배열은 파일 시스템 쪽에서나 보여요.)

시험엔 이렇게

준비 상태에는 우선순위별로 구분된 준비 큐가 있고 준비 상태로 들어오는 프로세스는 자기 우선순위에 해당하는 큐에 삽입된다. 대기 상태에는 입출력 장치마다 별도의 대기 큐가 있어 입출력이 끝나 인터럽트가 오면 해당 PCB를 쉽게 찾아 준비 상태로 옮긴다. 큐는 PCB를 포인터로 연결한 연결 리스트이며, 이 전체 과정을 CPU 스케줄러가 관리한다.

대기 시간 · 응답 시간 · 반환 시간 · 평균 대기 시간 · FCFS · 콘보이 효과 ★

비교하려면 기준이 있어야겠죠. 교재에 CPU 사용률, 처리량, 대기 시간, 응답 시간, 반환 시간이 나와요.

  • 대기 시간 — 프로세스가 도착해서 CPU를 처음 잡기까지 기다린 시간. 식당 밖에서 줄 선 시간이에요.
  • 응답 시간 — 실행돼서 첫 결과(첫 printf)가 나오기까지. 프로그램마다 달라서 좀 애매해요.
  • 반환 시간 — 도착부터 작업이 다 끝날 때까지 전부. 대기 시간 + 실행 시간.

이 수업에서는 평균 대기 시간으로 비교해요. 교재 정의: 모든 프로세스의 대기 시간을 합한 뒤 프로세스 수로 나눈 값. 같은 작업 패턴에서 짧을수록 좋은 알고리즘이에요. 다만 교재는 평균 대기 시간이 절대적인 성능 지표는 아니라고 덧붙여요. 어떤 작업 패턴에서 A가 B보다 짧아도 다른 패턴에선 반대일 수 있어서, 동작 방식과 환경도 같이 봐야 해요.

FCFS — 먼저 온 놈이 먼저 먹고 간다

FCFS(First Come First Served, 선입선출)는 준비 큐에 도착한 순서대로 CPU를 할당하는 방식으로, 일괄 작업 시스템에서 쓰였어요. 비선점형이라 한 번 CPU를 받은 프로세스는 작업이 끝날 때까지 CPU를 반환하지 않고, 모든 프로세스의 우선순위가 같아요. 교재 말풍선 그대로 "들어온 순서대로 끝까지 작업한 후 종료한다". 가장 단순하고 가장 옛날 방식이에요.

FCFS의 약점 — 콘보이 효과

P3는 실행 시간이 9밖에 안 되는데 42나 기다렸어요. 앞에 긴 P1·P2가 있어서죠. 이렇게 처리 시간이 긴 프로세스 때문에 뒤의 짧은 프로세스들이 줄줄이 오래 기다리는 현상을 콘보이 효과(호위 효과)라고 해요. 컨베이어 벨트처럼 앞이 막히면 뒤가 다 밀리는 거예요. 그래서 FCFS는 지금은 거의 안 써요.

같은 세 작업(24, 3, 3)이 동시에 도착했을 때 순서만 바꿔 봐도 차이가 커요.

도착 순서각 대기 시간평균 대기 시간
24 → 3 → 3 (긴 게 먼저)0, 24, 2751 ÷ 3 = 17
3 → 3 → 24 (짧은 게 먼저)0, 3, 69 ÷ 3 = 3

"짧은 걸 먼저 하면 평균이 확 줄어드네?" — 이 생각이 다음 알고리즘(SJF)으로 이어져요.

시험엔 이렇게

FCFS는 준비 큐에 도착한 순서대로 CPU를 할당하는 비선점형 알고리즘으로, 일괄 작업 시스템에서 사용되었으며 모든 프로세스의 우선순위가 동일하다. 대기 시간 = 시작 시각 − 도착 시각, 평균 대기 시간 = 대기 시간의 합 ÷ 프로세스 수. 처리 시간이 긴 프로세스 때문에 짧은 프로세스가 오래 기다리는 콘보이 효과가 생긴다.

외우는 법: 간트 차트 → 시작 − 도착 → 더하고 나누기
바로 확인
P1(도착 0, 실행 8), P2(도착 2, 실행 4), P3(도착 3, 실행 5)를 FCFS로 처리한다. 평균 대기 시간은?
간트 차트: P1 0~8, P2 8~12, P3 12~17. 대기 = 시작 − 도착: P1 0, P2 8 − 2 = 6, P3 12 − 3 = 9. 평균 = (0 + 6 + 9) ÷ 3 = 5. 도착 시각을 빼는 걸 잊으면 (0 + 8 + 12) ÷ 3 ≈ 6.67로 틀려요.

빈칸 채우기 눌러서 정답 확인

준비 상태의 프로세스 중 CPU를 줄 프로세스를 고르는 것은 저수준 스케줄링이다. 실행 중인 프로세스의 CPU를 빼앗을 수 있으면 선점형, 빼앗을 수 없으면 비선점형 스케줄링이다. 시스템 효율을 위해 I/O 집중 프로세스에 더 높은 우선순위를 준다. 대기 상태의 PCB는 장치별 대기 큐에 연결된다. 도착한 순서대로 CPU를 주는 알고리즘은 FCFS이며, 긴 프로세스 때문에 짧은 프로세스가 오래 기다리는 현상을 콘보이 효과라 한다. 알고리즘 비교에는 평균 대기 시간을 쓴다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
스케줄링 3단계와 이 장에서 다루는 것은?
고수준(장기·작업, 승인·거부), 중간 수준(보류·활성화로 부하 조절), 저수준(단기, 준비 상태 중 하나를 디스패치). CPU 스케줄링은 일반적으로 저수준을 의미.
선점형 스케줄링이란? 장단점은?
스케줄러가 실행 중인 프로세스의 CPU를 강제로 빼앗아 다른 프로세스에 할당하는 방식(시분할). 단점: 문맥 교환 같은 부가 작업의 낭비. 장점: CPU 독점이 없어 빠른 응답.
비선점형 스케줄링이란? 장단점은?
프로세스가 CPU를 사용하면 작업이 끝날 때까지 빼앗을 수 없는 방식(과거 일괄 작업 시스템). 장점: 문맥 교환이 적어 오버헤드가 작음. 단점: 긴 작업 때문에 짧은 작업이 오래 기다림.
우선순위가 없으면 생기는 문제는?
모든 프로세스의 중요도가 같아 한 줄로 순차 실행되므로, 중요한 커널 작업이 적절한 시점에 실행되지 않아 시스템이 불안정해질 수 있다.
비선점형 알고리즘 3개, 선점형 4개는?
비선점형: FCFS, SJF, HRN. 선점형: 라운드 로빈, SRT, 다단계 큐, 다단계 피드백 큐.
I/O 집중 프로세스에 우선순위를 더 주는 이유는?
I/O 요청 후 바로 대기로 빠져 CPU를 비켜 주므로 CPU 집중 프로세스와 겹쳐 진행돼 효율이 올라간다.
우선순위를 더 받는 쪽 4쌍은?
커널 > 일반, 전면 > 후면, 대화형 > 일괄 작업, I/O 집중 > CPU 집중.
준비 큐와 대기 큐는 어떻게 줄 서나?
준비 큐 = 우선순위별, 대기 큐 = I/O 장치별. 모두 링크드 리스트.
대기 시간과 반환 시간은?
대기 = CPU를 처음 받기까지 기다린 시간(시작 − 도착). 반환 = 도착부터 끝까지(대기 + 실행).
FCFS란?
준비 큐에 도착한 순서대로 CPU를 할당하는 비선점형 알고리즘(선입선출). 일괄 작업 시스템에서 사용, 모든 프로세스의 우선순위가 동일.
콘보이 효과란?
처리 시간이 긴 프로세스 때문에 뒤의 짧은 프로세스들이 오래 기다리는 현상(FCFS의 약점).

    Q1다음 중 비선점형 스케줄링에 대한 설명으로 옳은 것은?

    비선점 = 못 뺏는다. 1·2·4번은 모두 선점형의 특징이에요.

    Q2P1(도착 0, 실행 10), P2(도착 1, 실행 5), P3(도착 3, 실행 4)를 FCFS로 처리할 때 평균 대기 시간은?

    간트 차트: P1 0~10, P2 10~15, P3 15~19. 대기: P1 0, P2 10 − 1 = 9, P3 15 − 3 = 12. (0 + 9 + 12) ÷ 3 = 7.

    Q3Q2에서 P2의 반환 시간은?

    반환 시간 = 끝 − 도착 = 15 − 1 = 14. (대기 9 + 실행 5 = 14로도 확인. 15는 도착을 안 뺀 값, 9는 대기 시간)

    Q4CPU 집중 프로세스 A와 I/O 집중 프로세스 B가 있다. 시스템 효율을 높이려면?

    B가 먼저 CPU를 잡아도 금방 I/O 요청 → 대기로 빠지고, 그 사이 A가 CPU를 써서 둘이 겹쳐 진행돼요.

    Q5FCFS에서 실행 시간이 짧은 프로세스가 긴 프로세스 뒤에서 오래 기다리는 현상은?

    앞이 막히면 뒤가 줄줄이 밀리는 콘보이(호위) 효과. FCFS의 대표 약점이에요.

    Q6교수님이 "그런 시험 문제는 내지 않는다"고 한 것은?

    "치사하게 공평성·효율성 이런 짧고 쉬운 문제는 안 낸다, 중요한 게 얼마나 많은데." 나머지 셋은 시험 대비 1순위예요.

    내 말로 설명하기 친구한테 말하듯이

    FCFS로 P1(0, 30) · P2(3, 18) · P3(6, 9)의 평균 대기 시간을 구하는 과정을 말로 설명하고, 콘보이 효과까지 짚어 보세요.

    FCFS는 도착 순서대로 끝까지 실행하니까 간트 차트는 P1 0~30, P2 30~48, P3 48~57이에요. 대기 시간은 시작 시각에서 도착 시각을 빼서 P1 0, P2 30 − 3 = 27, P3 48 − 6 = 42. 평균은 (0 + 27 + 42) ÷ 3 = 23이에요. P3는 9만 실행하면 되는데 앞의 긴 작업 때문에 42나 기다렸어요. 이렇게 긴 프로세스 때문에 짧은 프로세스가 오래 기다리는 게 콘보이 효과예요.

    교재 미리보기 — SJF (다음 수업)

    최단 작업 우선(SJF)은 도착 순서와 관계없이 실행 시간이 가장 짧은 작업의 PCB를 먼저 실행 상태로 옮겨요(비선점형). 위와 같은 데이터(P1 0/30, P2 3/18, P3 6/9)면 P1이 0에 혼자 와서 먼저 끝까지 실행(0~30), 그다음 짧은 P3(30~39), 마지막 P2(39~57). 대기 시간은 P1 0, P3 30 − 6 = 24, P2 39 − 3 = 36 → 평균 (0 + 24 + 36) ÷ 3 = 20ms. FCFS(23ms)보다 줄었어요. 녹음이 오면 새 페이지로 자세히 다뤄요.

    다음에 나올 알고리즘 (교재 210~221쪽)

    SJF → HRN(여기까지 비선점) → 라운드 로빈(10ms마다 타임아웃, 계산이 훨씬 복잡) → SRT → 다단계 큐 → 다단계 피드백 큐. 맨 앞이 제일 옛날·제일 후진 것이고, 다음 것이 앞의 단점을 고치는 순서예요. 정보처리기사에도 자주 나와요.
