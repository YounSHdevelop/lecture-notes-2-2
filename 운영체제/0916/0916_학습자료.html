아이폰·안드로이드 OS 업데이트는 왜 공짜일까?

유닉스 · C 언어 · BSD · GNU와 오픈소스 · 리눅스

유닉스는 AT&T 연구소의 켄 톰프슨이 만든 세계 최초의 멀티유저 OS예요. 처음엔 어셈블리어로 짰는데, 너무 어려워서 아무도 고치는 걸 도와줄 수 없었어요. 그래서 동료가 유닉스를 다시 짜려고 B 언어 다음으로 만든 언어가 C예요(A, B, C의 C).

OS를 만들려고 만든 언어라서 C는 어셈블리어처럼 메모리 주소에 직접 접근할 수 있어야 했어요. 그래서 C에 포인터가 있는 거예요. C가 문법적으로 불친절한 것도(0이면 거짓, 0 아니면 전부 참) "자기들끼리 쓰려고 대충 만들어서"라고 해요.

  • BSD — 버클리 대학원생들이 C로 유닉스를 새로 짜서 소스를 공개. 전 세계 대학이 이걸 읽으려고 C를 가르치기 시작했어요. (반대로 AT&T는 System V로 상업 판매)
  • GNU — 리처드 스톨먼. "소프트웨어를 돈 받고 팔지 말자." 저작권(copyright)의 반대로 카피레프트. 고치고 다시 배포해도 되지만 무료로 나눠야 해요 → 오픈소스.
  • macOS · iOS — 스티브 잡스가 BSD 계열 오픈 커널(마하) 위에 GUI를 씌워 만들었어요.
  • 리눅스 — 리누스 토르발스가 만든 PC용 유닉스. 구글은 리눅스 커널에 껍질을 씌워 안드로이드를 만들었어요.

그래서 커널이 오픈소스인 iOS·안드로이드는 업데이트에 돈을 못 받아요. 교수님 말로는 돈 받고 파는 OS는 윈도우뿐이에요(대신 애플·구글은 앱 결제 수수료로 돈을 벌죠).

시험엔 이렇게

C 언어는 유닉스를 만들기 위해 만들어져 메모리에 직접 접근하는 포인터를 가진다. GNU(카피레프트)는 소프트웨어를 자유롭게 고치고 배포하되 무료로 나누자는 오픈소스 운동이며, 리눅스는 PC용 유닉스, 안드로이드는 리눅스 커널 기반이다.

외우는 법: 유닉스 → C → BSD 공개 → GNU 오픈소스 → 리눅스 → 안드로이드
바로 확인
C 언어에 포인터가 들어간 가장 근본적인 이유는?
C는 유닉스를 짜려고 만든 언어라서 저급 언어처럼 메모리 주소에 직접 접근할 수단(포인터)이 필요했어요.

컴퓨터에서 이거 둘만 있으면 다 된다, 둘은 뭘까?

필수장치 · 주변장치 · 메인보드 · 버스

교수님 부탁 하나: 자동차학과를 나왔는데 엔진 토크도 모르면 이상하죠. 컴퓨터를 배우는 우리도 하드웨어를 알아야 하고, 특히 OS는 하드웨어 위에서 돌아서 하드웨어에 아주 민감해요.

컴퓨터는 크게 둘로 나눠요. CPU와 메모리 = 필수장치, 나머지는 전부 주변장치예요.

  • 입력장치 — 키보드, 마우스
  • 출력장치 — 모니터, 프린터, 사운드카드
  • 저장장치 — 자기(하드디스크·카세트테이프), 레이저(CD·DVD·블루레이), 메모리(SSD·SD카드·USB)

이 부품들을 꽂는 판이 메인보드(마더보드)예요. 부품을 꽂고 전원을 연결하고, 데이터가 흐르는 길을 만들어 줘요. 이 길을 버스라고 불러요. 시내버스가 정해진 노선으로만 다니듯 데이터도 정해진 길로만 흘러서요.

시험엔 이렇게

컴퓨터는 필수장치(CPU, 메모리)와 주변장치(입력·출력·저장장치)로 구성되며, 메인보드의 버스(데이터가 흐르는 길)로 연결된다.

외우는 법: 필수는 CPU·메모리 둘, 나머지는 주변
바로 확인
다음 중 필수장치는?
필수장치는 CPU와 메인 메모리 둘뿐이에요. SSD는 저장장치, 키보드는 입력장치로 둘 다 주변장치.

창고에 가서 칼질하는 요리사가 있을까?

폰노이만 구조의 가장 중요한 특징 ★ · 메모리 = 유일한 작업 공간

폰노이만 구조는 CPU·메모리·입출력·저장장치가 버스로 연결된 구조예요. 그런데 교수님은 "버스로 연결된 게 중요한 게 아니다"라며 이 문장에 별도를 쳤어요.

교수
폰노이만 구조에서 가장 중요한 특징은, 모든 프로그램은 메모리로 올라와야지만 실행이 됩니다. 별도 해 놓으세요.9/16 강의 중 (말을 조금 다듬음)

한글 프로그램을 더블클릭하면 SSD에서 바로 실행되는 것처럼 보이죠? 아니에요. 먼저 메모리로 가져오고, 메모리에 올라온 다음에 실행돼요.

교수님 비유 — CPU는 요리사, 메모리는 조리대, 저장장치는 창고예요. 스테이크를 하려면 창고의 고기를 조리대로 옮겨 칼질하죠. 창고에서 칼질하는 요리사는 없어요. 그래서 메모리는 컴퓨터의 유일한 작업 공간이고, CPU는 메모리하고만 일해요.

이제 친구 질문에 답할 수 있어요. "1GB 컴퓨터가 너무 느려, 16GB로 늘리면 왜 빨라져?" — 조리대가 좁으면 당근 하나 올려서 손질하고 치우고, 고기 올리고 치우고… 재료를 옮기는 과정이 많아져서 느려요. 16GB면 한꺼번에 올려 놓고 일하니까 빨라지죠.

그럼 100GB면 더 빠를까요? 아니에요. 작업할 만큼 충분하면 그걸로 끝이에요. 조리대를 방만 하게 만든다고 요리가 빨라지진 않죠. 인터넷만 하시는 부모님 컴퓨터는 8GB면 충분해요.

또 하나 흔한 착각. 폰 128GB·256GB·512GB는 메인 메모리가 아니라 저장장치(창고) 크기예요. 같은 모델이면 메인 메모리는 같고, 창고가 크다고 속도가 빨라지진 않아요. 이 수업에서 "메모리"는 메인 메모리만 가리켜요.

시험엔 이렇게

폰노이만 구조에서 가장 중요한 특징은 모든 프로그램이 메모리에 올라와야만 실행된다는 것이다. 메모리는 CPU의 유일한 작업 공간이므로, 메모리가 작업량보다 작으면 데이터를 자주 옮겨야 해서 느려진다.

외우는 법: 창고에서 칼질 안 한다 → 조리대에 올려야 요리
✗ 틀린 생각저장 용량 512GB 폰이 128GB 폰보다 빠르다 / 메모리는 늘릴수록 계속 빨라진다
○ 맞는 생각저장 용량은 창고 크기라 속도와 무관. 메모리는 작업에 충분한 만큼이면 된다
바로 확인
SSD에 있는 게임을 더블클릭했다. 폰노이만 구조에 따르면 실행 직전에 반드시 일어나는 일은?
모든 프로그램은 메모리에 올라와야 실행돼요. CPU는 메모리하고만 일하니까요.

5GHz CPU는 1초에 몇 번 계산할까? 그럼 20GHz는 왜 안 만들까?

Hz · 클럭 · BSB · FSB(시스템 버스)

속도 단위 Hz(헤르츠)는 1초 동안 변화한 횟수예요. 1초에 1번이면 1Hz, 2번이면 2Hz.

CPU는 아무 때나 계산하는 게 아니에요. 클럭이라는 놈이 "틱" 하고 전기 신호를 던져 줄 때마다 한 번씩 계산해요. 그래서 CPU 5GHz = 1초에 클럭이 50억 번 틱 = 1초에 약 50억 번 계산할 수 있다는 뜻이에요.

손을 1초에 50억 번 비비면? 터지겠죠. CPU도 열이 엄청나서 위에 팬을 달아요. 기술로는 10GHz, 20GHz도 만들 수 있지만 열 때문에 쓸 수가 없어요. (그래서 다음 시간에 나오는 "코어 늘리기"로 가요.)

CPU 안의 길과 메인보드의 길은 속도가 다르다

메인보드에서 데이터가 옮겨질 때도 클럭 틱에 맞춰 움직여요. 그런데 길이 둘이에요.

BSB (후면 버스)FSB (전면 버스)
어디CPU 내부에서 움직이는 버스메인보드에서 CPU와 주변장치(메모리 등)를 잇는 버스 = 시스템 버스
속도빠름 (CPU 클럭, 예: 5GHz)느림 (예: 3.2GHz, 메모리 속도와 같음)

CPU는 빠른데 메모리와 오가는 길은 느리니까, CPU에 비해 메모리 왕복이 너무 느린 문제가 생겨요. GPU는 더 심해서, 삼성·SK하이닉스가 메모리를 쌓아 올린 HBM을 만들었어요(9/21에 이어서).

시험엔 이렇게

1Hz는 1초에 1번 변화. CPU는 클럭 신호에 맞춰 연산하므로 5GHz CPU는 1초에 약 50억 번 연산한다. CPU 내부 버스는 BSB, 메인보드에서 주변장치를 잇는 버스는 FSB(시스템 버스)이며 FSB가 느려 메모리 병목이 생긴다.

외우는 법: B는 Back(안), F는 Front(밖)
바로 확인
3GHz CPU는 1초에 클럭 틱이 약 몇 번 들어올까?
G(기가) = 10억. 3GHz = 3 × 10억 = 30억 번. 틱 한 번에 연산 한 번이니 1초에 약 30억 번 계산해요.

OS 안에서는 왜 배열 대신 링크드 리스트를 쓸까?

저급·고급 언어 · 컴파일 · 큐·스택 · 링크드 리스트

컴퓨터가 알아듣는 건 숫자로 된 기계어, 그걸 글자로 바꾼 게 어셈블리어예요. 이 둘이 저급 언어예요. 일반인이 쓰기 편하게 if·for 같은 단어로 만든 C·자바 같은 건 고급 언어고요. 고급 언어로 짠 소스 코드는 컴파일(고급 언어 → 기계어 번역, 이때 오류 검사도 함)을 거쳐야 실행돼요.

자료구조에서 배운 큐와 스택은 앞으로 OS에서 엄청 많이 나와요. 반대로 배열은 거의 안 나와요. 이유는 이래요.

  • 배열은 같은 자료만 넣고, 한 번 선언하면 크기를 못 바꿔요. 넉넉히 잡으면 남는 공간이 낭비돼요.
  • OS가 공간을 낭비하면 사용자가 쓸 메모리를 잡아먹어요.
  • 그래서 필요할 때 메모리를 잡아 붙이고, 필요 없으면 풀어 주는(동적 메모리 할당) 링크드 리스트를 써요. OS에서 쓰는 건 앞뒤로 이동하는 더블 링크드 리스트예요.

(파이썬 "리스트"는 크기가 늘었다 줄었다 하지만, 그래서 배열이 아니라 리스트라고 부르는 거예요.)

시험엔 이렇게

고급 언어는 컴파일을 통해 기계어로 바뀐다. OS는 메모리 낭비를 줄이기 위해 크기가 고정된 배열 대신 동적으로 할당·해제하는 (더블) 링크드 리스트를 주로 사용한다.

외우는 법: 배열은 고정, 링크드 리스트는 필요한 만큼
바로 확인
OS가 배열보다 링크드 리스트를 선호하는 이유는?
배열은 선언하면 크기 고정이라 낭비가 생겨요. 링크드 리스트는 필요한 만큼 잡았다 푸는 동적 할당이 가능해요.

  • 폰 128/256GB = 저장장치(창고) 크기

④ 속도 B=안, F=밖

  • 1Hz = 1초 1번 · 클럭 틱마다 연산 · 5GHz ≈ 1초 50억 번
  • BSB = CPU 내부 / FSB = 시스템 버스(느림 → 메모리 병목)

⑤ 언어 · 자료구조

  • 저급(기계어·어셈블리) / 고급 → 컴파일
  • OS = 큐·스택·더블 링크드 리스트, 배열은 거의 X

빈칸 채우기 눌러서 정답 확인

컴퓨터의 필수장치는 CPU와 메모리다. 폰노이만 구조에서 가장 중요한 특징은 모든 프로그램이 메모리로 올라와야만 실행된다는 것이다. 메모리는 CPU의 유일한 작업 공간이다. 1초에 1번 변화하는 것을 1Hz라 하며, CPU는 클럭 신호에 맞춰 연산한다. 메인보드에서 주변장치를 연결하는 버스는 FSB(시스템 버스)다. 유닉스를 만들기 위해 만든 언어는 C다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
C 언어에 포인터가 있는 이유는?
유닉스(OS)를 만들려고 만든 언어라 어셈블리어처럼 메모리 주소에 직접 접근해야 했기 때문.
GNU · 카피레프트란?
소프트웨어를 자유롭게 복사·수정·배포하되 무료로 나누자는 운동. 오픈소스의 시작.
리눅스와 안드로이드의 관계는?
리눅스 = 리누스 토르발스의 PC용 유닉스. 안드로이드 = 리눅스 커널에 껍질을 씌운 OS.
필수장치와 주변장치는?
필수 = CPU, 메모리. 주변 = 입력·출력·저장장치.
폰노이만 구조의 가장 중요한 특징은?
모든 프로그램은 메모리로 올라와야만 실행된다.
메모리를 1GB에서 16GB로 늘리면 빨라지는 이유는?
메모리(조리대)가 작으면 데이터를 자주 옮겨야 해서 느리다. 작업에 충분하면 빨라지지만 그 이상은 효과 없음.
5GHz CPU의 의미는?
1초에 클럭이 50억 번 틱 → 1초에 약 50억 번 연산.
CPU 클럭을 계속 못 올리는 이유는?
열이 너무 많이 나서.
BSB와 FSB는?
BSB = CPU 내부 버스(빠름). FSB = 메인보드에서 주변장치를 잇는 시스템 버스(느림).
컴파일이란?
고급 언어 소스 코드를 기계어로 바꾸는 과정(오류 검사 포함).

    퀴즈 다 풀고 채점하기

    Q1폰노이만 구조에서 교수님이 꼽은 "가장 중요한 특징"은?

    버스로 연결됐다는 것보다 "메모리에 올라와야 실행"이 핵심이라고 별도까지 쳤어요.

    Q2친구가 같은 모델 폰의 512GB 버전을 사면 128GB보다 앱이 빨리 돌 거라고 한다. 맞는 대답은?

    128/256/512는 저장 용량이에요. 같은 모델이면 메인 메모리는 같아요.

    Q3메모리를 16GB에서 100GB로 늘려도 체감 속도가 거의 그대로였다. 이유는?

    메모리는 작업할 만큼 충분하면 끝. 그 이상은 놀고 있는 공간이에요.

    Q4CPU 클럭을 20GHz로 만들지 않는 이유는?

    만들 수는 있지만 1초에 수백억 번 계산하면 열을 감당할 수 없어요.

    Q5메인보드에서 CPU와 메모리 같은 주변장치를 연결하는 버스는?

    CPU 안쪽은 BSB, 메인보드에서 주변장치를 잇는 건 FSB = 시스템 버스예요.

    Q6다음 중 OS의 발전 흐름으로 옳은 것은?

    유닉스(어셈블리) → C로 재작성 → BSD 공개 → GNU 오픈소스 → 리눅스 → 안드로이드.

    내 말로 설명하기 친구한테 말하듯이

    "메모리 16GB로 늘리면 왜 빨라져?"라는 친구 질문에, 폰노이만 구조를 넣어서 대답해 보세요.

    폰노이만 구조에서는 모든 프로그램이 메모리에 올라와야만 실행돼. CPU가 요리사라면 메모리는 조리대, 저장장치는 창고야. 조리대가 1GB처럼 작으면 재료를 조금씩 올렸다 치웠다 하느라 느려. 16GB면 한꺼번에 올려 놓고 일하니까 빨라지는 거야. 그런데 작업에 충분한 크기를 넘으면 더 늘려도 별 차이는 없어.
