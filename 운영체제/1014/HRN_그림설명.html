HRN, 결국 "내 일 시간에 비해 몇 배나 기다렸나"를 재는 거예요

공식만 보면 (대기 + 실행) ÷ 실행이라 감이 안 오죠. 그런데 이 식을 쪼개면 1 + 대기 ÷ 실행이 돼요. "내 일은 2분짜리인데 6분이나 기다렸어" 같은 억울함 점수예요. 억울한 사람부터 먼저 해 주는 게 HRN이에요. 그림 다섯 개로 차근차근 볼게요.

장면 1

SJF에서 통장 10개 든 사람은 언제 차례가 올까?

SJF의 문제 · 기아 현상 · HRN이 나온 이유

먼저 SJF를 떠올려요. 실행 시간이 짧은 사람부터 해 주는 방식이었죠. 평균 대기 시간은 짧아지지만 문제가 있어요. 짧은 작업이 계속 새로 들어오면, 긴 작업은 영영 뒤로 밀려요.

SJF가 보는 건 실행 시간 하나뿐이에요. "이 사람이 벌써 얼마나 기다렸는지"는 안 봐요. 그래서 HRN은 생각했어요. 기다린 시간도 점수에 넣자. 오래 기다린 사람은 점수가 올라가서 언젠가는 먼저 하게 되도록.

시험엔 이렇게

HRN(최고 응답 우선)은 SJF 스케줄링에서 발생할 수 있는 기아 현상을 완화하는 비선점형 알고리즘이다. SJF는 CPU 사용 시간이 짧은 프로세스를 우선 실행하지만, HRN은 대기 시간과 실행 시간을 모두 고려하여 우선순위를 결정한다.

외우는 법: SJF는 실행 시간만, HRN은 기다린 시간도
바로 확인
SJF와 비교했을 때 HRN이 추가로 고려하는 것은?
SJF는 실행 시간만 봐요. HRN은 거기에 대기 시간을 더해서 오래 기다린 프로세스의 점수를 올려 줘요.

장면 2

응답률 = 1 + 대기 ÷ 실행 — "내 일에 비해 몇 배나 기다렸나"

응답률 공식 ★ · 식 쪼개 보기 · 막대로 보는 응답률 · 높을수록 먼저 ★
교재 공식
응답률 = (대기 시간 + CPU 사용 시간) ÷ CPU 사용 시간

이 식을 나눠 보면 이렇게 돼요.

(대기 + 실행) ÷ 실행 = 실행 ÷ 실행 + 대기 ÷ 실행 = 1 + 대기 ÷ 실행

앞의 1은 모두에게 똑같으니까 사실상 비교하는 건 대기 ÷ 실행, "내 일 시간에 비해 몇 배나 기다렸나"예요. 2분짜리 일인데 6분 기다렸으면 3배, 8분짜리 일인데 8분 기다렸으면 1배. 앞사람이 훨씬 억울하죠. 그래서 응답률이 높을수록 먼저 실행해요.

✗ 틀린 생각응답률이 낮을수록 빨리 응답받았으니 먼저 실행한다 / 더 오래 기다린 사람이 무조건 먼저다
○ 맞는 생각응답률이 높을수록 먼저. 기다린 시간을 실행 시간과 비교한 값이다
시험엔 이렇게

HRN 스케줄링에서 프로세스의 우선순위를 결정하는 기준은 응답률이며, 응답률 = (대기 시간 + CPU 사용 시간) ÷ CPU 사용 시간이다. 응답률이 높을수록 높은 우선순위를 가진다.

외우는 법: 응답률 = 1 + 대기 ÷ 실행 = 억울함 점수, 억울한 사람부터
바로 확인
대기 9 · 실행 3인 프로세스의 응답률은? (1 + 대기 ÷ 실행으로 풀어 보세요)
1 + 9 ÷ 3 = 1 + 3 = 4. 원래 공식 (9 + 3) ÷ 3 = 4와 같아요.

장면 3

긴 작업도 기다리다 보면 결국 1등이 된다 — 그래서 기아가 줄어든다

기다릴수록 응답률이 오른다 · 짧은 작업은 빨리, 긴 작업은 천천히 · 기아 완화의 원리

응답률은 고정된 점수가 아니에요. 기다리는 동안 계속 올라가요. 1 + 대기 ÷ 실행이니까, 대기가 1 늘 때마다 1 ÷ 실행만큼 올라가요. 짧은 작업(실행 2)은 1ms 기다릴 때마다 0.5씩 빠르게 오르고, 긴 작업(실행 8)은 0.125씩 천천히 올라요.

그래서 SJF처럼 영원히 밀리지는 않아요. 다만 긴 작업은 점수가 천천히 오르니까 여전히 불리해요. 교재: "HRN 스케줄링은 대기 시간이 긴 프로세스의 우선순위를 높게 설정하여 기아 현상을 완화한다. SJF와 비교했을 때 공평성을 조금 더 확보하지만, 여전히 실행 시간이 긴 프로세스가 불리할 가능성이 있다." 기아를 "없애는" 게 아니라 "완화"하는 거예요.

시험엔 이렇게

HRN은 대기 시간이 긴 프로세스의 우선순위를 높게 설정하여 기아 현상을 완화한다. SJF와 비교했을 때 공평성을 조금 더 확보하지만, 여전히 실행 시간이 긴 프로세스가 불리할 가능성이 있다.

외우는 법: 기다리면 점수가 쌓인다 → 언젠가는 1등 · 없애는 게 아니라 완화
바로 확인
실행 8인 긴 작업이 24ms를 기다렸고, 실행 2인 짧은 작업이 방금(대기 0) 도착했다. HRN은 누구를 먼저 실행할까?
긴 작업 1 + 24 ÷ 8 = 4, 짧은 작업 1 + 0 ÷ 2 = 1. SJF였다면 짧은 작업이 먼저였겠지만, HRN에선 오래 기다린 긴 작업이 이겨요.

한 단계씩 풀어 보기 — 고를 때마다 응답률을 새로 계산한다

P1 0/6 · P2 2/4 · P3 4/8 · P4 6/2 · 고르는 시점 · 대기 = 지금 시각 − 도착 · 간트 차트

압축본 연습과 같은 데이터예요(도착/실행). 규칙은 딱 세 줄.

  1. 언제 고르나: 비선점형이니까 앞 작업이 끝났을 때만 고른다.
  2. 누구 중에서: 그 시각까지 도착해 있는 프로세스만.
  3. 무엇으로: 각자 응답률 = 1 + (지금 시각 − 도착) ÷ 실행, 가장 큰 것.
프로세스시작 ~ 끝대기 시간 (시작 − 도착)
P10 ~ 60
P26 ~ 106 − 2 = 4
P410 ~ 1210 − 6 = 4
P312 ~ 2012 − 4 = 8
평균 대기 시간(0 + 4 + 4 + 8) ÷ 4 = 4 (대기 시간 합 16)

SJF였다면 6 시점에 실행 시간이 가장 짧은 P4(2)를 먼저 했을 거예요. HRN은 P2가 "4ms 일인데 4ms나 기다렸다(1배)"로 P4의 "방금 왔다(0배)"보다 억울해서 P2를 골랐어요. 이게 SJF와 HRN의 차이예요.

시험엔 이렇게

HRN은 비선점형이므로 실행 중인 작업이 끝날 때마다, 그 시점까지 도착한 프로세스들의 응답률 = (현재 시각 − 도착 시각 + 실행 시간) ÷ 실행 시간을 계산해 가장 큰 프로세스를 실행한다. 대기 시간은 고르는 시각에 따라 달라지므로 시점마다 다시 계산한다.

외우는 법: 끝날 때마다 → 와 있는 애들만 → 억울함 점수 다시 계산 → 1등
바로 확인
위 예제의 10 시점에서 P3의 대기 시간은 왜 6일까?
대기 시간은 고르는 그 시각 − 도착이에요. 6 시점엔 2였지만 4ms가 더 지나서 6이 됐어요. 그래서 시점마다 다시 계산해야 해요.

장면 5

교재 예제(그림 5-18) — SJF와 순서가 같아진 경우

P1 0/30 · P2 3/18 · P3 6/9 · 30 시점 응답률 2.5 vs 3.67 · 평균 20ms · 왜 안 쓰나

교재는 P1(도착 0 · 30ms), P2(도착 3 · 18ms), P3(도착 6 · 9ms)로 계산해요. P1은 혼자라 0~30 실행. 30 시점에 P2와 P3를 비교해요.

그래서 P3(30~39) → P2(39~57). 대기 시간은 P1 0, P3 30 − 6 = 24, P2 39 − 3 = 36. 평균 (0 + 24 + 36) ÷ 3 = 20ms. SJF와 순서도 평균도 같아요. 이 데이터에서는 짧은 P3가 억울함 점수도 더 높았거든요. 장면 4처럼 데이터에 따라 순서가 달라질 수도 있어요.

그런데 실제로는 널리 쓰이지 않아요. SJF와 거의 비슷하게 동작해서, 실행 시간을 미리 알아야 한다는 SJF의 문제를 그대로 갖고 있거든요. 교수님: "SJF를 못 쓰면 HRN도 쓰기가 쉽지 않습니다. 그런데 이걸 왜 가르쳐 주느냐, 응답률 공식이 가끔 정보처리기사 시험에 나와요."

시험엔 이렇게

교재 예제에서 P1 종료 시점(30)의 응답률은 P2 = (27 + 18) ÷ 18 = 2.5, P3 = (24 + 9) ÷ 9 ≈ 3.67이므로 P3가 먼저 실행되며, 평균 대기 시간은 (0 + 24 + 36) ÷ 3 = 20ms로 SJF와 같다. HRN은 실행 시간을 미리 알아야 하는 한계 때문에 실제로 널리 사용되지는 않는다.

외우는 법: 2.5 vs 3.67 → P3 먼저 → 20ms
바로 확인
HRN이 실제 운영체제에서 널리 쓰이지 않는 이유는?
응답률 공식 분모에 실행 시간이 들어가니까, SJF와 똑같이 실행 시간을 미리 알아야 해요. HRN은 비선점형이에요.

    "응답률"이라는 이름

    Highest Response Ratio Next의 Response Ratio. (대기 + 실행)은 "도착해서 끝날 때까지 걸릴 전체 시간"이라, 응답률은 "전체 걸린 시간이 실제 일 시간의 몇 배인가"라고도 볼 수 있어요. 1이면 기다림 없이 바로 끝난 것.
