장면 1

sum = D2 + D3; 한 줄이 CPU에서는 몇 단계일까?

ALU ★ · 제어장치(CU) ★ · 레지스터 ★ · LOAD / ADD / MOVE

CPU는 명령어를 해석하고 실행하는 핵심 장치, 컴퓨터의 두뇌예요. 세 장치가 협업해서 일해요. 교재는 9/16의 요리사 모형으로 설명해요.

장치요리사로 치면하는 일
산술논리 연산장치(ALU) ★요리사가 재료를 조리하듯덧셈·뺄셈·곱셈·나눗셈 같은 산술 연산과 AND·OR 같은 논리 연산을 한다
제어장치(CU) ★요리사가 보조에게 작업을 지시하듯명령어를 해석하고 다른 장치에 작업을 지시한다
레지스터 ★미리 손질한 재료를 작은 그릇에 담아 두듯연산에 필요한 데이터나 중간 결과를 임시로 저장하는 CPU 내부 메모리
교수님 비유 — 짜장면을 만들려고 양파를 썰었어요. 고기를 썰려면 썬 양파를 잠깐 종지에 덜어 둬야죠. 볶기 전까지 재료를 잠깐 두는 그 종지가 레지스터예요. 교재 그림 속 말풍선도 "토마토 1개와 양파 1개를 슬라이스하고 대파 1개는 다져주세요" — 요리사(제어장치)가 지시하는 장면이에요.

이제 D2 = 2, D3 = 3, sum = D2 + D3을 따라가 볼게요. 사실 D2, D3이라는 변수 이름은 사람을 위한 별명일 뿐이고, 기계는 메모리 주소만 알아요. 전화번호를 못 외우니까 이름을 붙여 두는 것과 같죠. (이게 C에 포인터가 있는 근본 이유예요.)

코드 2-2 · 어셈블리어로 바꾸면 (D2 = 100번지, D3 = 120번지, sum = 160번지)1  LOAD   R2 ← 메모리 100번지   // 2를 레지스터 R2로 (3이 올 때까지 대기)
2  LOAD   R3 ← 메모리 120번지   // 3을 레지스터 R3로
3  ADD    R5 ← R2 + R3         // ALU가 더함, 결과 5도 일단 레지스터에
4  MOVE   메모리 160번지 ← R5   // 5를 sum 자리(메모리)로 옮김

CU가 LOAD·ADD·MOVE 명령을 내리고, ALU가 더하고, 레지스터가 중간값을 들고 있어요. 덧셈 한 줄에 이만큼이니, 조금만 복잡한 코드를 짜도 CPU는 정신없이 바쁜 거예요.

시험엔 이렇게

CPU는 산술논리 연산장치, 제어장치, 레지스터로 구성된다. 산술논리 연산장치(ALU)는 산술 연산과 논리 연산을, 제어장치는 명령어를 해석하고 다른 장치에 작업을 지시하며, 레지스터는 연산에 필요한 데이터나 중간 결과를 임시로 저장하는 CPU 내부 메모리다. 메모리의 값은 레지스터로 가져와(LOAD) 연산(ADD)한 뒤 다시 메모리로 옮긴다(MOVE).

외우는 법: ALU 계산, CU 지시, 레지스터 종지
바로 확인
위 코드 3번 줄의 결과 5는 바로 어디에 놓일까?
ALU 결과는 먼저 레지스터에 잠깐 보관되고, 4번 줄 MOVE로 메모리 160번지(sum)로 옮겨져요.

장면 2

CPU가 메모리 100번지 값을 직접 들고 오지 못한다면, 어떻게 가져올까?

레지스터 7종 ★ · PC · IR · MAR · MBR

레지스터는 종류가 많아요. 교수님이 "꼭 외우셔야 된다"고 한 표예요. 이 중 PC·IR·MAR처럼 특수한 용도로 쓰여서 사용자가 임의로 바꿀 수 없는 레지스터를 특수 레지스터, 또는 사용자 불가시 레지스터라고 불러요.

레지스터하는 일
데이터 레지스터 (DR)메모리에서 가져온 데이터(2, 3 같은 값)를 보관하거나 작업 결과를 임시 저장. CPU 레지스터 대부분이 이거라 범용 레지스터라고도 함
주소 레지스터 (AR)처리할 데이터가 저장된 메모리 주소를 저장. 데이터 접근에 필요한 주소를 관리
프로그램 카운터 (PC) ★다음에 실행할 명령어의 위치를 저장(코드 2-2의 1행·2행·3행 같은 행 번호). 명령어 위치를 가리키므로 명령어 포인터(IP)라고도 함
명령어 레지스터 (IR)현재 실행 중인 명령어(LOAD · ADD · MOVE)를 저장. 제어장치는 IR의 명령어를 해석한 뒤 외부 장치에 제어 신호를 보냄
메모리 주소 레지스터 (MAR) ★메모리에서 CPU로 데이터를 가져오거나 CPU에서 메모리로 보낼 때 그 메모리 주소를 저장
메모리 버퍼 레지스터 (MBR) ★메모리에서 가져온 / 메모리에 쓸 값
프로그램 상태 레지스터 (PSR)연산 결과 상태 → if 같은 분기를 할지 결정

1번 줄 LOAD R2 ← 100번지를 레지스터로 따라가기

  1. 제어장치가 PC를 읽어요. 1이니까 "1번 줄 실행할 차례구나".
  2. 1번 줄의 명령 LOAD가 IR에 들어가요. "메모리에서 가져오라는 거구나".
  3. MAR에 100을 써요. CPU와 메모리는 서로 독립된 장치라 CPU가 메모리에 들어가 직접 들고 올 수 없거든요.
  4. 메모리가 MAR을 보고 100번지 값 2를 MBR에 올려놔요. 메모리도 CPU 안방엔 못 들어가니까요.
  5. 제어장치가 MBR의 2를 R2(데이터 레지스터)로 옮기고, PC가 2로 증가해요.
교수님 비유 — 은행 번호표 같아요. CPU가 MAR에 "100번 손님!" 하고 띄우면, 메모리가 그 손님(값)을 MBR이라는 창구까지 보내 줘요. 그래서 MAR과 MBR은 CPU와 메모리 사이의 인터페이스예요.
시험엔 이렇게

PC(명령어 포인터)는 다음에 실행할 명령어의 위치를 저장하고, IR은 현재 실행 중인 명령어를 저장하며 제어장치가 이를 해석한다. MAR은 메모리에서 읽거나 쓸 주소를, MBR은 메모리와 주고받는 데이터를 저장하며, 두 레지스터는 CPU와 메모리 사이의 인터페이스다. PSR은 분기 여부를 결정할 때 쓰인다.

외우는 법: MAR = Address(주소), MBR = Buffer(값) · PC = 다음 줄
바로 확인
메모리 120번지의 값을 읽으려고 한다. CPU가 "120"을 써 넣는 레지스터는?
주소는 MAR(Memory Address Register)에 써요. 메모리가 보내 준 값이 올라오는 곳이 MBR, 다음 줄 번호를 가진 게 PC예요.

주소가 바깥에서 CPU 쪽으로 들어오는 경우가 있을까?

제어 버스 · 주소 버스 · 데이터 버스와 방향

지금까지 버스를 한 줄로 그렸지만, 실제로는 세 종류예요.

  • 제어 버스 — CU의 명령("가져와", "소리 내")이 나가는 길. 그런데 랜카드가 멈췄다, 프린터가 고장 났다 같은 오류 신호는 거꾸로 CU로 올라와요. 그래서 양방향. 모든 오류 신호는 제어 버스로 들어와요.
  • 데이터 버스 — 데이터가 CPU로 들어오기도, 나가기도 하니까 양방향. MBR에 붙어 있어요.
  • 주소 버스 — "메모리 100번지", "하드디스크 200번지"처럼 CPU가 주소를 내보내기만 해요. 바깥에서 CPU로 주소가 들어올 일은 없죠. 그래서 단방향. MAR에 붙어 있어요.
시험엔 이렇게

버스는 제어 버스(양방향, 명령과 오류 신호), 주소 버스(단방향, CPU에서 밖으로 주소 전달, MAR과 연결), 데이터 버스(양방향, MBR과 연결)로 나뉜다.

외우는 법: 주소만 혼자 일방통행 · 주소-MAR, 데이터-MBR
바로 확인
프린터가 고장 났다는 신호는 어느 버스를 타고 CPU로 올라올까?
오류 신호는 전부 제어 버스로 들어와요. 그래서 제어 버스가 양방향이에요. 주소 버스는 CPU → 밖 단방향이라 들어올 수 없어요.

장면 4

옛날 32비트 컴퓨터는 램을 8GB 꽂아도 왜 4GB만 인식했을까?

32비트 · 64비트 · 2³² = 4GB

"64비트 CPU"는 레지스터 크기가 64비트이고, 버스가 한 번에 실어 나르는 폭(대역폭)도 64비트라는 뜻이에요. 한 번에 더 많이 나르니 32비트보다 빨라요.

더 중요한 건 메모리 크기예요. 메모리는 1바이트마다 주소 하나가 붙어요. MAR이 32비트면 만들 수 있는 주소가 0번부터 2³² − 1번까지, 즉 2³²개 = 4GB예요. 그래서 32비트 CPU는 4GB 넘게 꽂아도 주소를 붙일 수가 없어서 인식을 못 했어요. 64비트는 사실상 걱정 없는 크기까지 쓸 수 있고요.

윈도우의 Program Files (x86) 폴더가 바로 32비트용 옛 프로그램이 깔리는 곳이에요(인텔 32비트 CPU 이름이 286·386·486…처럼 86으로 끝나서 x86).

시험엔 이렇게

64비트 CPU는 레지스터 크기와 버스 대역폭이 64비트다. 메모리는 1바이트마다 주소가 붙으므로 32비트 CPU는 2³²바이트 = 4GB까지만 사용할 수 있다.

외우는 법: 2의 32승 = 4G (2¹⁰ = 1K, 2³⁰ = 1G, ×4)
바로 확인
32비트 CPU에서 메모리를 4GB까지만 쓸 수 있는 직접적인 이유는?
1바이트당 주소 하나, 32비트 주소로 만들 수 있는 주소는 2³²개 = 4GB. 그 이상은 이름(주소)을 붙일 수 없어요.

장면 5

전원이 꺼져도 남는 플래시 메모리를, 왜 메인 메모리로 안 쓸까?

RAM · ROM · 휘발성 · 비휘발성 · CPU vs GPU · HBM
휘발성 (전원 끄면 사라짐)비휘발성 (전원 꺼도 남음)
예DRAM, SDRAM, DDR(PC 메인 메모리), HBM플래시 메모리(USB, SD카드, SSD)
용도메인 메모리저장장치

먼저 메인 메모리의 생김새. 메인 메모리는 데이터를 1바이트 단위로 저장하고, 각 바이트는 주소로 구분해요. 주소는 보통 0번지부터 시작하고, 이 주소로 CPU와 데이터를 주고받아요(100번지 값을 CPU로 보내고, CPU 결과를 120번지에 저장하는 식).

메모리는 크게 램(RAM)과 롬(ROM)으로 나눠요. 램은 데이터를 읽고 쓸 수 있는 메모리예요. 이름의 Random Access는 저장된 위치와 관계없이 같은 속도로 읽을 수 있다는 뜻이고요. 롬은 데이터를 쓸 수 없고 읽기만 할 수 있어요. 일반적으로 "메모리"라고 하면 램을 말해요.

또 하나의 기준이 휘발성이에요. 휘발성 메모리는 전원이 없으면 데이터가 사라지는 반도체 메모리, 비휘발성 메모리는 전원이 없어도 데이터를 보관하지만 내부 구조가 복잡하고 동작이 느려요. 그래서 작업 공간인 메인 메모리에는 동작이 빠른 휘발성 메모리를 쓰고, SSD나 USB 같은 저장장치에는 비휘발성 메모리를 써요. 휘발성 메모리는 SRAM과 DRAM으로 나뉘고, DRAM에서 SDRAM → DDR SDRAM으로 발전했어요.

CPU보다 GPU가 더 팔리는 이유

속도를 올리는 첫 방법은 클럭인데 열 때문에 한계가 있죠(9/16). 두 번째 방법은 ALU·CU·레지스터 묶음인 코어를 여러 개 넣는 거예요. CPU 코어엔 명령을 내리는 CU가 붙어 있어서 작게 만들기 어려워 보통 8~64개 정도예요. GPU는 계산만 하도록 만들어서 CU가 거의 없고, 코어를 작게 수천 개 넣을 수 있어요. 그래서 대량 계산(AI)에선 GPU가 이겨요.

문제는 수천 개 코어에 데이터를 동시에 넣고 빼야 한다는 것. 평면 DDR로는 못 따라가니까, DDR을 위로 여러 장 쌓아 동시에 돌리는 HBM이 나왔어요. 층 사이 아주 가는 선을 다 연결해야 해서 삼성·SK하이닉스만 잘 만든다는 얘기였어요.

시험엔 이렇게

램(RAM)은 읽고 쓸 수 있고 위치와 관계없이 같은 속도로 읽을 수 있는 메모리, 롬(ROM)은 읽기만 할 수 있는 메모리다. 휘발성 메모리는 전원이 없으면 데이터가 사라지고, 비휘발성 메모리는 데이터를 보관하지만 구조가 복잡하고 느리므로 메인 메모리에는 빠른 휘발성 메모리(DRAM 계열, DDR)를, SSD·USB에는 비휘발성 메모리를 쓴다. GPU는 CU가 거의 없어 코어를 수천 개 넣을 수 있고, 그 속도를 메모리가 따라가도록 DDR을 수직으로 쌓은 것이 HBM이다.

외우는 법: 메인은 휘발성(빨라서), 저장은 플래시(남아서)
바로 확인
GPU에 CPU보다 훨씬 많은 코어를 넣을 수 있는 이유는?
CPU 코어는 명령을 내리는 CU가 붙어 있어 크고, GPU는 계산 전용이라 CU가 거의 없어 작게 수천 개를 넣어요.

① CPU 구성 계산·지시·종지

  • ALU는 산술·논리 연산(요리사가 조리), 제어장치는 명령어 해석·지시(보조에게 지시), 레지스터는 데이터·중간 결과를 임시 저장하는 CPU 내부 메모리(작은 그릇)예요.
  • LOAD(메모리→레지스터) → ADD → MOVE(레지스터→메모리) · 변수 이름 = 주소의 별명

② 레지스터 ★ 꼭 외움

  • PC는 다음에 실행할 명령어의 위치(명령어 포인터 IP라고도 해요), IR은 현재 실행 중인 명령어를 저장해요.
  • MAR = 메모리 주소 / MBR = 주고받는 값 → CPU↔메모리 인터페이스
  • DR 데이터 · AR 데이터의 주소 · PSR = 분기 결정

③ 버스 주소만 일방통행

  • 제어 양방향(오류 신호 ↑) · 데이터 양방향(MBR)
  • 주소 단방향 CPU→밖(MAR)

④ 비트 수

  • 64비트 = 레지스터 크기 · 버스 대역폭
  • 32비트 → 2³² = 4GB까지 · x86 = 32비트

⑤ 메모리

  • 램은 읽고 쓸 수 있고 위치와 상관없이 같은 속도로 읽어요. 롬은 읽기만 돼요. 보통 "메모리" = 램.
  • 메인 메모리는 빠른 휘발성(DDR), SSD·USB는 구조가 복잡하고 느린 비휘발성이에요. 메모리는 1바이트마다 주소가 붙고 0번지부터 시작해요.
  • GPU = CU 없어 코어 수천 개 → HBM(DDR 수직 적층)

빈칸 채우기 눌러서 정답 확인

CPU는 연산을 하는 ALU, 명령을 내리는 제어장치, 데이터를 임시 보관하는 레지스터로 구성된다. 다음에 실행할 명령어의 위치를 가진 레지스터는 프로그램 카운터(PC), 현재 명령어를 가진 것은 명령어 레지스터(IR)다. 메모리에서 읽을 주소는 MAR에, 메모리에서 가져온 값은 MBR에 저장된다. 버스 중 단방향인 것은 주소 버스이고, 오류 신호가 올라오는 것은 제어 버스다. 32비트 CPU가 쓸 수 있는 최대 메모리는 4GB다. 메인 메모리는 전원이 꺼지면 내용이 사라지는 휘발성 메모리다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
CPU의 세 구성 요소는?
산술논리 연산장치(ALU), 제어장치(CU), 레지스터.
프로그램 카운터(PC)는?
다음에 실행할 명령어의 위치(행 번호)를 저장하는 레지스터. 명령어 위치를 가리키므로 명령어 포인터(IP)라고도 한다.
레지스터란? (교재 정의)
연산에 필요한 데이터나 중간 결과를 임시로 저장하는 CPU 내부 메모리.
램(RAM)과 롬(ROM)의 차이는?
램 = 읽고 쓸 수 있고, 저장 위치와 관계없이 같은 속도로 읽을 수 있음. 롬 = 쓸 수 없고 읽기만 가능.
명령어 레지스터(IR)는?
현재 실행할 명령어(LOAD, ADD, MOVE 등)를 가진 레지스터.
MAR은?
메모리 주소 레지스터. 메모리에서 읽거나 쓸 주소를 저장.
MBR은?
메모리 버퍼 레지스터. 메모리에서 가져온 값이나 메모리에 쓸 값을 저장.
PSR은?
프로그램 상태 레지스터. 연산 결과 상태로 분기(if 등) 여부를 결정할 때 사용.
MAR·MBR이 필요한 이유는?
CPU와 메모리는 독립된 장치라 서로의 영역에 직접 못 들어가서, 둘 사이의 인터페이스 역할을 한다.
버스 3종류와 방향은?
제어 버스 양방향, 데이터 버스 양방향, 주소 버스 단방향(CPU → 밖).
32비트 CPU의 최대 메모리는?
2³²바이트 = 4GB. 1바이트마다 주소가 하나 붙기 때문.
메인 메모리로 플래시 메모리를 안 쓰는 이유는?
플래시는 전원 없이 기억하는 구조라 복잡하고 느리다. 작업 공간은 빠른 휘발성 메모리를 쓴다.
HBM이란?
DDR을 수직으로 여러 장 쌓아 동시에 돌리는 적층 메모리. GPU 속도를 따라가기 위해 만듦.

    퀴즈 다 풀고 채점하기

    Q1프로그램의 7번 줄을 실행하는 중이다. 이때 프로그램 카운터(PC)가 가리키는 것은?

    PC는 다음에 실행할 명령어의 위치를 가져요. 한 줄 처리될 때마다 1씩 증가해요.

    Q2CPU가 메모리에 값을 저장하려 한다. 저장할 값이 놓이는 레지스터는?

    주소는 MAR, 값은 MBR. 가져올 때도 저장할 때도 값은 MBR을 거쳐요.

    Q3if (x > 0)에서 참·거짓에 따라 다음 실행할 줄을 정할 때 쓰이는 레지스터는?

    분기를 할지 말지는 연산 결과 상태를 담은 PSR로 결정해요.

    Q4버스에 대한 설명으로 옳은 것은?

    주소 버스는 단방향(MAR), 데이터 버스는 양방향(MBR), 제어 버스는 오류 신호 때문에 양방향이에요.

    Q532비트 윈도우 PC에 램을 16GB 꽂았다. 인식되는 최대 크기는?

    32비트 주소로 만들 수 있는 주소는 2³²개 = 4GB. 나머지는 주소를 못 붙여요.

    Q6다음 중 비휘발성 메모리를 쓰는 것은?

    SSD·USB·SD카드는 플래시 메모리(비휘발성). DDR·HBM은 휘발성이에요.

    내 말로 설명하기 친구한테 말하듯이

    CPU가 메모리 100번지의 값을 레지스터로 가져오는 과정을 PC · IR · MAR · MBR을 넣어서 설명해 보세요.

    제어장치가 PC를 보고 이번에 실행할 줄을 알아내고, 그 줄의 명령(LOAD)을 IR에 넣어요. CPU와 메모리는 서로 독립된 장치라 직접 들어갈 수 없으니까, CPU는 MAR에 100이라고 주소를 써요. 메모리는 MAR을 보고 100번지 값을 MBR에 올려 주고, 제어장치가 MBR의 값을 데이터 레지스터로 옮겨요. 그리고 PC는 다음 줄로 1 증가해요.

    DDR 세대

    교수님 설명으로는 DDR은 SDRAM보다 한 번에 2배씩 실어 나르고, 세대가 올라갈수록 그 폭이 넓어져요(지금 PC는 DDR4~DDR5).

    메모리 시장 이야기

    HBM 수요로 공장이 HBM 쪽으로 바뀌면서 일반 DRAM이 부족해졌다는 여담이었어요.
