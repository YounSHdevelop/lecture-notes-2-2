프로그램은 왜 하드디스크에 직접 못 쓸까?

컴퓨팅 환경의 변화를 짧게 마무리하고, 본격적으로 운영체제의 속을 들여다보는 날이에요. 교수님이 "이 그림이 흐리면 위에 탑을 못 쌓는다"며 일부러 천천히 나간 부분이라 오늘 그림이 이 과목 전체의 바닥이에요.

이 페이지를 다 보면 할 수 있는 것

  2. 시스템 콜이 왜 필요한지, 듀얼 모드와 어떻게 연결되는지 설명할 수 있다
  3. 디바이스 드라이버, API, SDK를 구분할 수 있다

장면 1

MP3를 서버 한 대에 다 모으면 서버가 터진다. 그럼 어떻게?

클라이언트-서버 · P2P · 클라우드 · 사물인터넷

시분할 이후 컴퓨팅 환경은 이렇게 흘러가요. 짧게 정리할게요.

  • 분산 시스템 — 작은 컴퓨터들을 네트워크로 묶어 큰 컴퓨터처럼 쓰려 했지만, 한 대가 고장 나면 복구가 어려워 잘 안 쓰였어요.
  • 클라이언트-서버 — 서비스를 요청하는 클라이언트와 응답하는 서버. 웹이 이 구조라 엄청 퍼졌어요. 문제는 모든 부하가 서버에 몰린다는 것.
  • P2P — 미국의 한 대학생이 MP3 공유 서비스를 만들면서 꾀를 냈어요. 서버엔 "누가 어떤 파일을 가졌는지" 목록만 두고, 파일은 가진 사람에게서 직접 받는 거죠. 서버 과부하를 줄이려고 만든 구조예요. 지금 메신저(데이터는 직접 전송)와 블록체인으로 이어졌어요.
  • 클라우드 컴퓨팅 — 하드웨어·소프트웨어를 사지 않고 빌려 쓰고 돈만 내요(AWS). 뒤에서 어떤 컴퓨터가 도는지 구름에 가려 안 보인다고 클라우드. 포토샵·AI처럼 소프트웨어를 빌려 쓰는 걸 SaaS라고 해요.
  • 사물인터넷(IoT) — 버스·지하철·CCTV·가전까지 인터넷에 연결되는 것. 정류장의 "몇 분 뒤 도착"이 이 덕분이에요.
시험엔 이렇게

P2P는 클라이언트-서버 구조의 서버 과부하를 줄이기 위해, 서버는 연결 정보(목록)만 관리하고 데이터는 사용자끼리 직접 주고받는 구조다.

외우는 법: 서버는 목록만, 파일은 직접
바로 확인
P2P가 만들어진 가장 직접적인 이유는?
P2P = 서버 과부하 줄이기. 하드웨어를 빌려 쓰는 건 클라우드, 작은 컴퓨터를 묶는 건 분산 시스템이에요.

장면 2

운영체제를 열어 보면 무엇과 무엇으로 되어 있을까?

커널 · 사용자 인터페이스 · CLI와 GUI · 커널의 4가지 기능

운영체제의 핵심 기능만 담당하는 부분을 커널이라고 해요. 첫 번째로 기억할 것: 어떤 사용자나 프로그램도 커널을 거치지 않고는 하드웨어에 접근할 수 없어요. 9/9의 바리스타가 바로 커널이에요.

그런데 커널만 있으면 명령을 내리고 결과를 받아 볼 창구가 없죠. 그래서 사용자와 커널 사이에 사용자 인터페이스(UI)가 있어요.

교수님 비유 — 커널이 자동차 엔진이라면, 엔진만 있다고 차가 가나요? 핸들·액셀·브레이크·계기판이 있어야죠. 내 명령을 기계에 전하고 결과를 알려 주는 그 부분이 인터페이스예요.

초기 유닉스나 MS-DOS는 글자를 쳐서 명령하는 CLI(문자 인터페이스)였어요. 생성형 AI에 글로 명령하는 것과 비슷하죠. 지금은 마우스로 클릭하는 GUI(그래픽 사용자 인터페이스)가 대부분이고, 스마트폰은 터치로 발전했어요.

여기서 교수님이 짚은 착각 하나. "유닉스는 어렵고 윈도우는 쉽다"는 건 인터페이스 얘기지 커널 얘기가 아니에요. 스마트폰 OS도 유닉스 계열인데 쓰기 어렵지 않잖아요. 쉽다/어렵다는 UI가 결정하고, 커널의 좋고 나쁨과는 다른 문제예요.

커널의 핵심 기능은 프로세스 관리 · 메모리 관리 · 저장장치 관리 · 입출력 관리 4가지예요. 앞으로 배울 목차(프로세스 → 스케줄링 → 메모리 → 파일 시스템 → 입출력)가 바로 이 순서고, 기말까지 이걸 다 배워요.

시험엔 이렇게

운영체제 = 사용자 인터페이스 + 커널. 커널은 프로세스·메모리·저장장치·입출력 관리를 담당하며, 하드웨어는 커널을 통해서만 접근할 수 있다.

외우는 법: 엔진(커널) + 핸들(UI) · 커널 기능 프·메·저·입
바로 확인
"리눅스 터미널은 어렵고 윈도우는 쉽다"는 느낌은 무엇의 차이일까?
쉽고 어려운 건 인터페이스(CLI냐 GUI냐)의 차이예요. 커널이 좋고 나쁜 것과는 다른 문제라는 게 교수님 포인트.

장면 3

내가 10을 써 둔 자리에 남이 10을 또 쓰면?

시스템 콜 ★ · write / read · printf

OS 없이 모두가 하드디스크에 직접 쓸 수 있다면

누군가 써 둔 자리에 다른 프로그램이 또 쓰면 원래 데이터가 날아가요. 비행기에서 "아무 데나 앉으세요" 하면 다들 다리 뻗을 수 있는 앞자리로 몰리는 것처럼요.

그래서 OS는 하드디스크를 자기 뒤에 숨기고, 앞에 "저장해 주세요" 하고 부를 수 있는 함수만 내놓아요. 프로그램은 write(10)처럼 값을 맡길 수는 있지만 위치는 정할 수 없어요. OS가 알아서 빈 곳에 넣었다가, read를 부르면 돌려줘요.

이렇게 OS가 제공하는 함수를 불러서만 하드웨어를 쓸 수 있게 한 것, 이 함수를 시스템 콜(시스템 호출)이라고 해요. 교수님이 "별표, 이게 제일 중요하다"고 한 개념이에요. 시스템 콜은 OS가 자신과 하드웨어를 보호하는 방법이에요.

교수
나는 하드디스크의 몇 번째 위치에 저장할 수 있는 권한이 없어요. 대신 저장을 하려면 OS가 제공해 주는 함수를 불러서만 쓸 수 있다. 이게 제일 중요하죠.9/14 강의 중 (말을 조금 다듬음)

C에서 쓰던 printf도 같아요. printf로 "화면 위에서 7칸, 왼쪽에서 10칸 위치"에 글자를 박을 수 있나요? 못 해요. 그냥 부탁하면 OS가 적당한 위치에 써 주죠. printf, scanf가 우리가 이미 써 온 시스템 콜 계열 함수예요.

시험엔 이렇게

시스템 콜 = 커널이 제공하는 하드웨어 접근용 함수. 응용 프로그램은 하드웨어에 직접 접근할 수 없고 시스템 콜을 통해서만 커널의 기능을 사용할 수 있다. 이를 통해 OS는 자원을 보호한다.

외우는 법: 값은 맡기되 자리는 OS가
✗ 틀린 생각시스템 콜을 쓰면 하드디스크의 원하는 위치에 직접 저장할 수 있다
○ 맞는 생각시스템 콜로 요청만 하고, 위치는 OS가 정한다
바로 확인
응용 프로그램이 파일을 저장하려 할 때 실제로 일어나는 일은?
프로그램은 시스템 콜로 부탁만 하고, 위치 결정과 실제 저장은 OS가 해요.

장면 4

내 프로그램은 실행되는 동안 몇 번이나 커널에 들어갔다 나올까?

사용자 모드 · 커널 모드 · 듀얼 모드 ★

덧셈·나눗셈 같은 일반 연산은 사용자 모드에서 돌아요. 그러다 write 같은 시스템 콜을 부르면 커널 모드로 들어가요. 커널 모드란 내 연산이 커널 안에서 돌아간다는 뜻인데, 내가 직접 들어가는 건 아니고 OS가 나 대신 작업해 줘요. 결과를 돌려받으면 다시 사용자 모드로 나와요.

이렇게 사용자 모드와 커널 모드를 번갈아 오가는 것을 이중 모드(듀얼 모드)라고 해요. C 코드에서 printf를 만날 때마다 커널 모드에 들어갔다 나오는 걸 우리는 모르고 있었던 거죠.

교수
사용자가 자발적으로 커널 모드에 들어갈 수 있는 유일한 방법은 시스템 콜밖에 없어요. 그래서 거기다 색깔로 표시를 해 놨지.9/14 강의 중 (말을 조금 다듬음)
시험엔 이렇게

이중 모드 = 사용자 모드와 커널 모드를 오가며 작업하는 방식. 사용자가 자발적으로 커널 모드에 진입할 수 있는 유일한 방법은 시스템 콜이다.

외우는 법: 커널 문은 하나, 시스템 콜
바로 확인
C 프로그램에서 a = b + c; 다음 줄에 printf("%d", a);가 있다. 각각 어느 모드에서 처리될까?
일반 연산은 사용자 모드, 화면 출력은 하드웨어를 쓰니까 시스템 콜 → 커널 모드. 끝나면 다시 사용자 모드로 돌아와요.

장면 5

35만 원짜리 마우스도, 만 원짜리 마우스도 꽂으면 되는 이유는?

디바이스 드라이버 · 플러그 앤 플레이 · API · SDK

마우스·키보드·그래픽카드는 종류가 엄청 많죠. OS가 그걸 다 알 수는 없어요. 그래서 커널과 하드웨어 사이를 표준 규격으로 연결해 주는 디바이스 드라이버를 설치해요. 하드웨어 쪽 인터페이스가 바로 이거예요.

요즘은 커널이 좋아져서 마우스·키보드는 꽂으면 바로 돼요. 이걸 플러그 앤 플레이라고 해요. 하지만 기능이 복잡한 그래픽카드와 프린터는 지금도 드라이버를 따로 설치해야 해요.

API와 SDK — "사람들이 되게 헷갈려 한다"

배달 앱을 만드는데 지도를 직접 구축하면 배보다 배꼽이 크죠. 구글이 "위치 찍기", "두 지점 거리" 같은 함수를 제공해 주면 그걸 불러 쓰면 돼요. OS의 시스템 콜처럼, 어떤 서비스가 응용 프로그램용으로 내놓은 함수 모음이 API예요(구글 API, 안드로이드 API, 카카오톡 API).

그런데 함수만 덜렁 있으면 뭘 하는 함수인지, 매개변수가 뭔지 모르잖아요. 그래서 API + 매뉴얼 + 코딩할 에디터까지 종합 선물 세트로 묶어 주는 게 SDK예요. 대표적인 예가 안드로이드 스튜디오.

APISDK
무엇응용 프로그램이 불러 쓰는 함수 모음API + 매뉴얼 + 에디터 등 개발 도구 묶음
예구글 지도 API, 카카오톡 API안드로이드 스튜디오
시험엔 이렇게

디바이스 드라이버 = 커널과 하드웨어를 연결하는 하드웨어 인터페이스. API = 응용 프로그램용 함수 모음. SDK = API에 매뉴얼·에디터 등 개발 도구를 합친 종합 패키지.

외우는 법: API는 함수, SDK는 선물 세트
바로 확인
함수 목록뿐 아니라 설명서와 코드 편집기까지 한꺼번에 받았다. 이것은?
함수(API)에 매뉴얼·에디터까지 묶은 종합 세트 = SDK. 안드로이드 스튜디오가 대표 예예요.

= 정의 · → 흐름 · / 대비 · ★ 출제

① 컴퓨팅 환경

  • 클라이언트-서버 → 서버 과부하 → P2P(목록만 서버, 파일은 직접)
  • 클라우드 = 빌려 쓰기(SaaS) · IoT = 사물이 인터넷에

② OS 구조 엔진 + 핸들

  • OS = UI + 커널 · 하드웨어는 커널 통해서만
  • 커널 기능 = 프로세스·메모리·저장장치·입출력 관리
  • CLI → GUI · 쉽다/어렵다 = UI 문제 ≠ 커널

③ 시스템 콜 ★ 제일 중요

  • = 커널이 제공하는 하드웨어 접근 함수 (write, read, printf)
  • 값은 맡기고 위치는 OS가 → OS의 자기 보호

④ 듀얼 모드 ★

  • 사용자 모드 ↔ 커널 모드 번갈아 = 이중 모드
  • 자발적 커널 모드 진입 유일한 방법 = 시스템 콜

⑤ 드라이버 / API / SDK 함수 vs 선물 세트

  • 디바이스 드라이버 = 커널↔하드웨어 · 플러그 앤 플레이(그래픽카드·프린터는 예외)
  • API = 함수 모음 / SDK = API + 매뉴얼 + 에디터

빈칸 채우기 눌러서 정답 확인

운영체제의 핵심 기능을 담당하는 부분을 커널이라 하고, 사용자와 커널 사이에서 명령과 결과를 주고받는 부분을 사용자 인터페이스라 한다. 응용 프로그램은 커널이 제공하는 함수인 시스템 콜을 통해서만 하드웨어를 쓸 수 있다. 사용자 모드와 커널 모드를 오가는 방식을 이중 모드라 하며, 자발적으로 커널 모드에 들어가는 유일한 방법은 시스템 콜이다. 커널과 하드웨어를 표준 규격으로 연결하는 것은 디바이스 드라이버이고, API에 매뉴얼과 에디터를 합친 것은 SDK다. 서버 과부하를 줄이려고 만든 구조는 P2P다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
P2P가 만들어진 이유는?
클라이언트-서버 구조에서 서버에 몰리는 과부하를 줄이기 위해. 서버는 목록만, 데이터는 직접 전송.
커널이란?
운영체제의 핵심 기능만 담당하는 부분. 하드웨어는 커널을 통해서만 접근할 수 있다.
커널의 4가지 핵심 기능은?
프로세스 관리, 메모리 관리, 저장장치 관리, 입출력 관리.
CLI와 GUI의 차이는?
CLI는 글자로 명령(초기 유닉스·MS-DOS), GUI는 마우스로 클릭하는 그래픽 인터페이스.
시스템 콜이란?
커널이 제공하는 하드웨어 접근용 함수. 응용 프로그램은 이걸 불러서만 하드웨어를 쓸 수 있다.
시스템 콜이 OS에게 주는 이점은?
프로그램이 하드웨어에 직접 접근하지 못하게 해서 자원과 OS 자신을 보호한다.
이중 모드(듀얼 모드)란?
사용자 모드와 커널 모드를 번갈아 오가며 작업하는 방식.
자발적으로 커널 모드에 들어가는 유일한 방법은?
시스템 콜.
디바이스 드라이버란?
커널과 하드웨어를 표준 규격으로 연결해 주는 소프트웨어(하드웨어 인터페이스).
API와 SDK의 차이는?
API = 응용 프로그램용 함수 모음. SDK = API + 매뉴얼 + 에디터 등 개발 도구 묶음(안드로이드 스튜디오).

    퀴즈 다 풀고 채점하기

    Q1운영체제 구조에 대한 설명으로 옳은 것은?

    하드웨어는 사용자·프로그램으로부터 완전히 격리되고 커널을 통해서만 쓸 수 있어요.

    Q2사용자가 자발적으로 커널 모드에 진입할 수 있는 유일한 방법은?

    교수님이 교재에 색깔로 표시해 둔 문장이에요. 커널 모드로 가는 문은 시스템 콜 하나.

    Q3프로그램이 write로 숫자 10을 저장했다. 저장 위치를 정하는 것은?

    프로그램은 값만 맡기고 위치는 정할 수 없어요. 그래야 남의 데이터를 덮어쓰는 일이 없죠.

    Q4새로 산 프린터를 꽂았더니 별도 프로그램을 설치하라고 한다. 이 프로그램은?

    프린터·그래픽카드처럼 기능이 복잡한 하드웨어는 플러그 앤 플레이가 안 돼서 드라이버를 설치해야 해요.

    Q5카카오톡 안에서 돌아가는 게임을 만들려면 카카오가 제공하는 무엇이 필요할까?

    서비스가 응용 프로그램용으로 내놓은 함수 모음 = API. 매뉴얼·에디터까지 묶여 있다면 SDK예요.

    Q6"스마트폰 OS는 유닉스 계열인데도 쓰기 쉽다"는 사실이 보여 주는 것은?

    같은 유닉스 계열이라도 전문가용 CLI는 어렵게, 터치 GUI는 쉽게 느껴져요. 인터페이스 차이예요.

    내 말로 설명하기 친구한테 말하듯이

    시스템 콜이 무엇이고 왜 필요한지, 듀얼 모드와 엮어서 설명해 보세요.

    프로그램들이 하드디스크에 마음대로 쓰면 서로 데이터를 덮어써 버려요. 그래서 OS는 하드웨어를 숨기고 write·read 같은 함수만 내놓는데, 이게 시스템 콜이에요. 프로그램은 값만 맡기고 위치는 OS가 정해요. 평소 연산은 사용자 모드에서 하다가 시스템 콜을 부르면 커널 모드로 들어가서 OS가 대신 처리하고, 끝나면 사용자 모드로 돌아와요. 이게 이중 모드이고, 사용자가 자발적으로 커널 모드에 들어가는 유일한 방법이 시스템 콜이에요.
