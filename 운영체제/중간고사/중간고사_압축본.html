1장 — 프로그램은 어떻게 하드웨어에 닿을까?

OS의 역할 · 일괄 처리 / 시분할 · 커널 · 시스템 콜 · 듀얼 모드 · 드라이버 · API/SDK

운영체제가 뭘까

  • 운영체제는 컴퓨터 자원을 효율적으로 관리하고, 응용 프로그램이 원활하게 작동하도록 지원하는 소프트웨어예요(바리스타).
  • 컴퓨터를 켜면 운영체제가 가장 먼저 실행돼요.

컴퓨터의 시작

  • 에니악은 키보드·모니터가 없었지만, 스위치와 전선으로 회로를 짜는 하드와이어링으로 프로그래밍이 가능해서 컴퓨터예요.
  • 폰노이만 구조는 프로그램을 메모리에 저장해 두고 CPU가 읽어서 처리하는 구조예요. 명령어와 데이터를 메모리에 두고 차례대로 처리해요.

시스템은 이렇게 바뀌었다

  • 일괄 작업 시스템: 모든 작업을 한꺼번에 처리하고, 실행 도중에는 데이터를 고칠 수 없어요. 멀티프로그래밍 수준은 1이에요.
  • 대화형 시스템: 사용자와 컴퓨터가 실시간으로 주고받아요. 대신 작업 시간을 예측하기 어려워요.
  • 시분할 시스템: 짧은 시간 단위로 작업을 나눠 동시에 실행되는 것처럼 보이게 해요. 그 시간 조각을 타임 슬라이스(타임 퀀텀)라고 해요.
  • 시분할 덕분에 여러 사람이 함께 쓰는 다중 사용자 시스템이 나왔고, 이를 지원하는 OS가 유닉스예요.

작은 컴퓨터와 원격 업데이트

  • 임베디드 시스템은 스마트워치처럼 특정 기능을 하도록 설계된 기기에 들어간 컴퓨터예요. PC처럼 여러 일을 하는 건 범용 컴퓨터고요.
  • OTA는 인터넷에 연결된 기기의 소프트웨어를 원격으로 업그레이드하거나 설정을 바꾸는 기술이에요.

운영체제의 속 — 이 장의 핵심

  • 운영체제는 사용자 인터페이스와 커널로 되어 있어요. 사용자 인터페이스는 CLI(명령어 입력)와 GUI(그래픽)로 나뉘어요.
  • 커널은 프로세스 관리, 메모리 관리, 저장장치 관리, 입출력 관리를 해요.
  • ★ 시스템 호출은 커널이 제공하는 시스템 함수(read·write)를 불러 쓰는 거예요. 프로그램은 요청만 하고, 커널이 자원을 안전하게 처리한 뒤 결과만 돌려줘요.
  • ★ 이중 모드 연산은 사용자 모드와 커널 모드를 오가며 일하는 방식이에요. printf·scanf도 안에서 write·read를 불러서 커널 모드에 다녀와요.
  • ★ 일반 프로세스가 자발적으로 커널 모드에 들어가는 유일한 방법은 시스템 호출이에요. 0으로 나누기나 배열 범위 초과 같은 오류가 나면 비자발적으로 커널 모드로 가요.

드라이버 · API · SDK

  • ★ 디바이스 드라이버는 커널과 하드웨어 사이의 인터페이스예요. 하드웨어를 만든 회사가 제공해요.
  • API는 특정 플랫폼용 프로그램을 개발하라고 제공하는 인터페이스예요(구글 맵 API).
  • SDK는 API에 사용 매뉴얼, 코드 편집기, 에뮬레이터까지 묶은 종합 개발 도구예요(안드로이드 스튜디오).

P2P와 클라우드

  • P2P는 서버가 중재만 하고, 파일은 그 파일을 가진 사용자에게서 직접 받는 구조예요. 서버 과부하를 줄이려고 나왔어요.
  • 클라우드 컴퓨팅은 하드웨어·소프트웨어를 중앙에 두고, 사용자는 인터넷으로 필요한 기능만 받아 쓰는 구조예요.
시험엔 이렇게

시스템 호출이란 커널이 제공하는 시스템 함수를 호출하여 사용하는 것으로, 응용 프로그램은 직접 자원에 접근하지 않고 read()·write() 같은 시스템 함수로 요청하며 커널이 안전하게 처리한 후 결과만 전달한다. 일반 프로세스가 자발적으로 커널 모드에 진입할 수 있는 유일한 방법은 시스템 호출뿐이다.

외우는 법: 커널 문은 하나, 시스템 콜
바로 확인

2장 — CPU는 메모리의 값을 어떻게 가져올까?

폰노이만 특징 · 필수장치 · Hz · 레지스터 7종 · 버스 방향 · 32비트 4GB · 휘발성

폰노이만 구조와 메모리

  • ★ 폰노이만 구조의 가장 중요한 특징은 모든 프로그램은 메모리로 올라와야만 실행된다는 거예요. 메모리가 유일한 작업 공간(조리대)이에요.
  • 운영체제도 프로그램이라, 전원을 켜면 가장 먼저 메모리로 올라와요. 이게 부팅이에요.
  • 그래서 필수장치는 CPU와 메모리 둘이에요.
  • 메모리가 작으면 데이터를 자주 옮기느라 느려지고, 작업에 충분하면 더 늘려도 빨라지지 않아요. 폰의 128·256GB는 메모리가 아니라 저장장치 크기예요.

속도와 버스

  • 헤르츠는 1초 동안 발생한 펄스 횟수예요. 모든 작업이 클럭 신호에 맞춰 진행돼서, 3GHz CPU는 1초에 약 30억 번 일해요. 클럭을 더 못 올리는 이유는 열이에요.
  • FSB(시스템 버스)는 메모리와 주변장치를 잇고 메인보드 속도를 정해요.
  • BSB(CPU 버스)는 CPU 내부를 잇고 CPU 클럭과 같은 속도로 움직여요.

CPU의 세 부분

  • ALU는 산술·논리 연산을 해요.
  • 제어장치는 명령어를 해석하고 다른 장치에 지시해요.
  • 레지스터는 데이터나 중간 결과를 잠깐 담아 두는 CPU 내부 메모리예요.

자료구조

  • 큐는 먼저 들어온 게 먼저 나가요(FIFO). 스택은 나중에 들어온 게 먼저 나가요(LIFO).
  • 배열은 크기가 고정이라 삽입·삭제가 어렵고, 연결 리스트는 포인터로 이어서 삽입·삭제가 쉬워요. 그래서 OS는 연결 리스트를 주로 써요.

버스 방향과 메모리

  • 제어 버스는 양방향이에요. 오류 신호가 CPU 쪽으로 올라오거든요.
  • 데이터 버스도 양방향이에요(MBR과 연결).
  • 주소 버스만 단방향이에요. 주소는 CPU에서 밖으로만 나가요(MAR과 연결).
  • 32비트 CPU는 주소를 2³²개 만들 수 있어서 메모리를 4GB까지만 써요.
  • 램은 읽고 쓸 수 있고 위치와 상관없이 같은 속도로 읽어요. 롬은 읽기만 돼요.
  • 메인 메모리는 빠른 휘발성 메모리(DDR)이고, SSD·USB는 구조가 복잡하고 느린 비휘발성 메모리예요.
  • GPU는 제어장치가 거의 없어 코어를 수천 개 넣을 수 있고, 그 속도를 따라가려고 메모리를 쌓아 올린 게 HBM이에요.
시험엔 이렇게

CPU가 메모리 값을 읽을 때 MAR에 주소를 쓰면 메모리가 그 값을 MBR에 올려 주고, 제어장치가 MBR의 값을 레지스터로 옮긴다. MAR과 MBR은 CPU와 메모리 사이의 인터페이스다.

외우는 법: MAR = Address, MBR = Buffer(값) · 주소만 일방통행
바로 확인

3장 — 프로세스는 어떤 상태들을 돌아다닐까?

프로그램 vs 프로세스 · 메모리 영역 · 5가지 상태 ★ · PCB · 문맥 교환

프로세스와 메모리 영역

  • ★ 프로세스는 프로그램이 실행되어 메모리에 올라온 상태예요. 움직이는 동적 상태이고, OS 입장에선 하나의 작업 단위예요.
  • 프로그램은 저장장치에 가만히 있는 정적 상태(레시피)예요.
  • 프로세스는 코드 영역과 데이터 영역으로 나뉘어요.
  • 데이터 영역의 정적 영역에는 정적·전역 변수가 들어가고, 크기가 고정이에요.
  • 힙에는 실행 중에 동적으로 할당한 변수(malloc)가 들어가요.
  • 스택에는 함수 호출 관련 데이터(반환 주소, 매개변수, 지역 변수)가 들어가요. 스택과 힙은 서로 반대 방향으로 자라요.

상태와 PCB

  • 대기 상태는 필수가 아니라 효율을 위해 만든 상태예요. I/O가 끝나면 실행이 아니라 준비로 돌아가요.
  • ★ PCB는 OS가 프로세스마다 상태 정보를 저장하는 자료구조예요(주문서). 프로세스 = 프로그램 + PCB.
  • PCB에는 포인터, 프로세스 상태, PID, PC, 우선순위, 레지스터 정보, 메모리 정보, 자원 정보, 계정 정보, PPID·CPID가 들어 있어요.

문맥 교환과 타임 슬라이스

  • ★ 문맥 교환은 CPU를 쓰던 프로세스를 멈추고 새 프로세스로 바꾸는 과정이에요. 나가는 쪽은 PCB에 작업 내용을 저장하고, 들어오는 쪽은 PCB 값으로 레지스터를 바꿔요.
  • 타임 슬라이스가 너무 크면 다른 프로세스가 오래 기다려요.
  • 너무 작으면(1ms인데 문맥 교환에 5ms) 교환에 시간을 더 써서 오버헤드가 커져요. 그래서 문맥 교환 시간을 고려해 충분히 크게 잡아요(유닉스 10~200ms).
시험엔 이렇게

준비 → 실행은 디스패치, 실행 → 준비는 타임아웃, 실행 → 대기는 I/O 요청, 대기 → 준비는 I/O 완료 인터럽트다. 대기 상태는 시스템 효율을 위한 상태다.

외우는 법: 생 · 준 · 실 · 완 + 실행에 매달린 대기 → 나오면 준비로
바로 확인
대기 상태에 있던 프로세스의 I/O가 끝났다. 다음 상태와 그 사건은?
CPU는 이미 다른 프로세스가 쓰고 있어서 준비로 가서 줄을 서요. 사건은 I/O 완료 인터럽트.

3장 — 이 코드는 몇 줄, 어떤 순서로 찍힐까?

부모-자식 · init · fork 반환값 · wait · 고아 · 좀비 · exec

부모-자식과 init

  • 가비지 컬렉션은 프로세스를 종료시키고 자원을 회수하는 일이에요.
  • 그래서 OS는 프로세스를 부모-자식 관계로 묶고, 자식이 끝나면 부모가 자원을 회수해요.
  • 모든 프로세스의 최상위 부모는 init(PID 1)이에요.

fork

  • 자식을 만드는 시스템 호출은 fork(), 내용을 바꾸는 시스템 호출은 exec()예요.
  • ★ fork는 프로세스를 메모리 안에서 그대로 복사해서 빨라요. 복사본과 다른 건 PID 하나이고, 부모·자식 번호는 PPID·CPID로 적혀요.
  • fork의 장점은 병렬 처리 구현, 빠른 프로세스 생성, 손쉬운 자원 상속, 편리한 자원 회수예요.
  • fork의 반환값은 자식에게 0, 부모에게 양수(자식 PID), 실패하면 −1이에요.
  • fork 뒤엔 프로세스가 2개라 출력도 2배가 돼요. 순서는 보장되지 않고, 부모가 wait하면 자식이 먼저 찍혀요.

고아 · 좀비 · exec

  • 부모가 먼저 끝나면 자식은 고아가 되고, 정리되지 못하고 남으면 좀비가 돼요.
  • return 0은 부모에게 "정상 종료했어요"를 알리는 거예요.
  • exec는 프로세스를 새로 만드는 대신 코드만 새 프로그램으로 바꿔요. PCB(PID)는 그대로, 데이터는 리셋돼요.
  • exec 아래 원래 코드는 이미 사라져서 실행되지 않아요. 셸은 fork로 자식을 만들고 exec로 바꿔서 내 프로그램을 실행해요.
연습 · 출력은? (폴더에 a.c만 있음)printf("start\n");
pid = fork();
if (pid == 0) {
    execlp("ls", "ls", NULL);
    printf("child end\n");      // ?
} else {
    wait(NULL);
    printf("parent end\n");
}

답: start → a.c → parent end. start는 fork 전이라 한 번만. 자식은 exec로 ls가 돼서 a.c를 찍고, child end는 사라진 코드라 안 찍혀요. 부모는 wait로 자식(ls)이 끝나길 기다렸다가 parent end를 찍어요.

시험엔 이렇게

fork는 자식에게 0, 부모에게 자식의 PID를 반환하며 이후 두 프로세스가 독립적으로 실행된다. exec는 PCB를 유지한 채 코드 영역을 교체하므로 exec 이후의 원래 코드는 실행되지 않는다.

외우는 법: fork는 복사(자식 0), exec는 바꿔치기(뒤는 사라짐)
바로 확인
fork(); fork(); printf("A\n"); — A는 몇 번 찍힐까? (응용)
첫 fork로 2개, 그 2개가 각각 두 번째 fork를 만나 4개. 4개의 프로세스가 모두 printf를 실행하니 4번이에요. fork 하나에 프로세스가 2배.

4장 — 프로세스를 늘릴까, 스레드를 늘릴까?

스레드 · 경량 프로세스 · 장점 4 · 크롬 · start/join · IPC · 동기/비동기 ★
멀티태스킹(프로세스 여러 개)멀티스레드

하나가 죽으면다른 건 멀쩡(안정성)같이 영향
예크롬 탭IE 탭, 한글 맞춤법, 카톡 파일 전송

스레드

  • 스레드는 프로세스 코드의 절차에 따라 CPU에 작업을 요청하는 실행 단위예요. 크기는 작업 > 프로세스 > 스레드 순이에요.
  • 멀티스레딩은 한 프로세스 안에서 여러 스레드가 동시에 작업하는 방식이에요.
  • 멀티스레드의 장점은 자원 공유, 문맥 교환이 효율적, 응답 속도 향상(곰플레이어), 적응성 향상(멀티코어)이에요.

스레드 코드

  • 자바에서 start()로 스레드를 실행하면 main과 따로 돌아서 출력 순서가 보장되지 않아요.
  • join()을 try 안에서 쓰면 스레드가 끝난 뒤 main이 실행돼요.
  • C에서는 pthread_create로 만들고 pthread_join으로 기다려요.

프로세스 간 통신(IPC)

  • 방법은 공유 메모리·공유 파일, 파이프(같은 컴퓨터 안, 단방향이라 양방향은 2개), 소켓(네트워크로 다른 컴퓨터)이에요.
  • 양쪽으로 되지만 한순간엔 한쪽만 말하는 반양방향의 예는 무전기예요.
  • ★ 비동기화 통신(논블로킹, 전보)은 데이터가 언제 올지 몰라서 반복문으로 계속 확인해요. 이걸 바쁜 대기라고 하고, 공유 메모리·공유 파일이 여기에 해당해요.
  • ★ 동기화 통신(블로킹, 전화)은 데이터가 올 때까지 OS가 대기시켜 줘요. 파이프·소켓이 여기에 해당해요.
  • 파일 입출력은 open(존재·권한 확인 후 FD 받기) → read/write → close 순서예요(찜질방 락커 키).
시험엔 이렇게

스레드는 프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위로, 자원을 공유해 가볍고 문맥 교환이 효율적이지만 한 스레드의 문제가 프로세스 전체에 영향을 준다. 안정성이 중요하면 멀티프로세스, 효율이 중요하면 멀티스레드를 택한다.

외우는 법: 안정성은 프로세스, 효율은 스레드 · 장점 공·교·응·확
바로 확인
소켓으로 receive를 걸어 두면 데이터가 올 때 시스템이 받아 주고 다음 줄이 실행된다. 이 방식은?
느긋하게 기다리다 도착하면 이어서 실행 = 동기화 통신. 내가 계속 들여다봐야 하는 게 비동기화예요.

5장 — 평균 대기 시간, 손으로 구할 수 있을까?

저수준 스케줄링 · 선점/비선점 ★★★★★ · 우선순위 · 큐 · FCFS 계산 · 콘보이 효과

스케줄링의 기본

  • 이 장은 저수준 스케줄링(준비 상태 중 하나를 골라 디스패치)만 다뤄요. CPU 스케줄링이라고 하면 보통 저수준을 말해요.
  • ★ 선점형은 스케줄러가 실행 중인 프로세스의 CPU를 강제로 빼앗을 수 있어요(시분할). 문맥 교환 낭비가 있지만 응답이 빨라요.
  • ★ 비선점형은 끝날 때까지 CPU를 못 빼앗아요(과거 일괄 작업). 오버헤드는 작지만 긴 작업 때문에 짧은 작업이 오래 기다려요.
  • 비선점형 알고리즘은 FCFS·SJF·HRN, 선점형은 RR·SRT·다단계 큐·다단계 피드백 큐예요.

우선순위와 큐

  • 우선순위는 커널이 일반보다, 전면이 후면보다, 대화형이 일괄 작업보다 높아요.
  • I/O 집중 프로세스가 CPU 집중 프로세스보다 높아요. I/O를 요청하면 바로 대기로 빠져서 CPU를 비켜 주니까 효율이 올라가요.
  • 요즘은 상황에 따라 우선순위를 바꾸는 변동 우선순위를 써요. 이 수업에선 0번이 가장 높아요.
  • 준비 큐는 우선순위별, 대기 큐는 장치별로 줄을 서고, 모두 연결 리스트예요.

평균 대기 시간과 FCFS

  • 대기 시간은 시작 시각 − 도착 시각이에요. 반환 시간은 끝 − 도착(= 대기 + 실행)이에요.
  • 알고리즘은 평균 대기 시간(대기 시간의 합 ÷ 프로세스 수)으로 비교해요.
  • FCFS는 준비 큐에 도착한 순서대로 처리하는 비선점형이고, 모든 프로세스의 우선순위가 같아요. 교재 예제의 평균 대기 시간은 (0 + 27 + 42) ÷ 3 = 23ms예요.
  • FCFS의 약점은 콘보이 효과예요. 긴 작업 뒤에서 짧은 작업이 오래 기다려요.

① 1장 운영체제 개요 ★커널 문은 하나

  • 운영체제는 컴퓨터 자원을 효율적으로 관리하고 응용 프로그램이 원활하게 작동하도록 지원하는 소프트웨어예요. 모든 작업을 한꺼번에 처리하던 일괄 작업 시스템에서, 사용자와 실시간으로 주고받는 대화형 시스템을 거쳐, 짧은 시간 단위(타임 슬라이스)로 나눠 동시에 도는 것처럼 보이게 하는 시분할 시스템으로 발전했어요.
  • 운영체제는 사용자 인터페이스와 커널로 되어 있고, 프로그램은 커널이 제공하는 시스템 함수(read·write)를 불러서만 자원을 써요. 이게 시스템 호출이고, 사용자 모드와 커널 모드를 오가는 이중 모드 연산에서 자발적으로 커널 모드에 들어가는 유일한 방법이에요.
  • 커널과 하드웨어 사이의 인터페이스는 디바이스 드라이버, 특정 플랫폼용 개발 인터페이스는 API, 거기에 매뉴얼·편집기·에뮬레이터까지 묶으면 SDK예요.

② 2장 컴퓨터의 구조 ★ 레지스터

  • 폰노이만 구조에서 가장 중요한 특징은 모든 프로그램이 메모리에 올라와야만 실행된다는 것이에요. 메모리가 유일한 작업 공간이고, OS가 가장 먼저 올라오는 과정이 부팅이에요.
  • CPU는 ALU(연산)·제어장치(명령 해석·지시)·레지스터(임시 저장)로 돼요. PC는 다음 명령어 위치, IR은 현재 명령어, MAR은 메모리 주소, MBR은 주고받는 값을 저장해요.
  • 버스 중 주소 버스만 단방향이고, 32비트 CPU는 4GB까지 써요. 메인 메모리는 빠른 휘발성 램이에요.

③ 3장 프로세스 상태 ★ 평생

  • 프로세스는 프로그램이 실행되어 메모리에 올라온 상태예요. 준비 → 실행은 디스패치, 실행 → 준비는 타임아웃, 실행 → 대기는 I/O 요청, 대기에서는 I/O 완료 인터럽트를 받아 준비로 돌아가요.
  • OS는 프로세스마다 상태 정보를 PCB에 저장하고, CPU를 쓰던 프로세스를 중단하고 새 프로세스로 바꾸는 문맥 교환 때 PCB를 저장·복원해요. 타임 슬라이스가 너무 작으면 문맥 교환 오버헤드가 커져요.

④ 3장 fork · exec 복사 / 바꿔치기

  • fork는 자식을 만드는 시스템 호출이에요. 자식에게 0, 부모에게 자식의 PID를 돌려주고, 두 프로세스가 같이 돌아서 출력이 2배가 돼요. 부모가 wait하면 자식이 먼저 찍혀요.
  • 부모가 먼저 끝나면 고아, 정리되지 못하면 좀비가 돼요. exec는 PCB는 그대로 두고 코드만 새 프로그램으로 바꾸니까 exec 아래 원래 코드는 실행되지 않아요.

⑤ 4장 스레드 · IPC ★ 동기/비동기

  • 스레드는 CPU에 작업을 요청하는 실행 단위예요. 자원을 공유해 가벼운 경량 프로세스이고, 장점은 자원 공유·문맥 교환 효율·응답 속도 향상·적응성 향상이에요. 크롬은 안정성 때문에 탭마다 프로세스를 써요.
  • 자바 스레드는 start 후 순서가 보장되지 않고, join(try 안)으로 기다리면 스레드가 먼저 끝나요. 데이터가 언제 올지 몰라 반복문으로 확인(바쁜 대기)하는 게 비동기화 통신(공유 메모리·파일), OS가 기다려 주는 게 동기화 통신(파이프·소켓)이에요.

⑥ 5장 CPU 스케줄링 ★ 계산

  • 실행 중인 프로세스의 CPU를 빼앗을 수 있으면 선점형, 끝날 때까지 못 빼앗으면 비선점형이에요. 시스템 효율을 위해 I/O 집중 프로세스에 우선순위를 더 줘요.
  • 대기 시간은 시작 시각 − 도착 시각이고, 평균 대기 시간은 그 합을 프로세스 수로 나눠요. 도착 순서대로 처리하는 FCFS는 긴 작업 뒤에서 짧은 작업이 오래 기다리는 콘보이 효과가 약점이에요.

빈칸 채우기 눌러서 정답 확인

사용자가 자발적으로 커널 모드에 들어가는 유일한 방법은 시스템 콜이다. 폰노이만 구조에서 모든 프로그램은 메모리에 올라와야만 실행된다. 다음에 실행할 명령어의 위치는 PC가, 메모리에서 읽을 주소는 MAR가 가진다. 준비 상태의 프로세스에 CPU를 주는 것을 디스패치라 하고, 실행 중인 프로세스의 정보를 PCB에 저장하고 다음 것으로 바꾸는 것을 문맥 교환이라 한다. fork는 자식에게 0을 반환하며, 코드를 바꿔치기하는 시스템 콜은 exec이다. 실행 중인 프로세스의 CPU를 빼앗을 수 있는 스케줄링은 선점형이고, FCFS에서 긴 작업 때문에 짧은 작업이 오래 기다리는 현상은 콘보이 효과다.

시스템 콜이란?
커널이 제공하는 하드웨어 접근용 함수. 응용 프로그램은 이걸 통해서만 하드웨어를 쓴다.
자발적으로 커널 모드에 들어가는 유일한 방법은?
시스템 콜.
폰노이만 구조의 가장 중요한 특징은?
모든 프로그램은 메모리로 올라와야만 실행된다.
PC · IR · MAR · MBR · PSR은?
PC 다음 명령어 위치, IR 현재 명령어, MAR 메모리 주소, MBR 메모리와 주고받는 값, PSR 분기 결정.
단방향 버스는?
주소 버스(CPU → 밖). 제어·데이터 버스는 양방향.
상태 이동과 사건 4개는?
준비→실행 디스패치, 실행→준비 타임아웃, 실행→대기 I/O 요청, 대기→준비 I/O 인터럽트.
문맥 교환과 타임 슬라이스의 관계는?
타임 슬라이스가 너무 작으면 문맥 교환 오버헤드가 커진다. 문맥 교환 시간보다 충분히 크게, 가능한 작게.
fork의 반환값은?
자식 0, 부모 자식의 PID(양수), 실패 −1.
exec 후 그대로인 것과 바뀌는 것은?
PCB(PID) 그대로, 코드 교체, 데이터 리셋. exec 아래 원래 코드는 실행 안 됨.
멀티스레드 장점 4가지는?
자원 공유, 문맥 교환이 효율적, 응답 속도 향상, 적응성 향상.
동기화 통신과 비동기화 통신은?
비동기 = 받는 쪽이 계속 확인. 동기 = 도착하면 알려 줌.
선점형과 비선점형은?
선점형 = CPU를 뺏을 수 있음(시분할). 비선점형 = 끝날 때까지 못 뺏음(일괄 작업).

    퀴즈 다 풀고 채점하기

    Q1다음 중 옳은 것은?

    위치는 OS가 정하고(1 ✗), 커널 모드 진입은 시스템 콜(2 ✗), 에디터까지 합친 건 SDK(3 ✗).

    Q2메모리 200번지의 값을 읽는다. 순서로 옳은 것은?

    주소는 MAR, 값은 MBR. CPU와 메모리는 독립 장치라 직접 들어가지 않아요.

    Q332비트 CPU가 최대로 쓸 수 있는 메모리 크기와 이유는?

    1바이트당 주소 하나, 32비트 주소 = 2³² = 4G개.

    Q4실행 중인 프로세스가 키보드 입력을 기다리게 됐다. 상태 변화와 그 이유는?

    I/O 요청 → 대기 상태. 효율을 위한 상태예요.

    Q5pid = fork(); if (pid > 0) printf("P"); else if (pid == 0) printf("C"); (wait 없음) 출력으로 가능한 것은?

    부모는 P, 자식은 C를 한 번씩. wait가 없으니 순서는 보장되지 않아요.

    Q6exec에 대한 설명으로 틀린 것은?

    새 PID의 자식을 만드는 건 fork. exec는 집(PCB)은 그대로 두고 코드만 바꿔요.

    Q7탭 하나가 죽어도 다른 탭은 멀쩡한 브라우저는 탭을 무엇으로 만들었을까?

    크롬처럼 안정성을 위해 탭을 프로세스로. 스레드면 같이 영향을 받아요.

    Q8P1(도착 0, 실행 5), P2(도착 1, 실행 3), P3(도착 2, 실행 8), P4(도착 3, 실행 6)를 FCFS로 처리할 때 평균 대기 시간은?

    간트 차트: P1 0~5, P2 5~8, P3 8~16, P4 16~22. 대기: 0, 5 − 1 = 4, 8 − 2 = 6, 16 − 3 = 13. (0 + 4 + 6 + 13) ÷ 4 = 23 ÷ 4 = 5.75.

    내 말로 설명하기 서술형 대비

    프로세스가 생성돼서 종료될 때까지의 과정을 상태도·PCB·문맥 교환을 넣어 설명해 보세요.

    프로그램이 메모리에 올라오면서 PCB를 받아 생성되고, 준비 상태의 우선순위별 큐에서 CPU를 기다려요. 디스패치되면 CPU는 그 프로세스의 PCB에 저장된 PC와 레지스터 값으로 자기 레지스터를 채우고 실행해요. 타임 슬라이스를 다 쓰면 현재 레지스터 값을 PCB에 저장하고(문맥 교환) 타임아웃으로 준비 상태로 돌아가요. 실행 중 I/O를 요청하면 대기 상태로 가서 장치별 대기 큐에 서고, I/O가 끝나면 인터럽트를 받아 준비 상태로 가요. 작업이 끝나면 PCB를 지우고 완료돼요.
