1장 — 프로그램은 어떻게 하드웨어에 닿을까?

OS의 역할 · 일괄 처리 / 시분할 · 커널 · 시스템 콜 · 듀얼 모드 · 드라이버 · API/SDK

운영체제가 뭘까

  • 운영체제 : 컴퓨터 자원을 효율적으로 관리하고, 응용 프로그램이 원활하게 작동하도록 지원하는 소프트웨어. 컴퓨터를 켜면 가장 먼저 실행된다 (바리스타)

컴퓨터의 시작

  • ★ 에니악 : 최초의 전자식 컴퓨터. 키보드·모니터는 없었지만 하드와이어링으로 프로그래밍이 가능해서 컴퓨터다
  • 하드와이어링 : 스위치와 전선으로 회로를 구성해 프로그램을 대신하는 방식
  • ★ 폰노이만 구조 : 하드웨어는 그대로 두고 프로그램을 메모리에 저장해 CPU가 읽고 처리하는 구조. 명령어와 데이터를 메모리에 두고 순차 처리

시스템은 이렇게 바뀌었다

  • ★ 일괄 작업 시스템 : 모든 작업을 한꺼번에 처리하는 시스템. 실행 도중 데이터 수정 불가, 작업 시간 예측 가능
  • 대화형 시스템 : 사용자와 컴퓨터가 실시간으로 상호작용하는 시스템. 작업 시간 예측이 어려움
  • ★ 시분할 시스템 : 짧은 시간 단위로 작업을 나눠 동시에 실행되는 것처럼 보이게 하는 시스템
  • 타임 슬라이스(타임 퀀텀) : CPU 작업 시간을 잘게 나눈 조각
  • 멀티프로그래밍 수준 : 동시에 실행되는 작업의 개수. 일괄 작업 시스템은 1
  • 다중 사용자 시스템 : 여러 사람이 한 컴퓨터를 동시에 쓰는 시스템. 이를 지원하는 OS가 유닉스

작은 컴퓨터와 원격 업데이트

  • 임베디드 시스템 : 특정 기능을 하도록 설계된 기기에 탑재된 컴퓨터 (스마트워치, 스마트 TV)
  • 범용 컴퓨터 : 다양한 작업을 처리하는 일반 컴퓨터 (PC)
  • ★ OTA : 인터넷에 연결된 기기의 소프트웨어를 원격으로 업그레이드하거나 설정을 바꾸는 기술

운영체제의 속 — 이 장의 핵심

  • ★ 사용자 인터페이스 : 사용자가 운영체제와 직접 소통하는 수단. CLI(명령어 입력)와 GUI(그래픽)로 나뉨
  • ★ 커널 : 운영체제의 핵심 기능을 하는 중앙 제어 소프트웨어. 프로세스·메모리·저장장치·입출력 관리
  • ★ 시스템 호출 : 커널이 제공하는 시스템 함수(read·write)를 호출해 사용하는 것. 커널이 자원을 안전하게 처리하고 결과만 전달
  • ★ 이중 모드 연산 : 사용자 모드와 커널 모드를 오가는 작업 방식. printf·scanf도 안에서 write·read를 호출
  • ★ 일반 프로세스가 자발적으로 커널 모드에 들어가는 유일한 방법은 시스템 호출. 0으로 나누기·배열 범위 초과 같은 오류가 나면 비자발적으로 커널 모드로 간다.

드라이버 · API · SDK

  • ★ 디바이스 드라이버 : 커널과 하드웨어 사이의 인터페이스. 하드웨어 제작자가 제공
  • ★ API : 특정 플랫폼이나 소프트웨어용 프로그램을 개발할 수 있도록 제공되는 인터페이스 (구글 맵 API)
  • SDK : API + 사용 매뉴얼 + 코드 편집기 + 에뮬레이터를 묶은 종합 개발 도구 (안드로이드 스튜디오)

P2P와 클라우드

  • P2P : 서버는 중재만 하고 파일은 가진 사용자(peer)에게서 직접 받는 구조. 서버 과부하를 줄이려고 등장
  • 클라우드 컴퓨팅 : 하드웨어·소프트웨어를 중앙에 두고, 사용자는 인터넷으로 필요한 기능만 제공받는 구조
시험엔 이렇게

시스템 호출이란 커널이 제공하는 시스템 함수를 호출하여 사용하는 것으로, 응용 프로그램은 직접 자원에 접근하지 않고 read()·write() 같은 시스템 함수로 요청하며 커널이 안전하게 처리한 후 결과만 전달한다. 일반 프로세스가 자발적으로 커널 모드에 진입할 수 있는 유일한 방법은 시스템 호출뿐이다.

외우는 법: 커널 문은 하나, 시스템 콜
바로 확인

2장 — CPU는 메모리의 값을 어떻게 가져올까?

폰노이만 특징 · 필수장치 · Hz · 레지스터 7종 · 버스 방향 · 32비트 4GB · 휘발성

폰노이만 구조와 메모리

  • ★ 폰노이만 구조의 가장 중요한 특징 : 모든 프로그램은 메모리로 올라와야만 실행된다. 메모리가 유일한 작업 공간(조리대)
  • ★ 요리사 모형 : 요리사 = CPU, 조리대 = 메모리, 창고 = 저장장치, 주방 보조 = OS, 보조 요리사 = GPU. 요리사는 창고 재료를 조리대로 가져와야만 요리할 수 있다
  • 부팅 : 전원을 켜면 운영체제가 가장 먼저 메모리로 올라오는 과정
  • 필수장치 : CPU와 메모리. 나머지(입력·출력·저장장치)는 주변장치
  • 메모리가 작으면 데이터를 옮기느라 느려지고, 작업에 충분하면 더 늘려도 빨라지지 않는다. 폰의 128·256GB는 메모리가 아니라 저장장치 크기.

속도와 버스

  • 헤르츠(Hz) : 1초 동안 발생한 펄스의 횟수. 3GHz CPU는 1초에 약 30억 번 작업
  • 클럭 : 컴퓨터 작업의 박자를 만드는 장치. 모든 작업이 클럭 신호에 맞춰 진행. 더 못 올리는 이유는 열
  • FSB(시스템 버스, 전면 버스) : 메모리와 주변장치를 연결하는 버스. 메인보드의 동작 속도를 결정
  • BSB(CPU 버스, 후면 버스) : CPU 내부 구성 요소를 연결하는 버스. CPU 클럭과 같은 속도

CPU의 세 부분

  • ★ ALU(산술논리 연산장치) : 덧셈·뺄셈 같은 산술 연산과 AND·OR 같은 논리 연산을 함
  • ★ 제어장치 : 명령어를 해석하고 다른 장치에 작업을 지시
  • ★ 레지스터 : 연산에 필요한 데이터나 중간 결과를 임시로 저장하는 CPU 내부 메모리

자료구조

  • 큐 : 먼저 들어온 데이터가 먼저 나가는 구조(FIFO). 햄버거 주문 줄
  • 스택 : 나중에 들어온 데이터가 먼저 나가는 구조(LIFO). 좁은 봉투 속 햄버거
  • 배열 : 일정 크기의 연속된 메모리. 크기 고정, 삽입·삭제 어려움
  • 연결 리스트 : 데이터를 포인터로 연결. 삽입·삭제가 쉬워 OS가 주로 사용
레지스터 (꼭 외움)역할
PC ★다음에 실행할 명령어 위치
IR현재 명령어(LOAD·ADD·MOVE)
MAR ★메모리에서 읽거나 쓸 주소
MBR ★메모리와 주고받는 값
PSR분기(if) 결정
DR / AR데이터 임시 보관 / 데이터의 메모리 주소

버스 방향과 메모리

  • 제어 버스 : 양방향. 명령과 오류 신호가 오감
  • 데이터 버스 : 양방향. MBR과 연결
  • 주소 버스 : 단방향 (CPU → 밖). MAR과 연결
  • 32비트 CPU : 주소를 2³²개 만들 수 있어 메모리를 4GB까지 사용
  • 램(RAM) : 읽고 쓸 수 있고, 저장 위치와 관계없이 같은 속도로 읽는 메모리
  • 롬(ROM) : 읽기만 할 수 있는 메모리
  • 휘발성 메모리 : 전원이 꺼지면 데이터가 사라지는 메모리. 빨라서 메인 메모리(DDR)로 사용
  • 비휘발성 메모리 : 전원이 없어도 데이터를 보관. 구조가 복잡하고 느려서 저장장치(SSD·USB)로 사용
  • HBM : GPU 속도를 따라가려고 메모리(DDR)를 수직으로 쌓은 것
시험엔 이렇게

CPU가 메모리 값을 읽을 때 MAR에 주소를 쓰면 메모리가 그 값을 MBR에 올려 주고, 제어장치가 MBR의 값을 레지스터로 옮긴다. MAR과 MBR은 CPU와 메모리 사이의 인터페이스다.

3장 — 프로세스는 어떤 상태들을 돌아다닐까?

프로그램 vs 프로세스 · 메모리 영역 · 5가지 상태 ★ · PCB · 문맥 교환

프로세스와 메모리 영역

  • ★ 프로세스 : 프로그램이 실행되어 메모리에 올라온 상태. 동적이며 OS의 작업 단위. 프로세스 = 프로그램 + PCB
  • 프로그램 : 저장장치에 있는 정적인 상태 (레시피)
  • 코드 영역 : 프로그램 본체(명령어)가 있는 영역
  • 정적 데이터 영역 : 정적 변수·전역 변수가 저장되는 영역. 크기 고정, 프로그램이 끝날 때까지 유지
  • ★ 힙 : 실행 중에 동적으로 할당된 변수(malloc)가 저장되는 영역
  • 스택 : 함수 호출 관련 데이터(반환 주소, 매개변수, 지역 변수)가 쌓이는 영역. 함수가 끝나면 제거. 힙과 반대 방향으로 자람

상태와 PCB

  • ★ 대기 상태 : I/O를 요청한 프로세스가 가는 상태. 필수가 아닌, 시스템 효율을 위한 상태. I/O가 끝나면 실행이 아니라 준비로
  • ★ PCB(프로세스 제어 블록) : OS가 프로세스별 상태 정보를 저장하는 자료구조 (주문서)
  • ★ PCB 구성 : 포인터, 프로세스 상태, PID, PC, 우선순위, 레지스터 정보, 메모리 관리 정보, 할당된 자원 정보, 계정 정보, PPID·CPID

문맥 교환과 타임 슬라이스

  • ★ 문맥 교환 : CPU를 쓰던 프로세스를 중단하고 새 프로세스로 전환하는 과정. 나가는 쪽은 PCB에 저장, 들어오는 쪽은 PCB 값으로 레지스터 변경
  • 오버헤드 : 실제 작업이 아닌 문맥 교환 같은 부가 작업에 드는 낭비
  • 타임 슬라이스가 너무 크면 다른 프로세스가 오래 기다리고, 너무 작으면(1ms인데 교환 5ms) 오버헤드가 커진다. 그래서 문맥 교환 시간을 고려해 충분히 크게 (유닉스 10~200ms).
시험엔 이렇게

준비 → 실행은 디스패치, 실행 → 준비는 타임아웃, 실행 → 대기는 I/O 요청, 대기 → 준비는 I/O 완료 인터럽트다. 대기 상태는 시스템 효율을 위한 상태다.

외우는 법: 생 · 준 · 실 · 완 + 실행에 매달린 대기 → 나오면 준비로

3장 — 이 코드는 몇 줄, 어떤 순서로 찍힐까?

부모-자식 · init · fork 반환값 · wait · 고아 · 좀비 · exec

부모-자식과 init

  • 가비지 컬렉션 : 프로세스를 종료시키고 자원을 회수하는 일
  • 부모-자식 관계 : 관련 프로세스를 묶어 관리하는 방식. 자식이 끝나면 부모가 자원을 회수
  • ★ init : PID 1번. 모든 프로세스의 최상위 부모 (그 위 swapper는 PID 0, OS 그 자체)

fork

  • ★ fork() : 기존 프로세스로부터 자식 프로세스를 생성하는 시스템 호출. 메모리 안에서 복사해서 빠름
  • ★ fork의 장점 : 병렬 처리 구현, 빠른 프로세스 생성, 손쉬운 자원 상속, 편리한 자원 회수
  • fork 반환값 : 자식에게 0, 부모에게 양수(자식 PID), 실패하면 −1
  • PPID · CPID : 부모 PID, 자식 PID. 복사본과 원본은 PID만 다름
  • wait : 부모가 자식이 끝날 때까지 기다리게 함. 그래서 자식 출력이 먼저
  • fork 뒤엔 프로세스가 2개라 출력도 2배. 순서는 보장되지 않는다.

고아 · 좀비 · exec

  • 고아 프로세스 : 부모가 먼저 끝나 버린 자식 프로세스
  • 좀비 프로세스 : 끝났는데 정리되지 못하고 남아 자원을 낭비하는 프로세스
  • return 0 : 부모에게 정상 종료를 알리는 것
  • ★ exec() : 프로세스를 새로 만드는 대신 코드만 새 프로그램으로 바꾸는 시스템 호출. PCB(PID) 그대로, 데이터 리셋. exec 아래 원래 코드는 실행 안 됨
  • 셸 : fork로 자식을 만들고 exec로 바꿔서 내 프로그램을 실행
연습 · 출력은? (폴더에 a.c만 있음)printf("start\n");
pid = fork();
if (pid == 0) {
    execlp("ls", "ls", NULL);
    printf("child end\n");      // ?
} else {
    wait(NULL);
    printf("parent end\n");
}

답: start → a.c → parent end. start는 fork 전이라 한 번만. 자식은 exec로 ls가 돼서 a.c를 찍고, child end는 사라진 코드라 안 찍혀요. 부모는 wait로 자식(ls)이 끝나길 기다렸다가 parent end를 찍어요.

시험엔 이렇게

fork는 자식에게 0, 부모에게 자식의 PID를 반환하며 이후 두 프로세스가 독립적으로 실행된다. exec는 PCB를 유지한 채 코드 영역을 교체하므로 exec 이후의 원래 코드는 실행되지 않는다.

외우는 법: fork는 복사(자식 0), exec는 바꿔치기(뒤는 사라짐)
바로 확인
fork(); fork(); printf("A\n"); — A는 몇 번 찍힐까? (응용)
첫 fork로 2개, 그 2개가 각각 두 번째 fork를 만나 4개. 4개의 프로세스가 모두 printf를 실행하니 4번이에요. fork 하나에 프로세스가 2배.

4장 — 프로세스를 늘릴까, 스레드를 늘릴까?

스레드 · 경량 프로세스 · 장점 4 · 크롬 · start/join · IPC · 동기/비동기 ★
멀티태스킹(프로세스 여러 개)멀티스레드
만드는 법fork로 통째 복사한 프로세스 안에 실행 단위만 추가
자원각자 따로코드·파일·데이터 공유 → 경량 프로세스
하나가 죽으면다른 건 멀쩡(안정성)같이 영향
예크롬 탭IE 탭, 한글 맞춤법, 카톡 파일 전송

스레드

  • 스레드 : 프로세스 코드의 절차에 따라 CPU에 작업을 요청하는 실행 단위. 작업 > 프로세스 > 스레드
  • 멀티스레딩 : 한 프로세스 안에서 여러 스레드가 동시에 작업하는 방식
  • 경량 프로세스 : 자원을 공유해 가벼운 스레드를 부르는 말
  • 멀티스레드 장점 : 자원 공유, 문맥 교환이 효율적, 응답 속도 향상(곰플레이어), 적응성 향상(멀티코어)

스레드 코드

  • ★ start() : 자바 스레드 실행. main과 따로 돌아 출력 순서가 보장되지 않음
  • ★ join() : 스레드가 끝날 때까지 main이 기다리게 함. try 안에서 사용
  • ★ pthread_create / pthread_join : C에서 스레드 생성 / 스레드 기다림(자원 회수)

프로세스 간 통신(IPC)

  • IPC : 독립된 프로세스끼리 데이터를 주고받는 것. 공유 메모리·공유 파일·파이프·소켓
  • 파이프 : 같은 컴퓨터 안의 프로세스끼리 통신. 단방향이라 양방향은 2개
  • 소켓 : 네트워크로 연결된 다른 컴퓨터와 통신
  • 반양방향 : 양쪽으로 되지만 한순간엔 한쪽만 말함 (무전기)
  • ★ 비동기화 통신(논블로킹) : 데이터가 언제 올지 몰라 프로세스가 반복문으로 계속 확인. 공유 메모리·공유 파일 (전보)
  • 바쁜 대기 : 비동기화 통신에서 while 같은 반복문으로 도착을 계속 확인하며 기다리는 것
  • ★ 동기화 통신(블로킹) : 데이터가 올 때까지 OS가 대기시켜 줌. 파이프·소켓 (전화)
  • 파일 입출력 구조 : open(존재·권한 확인 후 FD 받기) → read/write → close (찜질방 락커 키)
시험엔 이렇게

스레드는 프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위로, 자원을 공유해 가볍고 문맥 교환이 효율적이지만 한 스레드의 문제가 프로세스 전체에 영향을 준다. 안정성이 중요하면 멀티프로세스, 효율이 중요하면 멀티스레드를 택한다.

외우는 법: 안정성은 프로세스, 효율은 스레드 · 장점 공·교·응·확
바로 확인
소켓으로 receive를 걸어 두면 데이터가 올 때 시스템이 받아 주고 다음 줄이 실행된다. 이 방식은?
느긋하게 기다리다 도착하면 이어서 실행 = 동기화 통신. 내가 계속 들여다봐야 하는 게 비동기화예요.

5장 — 평균 대기 시간, 손으로 구할 수 있을까?

저수준 스케줄링 · 선점/비선점 ★★★★★ · 우선순위 · 큐 · FCFS 계산 · 콘보이 효과

스케줄링의 기본

  • 저수준 스케줄링 : 준비 상태 중 하나를 골라 디스패치하는 단계. CPU 스케줄링이라 하면 보통 이것. 이 장은 저수준만
  • ★ 선점형 스케줄링 : 스케줄러가 실행 중인 프로세스의 CPU를 강제로 빼앗을 수 있는 방식(시분할). 문맥 교환 낭비가 있지만 응답이 빠름
  • ★ 비선점형 스케줄링 : 끝날 때까지 CPU를 빼앗을 수 없는 방식(과거 일괄 작업). 오버헤드는 작지만 짧은 작업이 오래 기다림
  • 알고리즘 분류 : 비선점형 = FCFS·SJF·HRN / 선점형 = RR·SRT·다단계 큐·다단계 피드백 큐

우선순위와 큐

  • ★ 우선순위 : 커널 > 일반, 전면 > 후면, 대화형 > 일괄 작업, I/O 집중 > CPU 집중. 이 수업에선 0번이 가장 높음
  • I/O 집중 프로세스 : 입출력이 많아 대기 상태로 자주 가는 프로세스. 바로 CPU를 비켜 주니 우선순위를 높게 주면 효율이 올라감
  • CPU 집중 프로세스 : 수학 연산처럼 CPU를 오래 쓰는 프로세스
  • 변동 우선순위 : 상황에 따라 우선순위를 바꾸는 방식
  • ★ 준비 큐 : 우선순위별로 줄 선 큐 (연결 리스트)
  • ★ 대기 큐 : 입출력 장치별로 줄 선 큐 (연결 리스트)

평균 대기 시간과 FCFS

  • 대기 시간 : 시작 시각 − 도착 시각
  • 반환 시간 : 끝 시각 − 도착 시각 (= 대기 + 실행)
  • 평균 대기 시간 : 모든 프로세스의 대기 시간 합 ÷ 프로세스 수. 알고리즘 비교 기준
  • FCFS : 준비 큐에 도착한 순서대로 처리하는 비선점형. 우선순위 동일. 교재 예제 (0 + 27 + 42) ÷ 3 = 23ms
  • 콘보이 효과 : 긴 작업 뒤에서 짧은 작업들이 오래 기다리는 현상 (FCFS의 약점)

5장 ② — SJF부터 MLFQ, 그리고 멀티프로세서까지

자세히: 10/14 페이지 · 대기 시간 계산 · 응답률 · MLQ/MLFQ · CPU 선호도

비선점형 스케줄링 — FCFS · SJF · HRN

  • ★ FCFS : 준비 큐에 도착한 순서대로 CPU를 주는 비선점형. 우선순위 동일. 교재 예제 평균 대기 23ms. 약점은 콘보이 효과
  • ★ SJF : 실행 시간이 가장 짧은 작업부터 CPU를 주는 비선점형. 교재 예제 평균 대기 20ms (FCFS 23ms)
  • ★ 기아 현상 : 특정 프로세스가 CPU나 자원을 계속 할당받지 못하는 상태. SJF에서 긴 작업이 계속 밀림
  • ★ 에이징 : 양보할 때마다 나이를 먹여 상한선을 정해 기아를 완화하는 기법
  • ★ HRN : 대기 시간과 실행 시간을 모두 고려해 기아를 완화한 비선점형. 응답률 = (대기 + CPU 사용) ÷ CPU 사용, 높을수록 먼저

선점형 스케줄링 — RR · SRT · MLQ · MLFQ

  • ★ 라운드 로빈(RR) : 타임 슬라이스 동안만 실행하고 안 끝나면 큐 맨 뒤로. 선점형의 대표, 현대 스케줄링의 기본
  • ★ RR 계산 : 대기 0 · 7 · 14 · 19 · 19 · 8, 합 67, 평균 22.33. 재시작 대기 = 이번 시작 − 지난번 멈춤
  • ★ RR 주의 : 문맥 교환 시간이 추가되므로 평균 대기 시간만으로 성능을 판단할 수 없다
  • SRT : SJF를 선점형으로 바꾼 것. 남은 시간이 적은 것부터. 평균 15.66이지만 기아 · 오버헤드로 안 씀
  • 우선순위 스케줄링 : 프로세스의 중요도에 따라 우선순위를 부여. 비선점 · 선점 모두 적용
  • ★ MLQ(다단계 큐) : 우선순위별 여러 준비 큐, 고정 우선순위, 높은 큐 먼저, 각 큐는 RR (RR + priority). 하위 큐가 계속 지연
  • ★ MLFQ(다단계 피드백 큐) : 변동 우선순위. CPU를 쓰면 우선순위가 낮아지고, 아래 큐일수록 타임 슬라이스가 커지며, 맨 아래는 FCFS. 리눅스 · 유닉스

멀티프로세서

  • ★ CPU 선호도 : 같은 프로세스의 스레드를 계속 같은 코어에서 실행 (프로세스 · 코어 · 캐시 선호도). 캐시를 계속 활용
  • SQMS(단일 큐) : 모든 스레드를 한 큐에. 로드 밸런싱 수월, 선호도 구현 어려움
  • MQMS(다중 큐) : 코어마다 큐. 선호도 쉬움, 부하 불균형 발생
  • ★ 작업 훔치기 : 스레드가 많은 큐에서 빈 큐로 작업을 가져오는 기법. CPU 선호도를 해침

★ 계산법 — 다섯 가지 한 번에 (교재 예제: P1 도착 0 · 30ms, P2 도착 3 · 18ms, P3 도착 6 · 9ms)

  • 순서 : ① 간트 차트(누가 언제부터 언제까지)를 먼저 그린다 → ② 프로세스마다 대기 시간 → ③ 더해서 합, 개수로 나눠 평균
  • 대기 시간 : 시작 시각 − 도착 시각. 여러 번 나눠 실행되면 각 구간마다 이번 시작 − 지난번 멈춘 시각을 구해 모두 더한다
  • 반환 시간 : 끝난 시각 − 도착 시각 (= 대기 + 실행)
  • 고르는 시점 : 비선점형은 앞 작업이 끝났을 때, 선점형은 타임 슬라이스가 끝났을 때 고른다. 아직 도착 안 한 프로세스는 고를 수 없다

라운드 로빈은 타임 슬라이스 동안만 CPU를 사용하고 끝나지 않으면 준비 큐 맨 뒤로 이동하는 선점형 알고리즘으로 현대 스케줄링의 기본이며, 여기에 우선순위를 결합한 것이 다단계 큐(MLQ)다. MLQ의 하위 큐 지연 문제는 우선순위를 동적으로 바꾸는 다단계 피드백 큐(MLFQ)로 해결한다. HRN의 응답률은 (대기 시간 + CPU 사용 시간) ÷ CPU 사용 시간이다.

① 1장 운영체제 개요 ★커널 문은 하나

  • 운영체제는 컴퓨터 자원을 효율적으로 관리하고 응용 프로그램이 원활하게 작동하도록 지원하는 소프트웨어예요. 모든 작업을 한꺼번에 처리하던 일괄 작업 시스템에서, 사용자와 실시간으로 주고받는 대화형 시스템을 거쳐, 짧은 시간 단위(타임 슬라이스)로 나눠 동시에 도는 것처럼 보이게 하는 시분할 시스템으로 발전했어요.
  • 운영체제는 사용자 인터페이스와 커널로 되어 있고, 프로그램은 커널이 제공하는 시스템 함수(read·write)를 불러서만 자원을 써요. 이게 시스템 호출이고, 사용자 모드와 커널 모드를 오가는 이중 모드 연산에서 자발적으로 커널 모드에 들어가는 유일한 방법이에요.
  • 커널과 하드웨어 사이의 인터페이스는 디바이스 드라이버, 특정 플랫폼용 개발 인터페이스는 API, 거기에 매뉴얼·편집기·에뮬레이터까지 묶으면 SDK예요.

② 2장 컴퓨터의 구조 ★ 레지스터

  • 폰노이만 구조에서 가장 중요한 특징은 모든 프로그램이 메모리에 올라와야만 실행된다는 것이에요. 메모리가 유일한 작업 공간이고, OS가 가장 먼저 올라오는 과정이 부팅이에요.
  • CPU는 ALU(연산)·제어장치(명령 해석·지시)·레지스터(임시 저장)로 돼요. PC는 다음 명령어 위치, IR은 현재 명령어, MAR은 메모리 주소, MBR은 주고받는 값을 저장해요.
  • 버스 중 주소 버스만 단방향이고, 32비트 CPU는 4GB까지 써요. 메인 메모리는 빠른 휘발성 램이에요.

③ 3장 프로세스 상태 ★ 평생

  • 프로세스는 프로그램이 실행되어 메모리에 올라온 상태예요. 준비 → 실행은 디스패치, 실행 → 준비는 타임아웃, 실행 → 대기는 I/O 요청, 대기에서는 I/O 완료 인터럽트를 받아 준비로 돌아가요.
  • OS는 프로세스마다 상태 정보를 PCB에 저장하고, CPU를 쓰던 프로세스를 중단하고 새 프로세스로 바꾸는 문맥 교환 때 PCB를 저장·복원해요. 타임 슬라이스가 너무 작으면 문맥 교환 오버헤드가 커져요.

④ 3장 fork · exec 복사 / 바꿔치기

  • fork는 자식을 만드는 시스템 호출이에요. 자식에게 0, 부모에게 자식의 PID를 돌려주고, 두 프로세스가 같이 돌아서 출력이 2배가 돼요. 부모가 wait하면 자식이 먼저 찍혀요.
  • 부모가 먼저 끝나면 고아, 정리되지 못하면 좀비가 돼요. exec는 PCB는 그대로 두고 코드만 새 프로그램으로 바꾸니까 exec 아래 원래 코드는 실행되지 않아요.

⑤ 4장 스레드 · IPC ★ 동기/비동기

  • 스레드는 CPU에 작업을 요청하는 실행 단위예요. 자원을 공유해 가벼운 경량 프로세스이고, 장점은 자원 공유·문맥 교환 효율·응답 속도 향상·적응성 향상이에요. 크롬은 안정성 때문에 탭마다 프로세스를 써요.
  • 자바 스레드는 start 후 순서가 보장되지 않고, join(try 안)으로 기다리면 스레드가 먼저 끝나요. 데이터가 언제 올지 몰라 반복문으로 확인(바쁜 대기)하는 게 비동기화 통신(공유 메모리·파일), OS가 기다려 주는 게 동기화 통신(파이프·소켓)이에요.

⑥ 5장 CPU 스케줄링 ★ 계산

  • 실행 중인 프로세스의 CPU를 빼앗을 수 있으면 선점형, 끝날 때까지 못 빼앗으면 비선점형이에요. 시스템 효율을 위해 I/O 집중 프로세스에 우선순위를 더 줘요.
  • 대기 시간은 시작 시각 − 도착 시각이고, 평균 대기 시간은 그 합을 프로세스 수로 나눠요. 도착 순서대로 처리하는 FCFS는 긴 작업 뒤에서 짧은 작업이 오래 기다리는 콘보이 효과가 약점이에요.

빈칸 채우기 눌러서 정답 확인

사용자가 자발적으로 커널 모드에 들어가는 유일한 방법은 시스템 콜이다. 폰노이만 구조에서 모든 프로그램은 메모리에 올라와야만 실행된다. 다음에 실행할 명령어의 위치는 PC가, 메모리에서 읽을 주소는 MAR가 가진다. 준비 상태의 프로세스에 CPU를 주는 것을 디스패치라 하고, 실행 중인 프로세스의 정보를 PCB에 저장하고 다음 것으로 바꾸는 것을 문맥 교환이라 한다. fork는 자식에게 0을 반환하며, 코드를 바꿔치기하는 시스템 콜은 exec이다. 실행 중인 프로세스의 CPU를 빼앗을 수 있는 스케줄링은 선점형이고, FCFS에서 긴 작업 때문에 짧은 작업이 오래 기다리는 현상은 콘보이 효과다.

PC · IR · MAR · MBR · PSR은?

fork의 반환값은?
자식 0, 부모 자식의 PID(양수), 실패 −1.
exec 후 그대로인 것과 바뀌는 것은?
PCB(PID) 그대로, 코드 교체, 데이터 리셋. exec 아래 원래 코드는 실행 안 됨.

동기화 통신과 비동기화 통신은?

선점형과 비선점형은?
선점형 = CPU를 뺏을 수 있음(시분할). 비선점형 = 끝날 때까지 못 뺏음(일괄 작업).

    Q1다음 중 옳은 것은?

    위치는 OS가 정하고(1 ✗), 커널 모드 진입은 시스템 콜(2 ✗), 에디터까지 합친 건 SDK(3 ✗).

    Q2메모리 200번지의 값을 읽는다. 순서로 옳은 것은?

    주소는 MAR, 값은 MBR. CPU와 메모리는 독립 장치라 직접 들어가지 않아요.

    Q332비트 CPU가 최대로 쓸 수 있는 메모리 크기와 이유는?

    1바이트당 주소 하나, 32비트 주소 = 2³² = 4G개.

    Q4실행 중인 프로세스가 키보드 입력을 기다리게 됐다. 상태 변화와 그 이유는?

    I/O 요청 → 대기 상태. 효율을 위한 상태예요.

    Q5pid = fork(); if (pid > 0) printf("P"); else if (pid == 0) printf("C"); (wait 없음) 출력으로 가능한 것은?

    부모는 P, 자식은 C를 한 번씩. wait가 없으니 순서는 보장되지 않아요.

    Q6exec에 대한 설명으로 틀린 것은?

    새 PID의 자식을 만드는 건 fork. exec는 집(PCB)은 그대로 두고 코드만 바꿔요.

    Q7탭 하나가 죽어도 다른 탭은 멀쩡한 브라우저는 탭을 무엇으로 만들었을까?

    크롬처럼 안정성을 위해 탭을 프로세스로. 스레드면 같이 영향을 받아요.

    Q8P1(도착 0, 실행 5), P2(도착 1, 실행 3), P3(도착 2, 실행 8), P4(도착 3, 실행 6)를 FCFS로 처리할 때 평균 대기 시간은?

    간트 차트: P1 0~5, P2 5~8, P3 8~16, P4 16~22. 대기: 0, 5 − 1 = 4, 8 − 2 = 6, 16 − 3 = 13. (0 + 4 + 6 + 13) ÷ 4 = 23 ÷ 4 = 5.75.

    내 말로 설명하기 서술형 대비

    프로세스가 생성돼서 종료될 때까지의 과정을 상태도·PCB·문맥 교환을 넣어 설명해 보세요.

    프로그램이 메모리에 올라오면서 PCB를 받아 생성되고, 준비 상태의 우선순위별 큐에서 CPU를 기다려요. 디스패치되면 CPU는 그 프로세스의 PCB에 저장된 PC와 레지스터 값으로 자기 레지스터를 채우고 실행해요. 타임 슬라이스를 다 쓰면 현재 레지스터 값을 PCB에 저장하고(문맥 교환) 타임아웃으로 준비 상태로 돌아가요. 실행 중 I/O를 요청하면 대기 상태로 가서 장치별 대기 큐에 서고, I/O가 끝나면 인터럽트를 받아 준비 상태로 가요. 작업이 끝나면 PCB를 지우고 완료돼요.
