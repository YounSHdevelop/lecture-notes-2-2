레시피와 요리하는 중, 어느 쪽이 프로세스일까?

프로그램(정적) · 프로세스(동적)

하드디스크에 가만히 저장되어 있는 한글·카톡이 프로그램이에요. 움직이지 않는 정적인 상태죠. 9/16에 "모든 프로그램은 메모리에 올라와야 실행된다"고 했죠? 더블클릭해서 실행되어 메모리에 올라온 상태를 프로세스라고 해요(교재 별표 문장). 실제로 움직이는 동적인 상태예요. 운영체제 입장에서 프로세스는 하나의 작업 단위이기도 하고요.

교수님 비유 — 레시피는 요리가 아니라 요리하는 방법일 뿐이죠(프로그램). 그 레시피대로 실제로 조리하고 있는 것이 프로세스예요.

작업 관리자를 열어 보면, 컴퓨터를 막 켜서 아무것도 안 했는데도 프로세스가 100개 가까이 돌고 있어요. 운영체제 자신도 프로그램이자 프로세스이고, 그 안에서 수많은 프로세스가 컴퓨터를 굴리고 있는 거예요.

시험엔 이렇게

프로세스는 프로그램이 실행되어 메모리에 올라온 상태를 의미하며, 운영체제에서 하나의 작업 단위다. 프로그램(레시피)은 정적인 상태로 존재하지만 이를 구현하는 프로세스(조리)는 동적인 상태다.

장면 2

전역 변수, 지역 변수, malloc으로 잡은 메모리는 각각 어디로 갈까?

코드 영역 · 데이터 영역(정적 · 힙 · 스택)

프로세스가 메모리에 올라오면 크게 코드 영역(프로그램 본체)과 데이터 영역(코드가 쓰는 데이터)으로 나뉘어요. 문서 편집기라면 편집 중인 문서 데이터가 데이터 영역에 들어가요. 데이터는 실행 중에 값이 바뀔 수 있으니 데이터 영역은 읽기와 쓰기가 모두 가능해요(단, 상수로 선언한 데이터는 읽기 전용). 그리고 데이터 영역은 다시 셋으로 나뉘어요.

영역무엇이 들어가나언제 생기고 없어지나
정적 데이터정적 변수·전역 변수. 크기가 고정됨프로그램을 종료할 때까지 계속 저장 (프로그램과 운명을 같이함)
힙 ★실행 중에 동적으로 할당된 변수(malloc으로 잡은 메모리) = 동적 메모리 할당필요할 때 잡고 free로 해제
스택함수 호출과 관련된 데이터: 반환 주소, 매개변수, 지역 변수 등스택 자료구조로 쌓이고, 함수가 끝나면 그 데이터는 제거

main이 함수 A를 부르고, A가 B를 부르면 스택에 A, B 순서로 쌓였다가 B가 끝나면 B 것부터 빠져요. 그래서 지역 변수는 스택이에요.

스택도 힙도 크기가 계속 변해요. 한쪽 방향으로만 쌓으면 경계가 계속 밀려나서 관리가 어렵죠. 그래서 스택은 맨 아래에서 위로, 힙은 위에서 아래로 자라게 하고 가운데 빈 공간을 둬요. 주어진 공간을 크게 벗어나지 않고 쓸 수 있어요.

시험엔 이렇게

프로세스는 코드 영역과 데이터 영역으로 구성되며, 데이터 영역은 정적 데이터 영역(정적 변수·전역 변수, 크기 고정, 종료 시까지 유지), 힙 영역(실행 중 동적으로 할당된 변수), 스택 영역(함수 호출 관련 데이터: 반환 주소, 매개변수, 지역 변수, 함수 종료 시 제거)으로 나뉜다. 스택과 힙은 서로 반대 방향으로 커진다.

외우는 법: 전역은 정적, 지역은 스택, malloc은 힙
바로 확인
함수 안에서 int count = 0;으로 만든 변수는 어디에 저장될까?
함수 안의 지역 변수라 스택이에요. 함수가 끝나면 pop되어 사라져요. 함수 밖 전역 변수였다면 정적 영역, malloc이면 힙.

장면 3

요리사는 한 명, 주문표는 100장. 주문표는 어디를 돌아다닐까?

생성 · 준비 · 실행 · 대기 · 완료 ★ · 디스패치 · 타임아웃

레스토랑에서 코스 요리를 주문했다

주문표는 주방에 꽂혀 기다리다가, 수프가 나가면 다시 꽂혀서 메인 요리를 기다리고… 다 나올 때까지 주방을 계속 돌아다녀요. 프로세스도 똑같아요.

  1. 생성 — 프로세스가 처음 만들어지는 상태. 이때 PCB(장면 4)를 받아요.
  2. 준비 — CPU를 쓰려고 줄 서서 기다리는 상태. 한순간에 CPU를 잡는 건 하나뿐이니까 나머지는 주문표처럼 꽂혀 기다려요.
  3. 실행 — 준비 상태에서 하나를 골라 CPU를 주면 실행 상태. 이렇게 끌어다 CPU를 주는 사건을 디스패치라고 해요.
  4. 시분할 시스템이니까 받은 시간(타임 슬라이스, 예: 100ms)을 다 쓰고도 안 끝나면 다시 준비 상태로 돌아가요. 이 사건이 타임아웃이에요. 끝날 때까지 쳇바퀴처럼 준비 ↔ 실행을 돌아요.
  5. 완료 — 작업이 끝나면 PCB를 지우고(− PCB) 종료.

대기 상태는 왜 있을까?

실행 중인 프로세스가 "하드디스크에서 데이터 가져와 줘" 하고 I/O를 요청했어요. I/O는 입출력 장치가 따로 처리하는데 시간이 오래 걸리죠. 그동안 CPU가 이 프로세스랑 멍하니 기다리면 낭비잖아요. 그래서 I/O를 요청하면 그 프로세스를 대기 상태로 보내고, CPU는 다른 프로세스와 일해요. 시스템 효율을 위해서예요.

I/O가 끝나면 인터럽트가 와요. 그럼 바로 실행 상태로 돌아갈까요? 아니에요. 그 사이 CPU는 이미 다른 프로세스와 일하고 있어서, 바로 돌아가려면 상태 전이 두 개가 동시에 일어나야 해 복잡해져요. 그래서 I/O가 끝나면 준비 상태로 가서 다시 줄을 서요.

장면 4

주민등록이 말소되면 사람은 사라진다. 프로세스의 주민등록은?

PCB(프로세스 제어 블록) · 들어 있는 정보

운영체제는 실행 중인 각 프로세스를 관리하려고 프로세스별로 상태 정보를 저장해요. 이때 쓰는 자료구조가 PCB(프로세스 제어 블록)예요. 교재는 PCB를 식당의 주문서에 비유해요. 프로그램이 프로세스가 되면 운영체제로부터 PCB를 받고, 작업이 끝난 프로세스의 PCB는 삭제돼요. 학교에서 학번으로 같은 이름의 학생을 구분하듯, OS는 PCB로 프로세스를 구분하고 관리해요.

교수님 비유 — PCB는 주민등록 초본이에요. 사람이 세상을 떠나면 주민등록이 말소되듯, 프로세스에서 PCB를 빼면 다시 그냥 프로그램으로 돌아가요. 그래서 프로세스 = 프로그램 + PCB.

PCB는 일반 사용자 데이터가 아니라서 사용자 영역이 아닌 메모리의 OS 영역에 들어가요.

PCB 안의 정보왜 필요할까
포인터준비·대기 상태의 프로세스는 큐에서 기다리는데, 큐는 연결 리스트로 구현돼요. 포인터가 다음 PCB와 연결해 줘요("PCB가 큐에 삽입될 때 포인터가 필요해")
프로세스 상태 ★현재 상태를 저장하는 필드: 생성·준비·실행·대기·완료·보류 준비·보류 대기. 실행 중에 입출력을 요청하면 이 값이 실행 → 대기로 바뀌어요
PID(프로세스 구분자) ★OS는 여러 프로세스를 관리하므로 각 프로세스에 고유한 번호를 붙여요. ("프로세스 상태와 PID가 앞쪽에 나와")
PC(프로그램 카운터)100번 줄까지 하고 쫓겨났으면 다음엔 101번부터 해야 하니까
프로세스 우선순위누가 먼저 CPU를 받을지(5장)
각종 레지스터 정보실행 중에 쓰던 레지스터 값들 (다시 실행될 때 복원)
메모리 관리 정보메모리 어디를 얼마나 쓰고 있는지
할당된 자원 정보열어 둔 파일 등 내가 쓰는 자원
계정 정보사용자·CPU 사용 시간 같은 기록
PPID · CPID부모 PID, 자식 PID (9/30의 fork에서 나와요)
시험엔 이렇게

PCB는 운영체제가 실행 중인 각 프로세스를 관리하기 위해 프로세스별 상태 정보를 저장하는 자료구조로, 프로그램이 프로세스가 되면 OS로부터 PCB를 받고 작업이 끝나면 PCB는 삭제된다(프로그램 + PCB = 프로세스). PCB에는 포인터, 프로세스 상태, PID, PC, 우선순위, 각종 레지스터 정보, 메모리 관리 정보, 할당된 자원 정보, 계정 정보, PPID·CPID가 저장된다.

외우는 법: 포 · 상 · 아 · 피(포인터·상태·ID·PC) + 우선순위·메모리·자원
바로 확인
PCB의 첫 번째 칸에 포인터가 들어가는 이유는?
PCB들은 따로따로 흩어진 게 아니라 링크드 리스트로 줄줄이 매달려 있어서, 다음 PCB를 가리킬 포인터가 필요해요. 번호는 PID, 다음 줄은 PC의 몫.

장면 5

타임 슬라이스를 1ms로 아주 작게 하면 무조건 좋을까?

문맥 교환(PCB 스위칭) · 오버헤드 · 타임 슬라이스 크기

프로세스 P1이 디스패치되면 CPU는 먼저 P1의 PCB에 저장돼 있던 PC·레지스터 값으로 자기 레지스터를 싹 바꿔요. P1이 타임 슬라이스를 다 쓰면, 지금까지의 레지스터 값을 P1의 PCB에 저장하고 내보내요. 그다음 P2의 PCB 값으로 레지스터를 다시 채우고… 0.1초마다 이 짓을 반복해요.

이렇게 CPU를 쓰던 프로세스를 중단하고 새로운 프로세스로 전환하는 과정을 문맥 교환(context switching)이라고 해요(교재 별표). 실행 상태에서 나가는 프로세스의 PCB에는 지금까지의 작업 내용을 저장하고, 실행 상태로 들어오는 프로세스는 레지스터 값을 자기 PCB에 저장된 값으로 바꿔요. 교재 말풍선 그대로 "기존의 PCB를 내보내고 새로운 PCB를 받는 과정"이라 PCB 스위칭이라고도 해요.

  1. P1 실행 중 타임 슬라이스 아웃 → P1 상태를 PCB1에 저장
  2. PCB2에서 P2 상태를 가져옴 → P2 디스패치, 실행 (P1은 준비 상태)
  3. P2 타임 슬라이스 아웃 → P2 상태를 PCB2에 저장, PCB1에서 P1 상태를 가져와 다시 P1 실행

타임 슬라이스 크기는 어떻게 정할까

  • 너무 크면 — 하나의 프로세스가 오래 실행되니까 다른 프로세스의 대기 시간이 길어져요. 교재 예: 비디오 플레이어와 문서 편집기를 같이 켜면 비디오가 끊기고 글자 입력 반응도 매우 느려져요.
  • 너무 작으면 — 문맥 교환에도 시간이 걸리고, 문맥 교환 중에는 작업이 진행되지 않아요. 교재 예: 타임 슬라이스 1ms인데 문맥 교환에 5ms가 걸리면, 실제 작업 시간보다 문맥 교환에 더 많은 시간을 낭비해요. 배보다 배꼽이 커요. 이 낭비가 오버헤드예요.

결론: 타임 슬라이스는 동시에 도는 것처럼 보일 만큼 작게, 하지만 문맥 교환 시간을 고려해서 충분히 크게 잡아야 해요. 참고로 유닉스는 타임 슬라이스를 10~200ms로 설정해요.

"그럼 100ms로 딱 정하면 되잖아요?" — 안 돼요. ① 시스템마다 문맥 교환 시간이 달라서 모르고, ② 프로세스 우선순위에 따라 타임 슬라이스 크기가 달라지기 때문이에요(5장에서 이유가 나와요). 그래서 일반 원칙만 기억하면 돼요.

시험엔 이렇게

문맥 교환은 CPU를 사용하던 프로세스를 중단하고 새로운 프로세스로 전환하는 과정으로, 나가는 프로세스의 PCB에는 지금까지의 작업 내용을 저장하고 들어오는 프로세스는 레지스터 값을 PCB에 저장된 값으로 변경한다. 타임 슬라이스가 너무 크면 동시 실행처럼 보이지 않고, 너무 작으면 문맥 교환 오버헤드가 커지므로 문맥 교환 시간보다 충분히 크게, 가능한 한 작게 설정한다.

외우는 법: 크면 끊기고, 작으면 배꼽이 크다
바로 확인
문맥 교환에 2ms가 걸리는 시스템에서 타임 슬라이스를 3ms로 잡았다. 무슨 문제가 생길까?
3ms 일하고 2ms 교환하면 거의 절반이 교환에 쓰여요. 배보다 배꼽이 큰 오버헤드. 끊겨 보이는 건 너무 클 때의 문제예요.

= 정의 · → 흐름 · / 대비 · ★ 출제

① 프로그램 / 프로세스 레시피 / 조리 중

  • 프로세스는 프로그램이 실행되어 메모리에 올라온 상태예요(동적, OS의 작업 단위). 프로그램은 저장장치에 있는 정적인 상태(레시피)고요.

② 프로세스 메모리

  • 프로세스는 코드 영역 + 데이터 영역. 데이터 영역은 정적(정적·전역 변수, 크기 고정), 힙(실행 중 동적 할당, malloc/free), 스택(반환 주소·매개변수·지역 변수, 함수 끝나면 제거)으로 나뉘어요.
  • 스택 ↑ / 힙 ↓ 반대 방향으로 자람

③ 5가지 상태 ★ 평생생·준·실·완 + 대기

  • 준비 → 실행 = 디스패치 · 실행 → 준비 = 타임아웃
  • 실행 → 대기 = I/O 요청 · 대기 → 준비 = I/O 인터럽트
  • 필수 아님, 효율 위한 상태 = 대기 · 보류(sleep) = 잠깐 멈춤

④ PCB ★

  • 프로세스 = 프로그램 + PCB · OS 영역에 저장
  • 프로그램이 프로세스가 되면 OS에게서 PCB를 받고, 끝나면 PCB가 삭제돼요(주문서).
  • 포인터(큐에 엮기) · 프로세스 상태 · PID · PC · 우선순위 · 레지스터 · 메모리 · 자원 · 계정 · PPID/CPID

⑤ 문맥 교환 ★크면 끊김, 작으면 배꼽

  • 문맥 교환은 CPU를 쓰던 프로세스를 중단하고 새 프로세스로 전환하는 과정이에요. 나가는 쪽은 PCB에 작업 내용을 저장하고, 들어오는 쪽은 PCB 값으로 레지스터를 바꿔요(PCB 스위칭).
  • 타임 슬라이스가 크면 다른 프로세스가 오래 기다리고, 작으면(1ms인데 교환 5ms) 교환이 더 걸려 오버헤드. 문맥 교환 시간을 고려해 충분히 크게(유닉스 10~200ms).

빈칸 채우기 눌러서 정답 확인

프로그램이 메모리에 올라와 실행되는 상태를 프로세스라 한다. 함수의 지역 변수는 스택에, malloc으로 할당한 메모리는 힙에 저장된다. 준비 상태의 프로세스를 골라 CPU를 주는 것을 디스패치라 하고, 타임 슬라이스를 다 써서 준비 상태로 돌아가는 것을 타임아웃이라 한다. I/O를 요청한 프로세스는 대기 상태로 가며, I/O가 끝나면 준비 상태로 간다. 프로세스의 정보를 담은 블록을 PCB라 하고, 이를 저장하고 바꿔 넣는 과정을 문맥 교환이라 한다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
프로그램과 프로세스의 차이는?
프로그램 = 저장장치에 있는 정적 상태. 프로세스 = 메모리에 올라와 실행되는 동적 상태.
데이터 영역의 세 부분은?
정적 데이터(전역 변수), 스택(지역 변수), 힙(동적 메모리 할당 malloc/free).
스택과 힙을 반대 방향으로 배치하는 이유는?
둘 다 크기가 변하므로 마주 보고 자라게 해서 주어진 공간 안에서 관리하기 위해.
프로세스의 5가지 상태는?
생성, 준비, 실행, 대기, 완료.
디스패치란?
준비 상태의 프로세스 하나를 골라 CPU를 주어 실행 상태로 만드는 것.
타임아웃이란?
실행 중인 프로세스가 타임 슬라이스를 다 써서 준비 상태로 돌아가는 것.
대기 상태는 언제, 왜?
I/O를 요청했을 때. CPU가 기다리지 않고 다른 프로세스와 일하게 해 효율을 높이려고(필수 아닌 상태).
I/O가 끝난 프로세스는 어디로?
I/O 완료 인터럽트를 받아 준비 상태로. 실행으로 바로 가지 않는다.
PCB에 들어 있는 정보는?
포인터, 프로세스 상태, PID, PC, 프로세스 우선순위, 각종 레지스터 정보, 메모리 관리 정보, 할당된 자원 정보, 계정 정보, PPID와 CPID.
PCB의 포인터는 왜 필요할까?
준비·대기 상태의 프로세스는 큐에서 기다리는데 큐는 연결 리스트로 구현되므로, 다음 PCB와 연결하기 위해.
문맥 교환이란?
CPU를 사용하던 프로세스를 중단하고 새로운 프로세스로 전환하는 과정. 나가는 프로세스의 PCB에 작업 내용을 저장하고, 들어오는 프로세스는 레지스터 값을 PCB에 저장된 값으로 변경(PCB 스위칭).
유닉스의 타임 슬라이스 크기는?
10~200ms.
타임 슬라이스가 너무 작으면?
작업 시간에 비해 문맥 교환 시간이 커져 오버헤드가 심해진다.

    퀴즈 다 풀고 채점하기

    Q1음악 앱이 실행 중에 SSD에서 다음 곡 파일을 읽어 달라고 요청했다. 이 프로세스의 상태 변화는?

    파일 읽기는 I/O 요청이에요. I/O가 끝날 때까지 대기 상태로 가고, CPU는 다른 프로세스와 일해요.

    Q2Q1의 파일 읽기가 끝났다. 다음 상태는?

    CPU는 이미 다른 프로세스가 쓰고 있어서 바로 실행으로 못 가요. 준비 상태에 줄을 서요.

    Q35가지 상태 중 "필수가 아니라 시스템 효율을 위해 만든 상태"는?

    대기 상태가 없어도 돌아가긴 하지만, I/O 동안 CPU가 노는 걸 막으려고 만든 상태예요.

    Q4프로세스가 CPU를 다시 받았을 때 이어서 실행할 줄을 알 수 있는 이유는?

    문맥 교환 때 PC를 포함한 레지스터 정보가 PCB에 저장되고, 다시 디스패치되면 그 값으로 복원돼요.

    Q5전역 변수 total, main 안의 int i, malloc(100)으로 받은 공간의 위치를 순서대로 고르면?

    전역 = 정적, 지역(main 안도 함수 안이니 지역) = 스택, malloc = 힙.

    Q6타임 슬라이스 크기에 대한 설명으로 옳은 것은?

    너무 작으면 오버헤드, 너무 크면 끊김. 시스템마다 문맥 교환 시간이 다르고 우선순위에 따라서도 달라서 고정할 수 없어요.

    내 말로 설명하기 친구한테 말하듯이

    프로세스 상태도를 말로 설명해 보세요. 대기 상태가 왜 있는지, I/O가 끝나면 왜 준비 상태로 가는지까지.

    프로세스는 PCB를 받으며 생성되고, 준비 상태에서 CPU를 기다려요. 디스패치되면 실행 상태가 되고, 타임 슬라이스를 다 쓰면 타임아웃으로 준비 상태로 돌아가요. 작업이 끝나면 PCB를 지우고 완료돼요. 실행 중에 I/O를 요청하면 대기 상태로 가는데, I/O 동안 CPU가 놀지 않고 다른 프로세스와 일하게 하려는 효율용 상태예요. I/O가 끝나면 인터럽트를 받지만 CPU는 이미 다른 프로세스가 쓰고 있으니까 준비 상태로 가서 다시 줄을 서요.
