장면 1

가스레인지 화구가 하나일 때와 둘일 때, 스테이크는 언제 빨리 나올까?

스레드 · 멀티스레드 · fork와의 차이

교재 정의(동그라미 친 문장)부터. 스레드는 프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위예요. 프로세스가 생성되면 CPU 스케줄러는 프로세스가 해야 할 일을 CPU에 전달하는데, 이때 실제로 전달되는 실행 단위가 스레드예요.

누구 입장에서단위이름
전체작업(job)여러 개의 작업 단위로 나뉨
운영체제작업 단위(task)프로세스
CPU실행 단위(operation)스레드

크기 순으로 정리하면 작업 > 프로세스 > 스레드. 그리고 멀티스레딩은 하나의 프로세스 내부에서 여러 개의 스레드가 동시에 작업하는 방식이에요.

교수님 비유 — 화구가 하나면 고기를 다 굽고 나서 같은 팬에 야채를 구워야 해요. 화구가 둘이면 한쪽에선 스테이크, 다른 쪽에선 야채를 동시에 구우니 빨라요. 주방(프로세스)은 하나인데 일하는 자리(스레드)가 여럿인 거예요.

fork와 뭐가 다를까요? fork는 똑같은 프로세스를 통째로 하나 더 만들어요. 스레드는 프로세스는 하나 그대로 두고 그 안에 일하는 단위만 여러 개 만들어요.

  • 한글 — 옛날엔 다 쓰고 "맞춤법 검사" 버튼을 눌러야 했어요(스레드 1개). 지금은 교재 그림 4-2 (b)처럼 문서 입출력 스레드 · 문서 편집 스레드 · 맞춤법 검사 스레드가 독립적으로 동작해서, 내용을 입력하는 동시에 맞춤법 검사 스레드가 실시간으로 오류를 표시해요.
  • 카카오톡 — 파일 전송 스레드와 채팅 스레드가 따로 돌아서, 큰 파일을 보내는 동안에도 채팅이 돼요.

옛날 CPU는 코어가 하나라 스레드를 여러 개 만들어 봐야 소용없었어요. 지금은 코어가 4·8·16개라, 스레드를 여러 개 만들면 각 코어에서 돌아 CPU가 여러 개인 것처럼 일해요. 그래서 요즘 프로세스는 거의 다 멀티스레드예요.

시험엔 이렇게

스레드는 프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위다(작업 > 프로세스 > 스레드). 멀티스레딩은 하나의 프로세스 내부에서 여러 개의 스레드가 동시에 작업하는 방식이다. fork는 프로세스 전체를 복사하고, 스레드는 프로세스 하나 안에서 실행 단위만 늘린다.

장면 2

스레드가 더 효율적이라는데, 크롬은 왜 탭마다 프로세스를 만들까?

멀티태스킹 vs 멀티스레드 · 경량 프로세스 · 장점 4가지

먼저 단점부터. 교재 그림 4-2 (a) 멀티태스킹 예: 문서 편집기가 출력할 데이터를 프린터 프로세스(스풀러)에 보내 두고 계속 편집해요. 둘이 서로 다른 프로세스라 IPC로 데이터를 주고받고, 문서 편집기가 갑자기 꺼져도 프린터 프로세스는 정상적으로 출력해요. 독립적이라 한쪽이 죽어도 다른 쪽에 영향이 없어요. 그런데 한글 안의 입력 스레드와 맞춤법 스레드는 같은 프로세스라서, 한글을 끄면 맞춤법 스레드도 같이 죽어요. 한 스레드가 잘못되면 프로세스 전체에 영향을 줄 수 있어요.

그래도 스레드를 쓰는 이유 — 가볍다

fork는 코드·데이터·PCB를 통째로 복사해서 똑같은 코드가 메모리에 두 개 있어요. 멀티스레딩은 메모리나 파일 같은 시스템 자원을 스레드끼리 공유하고, 프로세스 간 통신(IPC) 없이도 스레드끼리 데이터를 주고받을 수 있어서 훨씬 가벼워요. 대신 프로세스가 비정상 종료되면 그 안의 모든 스레드도 강제 종료돼요. 그래서 스레드를 경량 프로세스(Lightweight Process)라고 불러요.

멀티스레드의 장점설명
자원 공유하나의 프로세스 안에서 여러 스레드가 코드·데이터·파일 등의 자원을 공유해 낭비를 최소화
문맥 교환이 효율적스레드는 프로세스 안에서 실행되니 문맥 교환 때 바꿀 정보가 적어 빠름. 또 IPC 없이 변수로 데이터를 주고받아 통신 비용이 줄어듦
응답 속도 향상입출력을 맡은 스레드만 대기 상태가 되고 나머지 스레드는 계속 실행 (곰플레이어: 다른 스레드가 이미 올라온 영상을 계속 화면에 뿌림)
적응성 향상멀티코어 CPU 환경에서 여러 코어에 스레드를 나눠 주어 멀티코어 환경을 최적화

크롬의 선택

인터넷 익스플로러·엣지는 탭을 스레드로, 크롬은 탭마다 프로세스로 만들었어요. 예전에 익스플로러에서 탭 하나가 오작동하면 다른 탭까지 다 같이 꺼졌죠. 크롬은 탭이 독립 프로세스라 하나가 죽어도 나머지는 멀쩡해요. 요즘 컴퓨터는 프로세스 몇 개 더 만든다고 느려지지 않으니 안정성을 택한 거예요.

교수
멀티스레드로 갈 거냐, 포크를 시켜서 멀티태스킹으로 갈 거냐는 프로그래머의 철학이에요. 구글처럼 안정성이 더 중요하면 멀티프로세스로, 효율이 더 중요하면 멀티스레드로 가시면 됩니다.10/7 강의 중 (말을 조금 다듬음)
시험엔 이렇게

멀티태스킹은 프로세스가 독립적이라 하나가 비정상 종료돼도 다른 프로세스에 영향이 없고, 멀티스레드는 자원을 공유해 가볍지만(경량 프로세스) 한 스레드의 문제가 프로세스 전체에 영향을 준다. 멀티스레드의 장점은 자원 공유, 문맥 교환이 효율적, 응답 속도 향상, 적응성 향상이다.

스레드를 먼저 start했는데, 왜 Main이 먼저 찍히기도 할까?

자바 스레드 · extends Thread · start · join ★ · try-catch ★ · pthread_create ★

교수님은 C의 pthread_create(포인터 함수가 나와서 어려움)보다 자바 코드로 설명했어요.

코드 4-2 · 자바 스레드 코드 (교재)class TH_test extends Thread {              // TH_test 스레드 클래스 정의 (Thread 상속)
    public void run() {                       // run() 메서드는
        for (int i = 0; i < 5; i++)
            System.out.println("Thread");     // "Thread" 문자열을 5번 출력
    }
}

public class Main {
    public static void main(String[] args) {   // 자바 시작점
        TH_test TH_print = new TH_test();       // 스레드 객체 생성

        TH_print.start();                       // 멀티스레드 실행

        for (int i = 0; i < 5; i++)
            System.out.println("* main");
    }
}

순서대로 읽으면 Thread 5줄 다음 * main 5줄일 것 같죠. 그런데 교재 결과처럼 * main이 먼저 찍히기도 해요. 이 코드에는 동기화 과정이 없어서 main()과 스레드가 독립적으로 실행되거든요. 그래서 Thread가 먼저일 수도, main이 먼저일 수도, 섞여서 찍힐 수도 있어요. 순서는 보장되지 않아요. (실행할 때마다 결과가 다르다는 필기가 여기 있어요.)

순서를 정하고 싶다면 join

fork에서 부모가 wait로 자식을 기다렸죠. 스레드엔 부모·자식 개념은 없지만, "저 일꾼이 파일을 다 읽어 와야 내가 일할 수 있다" 같은 경우가 있어요. 그때 다른 스레드가 끝날 때까지 기다리는 게 join이에요.

코드 4-3 · start 다음에 추가 (교재 12~15행)TH_print.start();
try {
    TH_print.join();                   // 동기화: 스레드가 끝날 때까지 main이 기다림
} catch (InterruptedException e) {}    // 문제가 생겼을 때 처리할 코드를 괄호 안에 등록
// → 출력: Thread 5줄이 먼저, 그다음 * main 5줄

★ 교재(별표 두 군데): join() 메서드는 try{} 내부에서 작동하고, catch의 괄호 안에는 문제가 발생했을 때 처리할 함수나 코드를 등록해요. join()을 쓰면 스레드가 끝난 후에 main()이 실행되니까 Thread가 5번 출력된 이후에 * main이 5번 출력돼요. 스레드가 안 만들어졌거나 비정상 종료될 수 있어서 join은 꼭 try-catch 안에 넣는 게 자바의 일반적인 방식이에요.

★ C로는 pthread — 교재에 별표

C 스레드 코드 (교재, 요지)int sum = 0;                                      // 메인과 스레드가 공유하는 변수

void *T_run() {                                   // 스레드 실행
    for (int i = 1; i < 5; i++)
        printf("Td: %d add -> sum = %d\n", i, sum = sum + i);
    pthread_exit(NULL);                           // 스레드 종료
}

int main() {
    pthread_t tid;                                // 스레드 구조체
    pthread_create(&tid, NULL, T_run, NULL);     // ★ 스레드 생성 → T_run() 실행
    printf("Main: sum = %d\n", sum);
    pthread_join(tid, NULL);                      // 스레드 기다림 - 자원 회수
    printf("Main: sum = %d\n", sum);
    return 0;
}

교재 실행 결과는 Main: sum = 0 → Td: 1 add -> sum = 1 → Td: 2 add -> sum = 3 → Td: 3 add -> sum = 6 → Td: 4 add -> sum = 10이에요. i가 1부터 4까지(i < 5) 더해지니까 1, 3, 6, 10. pthread_join으로 스레드가 끝날 때까지 기다린 뒤 찍는 마지막 줄은 sum = 10이 돼요. 자바의 start ↔ pthread_create, join ↔ pthread_join으로 짝지어 기억하면 돼요.

시험엔 이렇게

자바에서 Thread를 상속한 객체는 start()로 실행되며 동기화 과정이 없으면 main과 독립적으로 실행되므로 출력 순서가 보장되지 않는다. join()을 사용하면 스레드가 끝난 후 main()이 실행되도록 제어할 수 있으며, join()은 try-catch 방식으로 사용한다. C에서는 pthread_create()로 스레드를 생성하고 pthread_join()으로 기다린다(자원 회수).

방향으로도 나눠요. 한쪽으로만 가면 단방향, 양쪽으로 가면 양방향(대부분), 양쪽으로 가긴 하지만 한순간엔 한쪽만 말할 수 있으면 반양방향이에요. 반양방향의 대표는 무전기("오버").

동기화 통신 vs 비동기화 통신 — 별표

  • 비동기화 통신 — 특징은 데이터가 언제 도착할지 모른다는 것. 교재 비유로는 전보예요. 전보를 받는 사람은 언제 올지 몰라서 도착 여부를 직접 확인해야 하죠. 운영체제가 도착 여부를 알려 주지 않으니까, 프로세스가 스스로 while 같은 반복문으로 데이터가 올 때까지 계속 확인하며 기다려요. 이렇게 기다리는 방식을 바쁜 대기(busy waiting)라고 해요. 논블로킹 방식이라고도 하고, IPC 중 공유 메모리와 공유 파일이 비동기화 통신이에요.
  • 동기화 통신 — 데이터가 도착할 때까지 운영체제가 알아서 대기시켜 주는 방식. 교재 비유로는 전화예요. 걸면 상대방이 수화기를 들어야 통신이 시작되죠. 블로킹 방식이라고도 하고, OS가 대기를 처리하니 바쁜 대기가 필요 없어요. IPC 중 파이프와 소켓이 동기화 통신이라, 데이터가 도착한 다음에 다음 코드가 실행돼요.

시험엔 이렇게

프로세스 간 통신(IPC)에는 공유 메모리·공유 파일, 같은 컴퓨터 내의 파이프(단방향), 네트워크로 연결된 컴퓨터 간의 소켓이 있다. 비동기화 통신(논블로킹)은 데이터가 언제 도착할지 모르므로 프로세스가 반복문으로 직접 확인하는 바쁜 대기를 하며 공유 메모리·공유 파일이 해당한다. 동기화 통신(블로킹)은 데이터가 도착할 때까지 운영체제가 대기시켜 주므로 바쁜 대기가 필요 없으며 파이프·소켓이 해당한다.

찜질방 락커 키와 파일 읽기 코드는 무슨 관계일까?

open → read / write → close · 파일 디스크립터(FD) · 코드 구조 읽기

파일 입출력이든 통신이든 모든 형식은 똑같이 open → read/write → close예요.

  1. open — 파일이 정말 있는지, 나에게 권한이 있는지 확인하는 단계. 성공하면 FD(파일 디스크립터)를 받아요.
  2. read(fd) / write(fd) — 받은 FD로 읽고 써요.
  3. close(fd) — 다 쓰면 반납.
교수님 비유 — 찜질방 카운터에서 돈을 내면 락커 키를 줘요. 찜질방을 쓸 권리죠. 그 키(FD)로 락커를 열고 닫다가(read/write), 나갈 때 키를 반납해요(close).

교수님의 코드 읽는 법: 한 줄씩 읽지 말고 구조부터 찾으세요. 교재 코드 4-4라면 9번 줄 open의 fd에 동그라미, 16번 줄 read의 fd에 동그라미, 23번 줄 close의 fd에 동그라미. 그 뼈대가 보이면 나머지는 그걸 받쳐 주는 보조 코드예요.

코드 4-4 · 파일 읽기 (교재, 요지)int fd, n;
char buf[6];

fd = open("test.txt", O_RDONLY);   // 파일 open (읽기 전용)
if (fd == -1) {                       // 파일 열기 실패
    perror("Error opening file");
    return 1;
}
n = read(fd, buf, 5);               // read(fd): n은 실제 읽은 문자 수
if (n > 0) {
    buf[n] = '\0';                    // 맨 마지막에 NULL 문자 삽입
    printf("%s \n", buf);
} else {
    perror("Error reading file");
}
close(fd);                            // 파일 close

파이프 코드도 같은 뼈대예요. 교재: 파이프 통신은 파일 입출력과 비슷하게 동작하지만 open() 대신 pipe(fd)를 써서 pipe() → read()/write() → close() 형태예요. 파이프는 단방향 통신만 지원하고, 파이프 하나에 파이프 기술자가 2개(읽기용 fd[0], 쓰기용 fd[1]) 있어요.

코드 4-5 · 파이프 통신 (보내는 쪽, 교재)int fd[2];              // 2개의 파일 기술자: 읽기용 fd[0], 쓰기용 fd[1]
pipe(fd);               // 파이프 생성
close(fd[0]);           // 읽기용 기술자 닫기 (보내는 쪽이니까)
write(fd[1], "TEST", 5);  // fd[1]을 통해 데이터 쓰기
close(fd[1]);           // 쓰기용 기술자 닫기
시험엔 이렇게

파일 입출력과 통신은 open(존재·권한 확인 후 파일 디스크립터 획득) → read/write(디스크립터로 읽기·쓰기) → close(반납)의 구조를 따른다. 파이프 통신은 open() 대신 pipe(fd)를 사용하는 pipe() → read()/write() → close() 형태이며, 단방향이므로 읽기용 fd[0]과 쓰기용 fd[1] 두 개의 파이프 기술자를 사용한다.

① 스레드 주방 하나, 화구 여럿

  • 스레드는 프로세스 코드의 절차에 따라 CPU에 작업을 요청하는 실행 단위예요. 작업 > 프로세스(OS의 작업 단위) > 스레드(CPU의 실행 단위).
  • 멀티스레딩 = 하나의 프로세스 안에서 여러 스레드가 동시에 작업하는 방식(한글: 입출력·편집·맞춤법 스레드).
  • fork = 프로세스 통째 복사 / 스레드 = 한 프로세스 안에서 실행 단위만 늘림

② 프로세스 vs 스레드 공·교·응·적

  • 멀티태스킹 = 독립(하나 죽어도 OK) / 멀티스레드 = 같이 죽음
  • 경량 프로세스 · 장점 = 자원 공유 · 문맥 교환이 효율적 · 응답 속도 향상 · 적응성 향상(멀티코어)
  • 크롬 탭 = 프로세스(안정성) / IE 탭 = 스레드(효율)

③ 자바 스레드

  • extends Thread · start() → 독립 실행, 순서 보장 X
  • join() = 스레드가 끝난 뒤 main이 실행되도록(동기화), try{} 안에서 작동
  • C: pthread_create로 생성 → pthread_join으로 기다림(자원 회수)

④ IPC ★ 동기/비동기

  • 공유 메모리·파일 · 파이프(같은 컴퓨터, 단방향 → 2개) · 소켓(네트워크)
  • 단방향 / 양방향 / 반양방향(무전기)
  • 비동기(논블로킹, 전보) = 프로세스가 반복문으로 계속 확인하는 바쁜 대기 → 공유 메모리·공유 파일
  • 동기(블로킹, 전화) = OS가 대기시켜 줌, 바쁜 대기 X → 파이프·소켓

⑤ 입출력 구조 락커 키

  • open(존재·권한 → FD) → read/write(FD) → close
  • 파이프 = pipe(fd) → read/write → close, 기술자 2개(읽기 fd[0], 쓰기 fd[1])

빈칸 채우기 눌러서 정답 확인

CPU가 처리하는 가장 작은 작업 단위를 스레드라 하고, 자원을 공유해 가볍기 때문에 경량 프로세스라고도 부른다. 프로세스가 서로 독립적이라 하나가 죽어도 다른 것에 영향이 없는 방식은 멀티태스킹이다. 자바에서 스레드는 start()로 실행하고, 다른 스레드가 끝날 때까지 기다리려면 join()을 쓴다. 같은 컴퓨터 안에서 단방향으로 데이터를 보내는 통신 방법은 파이프, 다른 컴퓨터와 통신할 때는 소켓을 쓴다. 받는 쪽이 데이터 도착을 계속 확인해야 하는 방식은 비동기화 통신이고, 이렇게 반복문으로 기다리는 것을 바쁜 대기라 한다. 파일을 쓰려면 먼저 open으로 권한을 확인한다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
스레드란? (교재 정의)
프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위. 작업 > 프로세스 > 스레드.
멀티스레딩이란?
하나의 프로세스 내부에서 여러 개의 스레드가 동시에 작업하는 방식. 시스템 자원을 공유하고 IPC 없이 데이터를 주고받는다.
fork와 스레드의 차이는?
fork는 프로세스 전체를 복사해 새 프로세스를 만들고, 스레드는 한 프로세스 안에서 실행 단위만 늘린다.
멀티스레드의 단점은?
같은 프로세스 안이라 한 스레드가 잘못되면 다른 스레드도 같이 영향을 받는다(같이 죽음).
스레드를 경량 프로세스라 부르는 이유는?
코드·파일·데이터를 공유해서 프로세스를 통째로 복사하지 않아 가볍기 때문.
멀티스레드의 장점 4가지는?
자원 공유, 문맥 교환이 효율적, 응답 속도 향상, 적응성 향상.
C에서 스레드를 만들고 기다리는 함수는?
pthread_create()로 생성(→ T_run 실행), pthread_join()으로 기다림(자원 회수).
크롬이 탭마다 프로세스를 쓰는 이유는?
안정성. 한 탭이 죽어도 다른 탭에 영향이 없게.
자바 join()의 역할과 주의점은?
다른 스레드가 끝날 때까지 기다린다. 비정상 상황에 대비해 try-catch로 감싼다.
파이프와 소켓의 차이는?
파이프 = 같은 컴퓨터 안 프로세스끼리(단방향). 소켓 = 네트워크로 다른 컴퓨터와.
반양방향 통신의 예는?
무전기. 양쪽으로 되지만 한순간엔 한쪽만 말한다.
동기화 통신과 비동기화 통신은?
비동기(논블로킹) = 데이터가 언제 올지 몰라 프로세스가 반복문으로 직접 확인(바쁜 대기), 공유 메모리·공유 파일. 동기(블로킹) = OS가 도착할 때까지 대기시켜 줌, 파이프·소켓.
바쁜 대기(busy waiting)란?
비동기화 통신에서 OS가 도착을 알려 주지 않아 프로세스가 while 같은 반복문으로 데이터가 도착할 때까지 계속 확인하며 기다리는 방식.
파이프의 기술자 2개는?
읽기용 fd[0], 쓰기용 fd[1]. pipe(fd)로 만들고 단방향 통신만 지원.
파일 입출력의 기본 구조는?
open(존재·권한 확인, FD 받기) → read/write(FD 사용) → close(반납).

    스레드는 한 프로세스 안에서 코드랑 데이터를 공유해서 가볍고, 문맥 교환도 빠르고 응답도 빨라서 효율적이야. 대신 같은 프로세스라 한 스레드가 잘못되면 다른 스레드도 같이 죽어. 익스플로러는 탭이 스레드라 탭 하나가 죽으면 다 같이 꺼졌어. 크롬은 탭을 독립된 프로세스로 만들어서 하나가 죽어도 나머지는 멀쩡해. 요즘 컴퓨터는 성능이 좋으니까 효율보다 안정성을 택한 거야.
