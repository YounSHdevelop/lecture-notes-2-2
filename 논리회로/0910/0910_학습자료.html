100% 출제: 110010.011을 10진수로 바꾸면?

진법의 본질 · 자리값 · 예제 2-1

먼저 재밌는 얘기 하나. 옛날 바빌로니아나 로마 숫자는 1, 10, 100마다 기호가 다 달랐어요. 그런데 인도 사람들이 0에 "자릿수를 한 칸 민다"는 의미를 붙이면서, 기호 10개만으로 백만, 천만, 억까지 다 쓸 수 있게 됐어요. 이게 지금 쓰는 아라비아 숫자예요(사실은 인도에서 만들어졌고 아라비아 상인들이 퍼뜨린 거래요).

핵심은 이거예요. 어떤 진법이든 수의 본질은 같고, "각 자리 숫자 × 그 자리의 값"을 더하면 된다. 10진법은 자리값이 1, 10, 100…이고, 2진법은 1, 2, 4, 8…이에요.

소수점 왼쪽 첫 자리는 2⁰ = 1

여기서 제일 많이 틀려요. 어떤 수든 0제곱은 1이에요(2⁰ = 10⁰ = 3⁰ = 1). 그래서 소수점 바로 왼쪽이 1의 자리고, 왼쪽으로 갈수록 두 배(2, 4, 8, 16, 32…), 오른쪽으로 갈수록 반(½, ¼, ⅛…)이에요.

8진수, 16진수는 계산 안 해도 된다? 묶기만 하면 끝

2진수 ↔ 8진수 · 16진수

교수님 말로 8진수, 16진수는 2진수의 사촌이에요. 2³ = 8, 2⁴ = 16이니까 2진수를 3자리씩 묶으면 8진수, 4자리씩 묶으면 16진수가 돼요. 소수점을 기준으로 바깥쪽으로 묶고, 모자라면 0을 채워요.

110000.1101(2) 이어서3자리씩: 110 000 . 110 100   →  60.64(8)
4자리씩: 0011 0000 . 1101     →  30.D(16)

16진수는 한 자리에 0~15를 써야 하는데 10부터는 두 자리라 곤란하죠. 그래서 A = 10, B = 11, C = 12, D = 13, E = 14, F = 15를 써요. 이건 외워야 해요.

8진수 ↔ 16진수는 바로 가면 복잡해요. 반드시 2진수로 풀었다가 다시 묶으세요.

0011 0010은 32일까 50일까? 겉만 2진수인 BCD

BCD 코드

BCD는 10진수 한 자리를 4비트로 적는 코드예요. 32를 BCD로 쓰면 3 → 0011, 2 → 0010이라 0011 0010. 사람은 4자리씩 끊어서 "3, 2"로 바로 읽을 수 있어서 편해요.

그런데 이걸 진짜 2진수로 읽으면? 32 + 16 + 2 = 50이에요. 진짜 2진수 32는 0010 0000이고요. 그래서 BCD를 그대로 컴퓨터 연산에 넣으면 오류가 나요.

교수님 비유 (해님 달님) — 호랑이가 할머니 옷을 입고 "나 할머니야" 하는 거예요. 겉모습(형태)은 2진수인데 속(의미)은 10진수. 생긴 건 2진수인데 진짜 2진수가 아닌 "가짜"예요.

또 하나, 4비트는 0~15까지 표현할 수 있는데 BCD는 0~9만 쓰니까 10~15에 해당하는 6개 코드가 버려져요. 그래서 BCD로 덧셈할 땐 6을 더해서 보정하는 이야기가 나와요(나중에 다시 나와요).

시험엔 이렇게

3 − 3을 덧셈으로 하는 법, 그리고 1의 보수가 탈락한 이유

보수 · 1의 보수 · 2의 보수

보수는 왜 만들까?

반도체로 계산기를 만들 때 덧셈기만 만들었어요. 뺄셈기까지 만들면 회로가 복잡해지니까요. 그럼 3 − 3은 어떻게 할까요? 3 + (−3)으로 바꿔서 덧셈하면 돼요. 이때 "−3"을 만드는 방법이 보수예요. 보수는 "서로 모자란 걸 채워 주는 수"라는 뜻이에요. 10진수에서 3과 7은 합해서 10이 되는 보수 관계죠.

1의 보수 — 쉽지만 0이 두 개

2진수의 1의 보수는 0 ↔ 1을 전부 뒤집으면 끝이에요. 3 = 0011 → 1의 보수 1100. 만들기 엄청 쉽죠. 그런데 3 + (−3)을 해 보면:

1의 보수로 3 + (−3)  0011
+ 1100
= 1111      -- 0이 나와야 하는데 1111 (가짜 0)

0이 안 나와요. "1111도 0으로 치자"고 하면, 0000도 0이고 1111도 0인 0이 두 개인 상황이 돼요. 그럼 계산할 때마다 "이게 진짜 0이야?"를 한 번 더 판단해야 하니 컴퓨터가 쓸데없이 시간을 써요.

2의 보수 — 뒤집고 +1, 진짜 0

2의 보수는 1의 보수에 1을 더한 것이에요. 1100 + 1 = 1101.

2의 보수로 3 + (−3)   0011
+  1101
= 1 0000    -- 자리를 넘친 맨 앞 1(캐리)은 버린다 → 0000, 진짜 0!
장점단점
1의 보수만들기 쉽다 (뒤집기)0이 두 개(0000, 1111) → 매번 판단 필요
2의 보수결과가 정확하다 (진짜 0)만들기 조금 어렵다 (+1 필요)

결론: 컴퓨터는 2의 보수를 써요. 1의 보수는 2의 보수를 만드는 중간 과정으로만 존재해요.

    컴퓨터는 왜 보수를 쓰고, 1의 보수가 아니라 2의 보수를 쓰는 이유는 무엇인가요? 3 − 3 예시로 설명해 보세요.

    컴퓨터는 회로를 간단하게 하려고 덧셈기만 만들었어요. 그래서 3 − 3을 3 + (−3)처럼 덧셈으로 바꿔 계산하는데, 이때 −3을 만드는 게 보수예요. 1의 보수는 비트만 뒤집으면 돼서 만들기 쉽지만, 0011 + 1100 = 1111이 되어 0이 0000과 1111 두 개가 생겨요. 그럼 매번 진짜 0인지 판단해야 하죠. 2의 보수는 1의 보수에 1을 더한 1101이라 만들기 조금 번거롭지만, 0011 + 1101 = 1 0000에서 넘친 1을 버리면 정확히 0000이 나와요. 그래서 컴퓨터는 2의 보수를 쓰고, 1의 보수는 중간 과정으로만 쓰여요.
    더 알아두면 좋은 것 시험 비중 낮음

    r의 보수와 (r−1)의 보수

    일반식은 r의 보수 = rⁿ − x, (r−1)의 보수 = rⁿ − 1 − x. 10진수 567이면 9의 보수 = 999 − 567 = 432, 10의 보수 = 1000 − 567 = 433. 2진수에선 1의 보수와 2의 보수가 이 관계예요.

    컴퓨터 세대를 나누는 기준 (강의 중 이야기)

    진공관이냐 반도체냐, 10진법이냐 2진법이냐(초기 컴퓨터는 10진법을 썼어요), 전선을 꽂았다 뺐다 하느냐 프로그램을 내장하느냐, 고급 언어를 쓰느냐로 세대를 나눠요.
