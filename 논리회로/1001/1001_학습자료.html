"제대로 보낸 거 맞아?" 전화로 다시 물어보면 안 될까?

통신 에러 · 두 번 보내기의 비용 · 비트 하나만 더 보내기

8비트 데이터를 보냈는데 받는 쪽에서 0 하나가 1로 바뀌어 있어요. 제일 원시적인 방법은 똑같은 걸 두 번 보내서 비교하는 거예요. 다르면 에러죠. 그런데 그러면 통신 시간도 비용도 두 배예요. 다시 전화해서 물어보는 것도 시간 · 딜레이 · 비용이고요.

그래서 교수님 설명대로, 8비트를 또 보내지 말고 딱 1비트만 더 보내자는 아이디어가 나왔어요. 1비트는 0 아니면 1이라 "몇 번째가 바뀌었는지, 0→1인지 1→0인지" 같은 많은 정보는 못 담아요. 그건 포기하고 "에러가 났다/안 났다" 하나만 알려 주자. 8비트에 1비트를 더하니 비용은 10% 정도만 늘어나요. 이 추가 비트가 패리티 비트예요.

시험엔 이렇게

패리티 비트는 데이터 전송 과정에서 에러 검사를 위해 추가하는 비트로, 에러 검출만 가능하고 정정은 할 수 없다.

1의 개수를 짝수로 맞출까, 홀수로 맞출까?

짝수 패리티 · 홀수 패리티 · 예제 3-6 · 한계

방식은 두 가지예요. 보낼 데이터의 1 개수를 세서, 패리티 비트 자기 자신을 포함한 전체 1의 개수를

  • 짝수 패리티(even) — 짝수로 맞춰요.
  • 홀수 패리티(odd) — 홀수로 맞춰요.

어느 쪽을 쓸지는 통신 전에 미리 약속해요(프로토콜). 사실 원리는 똑같아요.

문자7비트 ASCII짝수 패리티홀수 패리티
A1000001 (1이 2개)0 10000011 1000001
C1000011 (1이 3개)1 10000110 1000011

받는 쪽은 1의 개수를 다 세서, 짝수 패리티인데 홀수가 나오면 에러. 패리티 검출기 출력은 짝수 패리티에서 Y=0이면 에러 없음, Y=1이면 에러예요(홀수 패리티는 반대).

한계비트 2개(짝수 개)가 동시에 바뀌면 1의 개수가 다시 짝수가 돼서 못 잡는다

짝수 패리티는 데이터에서 1의 개수를 짝수 개로, 홀수 패리티는 홀수 개로 맞춘다. 패리티는 에러 검출만 가능하며, 여러 비트에 에러가 발생하면 검출되지 않을 수도 있다.

가로로도 세로로도 패리티를 붙이면, 에러 위치가 보인다

병렬 패리티(블록 패리티) · 효율 87.5% · 예제 3-7

한 바이트마다 끝에 패리티를 붙여 보내고(가로), 여러 바이트를 다 보낸 뒤 세로 방향 패리티를 모은 바이트를 하나 더 보내요. 그러면 받는 쪽에서 "가로 몇 번째 줄이 홀수", "세로 몇 번째 칸이 홀수"를 찾을 수 있죠. 두 줄이 겹치는 칸이 에러예요. 그 칸을 뒤집으면 고쳐지고요. 교수님이 "이거 재밌죠?" 했던 부분이에요.

비용은? 7비트 ASCII 문자 N개에 패리티를 붙이면 총 8(N+1)비트를 보내고 순수 데이터는 7N이라, 효율 = 7N / 8(N+1). 단순 직렬 패리티면 7/8 = 87.5%예요(예제 3-7).

시험엔 이렇게

병렬 패리티는 블록 데이터의 가로와 세로에 패리티를 적용해, 에러를 검출하고 그 위치를 찾아 정정할 수 있다. 7비트 ASCII 문자 N개를 병렬 패리티로 보낼 때 효율은 7N / 8(N+1)이다.

외우는 법: 가로 홀수 × 세로 홀수 = 범인
바로 확인
단순 직렬 패리티(7비트 데이터 + 패리티 1비트)의 전송 효율은?
7 / 8 = 0.875. 나머지 12.5%가 패리티 몫.

보내는 쪽 도움 없이 받는 쪽이 스스로 고친다 — 해밍 코드

에러 정정 코드 · 패리티 개수 공식 · 위치 1, 2, 4, 8 · 짝수 패리티

해밍 코드는 패리티 비트를 여러 개 데이터 사이사이에 심어서, 받는 쪽이 송신 측 도움 없이 에러 위치를 찾아 스스로 정정하는 코드예요. 대신 추가 비트가 많이 필요해요.

패리티는 몇 개, 어디에?

패리티 비트 수 p, 데이터 비트 수 d 사이엔 이 관계가 있어요.

자료 p.25 공식

2p−1 − p + 1 ≤ d ≤ 2p − p − 1   → p = 4이면 5 ≤ d ≤ 11

8비트 데이터라면 → 패리티 4개, 총 12비트

패리티 비트 자리는 앞에서부터 1, 2, 4, 8, 16…번째(2의 거듭제곱 자리), 데이터는 나머지 자리에 순서대로 들어가요. 해밍 코드는 짝수 패리티를 써요.

각 패리티는 자기가 맡은 자리들을 봐요. 자리 번호를 2진수로 썼을 때 그 비트가 1인 자리들이에요.

패리티담당 자리 (12비트 기준)
P11, 3, 5, 7, 9, 11
P22, 3, 6, 7, 10, 11
P44, 5, 6, 7, 12
P88, 9, 10, 11, 12

받는 쪽: 다시 계산해서 줄 세우기

받은 뒤 각 영역의 1 개수를 패리티 포함해서 다시 검사해요(짝수면 0, 홀수면 1). 결과를 P8 P4 P2 P1 순서로 세우면 — 모두 0이면 에러 없음, 아니면 그 2진수를 10진수로 바꾼 값이 에러 난 자리 번호예요. 그 비트를 뒤집으면 정정 끝.

이해용 예시 (자료의 12비트 예제를 7비트로 줄임 · 짝수 패리티)자리:   7  6  5  4  3  2  1
기호:   D7 D6 D5 P4 D3 P2 P1
보냄:   1  1  0  0  1  1  0     // P1=D3⊕D5⊕D7=0, P2=D3⊕D6⊕D7=1, P4=D5⊕D6⊕D7=0
받음:   1  1  1  0  1  1  0     // 5번 자리가 뒤집힘
검사:   C4=1  C2=0  C1=1  →  C4C2C1 = 101 = 5  → 5번 자리를 뒤집어 정정
시험엔 이렇게

해밍 코드는 에러를 정정할 수 있는 코드로 짝수 패리티를 쓴다. 패리티 비트는 1, 2, 4, 8…번째 위치에 두고, 2p−1 − p + 1 ≤ d ≤ 2p − p − 1 관계로 개수를 정한다. 수신 측에서 다시 검사한 패리티를 P8 P4 P2 P1 순으로 정렬해 모두 0이면 에러 없음, 아니면 그 10진값 위치의 비트가 에러다.

외우는 법: 패리티 자리는 2의 거듭제곱(1 · 2 · 4 · 8) / 검사 결과를 거꾸로 세우면 범인 주소
바로 확인
해밍 코드 검사 결과 P8 P4 P2 P1 = 0110이었다. 의미는?
0110 = 10진수 6 → 6번 자리 비트를 뒤집어요. 0000이어야 에러 없음.

2진수 1100을 넣으면 "1"과 "2"가 따로 나오게 만들자

실습 과제 2 · BCD 코드 발생기 · 7485 비교기 · 7483 가산기 · +6

2진수 1100은 10진수로 12인데, 그냥 봐서는 바로 안 읽히죠. "1"과 "2" 두 자리로 따로 보이면 좋겠다.

그래서 9/29에 배운 대로 10이 넘으면 6(0110)을 더해서 두 자리로 나누는 게 BCD예요. 오늘 실습은 이걸 회로로 만드는 거였어요.

  1. 바이너리 스위치 4개로 입력 C3~C0 (0000~1111)을 넣어요.
  2. 7485 비교기가 입력이 9(1001)보다 큰지 비교해요. 10 이상이면 "A가 크다" 신호가 나와요.
  3. 크면 7483 4비트 가산기로 입력에 0110(6)을 더해요. 작으면 그대로.
  4. 결과 B4~B0: B4가 십의 자리(0 또는 1), B3~B0이 일의 자리.

    Q1데이터 1011001에 짝수 패리티 비트를 붙이면 패리티 값은?

    1이 4개(짝수) → 이미 짝수라 패리티 0.

    Q2데이터 1000011에 홀수 패리티 비트를 붙이면?

    1이 3개(홀수) → 이미 홀수라 0. (자료 표의 C)

    Q3짝수 패리티로 받은 11010은?

    1이 3개(홀수) → 짝수 패리티 위반.

    Q4패리티 방식에서 에러를 못 잡는 경우는?

    짝수 개가 바뀌면 1 개수의 짝홀이 그대로.

    Q58비트 데이터를 해밍 코드로 보내려면 패리티 비트는 몇 개?

    p=4이면 5 ≤ d ≤ 11 → 8 포함. 총 12비트.

    Q612비트 해밍 코드에서 패리티 비트가 놓이는 자리는?

    2의 거듭제곱 자리.

    Q7해밍 코드 수신 검사 결과 P8P4P2P1 = 0000이면?

    예제 3-8처럼 0000 → 에러 없음.

    Q8BCD 코드 발생기에 1101(13)을 넣으면 출력은?

    1101 + 0110 = 1 0011 → 13.

    내 말로 설명하기 서술형 대비

    "BCD 코드가 무엇인지, 장단점과 사용 예를 포함해 설명해 보세요." (실습 과제 3번 · 교수님 강조)

    BCD(Binary Coded Decimal) 코드는 10진수의 각 자리를 4비트 2진수로 따로 나타낸 코드예요. 예를 들어 12는 순수 2진수로 1100이지만 BCD로는 0001 0010이에요. 2진수가 9를 넘으면 6(0110)을 더해 자리를 나눠요. 장점은 사람이 자리별로 바로 읽을 수 있고 7세그먼트 같은 숫자 표시 장치로 보내기 쉽다는 것이고, 단점은 4비트로 0~9만 써서 비트가 낭비되고 연산할 때 +6 보정이 필요하다는 거예요. 엘리베이터 층 표시, 전자시계, 계산기 표시부처럼 10진수를 보여 주는 장치에 써요.

    직렬 통신 설정

    통신 전에 미리 정하는 것들: 비트 순서(MSB/LSB 먼저), 패리티(짝수 · 홀수 · 없음), 속도(9600 · 19200bps 등), 정지 비트 수. 직렬은 선이 적어 싸지만 느리고, 병렬은 빠르지만 선이 많아 비싸요.

    ASCII(128문자, 7비트 + 패리티), 표준 BCD(6비트, 64문자), EBCDIC(IBM, 8비트, 256문자).
