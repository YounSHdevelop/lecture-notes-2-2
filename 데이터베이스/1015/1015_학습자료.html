이 INSERT 문은 성공할까, 에러가 날까?

중간고사 전 마지막 수업이에요. 3장에서 배운 무결성 제약조건을 이번엔 진짜 SQL로 테이블에 걸어 보고, INSERT를 넣어 보면서 어떤 건 들어가고 어떤 건 에러가 나는지 확인했어요. 뒤에는 사용자 계정과 권한, 뷰 개념까지 나갔어요.

이 페이지를 다 보면 할 수 있는 것

  1. CREATE TABLE 문을 보고 NOT NULL · DEFAULT · PRIMARY KEY · UNIQUE · FOREIGN KEY가 각각 무엇을 막는지 말할 수 있다
  2. INSERT 문을 보고 성공인지, 에러라면 어떤 제약조건 때문인지 판별할 수 있다
  3. GRANT · REVOKE 문을 보고 누가 어떤 권한을 갖게 되는지 해석할 수 있다

장면 1

테이블을 만들 때 "이 칸은 꼭 채워라"는 어떻게 정할까?

CREATE TABLE · 데이터 유형 · NOT NULL · PRIMARY KEY · UNIQUE · FOREIGN KEY

3장에서 개체 · 참조 · 도메인 · 유일성 무결성을 배웠어요

그런데 그 규칙을 DBMS가 어떻게 알고 지켜 줄까요? 테이블을 만들 때 SQL로 미리 적어 두기 때문이에요.

테이블은 CREATE TABLE로 만들어요. 2장에서 배운 DDL(정의어)이죠. 열 이름마다 데이터 유형을 쓰고, 그 뒤에 이 열이 지켜야 할 제약조건을 붙여요.

CREATE TABLE 형식 (교재 p.2)CREATE TABLE 테이블_이름
  ( 열_이름 데이터_유형 [NULL | NOT NULL] [DEFAULT 기본_값],
    ...
    [PRIMARY KEY (열_이름)],
    [UNIQUE (열_이름)],
    [FOREIGN KEY (열_이름) REFERENCES 테이블_이름 (열_이름)] ) ;

데이터 유형은 이렇게 나뉘어요. 교수님은 문자 길이는 너무 넉넉하게 말고 꼭 맞게 잡는 게 좋다고 했고, 게시물처럼 올린 시각까지 알아야 하면 날짜만이 아니라 날짜시간으로 저장한다고 했어요.

분류유형뜻
문자형CHAR(길이) · VARCHAR(길이) · TEXTCHAR는 고정 길이(남는 칸은 공백으로 채움), VARCHAR는 가변 길이(남는 칸 없음), TEXT는 긴 문자열
정수형INT · SMALLINT소수점 없는 정수
실수형DECIMAL · FLOAT · DOUBLE소수점 있는 수
날짜형DATE · DATETIME · TIME · YEARDATE는 연-월-일, DATETIME은 연-월-일 시:분:초

이제 교재 예제로 제약조건을 하나씩 볼게요. 학생2 테이블이에요.

예제 6-2 · 학생2 테이블 생성CREATE TABLE 학생2
  ( 학번 CHAR(4) NOT NULL,
    이름 VARCHAR(20) NOT NULL,
    주소 VARCHAR(50) DEFAULT '미정',
    학년 INT NOT NULL,
    나이 INT NULL,
    성별 CHAR(1) NOT NULL,
    휴대폰번호 CHAR(13) NULL,
    소속학과 VARCHAR(20) NULL,
    PRIMARY KEY (학번),
    UNIQUE (휴대폰번호) ) ;
  • NOT NULL : 이 열은 비워 둘 수 없다. 값을 안 넣으면 에러
  • NULL : 비워 둬도 된다 (나이, 휴대폰번호, 소속학과)
  • DEFAULT '미정' : 주소를 안 넣으면 자동으로 '미정'이 들어간다
  • PRIMARY KEY (학번) : 학번이 기본키. 널도 중복도 안 됨
  • UNIQUE (휴대폰번호) : 기본키는 아니지만 중복은 안 됨. 교재는 휴대폰번호를 대체키로 지정했다고 설명해요

수강2 테이블에는 FOREIGN KEY가 나와요. 수강 기록의 학번은 학생2에, 과목번호는 과목2에 실제로 있어야 하니까요.

예제 6-3 · 수강2 테이블 생성CREATE TABLE 수강2
  ( 학번 CHAR(6) NOT NULL,
    과목번호 CHAR(4) NOT NULL,
    신청날짜 DATE NOT NULL,
    중간성적 INT NULL DEFAULT 0,
    기말성적 INT NULL DEFAULT 0,
    평가학점 CHAR(1) NULL,
    PRIMARY KEY (학번, 과목번호),
    FOREIGN KEY (학번) REFERENCES 학생2(학번),
    FOREIGN KEY (과목번호) REFERENCES 과목2(과목번호) ) ;

기본키가 (학번, 과목번호) 두 열의 조합이에요. 학생 한 명이 여러 과목을 듣고, 한 과목을 여러 학생이 들으니까 둘을 합쳐야 한 줄이 구별돼요. 3장의 후보키 판별과 똑같은 얘기예요.

시험엔 이렇게

CREATE TABLE에서 PRIMARY KEY는 개체 무결성, FOREIGN KEY ... REFERENCES는 참조 무결성, NOT NULL · DEFAULT · CHECK는 도메인 무결성, UNIQUE는 유일성 무결성을 지킨다.

외우는 법: PK = 개체 · FK = 참조 · NOT NULL/DEFAULT = 도메인 · UNIQUE = 유일성 (3장 개 · 참 · 도 · 유 그대로)
바로 확인
학생2 테이블에서 "이미 있는 휴대폰번호를 또 넣는 것"을 막는 부분은?
중복을 막는 건 UNIQUE예요. 휴대폰번호는 기본키가 아니라서 PRIMARY KEY와는 상관없고, NULL은 오히려 "비워도 된다"는 뜻이에요.

장면 2

NULL, 0, DEFAULT는 다 "비어 있는 거" 아니야?

NULL · DEFAULT 차이 · 테이블 만드는 순서
교수
0을 넣어 주는 것과 공백을 넣어 주는 것과 기본값을 넣어 주는 것은 달라요. DEFAULT랑 NULL은 다른 거예요.10/15 강의 중 (말을 조금 다듬음)

셋을 나눠 볼게요.

  • NULL : "아직 모르는 값"이에요. 값이 없다는 표시일 뿐, 0도 빈칸도 아니에요. 나중에 언제든 들어올 수 있어요.
  • DEFAULT : 값을 안 넣으면 미리 정해 둔 값이 자동으로 들어가요. 수강2의 중간성적은 DEFAULT 0이라서, 수강 신청만 하고 시험 전이면 0이 들어가 있어요.
  • 0 : 그냥 숫자 0이라는 진짜 값이에요.

교수님 예시가 딱 이거였어요. 수강 신청을 하면 성적은 아직 없잖아요. 그래서 중간성적 · 기말성적을 DEFAULT 0으로 만들어 두고, 시험을 보면 점수를 넣어요. 반면 평가학점은 DEFAULT 없이 NULL이라 값을 안 넣으면 NULL로 남아요.

테이블은 어떤 순서로 만들어야 할까

수강2는 학생2와 과목2를 참조해요. 그런데 참조할 테이블이 아직 없으면 어떻게 될까요? 가리킬 대상이 없으니 에러가 나요.

교수
외래키는 어떤 테이블의 열을 참조하는 거라서, 참조하려는 테이블은 반드시 먼저 있어야 돼요. 테이블만 있으면 되는 게 아니라 그 안에 그 속성도 반드시 있어야 돼요. 요것만 기억하시면 어렵지 않아요.10/15 강의 중 (말을 조금 다듬음)
시험엔 이렇게

NULL은 아직 모르는 값, DEFAULT는 값을 넣지 않았을 때 자동으로 들어가는 기본값이다. 외래키로 참조되는 테이블을 먼저 생성하고, 참조하는 테이블은 나중에 생성한다.

외우는 법: NULL = 모름 · DEFAULT = 안 넣으면 자동 · 0 = 진짜 값 / 만들 땐 부모 먼저, 지울 땐 자식 먼저
바로 확인
수강2에 학번 · 과목번호 · 신청날짜만 넣었다. 중간성적과 평가학점에는 각각 무엇이 들어갈까?
중간성적은 DEFAULT 0이라 0이 자동으로 들어가요. 평가학점은 DEFAULT 없이 NULL을 허용하니까 NULL이에요. 둘 다 NOT NULL이 아니라서 에러는 안 나요.

장면 3

이 INSERT는 들어갈까, 에러가 날까?

무결성 제약조건의 동작 확인 · 교재 p.6~7

테이블에 제약조건을 걸었으면, 이제 INSERT로 확인해 볼 차례예요. 교수님이 한 줄씩 실행해 보라고 한 예제예요. 판별하는 방법은 간단해요. 각 열의 조건과 넣는 값을 하나씩 맞대 보면 돼요.

먼저 과목2 테이블은 다섯 열이 전부 NOT NULL이에요.

예제 6-1 · 과목2CREATE TABLE 과목2
  ( 과목번호 CHAR(4) NOT NULL PRIMARY KEY,
    이름 VARCHAR(20) NOT NULL,
    강의실 CHAR(5) NOT NULL,
    개설학과 VARCHAR(20) NOT NULL,
    시수 INT NOT NULL ) ;
#넣으려는 것결과왜
①과목2 (과목번호, 이름, 강의실, 개설학과)
('c111', 'database', A-123, '산업공학')		에러강의실 값 A-123에 따옴표가 없어 문자형(CHAR(5))과 맞지 않음. 게다가 NOT NULL인 시수도 빠졌음
②과목2 (과목번호, 이름, 강의실, 개설학과, 시수)
('c111', 'database', 'A-123', '산업공학')		에러열은 5개인데 값은 4개, 시수가 빠졌는데 시수는 NOT NULL
③같은 문장에 시수 3까지 다섯 개성공다섯 열이 다 채워지고 형식도 맞음
④학생2 ('s111', '박태환', 4, NULL, '남', '010-1111-1111', '산업공학')성공나이는 NULL 허용, 주소는 안 넣었으니 DEFAULT '미정'
⑤학생2 ('s222', '박태환', 2, NULL, '남', '010-1111-1111', '산업공학')에러휴대폰번호가 ④와 같음 → UNIQUE 위반 (이름이 같은 건 상관없음)
⑥학생2 s222, 휴대폰번호만 '010-2222-2222'로 바꿈성공이제 중복 없음
⑦수강2 (학번, 과목번호, 신청날짜) ('s111', 'c111', '2019-12-31')성공s111 · c111 모두 있음. 성적은 DEFAULT 0, 평가학점은 NULL
⑧수강2 ('s111', 'c222', '2019-12-31', 93, 98, 'A')에러과목2에 c222가 없음 → 외래키(참조 무결성) 위반
⑨수강2 ('s111', 'c111', '2019-12-31', 93, 98, 'A')에러(s111, c111)은 ⑦에서 이미 들어감 → 기본키 중복 (개체 무결성) 위반
⑩수강2 ('s222', 'c111', '2019-12-31', 93, 98, 'A')성공s222는 ⑥에서 들어갔고, (s222, c111) 조합은 처음
✗ 헷갈리기 쉬운 것⑤에서 이름 '박태환'이 같아서 에러가 났다
○ 맞게 보기이름에는 제약이 없어요. 에러 원인은 UNIQUE가 걸린 휴대폰번호가 같아서예요.
시험엔 이렇게

INSERT 에러는 NOT NULL 열 누락, 데이터 유형 불일치, UNIQUE 열 중복, 기본키 중복, 참조 테이블에 없는 외래키 값 때문에 생긴다.

판별 순서: ① 빠진 NOT NULL 열? → ② 형식 맞나? → ③ PK · UNIQUE 중복? → ④ FK 값이 부모에 있나?
바로 확인
⑩까지 실행한 뒤 수강2에 ('s333', 'c111', '2019-12-31', 80, 90, 'B')를 넣으면?
과목번호 c111은 있지만 학번 s333은 학생2에 없어요. 외래키가 두 개라서 둘 다 부모 테이블에 있어야 해요. (s333, c111) 조합은 처음이라 기본키 중복은 아니에요.

장면 4

이미 만든 테이블은 어떻게 고치고 지울까?

ALTER TABLE · DROP TABLE

테이블 구조를 고칠 땐 ALTER TABLE이에요. 2장에서 "열 추가는 DDL의 ALTER"라고 했던 바로 그거예요. 테이블 이름 뒤에 무엇을 할지를 붙여요.

  • ADD : 열(또는 제약조건) 추가
  • MODIFY : 열의 형식 수정
  • DROP COLUMN : 열 삭제 (DROP CONSTRAINT는 제약조건 삭제)
예제 6-4 · 학생2에 '등록날짜' 열 추가ALTER TABLE 학생2
  ADD 등록날짜 DATETIME NOT NULL DEFAULT '2019-12-30' ;

예제 6-5 · '등록날짜' 열 삭제ALTER TABLE 학생2
  DROP COLUMN 등록날짜 ;

교수님은 테이블 수정이 이미 들어 있는 데이터에 영향을 줄 수 있어서 조심해야 한다고 했어요. 그래서 처음 만들 때 설계를 잘 해 두는 게 중요해요.

테이블 삭제는 DROP TABLE, 그런데 순서가 있어요

예제 6-6 · 과목2 삭제DROP TABLE 과목2 ;     // 삭제 불가 : 수강2가 과목2를 참조하고 있음

DROP TABLE 수강2 ;     // 참조하는(자식) 테이블을 먼저 삭제
DROP TABLE 과목2 ;     // 이제 삭제 가능

장면 2 그림을 거꾸로 따라가면 돼요. 수강2가 과목2를 가리키고 있는데 과목2를 먼저 지우면, 수강2의 과목번호가 없는 과목을 가리키게 되니까 DBMS가 막아요. 그래서 자식(수강2)부터 지워요.

시험엔 이렇게

ALTER TABLE은 ADD · MODIFY · DROP COLUMN으로 테이블 구조를 수정한다. 다른 테이블이 참조하는 테이블은 바로 DROP할 수 없고, 참조하는 테이블을 먼저 삭제해야 한다.

외우는 법: ALTER = 추가 · 수정 · 삭제(ADD · MODIFY · DROP) / 지울 땐 자식 먼저
바로 확인
학생2를 지우려고 DROP TABLE 학생2 ;를 바로 실행했더니 에러가 났다. 이유는?
수강2의 FOREIGN KEY (학번) REFERENCES 학생2(학번) 때문이에요. 수강2를 먼저 지우면 학생2도 지울 수 있어요.

장면 5

아무나 내 DB를 고치면 안 되잖아?

CREATE USER · GRANT · REVOKE · WITH GRANT OPTION · DCL

학교 DB에 교직원도, 교수도, 학생도 접속한다면?

교직원은 조회만, 교수는 성적 수정까지… 사람마다 할 수 있는 일을 다르게 줘야겠죠. 2장의 DCL(제어어)이 바로 이 일을 해요.

① 계정 만들기 : CREATE USER

CREATE USER 예제 (교재 p.10)CREATE USER 'user1'@'127.1.1.1' IDENTIFIED BY '1111' ;   // 이 IP에서만 접속 가능
CREATE USER 'user2'@'localhost' IDENTIFIED BY '2222' ;   // DB가 설치된 그 컴퓨터에서만
CREATE USER 'user4'@'%' IDENTIFIED BY '4444' ;           // 어디서든 접속 가능

계정은 '아이디'@'호스트' 모양이에요. @ 뒤의 호스트가 어디서 접속할 수 있는지를 정해요. %는 "어디서든"이라는 뜻이에요. 만든 계정은 SELECT host, user FROM mysql.user ;로 확인해요.

② 권한 주기 · 빼앗기 : GRANT · REVOKE

줄 수 있는 권한은 INSERT · UPDATE · DELETE · SELECT · ALL이에요. 형식은 "무슨 권한을 ON 어디에 TO 누구에게"예요.

GRANT 예제 (교재 p.12)GRANT INSERT, UPDATE, DELETE ON univDB.* TO 'user1'@'127.1.1.1' ;
GRANT ALL ON *.* TO 'user4'@'%' WITH GRANT OPTION ;
GRANT SELECT ON univDB.학생 TO 'user2'@'localhost' ;
  • univDB.* : univDB 안의 모든 테이블
  • *.* : 모든 DB의 모든 테이블
  • univDB.학생 : univDB의 학생 테이블 하나만
  • user2는 학생 테이블을 조회(SELECT)만 할 수 있어요. 교수님 말로는 교직원처럼 "검색만" 하는 사람에게 주는 권한이에요

WITH GRANT OPTION이 오늘의 함정이에요. 이걸 붙이면 권한을 받은 사람이 그 권한을 다른 사람에게 또 줄 수 있어요. user4는 ALL + WITH GRANT OPTION을 받았으니 사실상 관리자(root)에 가까워져요.

교수
WITH GRANT OPTION을 주면, 권한을 받는 사용자가 거꾸로 다른 사람에게 권한을 줄 수 있어요. 루트 권한에 거의 동급이 되는 거예요.10/15 강의 중 (말을 조금 다듬음)
REVOKE 예제 (교재 p.13)REVOKE DELETE ON univDB.* FROM 'user1'@'127.1.1.1' ;   // user1에게 남는 권한 : INSERT, UPDATE

SHOW GRANTS FOR 'user1'@'127.1.1.1' ;   // user1의 권한 확인
DROP USER 'user1'@'127.1.1.1' ;          // 계정 삭제

GRANT는 TO(누구에게 준다), REVOKE는 FROM(누구에게서 빼앗는다)이에요. 단어 뜻 그대로라 외우기 쉬워요.

시험엔 이렇게

GRANT 권한 ON 대상 TO 사용자로 권한을 부여하고, REVOKE 권한 ON 대상 FROM 사용자로 철회한다. WITH GRANT OPTION을 붙이면 받은 권한을 다른 사용자에게 다시 부여할 수 있다.

외우는 법: GRANT ~ TO (준다) / REVOKE ~ FROM (뺏는다) · 권한 5개 = INSERT · UPDATE · DELETE · SELECT · ALL
바로 확인
GRANT SELECT ON univDB.학생 TO 'user2'@'localhost' ; 이후 user2가 학생 테이블에 할 수 있는 것은?
SELECT만 받았으니 조회만 돼요. 다른 사람에게 권한을 주려면 WITH GRANT OPTION이 붙어 있어야 해요.

뷰는 테이블처럼 생겼는데 뭐가 다를까?

뷰 = 가상 테이블 · 실습은 다음 시간

수업 맨 앞과 끝에 나온 개념이에요. 실습은 다음 시간이라 오늘은 뜻만 잡으면 돼요.

뷰(view)는 실제 데이터를 저장하지 않는 가상 테이블이에요. 진짜 테이블들에서 내가 원하는 열과 행만 뽑아 하나의 표처럼 보여 줘요. 교재는 뷰를 "데이터베이스를 바라보는 창문"에 비유해요. 창문으로 방 안의 일부만 보이듯, 뷰로는 필요한 부분만 보여요.

교수
뷰하고 테이블은 형식은 비슷하지만, 테이블은 고정돼 있는 실체고, 뷰는 내가 필요한 부분들을 가상으로 모아서 하나의 테이블로 만들어 놓은 거예요.10/15 강의 중 (말을 조금 다듬음)

예를 들어 학생 정보를 보여 주는 화면을 만드는데 전화번호는 빼고 싶다면, 전화번호 열을 뺀 뷰를 하나 만들어 그 뷰만 쓰게 하면 돼요. 원래 테이블은 그대로 있고, 뷰는 원래 테이블에서 데이터를 가져와 보여 줄 뿐이에요.

시험엔 이렇게

뷰는 실제 데이터를 저장하지 않는 가상 테이블로, 기반 테이블에서 필요한 부분만 뽑아 하나의 테이블처럼 보여 준다.

외우는 법: 테이블 = 실체 · 뷰 = 창문(가상)
바로 확인
뷰에 대한 설명으로 맞는 것은?
뷰는 저장하지 않는 가상 테이블이에요. 데이터는 원래 테이블에만 있고, 뷰는 그걸 창문처럼 보여 줘요.

① CREATE TABLE 제약조건 ★개 · 참 · 도 · 유

  • NOT NULL : 반드시 값을 넣어야 함
  • DEFAULT : 값을 안 넣으면 정해 둔 기본값이 자동으로 들어감
  • PRIMARY KEY : 기본키, 널 · 중복 금지 (개체 무결성)
  • UNIQUE : 키가 아닌 열의 중복 금지 (유일성 무결성)
  • FOREIGN KEY ... REFERENCES : 다른 테이블의 키를 참조 (참조 무결성)

② NULL / DEFAULT · 순서

  • NULL : 아직 모르는 값 (0도 빈칸도 아님)
  • DEFAULT 0 : 안 넣으면 0이 자동으로 (수강2 중간성적)
  • 생성 순서 : 참조되는 테이블 먼저 (과목2 · 학생2 → 수강2)

③ INSERT 에러 판별 ★ 해석

  • NOT NULL 열 누락 · 유형 불일치 → 에러
  • UNIQUE · 기본키 값 중복 → 에러
  • 부모 테이블에 없는 외래키 값 → 참조 무결성 에러

④ ALTER · DROP

  • ALTER TABLE : ADD · MODIFY · DROP COLUMN
  • DROP TABLE : 참조당하는 테이블은 바로 못 지움 → 자식 먼저

⑤ 사용자와 권한 (DCL) ★GRANT ~ TO / REVOKE ~ FROM

  • CREATE USER '아이디'@'호스트' IDENTIFIED BY '비밀번호' (% : 어디서든)
  • 권한 : INSERT · UPDATE · DELETE · SELECT · ALL
  • WITH GRANT OPTION : 받은 권한을 다른 사람에게 다시 줄 수 있음

⑥ 뷰

  • 뷰 : 실제 데이터를 저장하지 않는 가상 테이블 (DB를 바라보는 창문)

빈칸 채우기 눌러서 정답 확인

테이블은 CREATE TABLE로 만든다. 반드시 값이 있어야 하는 열에는 NOT NULL을, 값을 안 넣으면 자동으로 들어갈 값은 DEFAULT로 정한다. 키가 아닌 열의 중복을 막으려면 UNIQUE를 쓴다. 다른 테이블을 참조하는 외래키는 FOREIGN KEY ... REFERENCES로 정하고, 참조되는 테이블을 먼저 만들어야 한다. 테이블 구조를 고칠 땐 ALTER TABLE을 쓴다. 권한을 줄 땐 GRANT ~ TO, 빼앗을 땐 REVOKE ~ FROM을 쓰고, 받은 권한을 남에게 다시 줄 수 있게 하려면 WITH GRANT OPTION을 붙인다. 뷰는 실제 데이터를 저장하지 않는 가상 테이블이다.

    퀴즈 다 풀고 채점하기

    Q1과목2(다섯 열 모두 NOT NULL)에 INSERT INTO 과목2(과목번호, 이름, 강의실, 개설학과) VALUES ('c333', 'os', 'B-101', '컴퓨터');를 실행하면?

    시수는 NOT NULL이고 DEFAULT도 없어서, 안 넣으면 에러예요. c333은 처음 넣는 과목번호라 중복은 아니에요.

    Q2학생2에 주소를 넣지 않고 학생을 추가했다. 주소에는 무엇이 들어갈까?

    학생2의 주소는 DEFAULT '미정'이라 안 넣으면 '미정'이 들어가요.

    Q3수강2에 이미 (s111, c111)이 있을 때 같은 (s111, c111)을 또 넣으면?

    수강2의 기본키는 (학번, 과목번호) 조합이에요. 같은 조합이 또 들어오면 기본키 중복이에요.

    Q4학생2 · 과목2 · 수강2를 모두 지우려고 한다. 올바른 순서는?

    참조하는 수강2를 먼저 지워야 과목2 · 학생2를 지울 수 있어요. 과목2와 학생2끼리는 순서가 상관없어요.

    Q5GRANT INSERT, UPDATE, DELETE ON univDB.* TO 'user1'@'127.1.1.1'; 다음에 REVOKE DELETE ON univDB.* FROM 'user1'@'127.1.1.1';를 했다. user1에게 남은 권한은?

    세 개를 받았다가 DELETE만 빼앗겼으니 INSERT, UPDATE가 남아요.

    Q6받은 권한을 다른 사용자에게 다시 줄 수 있게 하려면 GRANT 문 끝에 무엇을 붙일까?

    WITH GRANT OPTION이에요. ALL은 권한의 종류(전부)이고, 다시 줄 수 있는지와는 별개예요.

    Q7학생 테이블에서 전화번호만 빼고 보여 주고 싶다. 원래 테이블은 그대로 두고 쓰기 좋은 방법은?

    뷰는 원래 테이블을 건드리지 않고 필요한 열만 보여 주는 가상 테이블이에요. ALTER로 열을 지우면 원래 데이터가 사라져요.

    첫째, 학번 · 과목번호 · 신청날짜는 NOT NULL이라 하나라도 빠지면 에러예요. 둘째, 기본키가 (학번, 과목번호) 조합이라 이미 있는 조합을 또 넣으면 기본키 중복 에러예요. 셋째, 학번과 과목번호는 외래키라서 학생2나 과목2에 없는 값을 넣으면 참조 무결성 에러예요. 그리고 값의 형식이 데이터 유형과 맞지 않아도 에러가 나요.

    뷰의 장점 (교재 p.18, 수업에선 다음 시간)

    편의성(복잡한 질의를 간단하게), 보안성(보여 줄 부분만 공개), 재사용성(반복되는 질의를 한 번만), 독립성(스키마가 바뀌어도 뷰 질의문은 그대로)이에요. 뷰 만들기(CREATE VIEW) · 인덱스는 다음 시간 진도예요.

    관리자 계정 만들기 (교재 p.15)

    CREATE USER 'manager'@'%' IDENTIFIED BY '1234'; 다음에 GRANT ALL ON *.* TO 'manager'@'%' WITH GRANT OPTION;을 주면 root처럼 모든 권한을 가진 관리자 계정이 돼요. 지금 접속한 사용자는 SELECT user();로 확인해요.

    설계할 때 팁

    교수님은 이름 · 별칭처럼 바뀔 수 있는 값 대신, 바뀌지 않는 아이디를 따로 만들어 키로 쓰는 경우가 많다고 했어요. 3장의 "기본키는 안 바뀌는 것으로"와 같은 얘기예요. 또 요즘은 AI가 SQL을 대신 써 주다 보니 스키마를 직접 그려 보지 않는 학생이 많은데, 백엔드로 일하려면 데이터 스키마를 그릴 줄 아는 게 중요하다고 강조했어요.

    TEXT 길이

    교재 표에서 TEXT는 "긴 문자열(255자 이상)"이에요. VARCHAR로 담기 어려운 긴 글에 써요.
