장면 1

정수가 들어가야 할 칸에 글자가 들어가면 뭐가 문제일까?

데이터 무결성 · 구현 방법 2가지

학년 칸에 숫자 대신 "이학년"이라는 글자가 들어가 있다고 해 봐요. 나중에 "2학년 평균 학점"을 계산하려고 하면 계산이 깨지죠. 원하는 형태의 값이 정확히 들어가 있어야 가공할 수 있어요.

이렇게 데이터의 일관성과 정확성이 손상되지 않게 유지되는 것을 데이터 무결성이라고 해요. 그걸 지키기 위해 거는 규칙이 무결성 제약조건이고요.

헷갈리지 말기 — 정보보호 수업의 "무결성"은 위·변조가 없다는 뜻이에요(비밀번호가 몰래 바뀌면 안 된다). DB에서 말하는 무결성은 원하는 값이 정확하게 들어가 있다는 쪽이라 관점이 조금 달라요.

무결성은 누가 지켜야 할까?

  • 방법 1: 응용 프로그램 코드로 — 프로그램마다 검사 코드를 넣어요. 조건이 바뀔 때마다 코드를 다 고쳐야 하고, 담당자(사수)가 나가 버리면 아무도 몰라요. 부담스럽고 비효율적이에요.
  • 방법 2: DBMS에 제약조건 설정 — 제약조건만 선언하면 DBMS가 입력·수정·삭제할 때마다 자동으로 검사해 줘요. 대신 DBMS 라이선스 비용이 들어요.

당연히 방법 2가 정답이에요.

교수
응용 프로그램에서 개발해야 할 내용을 DBMS가 대신 해 주는 거다, 정도만 이해하시면 됩니다. 요즘은 AI가 테이블을 만들어 주기도 하는데, 그 대신 개념은 있어야 돼요. 나온 결과가 맞는지 판단하고 테스트할 수 있어야 하니까요.9/22 강의 중 (말을 조금 다듬음)

데이터 무결성 = 데이터의 일관성과 정확성이 손상되지 않게 유지되는 특성. 구현은 코드가 아니라 DBMS 제약조건 설정으로(자동 검사).

외우는 법: 코드는 부담, DBMS는 자동
바로 확인

DBMS가 자동 검사해 주니까 프로그램마다 코드를 넣고 고칠 부담이 없어요. 라이선스 비용은 들어요.

장면 2

학번이 빈 학생, 없는 학번을 가리키는 수강 기록. 둘 다 안 될까?

개체 무결성 · 참조 무결성

개체 무결성 — 기본키 지키기

기본키는 투플 하나하나를 구별하는 식별자예요. 학번이 비어 있으면 그 학생을 다른 학생과 구별할 수가 없죠. 그래서 기본키는 널(NULL)을 가질 수 없고, 중복도 안 돼요. 이게 개체 무결성 제약조건(= 기본키 제약조건)이에요.

참조 무결성 — 외래키 지키기

외래키는 다른 테이블의 기본키를 가리키는 참조자예요. 그래서 외래키 값은 참조하는 기본키에 실제로 있는 값이거나, 널이어야 해요. 학생 테이블에 없는 학번 s999를 수강 테이블에 넣으면 "없는 사람"을 가리키는 거라 안 돼요.

그런데 외래키는 왜 널이 될까요? 널은 0이나 빈칸이 아니라 "아직 모르는 값"이에요. 아직 어느 학과인지 정해지지 않은 상태는 있을 수 있잖아요. 없는 곳을 가리키는 건 안 되지만, 아직 안 가리키는 건 괜찮아요.

상황결과이유
학생.학번(PK) = NULL✗개체 무결성 위반
학생.학번(PK)이 두 명 똑같이 s001✗개체 무결성 위반 (중복)
수강.학번(FK) = 's999' (학생에 없음)✗참조 무결성 위반
수강.학번(FK) = NULL○ 허용아직 모르는 값
시험엔 이렇게

개체 무결성 = 기본키는 널 불가 + 유일. 참조 무결성 = 외래키는 참조하는 기본키 값이거나 널.

외우는 법: PK = 신분증 (비면 안 됨) · FK = 손가락 (허공은 OK, 없는 사람은 ✗)
✗ 헷갈리는 생각외래키도 키니까 널을 가질 수 없다
○ 맞는 생각널 불가는 기본키만. 외래키는 널 허용
바로 확인
수강 테이블에 학번 's999'를 넣었는데 학생 테이블에 s999가 없다. 무엇을 위반했나?
외래키가 없는 기본키를 가리키면 참조 무결성 위반이에요.

장면 3

나이는 18~100만, 이메일은 겹치면 안 되고, 상태는 기본이 "재학"

도메인 무결성 · 유일성 제약조건

교수님이 수업에서 직접 보여 준 학생 테이블 설계예요. 칸마다 어떤 규칙이 걸려 있는지 봅시다.

학생 테이블 설계 (교수님 예시)학번    PRIMARY KEY          -- 개체 무결성
이름    NOT NULL             -- 도메인: 비면 안 됨
이메일  UNIQUE               -- 유일성: 겹치면 안 됨
나이    CHECK (18 ~ 100)     -- 도메인: 범위
상태    DEFAULT '재학'       -- 도메인: 안 넣으면 '재학'
학과ID  FOREIGN KEY → 학과   -- 참조 무결성
  • NOT NULL이 칸은 꼭 채워야 해요. 이름이 빠지면 입력 안 됨.
  • CHECK값의 범위를 검사해요. 해수욕장 입장을 24~32도일 때만 허용하는 것처럼요.
  • DEFAULT입력 안 하면 들어가는 기본값. 웹사이트 입력란에 회색으로 미리 적혀 있는 그거예요.
  • UNIQUE기본키는 아니지만 겹치면 안 되는 값. 이메일, 아이디 같은 것. 대체키와 관련 있어요.

정리하면, 속성 값이 그 속성의 도메인(허용 범위)에 속해야 한다는 게 도메인 무결성이고 타입 · NOT NULL · DEFAULT · CHECK가 여기 속해요. 키가 아닌 속성의 중복을 막는 게 유일성 제약조건(= 키 제약조건, UNIQUE)이에요.

시험엔 이렇게

무결성 제약조건 4가지 = 기본: 개체(PK) · 참조(FK) / 추가: 도메인(타입·NOT NULL·DEFAULT·CHECK) · 유일성(UNIQUE)

외우는 법: 개 · 참 · 도 · 유 ("개참도유", 앞의 둘이 핵심)
바로 확인
이메일은 기본키가 아니지만 중복되면 안 된다. 어떤 설정?
키가 아닌 속성의 중복을 막는 건 UNIQUE예요.

장면 4

"2026년 휴학생 명단 줘"를 DB는 어떻게 알아들을까?

관계 연산 · 관계 대수 vs 관계 해석

릴레이션(테이블)에서 원하는 데이터를 꺼내려면 "명령"이 필요해요. 그 명령의 표준이 SQL이고, SQL 뒤에서 돌아가는 수학 이론이 관계 연산이에요. 관계 연산을 표현하는 방법은 두 가지예요.

관계 대수관계 해석
무엇을 쓰나어떻게 얻을지 연산 순서무엇을 원하는지 결과만
성격절차적선언적 (비절차적)
예학생 테이블에서 학과 조건으로 고르고 → 이름 열만 뽑아라"AI소프트웨어 학과 2학년 명단"

둘의 표현력은 똑같아요. 그리고 둘 다 수학적인 형식 언어라서 MySQL 같은 DBMS가 직접 실행하지는 않아요. SQL을 만드는 방법과 DBMS 내부 처리·최적화의 이론적 기반이 된 알고리즘이라고 이해하면 돼요. C로 치면 컴파일러가 뒤에서 하는 일 같은 거예요.

관계 대수의 연산 종류

  • 집합 연산: 합집합 ∪ · 교집합 ∩ · 차집합 − · 카티션 프로덕트 × (오늘, 장면 5)
  • 순수 관계 연산: 셀렉트 σ · 프로젝트 π · 조인 ⋈ · 디비전 ÷ (다음 시간)
  • 확장 연산: 세미 조인, 외부 조인 등

중요한 성질 하나: 관계 대수는 입력도 릴레이션, 결과도 새로운 릴레이션이에요. 표 두 개를 넣으면 표 하나가 나와요.

시험엔 이렇게

관계 대수 = 연산 순서를 명세하는 절차적 언어. 관계 해석 = 결과만 명세하는 선언적 언어. 표현력 동등, 둘 다 SQL의 이론적 기반(DBMS가 직접 지원 ✗).

외우는 법: 대수는 절차(레시피), 해석은 선언(주문)
바로 확인
"결과만 말하고 과정은 DBMS에 맡긴다"는 방식은?
무엇을 원하는지만 선언하면 관계 해석. 식당에서 메뉴만 주문하는 것과 같아요.

장면 5

두 명단을 합치면 몇 줄? 곱하면 몇 줄?

집합 연산 ∪ ∩ − × · 합병 가능 조건 · 차수와 카디널리티

먼저, 합칠 수 있는 모양인지 확인 (합병 가능 조건)

∪ ∩ −는 두 표의 투플을 섞는 연산이라 두 표의 모양이 같아야 해요. 차수(속성 수)가 같고, 서로 대응하는 속성의 도메인이 같아야 하죠. 한쪽 학년은 숫자, 다른 쪽 학년은 문자면 안 돼요.

단, ×(카티션 프로덕트)만 예외예요. ×는 투플을 옆으로 이어 붙이는 거라 모양이 달라도 돼요.

교수님 예제로 직접 세어 보기

R1 (학번, 이름)R2 (학번, 이름)
s001 김연아s001 김연아
s002 홍길동s002 홍길동
s003 이승엽s004 이영애
s005 송윤아
  • R1 ∪ R2다 합치되 겹치는 건 한 번만 → 3 + 4 − 2 = 5줄. 그래서 항상 "두 카디널리티의 합 이하"예요. (SQL에서 중복까지 남기려면 UNION ALL)
  • R1 ∩ R2둘 다에 있는 것만 → 김연아, 홍길동 = 2줄. 작은 쪽 이하.
  • R1 − R2R1에만 있는 것 → 이승엽 = 1줄. 반대로 R2 − R1은 이영애, 송윤아 = 2줄. 왼쪽이 기준이라 순서가 중요해요.
  • R1 × R2R1의 각 줄에 R2의 모든 줄을 붙임 → 3 × 4 = 12줄, 차수는 2 + 2 = 4. 결과가 너무 커져서 실무에선 잘 안 써요.
연산합병 조건결과 차수결과 카디널리티
R1 ∪ R2필요그대로≤ |R1| + |R2|
R1 ∩ R2필요그대로≤ 작은 쪽
R1 − R2필요그대로≤ |R1| (왼쪽)
R1 × R2불필요더하기곱하기
시험엔 이렇게

∪ ∩ −는 합병 가능(차수·도메인 같음)해야 하고 차수는 그대로. ×는 조건 없이 차수는 더하고 카디널리티는 곱한다.

외우는 법: 합 ≤ 더하기 · 교 ≤ 작은 쪽 · 차 ≤ 왼쪽 · 곱은 곱
바로 확인
학생(학번, 이름, 학년)과 수강(학번, 과목번호, 평가학점, 점수)에 바로 할 수 있는 연산은?
차수가 3과 4로 달라서 ∪ ∩ −는 불가. ×는 합병 조건이 필요 없어서 가능하고, 결과 차수는 7이에요.

① 무결성 제약조건 4 ★개·참·도·유

  • 개체 = PK 널 ✗ · 중복 ✗ (식별자)
  • 참조 = FK는 참조하는 PK 값 or 널 (참조자)
  • 도메인 = 타입 · NOT NULL · DEFAULT · CHECK / 유일성 = UNIQUE
  • 구현: 코드 ✗ 부담 → DBMS 설정 = 자동 검사

② 널

  • 널 = 0 · 빈칸 아님 → 아직 모르는 값

③ 관계 연산 대수 = 절차 · 해석 = 선언

  • 관계 대수 = 절차적 / 관계 해석 = 선언적 · 표현력 동등
  • 둘 다 SQL 아님 → SQL · 최적화의 이론적 기반 · 입력도 결과도 릴레이션
  • 집합 ∪ ∩ − × / 순수 관계 σ π ⋈ ÷ / 확장

④ 집합 연산 결과 ★ 계산곱은 곱

  • ∪ ∩ − → 합병 가능 필요 (차수 · 도메인 같음) / × 불필요
  • ∪ ≤ 합 · ∩ ≤ 작은 쪽 · − ≤ 왼쪽 (순서 중요)

빈칸 채우기 눌러서 정답 확인

기본키는 널을 가질 수 없고 유일해야 한다는 것은 개체 무결성, 외래키는 참조하는 기본키 값이나 널만 가져야 한다는 것은 참조 무결성이다. NOT NULL · DEFAULT · CHECK는 도메인 무결성, UNIQUE는 유일성 제약조건이다. 관계 대수는 절차적, 관계 해석은 선언적 표현이다. R1 × R2의 카디널리티는 두 카디널리티의 곱이다.

데이터 무결성이란?
데이터의 일관성과 정확성이 손상되지 않게 유지되는 특성.
무결성 제약조건 4가지는?
기본: 개체 · 참조 / 추가: 도메인 · 유일성
개체 무결성은?
기본키는 널 불가, 릴레이션 안에서 유일. (기본키 제약조건)
참조 무결성은?
외래키는 참조하는 기본키에 있는 값이거나 널만 가진다. (외래키 제약조건)
도메인 무결성의 SQL 키워드는?
타입, NULL / NOT NULL, DEFAULT, CHECK
유일성 제약조건의 키워드는?
UNIQUE (키 제약조건, 대체키와 관련)
널의 의미는?
0이나 빈칸이 아니라 아직 모르는 값.
관계 대수와 관계 해석의 차이는?
대수 = 연산 순서를 명세(절차적). 해석 = 결과만 명세(선언적). 표현력은 동등.
합병 가능 조건은? 어떤 연산에 필요?
차수가 같고 대응 속성의 도메인이 같을 것. ∪ ∩ −에 필요, ×는 불필요.
R1 × R2의 차수와 카디널리티는?
차수 = 두 차수의 합, 카디널리티 = 두 카디널리티의 곱.

    퀴즈 다 풀고 채점하기

    Q1학생 테이블의 학번(기본키)을 비워 둔 채 입력했다. 위반한 것은?

    기본키는 널 불가(개체 무결성). 외래키였다면 널이 허용돼요.

    Q2나이를 18~100 사이로만 받게 하는 CHECK는 어떤 제약조건?

    값이 허용 범위(도메인)에 있어야 한다는 제약. 타입·NOT NULL·DEFAULT·CHECK 전부 도메인 무결성.

    Q3카디널리티 5인 R1과 8인 R2(합병 가능)에 대해 항상 성립하는 것은?

    교집합은 작은 쪽(5) 이하. 합집합은 13 "이하", R1 − R2는 5 이하, 곱은 40.

    Q4R1(차수 3, 투플 3)과 R2(차수 3, 투플 4)의 R1 × R2 결과는?

    ×는 차수 더하기(3 + 3 = 6), 카디널리티 곱하기(3 × 4 = 12).

    Q5관계 대수에 대한 설명으로 옳은 것은?

    결과만 명세하는 건 관계 해석. 표현력은 동등하고, 둘 다 DBMS가 직접 실행하지 않아요.

    Q6R1 − R2와 R2 − R1에 대한 설명으로 옳은 것은?

    차집합은 왼쪽에만 있는 투플. 순서를 바꾸면 결과가 달라져요.

    Q7두 릴레이션에 똑같은 투플이 1개 있을 때 합집합 결과에서 그 투플은?

    릴레이션은 집합이라 중복은 한 번만. 중복까지 남기려면 SQL의 UNION ALL.

    내 말로 설명하기 친구한테 말하듯이

    기본키는 널이 안 되는데 외래키는 왜 널이 될까요? "식별자"와 "참조자"라는 말을 써서 설명해 보세요.

    기본키는 투플 하나하나를 구별하는 식별자예요. 학번이 비어 있으면 그 학생을 다른 학생과 구별할 수 없으니까 널도 안 되고 중복도 안 돼요(개체 무결성). 외래키는 다른 테이블의 기본키를 가리키는 참조자예요. 없는 대상을 가리키면 안 되지만, 아직 어디를 가리킬지 모르는 상태(널)는 괜찮아요(참조 무결성). 널은 0이 아니라 "아직 모르는 값"이에요.
