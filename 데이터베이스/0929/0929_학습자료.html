장면 1

"4학년 학생의 이름만 보여 줘"를 식으로 쓰면?

셀렉트 σ · 프로젝트 π

지난 시간의 집합 연산(∪ ∩ − ×)은 릴레이션을 통째로 다뤘어요. 오늘의 관계 연산은 릴레이션 안의 행과 열을 하나하나 골라낼 수 있어요. 그중 제일 많이 쓰는 게 이 두 개고, 거의 항상 짝으로 움직여요.

  • 셀렉트 σ (시그마) — 조건에 맞는 행(투플)만 고른다. 표를 가로로 자르는 "수평 분할". 조건식에는 =, ≠, <, > 같은 비교 연산자와 ∧(AND), ∨(OR), ¬(NOT)이 들어가요.
  • 프로젝트 π (파이) — 지정한 열(속성)만 고른다. 세로로 자르는 "수직 분할". 조건이 아니라 속성 이름 목록을 줘요.
"4학년 학생의 이름"σ 학년=4 (학생)              -- ① 4학년 행만 남기고
π 이름 ( σ 학년=4 (학생) )    -- ② 그중 이름 열만

안쪽에서 σ로 행을 줄이고, 바깥에서 π로 열을 고르는 모양이에요. 안에서 밖으로 읽으면 돼요.

π의 숨은 성질: 중복 제거

학생 7명 표에서 π 학년 (학생)을 하면 몇 줄이 나올까요? 7줄이 아니에요. 학년 값은 1~4뿐이고, 릴레이션은 집합이라 똑같은 투플은 자동으로 하나만 남아요. 그래서 많아야 4줄. π 결과의 카디널리티는 원본보다 작거나 같아요.

✗ 이름 때문에 헷갈림σ(셀렉트) = SQL의 SELECT 절
○ 실제 대응σ는 SQL의 WHERE(행 조건). SELECT 뒤의 열 목록이 π
시험엔 이렇게

σ = 조건에 맞는 투플(수평 분할). π = 지정한 속성(수직 분할, 중복 투플 자동 제거).

외우는 법: σ 시그마 = 시(행) · π 파이 = 파(열) — "시행 파열"

행 조건(학년·성별)은 σ, 열 선택(이름·학과)은 π. 안쪽 σ로 줄이고 바깥 π로 골라요.

학생 표와 수강 표를 학번으로 붙였더니, 학번이 두 번 나온다?

조인 ⋈ · 세타 ⊃ 동등 ⊃ 자연

조인 ⋈은 두 릴레이션에서 조건에 맞는 투플끼리 옆으로 붙여 하나로 만드는 연산이에요. 수학적으로는 × 한 다음 σ 한 것과 같아요. 모든 조합을 만든 뒤 조건에 맞는 것만 남기는 거죠. 그런데 ×는 결과가 너무 커서, 처음부터 조건에 맞는 것만 붙이는 조인이 훨씬 효율적이에요.

학생 ⋈ 학생.학번 = 수강.학번 수강 (동등 조인) — 학번 열이 두 번
학생.학번이름수강.학번과목번호
s001김연아s001c002
s002홍길동s002c001
  1. 세타 조인 — 조건에 비교 연산자 6개(=, ≠, <, ≤, >, ≥) 중 아무거나. 교수님: "잊어버려도 된다."
  2. 동등 조인 — 그중 =만 쓰는 조인. 보통 "조인"이라고 하면 이거예요. 단점: 위 표처럼 같은 학번 열이 두 번 나와요.
  3. 자연 조인 (⋈N) — 동등 조인 결과에서 중복 속성을 자동으로 제거. 학번이 한 번만 나와요. 가장 많이 쓰는 방식이에요.
교수

"137호에서 열리는 모든 과목을 수강한 학생"은 어떻게 찾을까?

디비전 ÷ · 기본 연산 5 · 복합 연산 3

문제에 "모든 ~을"이 보이면 디비전 ÷을 떠올리면 돼요. R1 ÷ R2는 R2의 모든 투플과 연관된 R1 투플을 찾아서, R2의 속성을 뺀 나머지만 돌려줘요. 나눗셈이랑 개념이 비슷해요.

c001과 c002를 둘 다 수강한 학생수강(학번, 과목번호) ÷ 과목(과목번호 = {c001, c002})
-- 결과: 두 과목을 모두 들은 학번만 남는다

기본 연산과 복합 연산

지금까지 나온 연산 8개를 둘로 나눌 수 있어요.

  • 기본 연산 5개 — ∪ 합집합 · − 차집합 · × 카티션 프로덕트 · σ 셀렉트 · π 프로젝트. 다른 연산으로 대체할 수 없어요.
  • 복합 연산 3개 — ∩ 교집합 · ⋈ 조인 · ÷ 디비전. 기본 연산을 조합해서 만들 수 있어요.
복합 연산을 기본 연산으로 바꾸면R ∩ S  =  R − (R − S)      -- 차집합 두 번
R ⋈ S  =  σ 조건 (R × S)    -- 곱한 뒤 고르기

수강 기록이 없는 학생도 명단에서 빠지면 안 된다면?

확장 연산: 세미 조인 · 외부 조인 · 외부 합집합

자연 조인은 깔끔하지만 두 가지 아쉬움이 있어요. ① 필요 없는 열까지 다 붙어 온다 ② 짝이 없는 투플은 빠져 버린다. 이걸 해결하려고 나온 게 확장 연산이에요. 방향이 정반대인 두 개를 기억하세요.

  • 세미 조인 (⋉ ⋊) — 자연 조인 결과에서 한쪽 릴레이션의 속성만 돌려줘요. 보내는 데이터 양이 줄어서 연산이 가벼워져요. → 줄이기
  • 외부 조인 (⟗ ⟕ ⟖) — 조인에 실패한 투플도 버리지 않고, 비는 칸은 널로 채워 포함해요. → 늘리기. 실무에서는 데이터를 빠뜨리지 않으려고 이걸 많이 써요.

학생 {s001 김연아, s002 홍길동, s003 이승엽}, 수강 {s001 c002, s002 c001, s004 c003}

학번이 짝이 맞는 건 s001, s002뿐이에요. s003은 수강 기록이 없고, s004는 학생 명단에 없어요.

하나 더, 외부 합집합은 모양이 일부만 같은 두 릴레이션을 널로 채워 합쳐요. 학부생 표와 지도교수 칸이 있는 대학원생 표를 한 표로 합치는 경우처럼요.

시험 문제: 두 질의 트리 중 어느 쪽이 빠르고, 왜?

질의 트리 · 질의 최적화

우리가 SQL을 쓰면 DBMS는 그걸 관계 대수식으로 바꾸고 → 질의 트리로 그린 뒤 → 가장 빠른 순서를 골라 → 실행해요. SQL은 "무엇을"만 말하니까, "어떤 순서로"는 DBMS가 정하는 거죠. 같은 결과라도 순서에 따라 속도가 크게 달라요. Oracle과 MySQL의 성능 차이도 여기서 나요.

질의: "김연아 학생이 수강한 과목번호와 평가학점"

교수님이 수업에서 그려 준 두 트리예요. 트리는 아래에서 위로 실행돼요.

답은 B예요. A는 학생과 수강의 모든 조합을 먼저 만들어요. 학생 1,000명, 수강 기록 10,000건이면 1,000만 줄을 만든 다음에야 김연아를 찾죠. B는 학생 표에서 김연아 1명을 먼저 고른 뒤 조인하니까 처음부터 다룰 양이 아주 적어요.

교수

최적화 규칙 (DBMS가 트리를 바꾸는 방법)

  • σ와 π는 트리 아래쪽으로 내려서 먼저 실행 (가장 중요)
  • 결과가 작아지는 σ부터 먼저
  • × 와 바로 위 σ는 조인 하나로 합치기
  • AND로 묶인 σ는 따로따로 쪼개기, OR는 AND로 바꾸기
시험엔 이렇게

질의 최적화의 핵심 = 연산 순서를 조정해 중간 릴레이션의 크기를 최소화. 셀렉트를 먼저 하는 트리가 효율적이다(처음부터 투플 수가 줄어서).

외우는 법: 먼저 고르고 → 줄이고 → 붙인다

  • 김연아 예: σ 이름='김연아'(학생) 먼저 → 조인 → π

빈칸 채우기 눌러서 정답 확인

셀렉트 연산자는 σ로 릴레이션을 수평 분할하고, 프로젝트 연산자는 π로 수직 분할한다. 비교 연산자 '='를 쓰는 조인은 동등 조인, 그 결과에서 중복 속성을 제거하면 자연 조인이다. 조인에 실패한 투플까지 널로 채워 포함하는 것은 외부 조인이다. 질의 최적화의 핵심은 중간 릴레이션의 크기를 최소화하는 것이며, 이를 위해 셀렉트를 먼저 실행한다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
집합 연산과 관계 연산의 차이는?
집합 연산은 릴레이션을 통째로 다룸. 관계 연산은 행과 열을 개별적으로 조작.
셀렉트 σ는?
조건식을 만족하는 투플만 추출. 수평 분할. SQL의 WHERE.
프로젝트 π는?
지정한 속성만 추출. 수직 분할. 중복 투플 자동 제거.
조인을 기본 연산으로 표현하면?
× 한 뒤 σ. R ⋈ S = σ 조건 (R × S)
동등 조인과 자연 조인의 차이는?
동등 = '=' 조건, 공통 속성이 두 번. 자연 = 동등 결과에서 중복 속성 제거, 한 번.
디비전 R1 ÷ R2는?
R2의 모든 투플과 연관된 R1 투플에서 R2 속성을 뺀 나머지. "모든 ~을 가진".
기본 연산 5개와 복합 연산 3개는?
기본: ∪ − × σ π / 복합: ∩ ⋈ ÷
세미 조인은?
자연 조인 결과 중 한쪽 릴레이션 속성만 반환. 데이터 양을 줄인다.
외부 조인 3종류는?
완전 ⟗(양쪽 전부) · 왼쪽 ⟕(왼쪽 전부) · 오른쪽 ⟖(오른쪽 전부). 짝 없으면 널.
DBMS가 SQL을 처리하는 흐름은?
SQL → 관계 대수식 → 질의 트리 → 최적화 → 질의 실행 계획 → 실행
질의 최적화의 핵심은?
연산 순서를 조정해 중간 릴레이션의 크기를 최소화. σ·π를 먼저(트리 아래로).

    퀴즈 다 풀고 채점하기

    Q1학생 릴레이션에서 4학년 학생의 이름만 구하는 식은?

    행 조건은 σ, 열 선택은 π. 안쪽 σ로 줄이고 바깥 π로 골라요.

    Q2학생 7명, 학년 값이 1~4인 학생 릴레이션에서 π 학년(학생)의 카디널리티는?

    π는 중복 투플을 제거해요. 학년 값이 1~4뿐이라 많아야 4줄.

    Q3질의 트리 최적화 규칙으로 옳지 않은 것은?

    ×는 중간 결과를 가장 크게 만들어요. 먼저 하는 건 σ·π.

    Q4학생 {s001, s002, s003}과 수강 {s001, s002, s004}를 학번으로 완전 외부 조인하면 투플 수는?

    짝 맞는 s001, s002 + 학생에만 있는 s003 + 수강에만 있는 s004 = 4. 비는 칸은 널.

    Q5"과목 릴레이션의 모든 과목을 수강한 학생"을 찾는 연산은?

    "모든 ~을 가진" = 디비전. 수강(학번, 과목번호) ÷ 과목(과목번호).

    Q6세미 조인을 쓰는 이점으로 가장 알맞은 것은?

    보존 = 외부 조인, 합병 불가 결합 = 외부 합집합, 모든 조합 = ×. 세미는 줄이기.

    Q7"김연아가 수강한 과목번호와 평가학점"에서 더 효율적인 트리와 이유는?

    결과는 같아도 순서에 따라 중간 크기가 달라요. 셀렉트를 먼저 하면 처음부터 투플 수가 줄어요.

    내 말로 설명하기 시험 서술형 연습

    같은 결과를 내는 두 질의 트리 중, 셀렉트를 먼저 하는 쪽이 왜 빠른지 설명해 보세요.

    SQL은 무엇을 원하는지만 쓰고 순서는 쓰지 않아서, DBMS가 관계 대수식과 질의 트리로 바꿔 순서를 정해요. 같은 결과라도 순서에 따라 중간 릴레이션의 크기가 크게 달라요. 학생과 수강을 먼저 곱하면 학생 수 × 수강 수만큼의 투플을 만든 뒤에야 김연아를 골라요. 반면 학생에서 김연아를 먼저 고르면(셀렉트를 트리 아래로) 투플이 1개로 줄어든 상태에서 조인하니까 처리할 양이 훨씬 적어요. 그래서 질의 최적화의 핵심은 연산 순서를 조정해 중간 결과를 최소화하는 거예요.
