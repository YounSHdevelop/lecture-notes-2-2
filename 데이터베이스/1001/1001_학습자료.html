Oracle에서 쓰던 SQL을 MySQL에서도 쓸 수 있는 이유는?

SQL = 관계형 DB의 표준 언어

SQL은 관계형 데이터베이스와 대화하기 위한 표준 언어예요. IBM 연구소의 실험용 DBMS인 SYSTEM R에서 처음 만들어졌고, 이후 ANSI와 ISO가 표준으로 정했어요.

왜 표준이 필요했을까요? 회사마다 DB와 말하는 방법이 다 다르면, 프로그램을 만들 때마다 따로따로 개발해야 하잖아요. 그래서 "공통으로 쓸 수 있는 말을 정하자" 해서 표준이 생겼어요. 덕분에 Oracle, MS SQL Server, MySQL 같은 거의 모든 관계형 DBMS가 SQL을 지원해요. 다만 DBMS마다 자기만의 변형 문법을 조금씩 갖고 있어서 100% 똑같지는 않아요.

비유로 보면 — C 언어에도 ANSI C라는 표준이 있죠. 컴파일러 회사가 달라도 표준 문법으로 쓴 코드는 대부분 돌아가요. SQL도 똑같아요.

그리고 지난주까지 배운 관계 대수 · 관계 해석이 바로 SQL의 이론적 배경이에요. SQL을 치면 DBMS 안에서는 관계 대수식으로 바뀌어 처리되거든요(9/29 질의 최적화).

교수
SQL을 쓸 때 관계 대수를 모르고 찾는 것과 관계 대수를 알고 찾는 것은 다릅니다. 그래서 1장부터 4장까지가 여러분이 SQL을 배우기 위한 기본기였던 거예요.10/1 강의 중 (말을 조금 다듬음)

SQL 부속 언어 (9/10 복습)

9/10에 배운 데이터 언어 세 가지가 그대로 SQL의 부속 언어예요. 한 번 더 확실히 잡고 가요.

부속 언어하는 일대표 명령누가 많이 쓰나
DDL 정의어테이블 같은 구조(틀)를 만들고 바꾸고 지움CREATE · ALTER · DROP개발자 (두 번째로 많이)
DML 조작어틀 안의 데이터를 검색 · 삽입 · 수정 · 삭제SELECT · INSERT · UPDATE · DELETE개발자가 가장 많이
DCL 제어어권한 · 보안 · 접근 제어, 사용자 등록, 백업GRANT · REVOKE관리자(admin)

TCL(COMMIT · ROLLBACK 등)도 있지만, 시험에는 안 나와요.

✗ 자주 틀리는 것SELECT는 "선택"이니까 DDL이다
○ 맞게 구별SELECT는 데이터를 검색하는 거라 DML. DDL은 CREATE · ALTER · DROP뿐
시험엔 이렇게

DDL = CREATE · ALTER · DROP (구조). DML = SELECT · INSERT · UPDATE · DELETE (데이터). DCL = GRANT · REVOKE (권한).

외우는 법: 틀은 DDL · 값은 DML · 권한은 DCL
바로 확인
CREATE TABLE · INSERT · SELECT · GRANT · DROP DATABASE · UPDATE 중 DML만 모은 것은?
데이터를 넣고 · 찾고 · 고치는 INSERT · SELECT · UPDATE가 DML. CREATE · DROP은 DDL, GRANT는 DCL.

학생이 여러 과목을 들으면, 그 정보는 어디에 넣을까?

univDB: 학생 · 과목 · 수강

앞으로 실습에서 계속 쓸 데이터베이스 univDB에는 테이블이 3개 있어요.

univDB 스키마 (밑줄 대신 PK 표시)학생( 학번 PK, 이름, 주소, 학년, 나이, 성별, 휴대폰번호, 소속학과 )
과목( 과목번호 PK, 이름, 강의실, 개설학과, 시수 )
수강( 학번 + 과목번호 PK, 신청날짜, 중간성적, 기말성적, 평가학점 )
       └ 학번 → 학생.학번 (FK)   과목번호 → 과목.과목번호 (FK)

왜 수강을 따로 만들었을까요? 학생 한 명이 여러 과목을 듣잖아요. 학생 테이블 한 칸에 과목 여러 개를 넣으면 속성 원자성(한 칸에 값 하나)을 어기게 되고, 과목 수만큼 학생 줄을 복사하면 중복이 생겨요. 그래서 "누가 무엇을 들었나"만 담는 수강 테이블을 따로 만들고 키로 연결해요.

수강 테이블의 학번과 과목번호는 둘을 합쳐서 기본키이면서, 각각은 외래키예요. 학생 한 명이 여러 과목을 들으니 학번만으론 유일하지 않거든요. 교수님 말대로 이 구조만 이해하면 나중에 ERD 그릴 때 손쉽게 그릴 수 있어요.

시험엔 이렇게

수강의 (학번, 과목번호)는 기본키이면서 각각 학생 · 과목을 참조하는 외래키. 학생 1 : 수강 N, 과목 1 : 수강 N.

외우는 법: 가리키는 쪽이 N (손가락이 여러 개)
바로 확인
학생과 수강의 관계에서 N은 어느 쪽?
학생 1명에 수강 기록이 여러 개. 외래키를 가진 수강이 N이에요.

9/22에 배운 무결성이 실제 코드로는 이렇게 생겼다

ex01.sql · CREATE TABLE · INSERT

수업 실습 파일 ex01.sql의 학생 테이블이에요. 한 줄에 제약조건이 하나씩 붙어 있어요. 타입 → 널 허용 → 기본값 → 키 순서로 읽으면 쉬워요.

ex01.sqlCREATE TABLE 학생(
    학번       CHAR(4)     NOT NULL,
    이름       VARCHAR(20) NOT NULL,
    주소       VARCHAR(50) NULL DEFAULT '미정',
    학년       INT         NOT NULL,
    나이       INT         NULL,
    성별       CHAR(1)     NOT NULL,
    휴대폰번호 CHAR(14)    NULL,
    소속학과   VARCHAR(20) NULL,
    PRIMARY KEY (학번)
);
  • CHAR(4)정확히 4글자 문자열 (s001). VARCHAR(20)은 최대 20글자.
  • NOT NULL꼭 채워야 함 → 도메인 무결성. 학년을 비우면 입력 거부.
  • NULL DEFAULT '미정'비워도 되고, 값을 안 주면 '미정'이 들어감.
  • PRIMARY KEY (학번)학번이 기본키 → 개체 무결성. 같은 학번을 또 넣으면 오류.

DEFAULT와 NULL은 다르다

ex01.sql 중 두 줄INSERT INTO 학생 VALUES ('s002', '홍길동', DEFAULT, 1, 26, '남', NULL, '통계');
-- 주소 = '미정' (정해 둔 기본값)
INSERT INTO 학생 VALUES ('s003', '이승엽', NULL, 3, 30, '남', NULL, '정보통신');
-- 주소 = NULL (아직 모름)

DEFAULT라고 쓰면 정해 둔 기본값('미정')이 들어가고, NULL이라고 직접 쓰면 "모름"으로 저장돼요.

교수
휴대폰이 두 개면 휴대폰1, 휴대폰2 이렇게 늘리고, 이메일도 이메일1, 이메일2로 늘리면 돼요. 추가는 될 수 있으나 프라이머리 키는 바뀌면 안 된다. 이것만 생각하시면 나중에 큰 문제가 없습니다.10/1 강의 중 (말을 조금 다듬음)
시험엔 이렇게

NOT NULL · DEFAULT = 도메인 무결성, PRIMARY KEY = 개체 무결성. INSERT에서 DEFAULT → 기본값, NULL → 널 저장.

외우는 법: 타입 · 널 · 기본값 · 키 순으로 한 줄씩 읽기
바로 확인
학생 테이블에 학년 값을 비워 두고 INSERT하면?
학년은 INT NOT NULL이고 DEFAULT도 없어서 값이 꼭 있어야 해요.

실습은 MySQL로 해요. 무료 커뮤니티 버전이 있고 가벼워서 공부하기 좋아요. 개인 노트북에 깔아 두면 집에서도 실습할 수 있어요. 설치할 건 두 가지예요.

  • MySQL Server — 실제 DB 엔진
  • MySQL Workbench — 엔진을 편하게 다루는 화면(툴)

교수님 경고: 학생의 약 50%가 Server와 Workbench를 따로 설치해서 연결이 안 된다

설치 때 Custom을 고르고, Server와 Workbench를 같이 선택하세요.

  1. 설치 유형에서 Custom 선택
  2. MySQL Server + MySQL Workbench를 함께 선택 (샘플 DB도 깔아 두면 좋아요)
  3. root 비밀번호 설정
  4. Workbench에서 root로 접속 → 왼쪽 창을 Administration → Schemas 탭으로 바꾸기

연결 확인SELECT VERSION(), NOW();   -- 버전과 현재 시각이 나오면 OK

문장 끝 ;는 습관적으로 붙이세요. 실행이 안 된다고 나오면 대부분 Workbench와 계정 연결 문제라 다시 로그인하면 돼요.

빈칸 채우기 눌러서 정답 확인

SQL은 IBM의 실험용 DBMS SYSTEM R에서 시작해 ANSI와 ISO 표준이 되었다. 테이블 구조를 정의하는 언어는 DDL, 데이터를 검색·삽입·수정·삭제하는 언어는 DML, 권한을 제어하는 언어는 DCL이다. univDB에서 수강의 학번은 학생을 가리키는 외래키이며, 학생과 수강은 1:N 관계다. INSERT에서 DEFAULT를 쓰면 정해 둔 기본값이 들어간다.

    퀴즈 다 풀고 채점하기

    Q1새 테이블을 만드는 CREATE TABLE은 어느 부속 언어?

    구조(테이블)를 정의하는 건 DDL.

    Q2다른 사용자에게 테이블 조회 권한을 주는 명령과 분류는?

    권한 부여는 GRANT, 회수는 REVOKE. 둘 다 DCL.

    Q3univDB의 수강 테이블에 대한 설명으로 옳은 것은?

    한 학생이 여러 과목을 들으니 학번만으론 유일하지 않아요. 둘을 합친 기본키, 각각은 외래키.

    Q4INSERT INTO 학생 VALUES ('s002', '홍길동', DEFAULT, 1, 26, '남', NULL, '통계'); 실행 후 주소와 휴대폰번호는?

    DEFAULT → 기본값 '미정', 명시적 NULL → 널. 휴대폰번호는 NULL 허용이라 오류 없음.

    Q5학번 's001'인 학생이 이미 있는데 's001'로 또 INSERT하면?

    학번은 PRIMARY KEY라 중복 불가. 개체 무결성이에요.

    Q6학생 테이블에 수강 정보를 넣지 않고 수강 테이블을 따로 만든 가장 큰 이유는?

    1:N 관계는 N쪽을 따로 테이블로 만들고 외래키로 연결해요.

    내 말로 설명하기 친구한테 말하듯이

    univDB에서 학생 · 과목 · 수강이 어떻게 연결되는지, 기본키 · 외래키 · 1:N이라는 말을 써서 설명해 보세요.

    학생 테이블은 학번, 과목 테이블은 과목번호가 기본키예요. 학생 한 명은 여러 과목을 들으니까 그 정보를 학생 테이블에 넣으면 한 칸에 여러 값이 들어가 원자성이 깨져요. 그래서 수강 테이블을 따로 만들고 (학번, 과목번호)를 합쳐 기본키로 둬요. 수강의 학번은 학생의 기본키를, 과목번호는 과목의 기본키를 가리키는 외래키라서 세 테이블이 키로 이어져요. 학생 1명에 수강 기록이 여러 개, 과목 1개에 수강 기록이 여러 개라 둘 다 1:N이고, 가리키는 쪽인 수강이 N이에요.

    질의 최적화 복습 (강의 앞부분)

    학생과 수강을 다 조인한 뒤 김연아를 고르는 것보다, 학생에서 김연아를 먼저 고르고 조인하는 쪽이 효과적이에요. 핵심은 연산 순서를 조정해 중간 릴레이션 크기를 줄이는 것이고, 이 일은 DBMS가 해요. 자세한 건 9/29 페이지.
