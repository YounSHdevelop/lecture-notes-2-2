CH01 — 데이터가 정보가 되고, 파일이 DB가 되기까지

9/3 · 9/8 수업 · 데이터와 정보 · 파일 시스템의 문제 · DB 정의와 특성

데이터와 정보

  • ★ 데이터 : 현실 세계에서 관찰·측정해 얻은 그대로의 값 (출석, 중간 80, 기말 90)
  • ★ 정보 : 데이터를 가공 처리해 의사 결정에 쓸 수 있게 만든 결과 ("A+" 판정)
  • 정보 시스템 : 데이터를 가공 처리(P)해 정보(I)를 만드는 시스템. I = P(D)
  • 정보의 연쇄 : 만들어진 정보는 다른 시스템의 입력 데이터가 된다. I = P(P(P(D)))

파일 시스템이 DB가 된 이유

  • ★ 종속성 : 프로그램이 파일 구조에 묶여, 파일 하나를 바꾸면 그 파일을 쓰는 프로그램을 다 고쳐야 하는 문제 (전통 파일 시스템)
  • ★ 중복성 : 프로그램마다 파일을 나눴더니 같은 데이터가 여러 파일에 생기는 문제 (개선 1)
  • ★ 공유 한계 : 파일을 하나로 합쳤더니 여러 명이 동시에 못 쓰고 회복도 안 되는 문제 (개선 2)
  • ★ DB 시스템 : 파일을 DBMS라는 보호 장치로 감싸 모든 접근을 DBMS를 통해서만 하게 한 시스템. 동시성·권한·회복 해결
  • 종속성의 해결책 : 공통 데이터 모델 + 표준 데이터 언어
  • 중복성의 해결책 : 통합 저장소 (이 짝을 바꿔 쓰는 실수가 많아요)

DB의 정의 · 특성 · 단점

  • ★ 데이터베이스 : 공용 · 통합 · 운영 · 저장 데이터의 저장소 (공 · 통 · 운 · 저)
  • 공용 데이터 : 여러 사용자가 함께 쓰는 데이터. 혼자만 쓰면 공용이 아니다
  • 통합 데이터 : 중복을 최소화해 논리적으로 통합한 데이터. 흩어져 있어도 연결돼 있으면 통합
  • 운영 데이터 : 조직의 업무를 수행하는 데 필요한 데이터
  • 저장 데이터 : 컴퓨터 저장 장치에 저장된 데이터
  • 실시간 접근 : 요청한 데이터를 몇 초 안에 바로 돌려준다 (남은 좌석 검색)
  • 끊임없는 변화 : 데이터가 삽입·삭제·수정되며 늘 최신 상태를 유지한다
  • ★ 동시 공용 : 여러 사용자가 같은 데이터를 동시에 쓸 수 있다. 교수님이 가장 중요하다고 한 특성
  • 내용 기반 참조 : 저장 위치가 아니라 값(내용)으로 데이터를 찾는다 ("홍길동"으로 검색)
  • DB의 단점 : 개발·운영·관리 비용이 크고, 한 시스템이라 뚫리거나 고장 나면 전체가 위험하다 (시스템 취약성)
  • 넓은 의미 / 좁은 의미의 DB : 콘텐츠 모음(웹 문서, VOD) / 형식이 엄격한 DB(뱅킹, 예매). 수업은 좁은 의미
시험엔 이렇게

그대로의 값 = 데이터, 처리해서 얻은 결과 = 정보. 파일 시스템의 문제는 종속성 → 중복성 → 공유 한계 순서로 생겼고, DB 시스템은 모든 접근을 DBMS를 통해서만 하게 해 해결했다.

외우는 법: D · P · I / 종 → 중 → 공 / 공통운저 · 실변동내

CH02 — 누가, 어떤 언어로, 무엇을 거쳐 데이터에 닿나

9/10 수업 · DB · DBMS · DBS · 사용자 · 데이터 언어 · DBMS 구성 · 데이터 모델

DB · DBMS · DBS

  • ★ DB : 데이터를 모아 둔 저장소 (창고)
  • ★ DBMS : DB를 관리하는 소프트웨어 (창고지기). MySQL·Oracle은 엄밀히 DBMS. 데이터의 신뢰성과 무결성을 지키려고 생겼다
  • DBS(DB 시스템) : DB + DBMS를 합친 전체 체계
  • DBMS 필수 기능 : 정의 · 조작 · 제어 3가지
  • ★ 제어 기능 : 동시성 · 무결성 · 보안 · 회복을 맡는 기능. 셋 중 가장 중요

사용자

  • 초급 일반 사용자 : DB가 있는지도 모르고 화면(UI)만 쓰는 사람
  • 중급 일반 사용자 : SQL로 직접 조회할 줄 아는 사람
  • 응용 프로그래머 : 프로그램 코드 안에 SQL을 넣어 DB를 쓰는 사람
  • ★ DBA(DB 관리자) : 모든 권한과 최종 책임을 가진 슈퍼 사용자

데이터 언어

  • ★ DDL(정의어) : 테이블의 구조(틀)를 정의하는 언어. CREATE · ALTER · DROP. 응용 프로그래머 · DBA
  • ★ DML(조작어) : 데이터 값을 조작하는 언어. SELECT · INSERT · UPDATE · DELETE. 일반 사용자 포함 모두
  • ★ DCL(제어어) : 권한 · 보안을 제어하는 언어. GRANT · REVOKE · CREATE USER. DBA만
  • TCL : 트랜잭션을 묶는 언어. COMMIT · ROLLBACK · SAVEPOINT. 시험 안 나옴

DBMS 구성 요소 (위 그림 순서)

  • DDL 컴파일러 : DDL로 정의한 구조를 해석해 데이터 사전에 저장
  • DML 프리컴파일러 : 프로그램 코드(PHP 등) 안에서 SQL만 뽑아 먼저 해석
  • 질의 처리기 → 런타임 DB 처리기 → 트랜잭션 관리자 → 저장 데이터 관리자 : 요청이 이 순서로 내려가 실제 데이터에 닿는다
  • 데이터 사전 : 어떤 데이터가 어디에 어떤 형태로 있는지 적어 둔 곳. 데이터에 대한 정보
  • 데이터 파일 : 실제 데이터가 저장된 파일

데이터 모델 5종

  • ★ 데이터 모델 : DB 구조를 표현하는 방식. DBMS를 분류하는 가장 중요한 기준
  • 계층형 : 트리 구조(1:N), 포인터로 연결. 이해·구축은 쉽지만 새 관계가 생기면 트리를 새로 만들어야 함
  • 네트워크형 : 계층형을 보완해 M:N 허용. 유연하지만 연결이 복잡해 유지 관리가 힘듦
  • ★ 관계형 : 행과 열로 된 테이블에 데이터를 담고 키로 연결. 가장 많이 씀, 수업에서 배우는 것
  • 객체 지향형 : 객체 지향 언어의 개념을 가져와 데이터를 객체 단위로 저장
  • 객체 관계형 : 관계형과 객체 지향형의 절충형
시험엔 이렇게

DB = 저장소, DBMS = 관리 SW, DBS = DB + DBMS. DDL = 구조, DML = 데이터, DCL = 권한(DBA만). DBMS 필수 기능 중 가장 중요한 것은 제어.

외우는 법: 틀은 DDL · 값은 DML · 권한은 DCL / 계 · 네 · 관 · 객 · 객관
✗ 함정CREATE USER는 CREATE로 시작하니까 DDL
○ 정답사용자 계정·권한을 다루니까 DCL

같은 DB인데 학생 · 교수 · DB 관리자가 보는 모습이 다르다?

교재 CH02 2절 · 3단계 구조 · 데이터 독립성 · 데이터 사전 (강의 녹음 없음, 교재로 정리)

이 부분은 수업 녹음이 없어서 놓치기 쉬워요. 그런데 "구조를 그려라" 단골 후보예요

교재 p.20~29를 그대로 따라가면서 쉽게 풀었어요.

스키마와 3단계 구조

  • ★ 스키마 : DB에 저장되는 데이터 구조와 제약 조건을 정의한 것 (학생(학번, 이름, 학년, 성별) + "학년은 정수 1~4")
  • ANSI/SPARC 3단계 구조 : 같은 DB를 보는 관점을 외부 · 개념 · 내부 세 단계로 나눈 구조 (미국 표준 기관 ANSI, 1978)

세 가지 스키마

  • ★ 외부 스키마 : 사용자 한 명 한 명이 바라보는 DB의 일부분. 서브 스키마라고도 하며 사용자마다 달라 여러 개 (교수의 "강의정보", 학생의 "수강정보")
  • ★ 개념 스키마 : 모든 사용자의 관점을 합친 조직 전체의 DB 구조. DB당 하나, 그냥 "스키마"라고 하면 보통 이것
  • ★ 내부 스키마 : 저장 장치 관점에서 데이터를 어떻게 저장할지 정한 구조(레코드 형식, 배치, 인덱스). DB당 하나
  • 사상(mapping) : 단계와 단계 사이를 연결하는 것. DBMS의 핵심 역할 중 하나
교재 비유로 보면 (F-35 전투기) — 외부 스키마는 조종석 · 날개 · 꼬리처럼 각자 담당하는 부품 한 조각, 개념 스키마는 그 부품들이 모인 비행기 전체 모습, 내부 스키마는 겉판을 벗긴 속 배선과 기계 구조예요.

데이터 독립성

  • ★ 데이터 독립성 : 아래 단계가 바뀌어도 위 단계가 영향을 거의 안 받는 성질. 파일 시스템의 종속성 문제에 대한 DB의 답
  • ★ 논리적 데이터 독립성 : 개념 스키마(논리 구조)를 바꿔도 외부 스키마·응용 프로그램이 영향을 덜 받는 것. 외부/개념 사상(위쪽)이 제공
  • ★ 물리적 데이터 독립성 : 내부 스키마(저장 구조, 예: 인덱스 추가)를 바꿔도 개념 스키마가 영향을 덜 받는 것. 개념/내부 사상(아래쪽)이 제공

데이터 사전

  • ★ 데이터 사전 : 스키마와 사상 정보 등 DB를 설명하는 정보를 저장하는 곳(테이블·열·뷰·인덱스·권한). DBMS가 만들고 유지, 사용자는 검색만 가능하고 변경은 DBMS만
  • 메타 데이터 : 실제 데이터가 아니라 데이터를 설명하는 데이터
  • 사용자 데이터베이스 : 실제 데이터가 저장된 DB
  • 시스템 데이터베이스(시스템 카탈로그) : 메타 데이터가 저장된 DB. 데이터 사전과 데이터 디렉토리가 들어 있음
  • 데이터 디렉토리 : 데이터의 위치 정보를 저장한 곳. 사용자 접근 불가
시험엔 이렇게

3단계 구조 = 외부(사용자별, 여러 개) · 개념(조직 전체, 1개) · 내부(저장 방식, 1개). 외부/개념 사상 → 논리적 독립성, 개념/내부 사상 → 물리적 독립성. 데이터 사전 = 메타 데이터 저장소, 변경은 DBMS만.

외우는 법: 외 · 개 · 내 = 여럿 · 하나 · 하나 / 위쪽 사상은 논리, 아래쪽 사상은 물리
✗ 자주 틀리는 것인덱스를 추가해도 앱이 멀쩡한 건 논리적 독립성
○ 맞게저장 구조(내부) 변경을 흡수한 거라 물리적 독립성 (개념/내부 사상)

  • 투플의 유일성 : 똑같은 투플은 없다
  • 투플의 무순서성 : 투플 순서는 상관없다
  • 속성의 무순서성 : 속성 순서도 상관없다
  • 속성의 원자성 : 한 칸에는 더 쪼갤 수 없는 값 하나만

키 — 시험 단골

  • 키 : 투플을 구별하는 기준이 되는 속성(들)
  • ★ 유일성 : 키 값으로 모든 투플을 하나씩 구별할 수 있는 성질 (하나도 안 겹침)
  • ★ 최소성 : 꼭 필요한 속성만으로 이루어진 성질 (하나라도 빼면 유일성이 깨짐)
  • ★ 슈퍼키 : 유일성만 만족하는 키
  • ★ 후보키 : 유일성과 최소성을 모두 만족하는 키
  • ★ 기본키(PK) : 후보키 중에서 골라 뽑은 1개. 안 바뀌고 · 널 없고 · 속성 적고 · 값 작은 것으로 (앞으로 들어올 값까지 고려)
  • 대체키 : 기본키로 뽑히지 못한 나머지 후보키
  • ★ 외래키(FK) : 다른 릴레이션의 기본키를 참조하는 속성. 릴레이션끼리 잇는 연결 고리

무결성 제약조건 4가지

  • ★ 개체 무결성 : 기본키는 널도, 중복도 안 된다. PRIMARY KEY (위반: 학번 NULL, 같은 학번 두 번)
  • ★ 참조 무결성 : 외래키는 참조하는 릴레이션의 기본키 값이거나 널이어야 한다. FOREIGN KEY (위반: 학생에 없는 s999를 수강에)
  • 도메인 무결성 : 속성 값이 도메인(허용 범위) 안에 있어야 한다. NOT NULL · DEFAULT · CHECK (위반: 학년 CHECK(1~4)에 5)
  • 유일성 무결성 : 키가 아닌 속성도 중복이 안 되게 막는다. UNIQUE (위반: 이메일 중복)
  • 널(NULL) : 0이나 빈칸이 아니라 아직 모르는 값. 그래서 외래키는 널 허용, 기본키는 구별이 안 되니 불가
  • 무결성을 지키는 방법 : 코드가 아니라 DBMS에 제약조건을 선언해 자동 검사
시험엔 이렇게

슈퍼키(유일성) ⊇ 후보키(유일성 + 최소성) ⊇ 기본키, 남은 후보키 = 대체키. 개체 무결성 = PK 널·중복 ✗, 참조 무결성 = FK는 참조 PK 값이거나 널.

외우는 법: 슈 > 후 > 기 + 대 / 개 · 참 · 도 · 유 / PK는 신분증, FK는 손가락

CH04 — SQL 뒤에서 돌아가는 수학, 관계 대수

9/22 · 9/29 수업 · 관계 대수 vs 해석 · 집합 연산 · σ π ⋈ ÷ · 질의 최적화

관계 대수와 관계 해석

  • ★ 관계 대수 : 원하는 결과를 얻는 연산 순서("어떻게")를 쓰는 절차적 언어
  • 관계 해석 : 원하는 결과("무엇을")만 쓰는 선언적 언어
  • 둘의 관계 : 표현력이 같고, DBMS가 직접 실행하는 언어가 아니라 SQL과 DBMS 내부 처리의 이론적 기반. 입력도 결과도 릴레이션

집합 연산 — 계산 문제

  • 합병 가능 : 두 릴레이션의 차수가 같고 대응 속성의 도메인이 같은 것. ∪ ∩ −에 필요
  • 합집합 ∪ : 두 릴레이션의 투플을 합친 것. 차수 그대로, 카디널리티 ≤ 두 쪽의 합 (겹치면 한 번만)
  • 교집합 ∩ : 양쪽에 다 있는 투플. 차수 그대로, 카디널리티 ≤ 작은 쪽
  • 차집합 − : 왼쪽에만 있는 투플. 차수 그대로, 카디널리티 ≤ 왼쪽 (순서 중요)
  • ★ 카티션 프로덕트 × : 두 릴레이션의 투플을 모두 짝지은 것. 합병 조건 불필요, 차수는 더하고 카디널리티는 곱한다
  • 계산 예 : R1 {s001, s002, s003}, R2 {s001, s002, s004, s005} → ∪ = 5, ∩ = 2, R1−R2 = 1, R2−R1 = 2, × = 12

관계 연산 — σ π ⋈ ÷

  • ★ 셀렉트 σ : 조건에 맞는 행을 고르는 연산 (SQL의 WHERE)
  • ★ 프로젝트 π : 지정한 열만 뽑는 연산. 중복 투플은 자동 제거. 예: π 이름 (σ 학년=4 (학생)) = 4학년의 이름
  • 조인 ⋈ : 두 릴레이션을 공통 속성으로 이어 붙이는 연산. × 한 뒤 σ 한 것과 같음
  • 세타 조인 : 비교 연산자(=, <, > 등)로 조건을 거는 조인
  • 동등 조인 : "=" 조건만 쓰는 조인. 공통 속성이 결과에 두 번 나온다
  • 자연 조인 : 동등 조인에서 중복 속성을 하나 뺀 조인. 공통 속성이 한 번만
  • 디비전 ÷ : "모든 ~을 가진" 투플을 찾는 연산
  • 기본 연산 : 다른 연산으로 대신할 수 없는 5가지. ∪ − × σ π
  • 복합 연산 : 기본 연산으로 만들 수 있는 3가지. ∩ ⋈ ÷ (∩ = R − (R − S))
  • 세미 조인 : 조인하되 한쪽 릴레이션의 속성만 남긴다 (결과가 줄어듦)
  • 외부 조인 : 짝이 없는 투플도 널로 채워 결과에 포함한다 (결과가 늘어남)

질의 최적화 — 서술형 1순위

  • 질의 처리 순서 : SQL → 관계 대수식 → 질의 트리 → 최적화 → 실행
  • ★ 질의 최적화 : 연산 순서를 조정해 중간 릴레이션 크기를 최소화하는 것. 같은 결과라도 순서에 따라 속도가 크게 달라짐
  • ★ 최적화 원칙 : 셀렉트·프로젝트를 트리 아래로(먼저), × + σ는 조인으로
  • 김연아 예시 : 학생 × 수강을 먼저 하면 "학생 수 × 수강 수"줄을 만든 뒤에야 김연아를 찾지만(A), σ로 김연아를 먼저 고르면 1명으로 줄인 채 조인한다(B) → B가 빠르다
시험엔 이렇게

질의 최적화의 핵심 = 연산 순서를 조정해 중간 릴레이션 크기를 최소화. 셀렉트·프로젝트를 트리 아래로(먼저), × + σ는 조인으로. 그래서 셀렉트를 먼저 하는 트리가 효율적이다.

CH05 — SQL 문장을 보고 "결과를 말하시오"

SELECT · WHERE · DISTINCT · ORDER BY · 집계 · GROUP BY · LIKE · IS NULL · UNION · INTERSECT · EXCEPT · 자세히: 10/8 · 10/13

시험 메모에 그대로 적혀 있어요: "mysql 문장 해석할 줄 알아야 함. 예시로 select 이름, 주소 from 학생; 이 구문의 결과를 말하시오." univDB 학생 테이블을 머릿속에 넣고, 문장을 실행 순서대로 읽는 연습을 해요.

SELECT 문 구성

  • ★ 실행 순서 : FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY (프 · 웨 · 그 · 해 · 셀 · 오)
  • SELECT : 결과에 보여 줄 열을 지정. 조건이 없으면 모든 행을 반환
  • DISTINCT : 결과에서 중복 행을 제거
  • WHERE : 조건에 맞는 행만 고른다
  • ORDER BY : 결과를 정렬. ASC 오름차순(기본) · DESC 내림차순
  • ★ COUNT(*) : 모든 행의 개수
  • ★ COUNT(열) : 그 열에서 NULL을 뺀 개수
  • GROUP BY : 같은 값끼리 그룹으로 묶는다
  • HAVING : 그룹에 거는 조건 (WHERE는 행 조건)
  • ★ LIKE : 문자열 패턴 검색. _는 정확히 1글자, %는 0글자 이상
  • ★ IS NULL : NULL인 행 찾기. = NULL로 쓰면 0행
  • UNION : 두 SELECT 결과의 합집합 (중복 제거)
  • INTERSECT : 교집합 (MySQL 8.0.31 이상)
  • EXCEPT : 차집합 (MINUS는 MySQL에 없음)

시험엔 이렇게

SELECT문은 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순으로 실행된다. 결과는 SELECT에 쓴 열만으로 된 테이블이며, 조건이 없으면 모든 행을 반환한다. DISTINCT는 중복 제거, COUNT(열)은 NULL 제외, HAVING은 그룹 조건, LIKE의 _는 1글자 · %는 0글자 이상. NULL은 = 대신 IS NULL로 찾고, UNION은 합집합(중복 제거) · INTERSECT는 교집합 · EXCEPT는 차집합이다.

① CH01 개념 ★ 그리기발전 순서 = 종 · 중 · 공 / DB 정의 = 공 · 통 · 운 · 저

  • 데이터는 측정한 값 그대로, 정보는 그걸 가공해서 판단에 쓸 수 있게 만든 것이에요. 정보 시스템은 데이터를 처리(P)해 정보를 만드니까 I = P(D). 단계는 데이터 → 정보 → 지식 → 지혜 → 판단.
  • 파일 시스템에서 DB로 오면서 생긴 문제는 차례로 종속성(프로그램이 파일 구조에 묶임) → 중복성(같은 데이터가 여러 파일에) → 공유 한계(여럿이 같이 못 씀). 이걸 해결한 게 DBMS예요.
  • 종속성은 데이터 모델 · 데이터 언어로, 중복성은 통합 저장소로 해결해요. DB의 단점은 비용이 많이 든다는 것과, 한 곳에 모여 있어서 고장 나면 다 멈춘다는 것(시스템 취약성).

② CH02 시스템 ★ 그리기DDL 틀 · DML 값 · DCL 권한

  • DB는 데이터 저장소, DBMS는 그걸 관리하는 소프트웨어, DBS(DB 시스템)는 둘을 합친 전체예요. DBMS 필수 기능 3가지는 정의 · 조작 · 제어.
  • DDL은 표의 틀(구조)을 만들고, DML은 안의 데이터를 넣고 고치고, DCL은 권한을 주고 뺏어요(DBA만 씀). TCL은 시험에 안 나와요.
  • 데이터 모델은 계층 · 네트워크 · 관계 · 객체 · 객체관계 5가지. 우리가 배우는 건 관계 모델이에요.

③ 3단계 구조 ★ 그리기외부 여러 개 · 개념 1개 · 내부 1개

  • 외부 스키마는 사용자마다 보는 모습이라 여러 개, 개념 스키마는 조직 전체 구조라 1개, 내부 스키마는 실제 저장 방식이라 1개예요(ANSI/SPARC, 1978).
  • 외부/개념 사이 연결(사상) 덕분에 논리적 독립성이, 개념/내부 사이 연결 덕분에 물리적 독립성이 생겨요. 한 층을 바꿔도 다른 층은 안 고쳐도 된다는 뜻.
  • 데이터 사전에는 "데이터에 대한 데이터"인 메타 데이터가 저장돼요. 사용자가 직접 못 바꾸고 DBMS만 바꿔요.

④ CH03 릴레이션 · 키 · 무결성 ★ 판별키 크기 순 = 슈퍼 ⊇ 후보 ⊇ 기본(+ 남은 건 대체) / 무결성 = 개 · 참 · 도 · 유

  • 차수는 속성(열) 개수라 잘 안 변하고, 카디널리티는 투플(행) 개수라 데이터가 들어오고 나가면 계속 변해요. 릴레이션 특성 4가지: 똑같은 투플은 없다 · 투플 순서는 상관없다 · 속성 순서도 상관없다 · 속성 값은 더 못 쪼개는 하나의 값(원자값).
  • 슈퍼키는 "한 명을 콕 집을 수 있다(유일성)"만 만족하면 되고, 후보키는 거기에 "꼭 필요한 속성만 있다(최소성)"까지 만족해야 해요 → 후보키 = 유일성 + 최소성. 후보키 중 기본키를 고를 땐 값이 잘 안 변하고, 널이 없고, 속성 수가 적고, 값이 짧은 것.
  • 개체 무결성: 기본키는 널이면 안 돼요(중복도 ✗). 참조 무결성: 외래키 값은 참조하는 표의 기본키에 실제로 있는 값이거나, 아니면 널이어야 해요(없는 학과 번호를 적으면 안 됨). 그 밖에 도메인 무결성은 CHECK · NOT NULL로, 유일성은 UNIQUE로 지켜요.

⑤ CH04 관계 대수 ★ 계산 · 서술카티션 곱은 카디널리티도 곱 / 셀렉트는 행, 프로젝트는 열

  • 관계 대수는 "어떻게 구할지" 순서를 적는 절차적 언어, 관계 해석은 "무엇을 원하는지"만 적는 선언적 언어예요.
  • 결과 투플 수: 합집합(∪)은 두 릴레이션 투플 수의 합 이하, 교집합(∩)은 작은 쪽 이하, 차집합(R − S)은 왼쪽 R 이하. 카티션 곱(×)은 차수는 더하고, 카디널리티는 곱해요(3행 × 4행 = 12행).
  • 셀렉트(σ)는 조건에 맞는 행을 고르고, 프로젝트(π)는 원하는 열만 뽑아요. 동등 조인은 같은 속성이 결과에 두 번 나오고, 그중 하나를 뺀 게 자연 조인(한 번만). 세미 조인은 한쪽 속성만 남아 결과가 작아지고, 외부 조인은 짝 없는 투플도 널로 채워 남겨서 결과가 커져요. 다른 연산으로 대신할 수 없는 기본 연산은 ∪ · − · × · σ · π.
  • 질의 최적화의 핵심은 중간 릴레이션을 최소화하는 것. 그래서 조인하기 전에 σ로 행부터 줄여요.

⑥ CH05 앞부분

  • SQL은 관계 DB의 표준 언어예요(IBM SYSTEM R에서 시작, ANSI · ISO 표준). univDB의 수강 테이블은 (학번 + 과목번호)가 기본키인데, 이 둘이 각각 학생 · 과목 테이블을 가리키는 외래키이기도 해요. 학생 한 명이 여러 과목을 들으니 학생 : 수강 = 1 : N.

빈칸 채우기 눌러서 정답 확인

DB의 정의는 공용 · 통합 · 운영 · 저장 데이터이고, 특성 중 가장 중요한 것은 동시 공용이다. 파일 시스템의 문제는 종속성 · 중복성 · 공유 한계다. 3단계 구조에서 여러 개 존재하는 것은 외부 스키마이고, 개념/내부 사상은 물리적 데이터 독립성을 제공한다. 데이터 사전에 저장된 데이터를 메타 데이터라 한다. 후보키는 유일성과 최소성을 만족한다. 외래키는 참조하는 기본키 값이나 널을 가진다. R1 × R2의 카디널리티는 두 카디널리티의 곱이고, 질의 최적화의 핵심은 중간 릴레이션의 크기를 줄이는 것이다.

    퀴즈 12문항 다 풀고 채점하기

    Q1"파일 구조가 바뀌면 그 파일을 쓰는 프로그램을 모두 고쳐야 하는" 문제는?

    프로그램이 파일 구조에 묶인 것 = 종속성. DB는 모델·언어와 3단계 구조의 데이터 독립성으로 해결해요.

    Q2인덱스를 추가하는 등 저장 방식을 바꿔도 개념 스키마와 응용 프로그램이 영향을 받지 않는 성질은?

    저장 구조 = 내부 스키마. 그 변경을 개념/내부 사상이 흡수 → 물리적 독립성.

    Q33단계 구조에 대한 설명으로 옳지 않은 것은?

    사용자마다 다른 건 외부 스키마. 개념 스키마는 조직 전체를 통합한 하나예요.

    Q4권한을 부여·회수하는 DCL을 쓰는 사용자는?

    DML은 모두, DDL은 응용 프로그래머 · DBA, DCL은 DBA만.

    Q5속성 6개, 투플 20개인 릴레이션에 5명을 추가했다. 차수와 카디널리티는?

    차수 = 속성 수 6 그대로, 카디널리티 = 투플 수 20 + 5 = 25.

    Q6폰번호만으로 유일할 때 {이름, 폰번호}가 후보키가 아닌 이유는?

    이름을 빼도 유일 → 군더더기 → 최소성 ✗. 복합키도 최소성만 지키면 후보키가 돼요.

    Q7이메일이 기본키는 아니지만 중복되면 안 될 때 쓰는 제약조건과 키워드는?

    키가 아닌 속성의 중복 금지 = 유일성 제약조건(UNIQUE).

    Q8수강 테이블의 학번(FK)에 허용되는 값은?

    참조 무결성: 참조하는 기본키 값 또는 널.

    Q9학생(학번, 이름, 학년)과 수강(학번, 과목번호, 평가학점, 점수)에 바로 할 수 있는 연산은?

    차수가 3과 4로 달라 합병 불가 → ∪ ∩ − 불가. ×는 조건이 필요 없어요(결과 차수 7).

    Q10학생(학번, 이름)과 수강(학번, 과목번호)을 자연 조인한 결과의 속성은?

    자연 조인은 중복 속성(학번)을 하나만. 두 번이면 동등 조인, 학생 속성만이면 세미 조인.

    Q11기본 연산이 아닌 것은?

    조인 = σ(×)로 표현되는 복합 연산. 복합은 ∩ ⋈ ÷.

    Q12질의 트리 최적화 규칙으로 옳은 것은?

    σ · π는 먼저, AND 셀렉트는 분리, OR는 AND로, × + σ는 조인으로. 목적은 중간 릴레이션 최소화.

    ① 파일 시스템의 종속성 문제를 DB 시스템은 어떻게 해결하나요? (3단계 구조 · 데이터 독립성이라는 말을 써서)

    파일 시스템에서는 프로그램이 파일을 직접 접근해서, 파일 구조가 바뀌면 그 파일을 쓰는 프로그램을 모두 고쳐야 했어요(종속성). DB 시스템에서는 모든 접근이 DBMS를 거치고, DB를 외부 · 개념 · 내부 세 단계 스키마로 나눠 관리해요. DBMS가 외부/개념 사상을 관리하니까 개념 스키마가 바뀌어도 응용 프로그램은 영향을 거의 안 받고(논리적 데이터 독립성), 개념/내부 사상을 관리하니까 저장 구조가 바뀌어도 개념 스키마는 그대로예요(물리적 데이터 독립성). 이 사상 정보는 데이터 사전에 메타 데이터로 저장돼요.

    ② 같은 결과를 내는 두 질의 트리 중 셀렉트를 먼저 하는 쪽이 왜 효율적인가요?

    질의 최적화의 핵심은 연산 순서를 조정해서 중간 릴레이션의 크기를 최소화하는 거예요. 카티션 프로덕트를 먼저 하면 두 릴레이션 카디널리티의 곱만큼 투플이 생긴 다음에야 조건으로 골라요. 셀렉트를 트리 아래쪽(먼저)으로 내리면 처음부터 투플 수가 줄어든 상태에서 조인하니까 처리할 양이 훨씬 적어요. 그래서 셀렉트를 먼저 하는 트리가 효율적이에요.
