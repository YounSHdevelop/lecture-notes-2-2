고객 파일에서 전화번호 하나 뺐을 뿐인데, 프로그램을 전부 고쳐야 한다?

전통적 파일 시스템 · 데이터 종속성

고객 관리 프로그램이 고객 파일을 직접 읽고 쓴다. 어느 날 "개인정보니까 전화번호 칸은 빼자"고 했다

파일 모양이 바뀌었으니, 그 파일을 읽던 프로그램은 어떻게 될까요?

옛날 방식은 이래요. 엑셀 같은 응용 프로그램 안에 "파일 처리 코드"가 들어 있고, 이 코드가 데이터 파일을 직접 열어서 읽고 써요. 직접 만들 필요도 없고 원하는 대로 쓸 수 있으니 편하죠. 그래서 지금도 작은 회사에서는 많이 씁니다.

문제는 파일과 프로그램이 딱 붙어 있다는 거예요. 파일에서 전화번호 칸을 빼거나, 저장 방식을 바꾸면 그 파일을 읽던 모든 프로그램의 파일 처리 코드를 다 고쳐야 해요. 하나 고치면 다 고쳐야 하는 이 상태를 데이터 종속성이라고 불러요.

교수
파일 시스템의 가장 큰 문제는 데이터의 종속성이 매우 많이 증가한다는 거예요. 하나 고치게 되면 다 고쳐야 된다.9/8 강의 중 (말을 조금 다듬음)
비유로 보면 — 충전기 모양이 폰마다 다 다른 상황이에요. 충전 단자 규격(파일 구조)이 바뀌면 거기 맞춰 쓰던 충전기(프로그램)를 전부 새로 사야 하죠.
시험엔 이렇게

데이터 종속성 = 파일의 구조·접근 방법을 바꾸면 연관된 응용 프로그램도 전부 수정해야 하는 문제. 전통적 파일 시스템의 첫 번째 문제.

외우는 법: 종속 = 묶여 있다 → 하나 바꾸면 다 바꾼다

고쳐 봤더니 또 문제. 수강 신청 날 무슨 일이?

개선 1: 중복성 · 개선 2: 공유의 한계

개선 1 — 프로그램마다 파일을 따로 주자

종속성을 줄이려고 프로그램마다 자기 데이터 파일을 따로 두게 했어요. 장점도 있었어요. 하나가 에러 나서 날아가도 다른 쪽 파일은 남으니까요.

그런데 이번엔 파일이 계속 늘어나요. 학생 정보가 수강 파일에도, 성적 파일에도, 장학 파일에도 똑같이 들어가게 되죠. 같은 데이터가 여러 파일에 쌓이니 관리가 어렵고, 저장 공간과 비용도 늘어요. 이게 데이터 중복성이에요.

개선 2 — 그럼 파일을 하나로 합치자

중복을 없애려고 파일을 하나로 통합했어요. 중복은 해결! 그런데 이제 한 파일을 여러 사람이 동시에 써야 하잖아요. 파일은 "파일 단위"로만 공유·보안이 되고, 누가 열면 닫을 때까지 기다려야 해요. 장애가 나면 복구도 어렵고, 한 번 날아가면 다 날아가요.

교수님 예시: 파일로 만든 수강 신청 시스템 (학생 파일 · 과목 파일 · 수강 파일 · 성적 파일)

이런 일이 생겨요.

  • 정원 한 자리 남았는데 9시 45분 25초에 두 명이 동시에 신청 → 한 명 또는 둘 다 오류
  • 학생과 학사팀이 같은 전화번호를 연달아 수정 → 서로 잘 바꿨다고 생각하지만 데이터가 꼬임 (무결성이 깨짐)
  • 200명 정원인데 230명이 8시 59분에 접속 → 시스템 다운, 복구 어려움
시험엔 이렇게

전통 파일(종속성) → 개선1 프로그램별 파일(중복성) → 개선2 파일 통합(파일 단위 공유만, 동시 사용·회복 어려움) → DB 시스템

외우는 법: 종 → 중 → 공 순서로 터지고, 마지막에 DBMS가 막는다
✗ 헷갈리는 생각파일을 하나로 합치면 문제가 다 해결된다
○ 맞는 생각중복은 줄지만 동시 접근·보안·회복이 안 된다. 그래서 DBMS가 필요

데이터베이스 시스템은 이 문제들을 어떻게 막았을까?

DBMS · 공통 데이터 모델 · 표준 데이터 언어 · 통합 저장소

재밌는 사실: 데이터베이스도 결국 맨 아래는 파일이에요. 다른 점은 그 파일을 DBMS라는 보호 장치가 감싸고 있다는 거예요. 응용 프로그램이나 사용자는 파일을 직접 못 만지고, 반드시 DBMS를 통해서만 데이터를 처리해요. 이때 DBMS한테 말 거는 언어가 SQL 같은 데이터 언어고요.

교수
이거 파일이잖아요. 파일을 감싸고 있는, 위에 감싸고 있는 보호 장치가 있는 게 데이터베이스 시스템이에요. INSERT 할 때 우연히 2명, 3명, 5명이 동시에 날려도 그건 내가 잘 관리해서 안전하게 해 줄게. 이런 기능이 장착된 게 데이터베이스 시스템입니다.9/8 강의 중 (말을 조금 다듬음)

문제별로 해결책이 짝지어져 있어요. 이 짝을 바꿔 쓰는 실수가 정말 많아요.

파일 시스템의 문제DB 시스템의 해결책
데이터 종속성공통 데이터 모델 + 표준 데이터 언어
데이터 중복성통합 저장소
동시 접근 · 보안 · 장애DBMS가 동시성 제어 · 접근 권한 · 백업과 회복(이중화)
비유로 보면 — 운전을 배울 때 D는 전진, R은 후진, N은 중립이라는 것만 배우면 엔진 속은 몰라도 차를 몰 수 있죠. 우리는 SQL이라는 "기어 쓰는 법"을 배우고, 복잡하고 힘든 데이터 처리는 DBMS가 다 도맡아요.
시험엔 이렇게

장면 4

내 폰 연락처도 데이터베이스일까?

DB 정의: 공용 · 통합 · 운영 · 저장

데이터가 많이 모였다고 다 데이터베이스는 아니에요. 교과서 정의는 이래요. 데이터베이스는 여러 사용자가 함께 쓰는 공용·통합·운영·저장 데이터의 저장소. 네 단어가 다 들어맞아야 진짜 DB예요.

단어뜻예시
공용 (shared)여러 사용자가 함께 쓴다혼자 쓰는 연락처·가계부는 진정한 DB ✗
통합 (integrated)여러 곳의 데이터를 하나로 연결증권사 본점·지점 데이터를 묶어서 관리. 꼭 한 곳에 모을 필요 없이 연결만 되면 OK
운영 (operated)조직 운영에 꼭 필요한 데이터학생의 수업 상태처럼 함부로 바꾸면 안 되는 데이터
저장 (stored)컴퓨터가 접근할 수 있는 매체에 저장디스크·테이프·데이터 센터 서버·클라우드

"통합"에서 많이 틀려요. 통합은 물리적으로 한 곳에 모으는 게 아니라, 여러 장소에 흩어져 있어도 서로 연결돼 있으면 되는 논리적 통합이에요. 교수님이 부산·춘천 데이터 센터 얘기를 했는데, 지진 같은 재해에 대비해 지역마다 나눠 두고 백업하면서도 하나처럼 쓰는 거죠.

시험엔 이렇게

데이터베이스 = 공용 데이터 · 통합 데이터 · 운영 데이터 · 저장 데이터의 저장소. 통합은 논리적 통합.

외우는 법: 공 · 통 · 운 · 저 ("공통으로 운전해 저장")
바로 확인
내 휴대폰에 나 혼자 쓰는 연락처 500개. 교과서 정의로 보면 무엇이 빠져서 진정한 DB가 아닐까?
혼자만 쓰니까 공용이 아니에요. 넓은 의미로는 DB라고 부를 수 있지만 수업에서 말하는 DB는 아니에요.

콘서트 예매 1분 컷, DB가 버텨 주려면?

DB 특성: 실시간 접근 · 끊임없는 변화 · 동시 공용 · 내용 기반 참조

인기 가수 예매 사이트는 1분이면 끝나죠. 그게 로딩 걸려서 10분, 20분 걸리면 난리 나요. 네트워크 탓 같지만 DB의 영향도 커요. DB가 갖춰야 할 성질 네 가지를 이 장면으로 봅시다.

  • 실시간 접근 — 남은 좌석 검색이 몇 초 안에 나와야 해요.
  • 끊임없는 변화 — 좌석이 팔릴 때마다 데이터가 바로 바뀌어야 해요. 주식 시세가 몇 분 전 것이면 곤란하죠.
  • 동시 공용 — 수만 명이 순번 대기 없이 동시에 같은 데이터를 써요. 교수님이 제일 중요하다고 한 특성이에요.
  • 내용 기반 참조 — 저장 위치를 몰라도 "홍길동"이라는 내용(값)만 넣으면 찾아 줘요.
교수
동시 공용, 이게 제일 중요하긴 하죠. 데이터베이스는 파일 시스템의 종속성, 중복성을 해결하려고 나온 거니까요.9/8 강의 중 (말을 조금 다듬음)
시험엔 이렇게

DB의 특성 = 실시간 접근 · 끊임없는 변화 · 동시 공용 · 내용 기반 참조. 가장 중요한 건 동시 공용.

외우는 법: 실 · 변 · 동 · 내 ("실변동내")
✗ 헷갈리는 짝정의(공·통·운·저)와 특성(실·변·동·내)을 섞어 쓰기
○ 구별법정의 = 어떤 데이터인가 (명사) / 특성 = DB가 어떻게 동작하나

DB가 다 좋은 건 아니잖아? 단점은 딱 두 개

넓은 의미 · 좁은 의미 · 장단점

넓은 의미와 좁은 의미

넓은 의미의 DB는 형식 제약 없이 콘텐츠를 모아 둔 것이에요. 웹 문서, 전자도서관, VOD 같은 거죠. 가방을 열어 보면 휴대폰에, 집에 가면 아파트 현관 잠금 장치에도 최소 2개는 있어요.

좁은 의미의 DB는 데이터 형식과 구성에 엄격한 제약을 둔 시스템 관점의 DB예요. 인터넷 뱅킹, 극장 예매, 쇼핑몰, 편의점 재고 관리. 우리 수업은 좁은 의미를 다뤄요. 과제도 "학사 시스템·수강 신청 시스템의 DB 구성을 그려 보라" 식으로 나온다고 했어요.

장점은 많고, 단점은 두 개

항목파일 시스템DB 시스템
종속성 · 중복성높음낮음
동시 공유 · 일관성안 됨, 데이터 꼬임DBMS가 보장
표준화어려움SQL 표준 (90% 이상 호환)
가용성거의 없음이중화 · 삼중화
비용적음개발·운영·관리 비용 많음
취약성파일이 흩어져 있어 낮게 봄시스템 취약성 높음

"DB가 더 안전한데 취약성이 높다고?" 싶죠. 개인이 실수로 지울 확률은 당연히 DB가 낮아요. 여기서 말하는 건 시스템 취약성이에요. DB는 하나의 시스템이라 거기만 뚫리면 전체가 위험하다는 뜻이에요.

시험엔 이렇게

DB 시스템의 단점 = 개발·운영·관리 비용 부담 + 시스템 취약성(하나의 시스템이라 해킹 시 전체 위험). 나머지는 전부 DB가 유리.

③ DB 정의 4 ★공·통·운·저

④ DB 특성 4 ★실·변·동·내

  • 실시간 접근 · 끊임없는 변화 · 동시 공용(제일 중요) · 내용 기반 참조

⑤ 의미 · 단점

  • 넓은 의미 = 콘텐츠 모음 / 좁은 의미 = 형식 엄격 (수업 대상)
  • 단점 2개뿐: 비용 · 시스템 취약성 ✗

빈칸 채우기 눌러서 정답 확인

전통적 파일 시스템의 첫 문제는 데이터 종속성이고, 이를 고치려고 프로그램마다 파일을 나누자 데이터 중복성이 생겼다. DB 시스템은 종속성을 공통 데이터 모델과 표준 데이터 언어로, 중복성을 통합 저장소로 해결하며, 모든 접근은 DBMS를 통해서만 이루어진다. DB 특성은 실시간 접근, 끊임없는 변화, 동시 공용, 내용 기반 참조다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
데이터 종속성이란?
파일의 구조·접근 방법을 바꾸면 연관된 모든 응용 프로그램도 고쳐야 하는 문제.
데이터 중복성은 어느 단계에서 생기나?
개선 1 (프로그램마다 파일을 따로 둠). 같은 데이터가 여러 파일에 쌓인다.
개선 2(파일 통합)에 남는 문제는?
파일 단위 공유·보안만 가능 → 동시 사용, 대용량 공유, 장애 회복이 어렵다.
DB 시스템이 종속성·중복성을 해결한 방법은?
종속성: 공통 데이터 모델 + 표준 데이터 언어. 중복성: 통합 저장소.
DB 시스템에서 사용자는 데이터에 어떻게 접근하나?
반드시 DBMS를 통해서만 (데이터 언어 사용).
DB 정의 4가지는?
공용 · 통합 · 운영 · 저장 데이터의 저장소 (공·통·운·저)
통합 데이터의 "통합"은 물리적? 논리적?
논리적. 흩어져 있어도 서로 연결돼 있으면 된다 (증권사 본·지점).
DB 특성 4가지는? 제일 중요한 건?
실시간 접근 · 끊임없는 변화 · 동시 공용 · 내용 기반 참조. 제일 중요한 건 동시 공용.
넓은 의미 vs 좁은 의미 DB 예시는?
넓은: 웹 문서, 전자도서관, VOD. 좁은: 인터넷 뱅킹, 극장 예매, 쇼핑몰, 편의점 재고.
DB 시스템의 단점 두 가지는?
개발·운영·관리 비용 부담, 시스템 취약성 (하나의 시스템이라 뚫리면 전체 위험).

    퀴즈 다 풀고 채점하기

    Q1고객 파일에서 전화번호 항목을 삭제했더니 그 파일을 읽는 모든 프로그램을 수정해야 했다. 어떤 문제인가?

    파일 구조 변경이 프로그램 수정으로 번지는 것이 종속성. 전통 파일 시스템의 첫 문제예요.

    Q2정원 한 자리에 두 학생이 같은 초에 신청해 오류가 났다. 파일 시스템의 어떤 한계이고, DB의 어떤 특성과 관련될까?

    파일은 동시 접근 순서를 보장 못 해요(개선 2의 공유 한계). DBMS가 동시성 제어로 동시 공용을 보장합니다.

    Q3DB 시스템이 데이터 종속성을 해결한 방법은?

    종속성 ↔ 모델·언어, 중복성 ↔ 통합 저장소. 짝을 바꿔 쓰지 마세요.

    Q4증권사 본점과 전국 지점 데이터가 각자 다른 곳에 있지만 서로 연결돼 하나처럼 관리된다. DB 정의 중 무엇?

    흩어져 있어도 연결돼 있으면 통합이에요. 물리적으로 한 곳에 모을 필요는 없어요.

    Q5교수님이 DB의 특성 중 가장 중요하다고 한 것은?

    여러 사용자가 동시에 쓰는 동시 공용. 파일 시스템의 공유 한계를 해결하는 핵심이에요.

    Q6다음 중 DB 시스템의 단점으로 맞는 것은?

    단점은 비용과 시스템 취약성 두 개뿐. 나머지는 전부 DB가 유리해요.

    Q7"좁은 의미의 데이터베이스"에 해당하는 것은?

    형식에 엄격한 제약을 둔 시스템이 좁은 의미. 나머지는 콘텐츠 모음(넓은 의미).

    내 말로 설명하기 친구한테 말하듯이

    수강 신청 시스템을 예로, 파일 시스템에서 생기는 문제와 DBMS가 그걸 어떻게 막는지 설명해 보세요.

    파일로 만들면 정원 한 자리에 두 명이 동시에 신청할 때 순서를 보장 못 해서 오류가 나요. 학생과 학사팀이 같은 전화번호를 연달아 고치면 데이터가 꼬여 무결성이 깨지고, 접속이 몰려 다운되면 복구도 어려워요. DB 시스템은 파일을 DBMS라는 보호 장치로 감싸서, 모든 접근을 DBMS를 통해서만 하게 해요. DBMS가 동시성 제어, 무결성 유지, 접근 권한, 백업과 회복(이중화)을 맡아 줍니다.

    기업의 4대 요소

    사람 · 자본 · 기술 · 데이터. 예전엔 데이터가 맨 뒤였지만 지금은 데이터가 맨 앞이라는 게 교수님 생각이에요. 데이터가 쌓이면 돈이 되기 때문이죠.

    정보 시스템의 종류

    업무별로는 생산·마케팅·인사·재무회계 4종, 기능별로는 5종이에요. 회사에 가면 ERP·DSS·MIS 정도는 다 쓴다고 했어요.

    약어이름특징
    TPS거래처리시스템수입·지출 같은 일상 거래 처리
    MIS경영정보시스템조직 경영 상태 확인
    ES전문가시스템특정 직무의 전문 지식 제공
    DSS의사결정지원시스템경영자 의사 결정 지원
    ERP전사적자원관리시스템기업 전반 운영·관리 정보 통합

    최근 정보 시스템은 클라우드·빅데이터·AI가 결합된 형태, AI 에이전트로 업무를 자동화하는 형태, 물류센터 없이 입점·배송·결제만 연결해 주는 플랫폼형으로 가고 있어요. 특허정보원의 수십 년치 특허를 AI 에이전트로 검색·정리하는 예도 들었어요.

    DB의 연대별 발전

    1970년대까지는 정보화 이전, 1990~2000년대 정보화·디지털 전환과 함께 Oracle 같은 관계형 DBMS가 자리 잡았어요. 2000년대 모바일 시대에 음원·사진·영상 같은 비정형 대용량 데이터가 늘면서 NoSQL이 나왔고, 2020년대에는 누구나 데이터를 만드는 크리에이터 시대가 되면서 클라우드 DB, 데이터 레이크, 멀티모델 DB(주소를 텍스트뿐 아니라 이미지·음성으로도 저장)가 중요해졌어요.
