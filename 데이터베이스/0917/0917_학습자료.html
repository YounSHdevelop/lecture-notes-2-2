그냥 표처럼 보이는데, 왜 "릴레이션"이라고 부를까?

표(테이블) 안에 숨어 있는 규칙과, 그 규칙을 지키게 해 주는 "키"를 배우는 날이에요. 키는 이후 수업 내내 나오니까 오늘 꼭 잡고 가요.

이 페이지를 다 보면 할 수 있는 것

  1. 표를 보고 차수·카디널리티를 바로 셀 수 있다
  2. 릴레이션의 특성 4가지를 "집합이라서"로 설명할 수 있다
  3. 후보키를 판별하고, 슈퍼키 ⊃ 후보키 ⊃ 기본키·대체키 그림을 그릴 수 있다

장면 1

학생 표에서 "가로줄"과 "세로줄"은 뭐라고 부를까?

속성 · 투플 · 도메인 · 차수 · 카디널리티 · 스키마 · 인스턴스

관계형 데이터 모델에서는 데이터를 2차원 표에 담고, 이 표를 릴레이션이라고 불러요. 학생 릴레이션 = 학생 테이블이에요. 먼저 표의 각 부분 이름부터 붙여 봅시다.

학생 릴레이션 — 맨 위 줄이 스키마, 그 아래가 인스턴스
학번이름학년학과
s001김연아4체육학과
s002박지성2경영학과
s003손흥민3AI소프트웨어
  • 속성 = 열(세로). 학번, 이름, 학년, 학과. 데이터를 표현하는 가장 작은 논리 단위예요.
  • 투플 = 행(가로). 학생 한 명(개체 하나)의 정보 묶음. (s001, 김연아, 4, 체육학과)
  • 도메인 = 한 속성이 가질 수 있는 값의 범위. 학년의 도메인은 {1, 2, 3, 4}. 5를 넣으면 오류가 나요. 자료형(정수·문자·날짜), 길이, 허용 범위, 널 허용 여부까지 도메인이 정해요.

개수를 세는 이름 두 개

  • 차수(degree) = 속성의 개수. 위 표는 4. 설계 후 거의 안 바꿔서 정적이에요.
  • 카디널리티(cardinality) = 투플의 개수. 위 표는 3. 학생이 들어오고 나갈 때마다 계속 바뀌어서 동적이에요.
교수
한 번 테이블을 만들고 속성을 뺐는데 다시 넣기 애매해. 그럴 때 어떻게 해요? 테이블을 하나 더 만들어. 그래서 차수는 대체로 안 바뀌는 정적인 거예요. 카디널리티는 학생이 추가되면 5개, 6개, 7개 계속 바뀌고요.9/17 강의 중 (말을 조금 다듬음)

스키마와 인스턴스

표의 맨 윗줄(머리글)이 릴레이션 스키마예요. 학생(학번, 이름, 학년, 학과)처럼 쓰고, 키에는 밑줄을 쳐요. 구조라서 잘 안 바뀌어요(정적, 내포). 그 아래 실제 값들이 릴레이션 인스턴스예요. 특정 시점에 들어 있는 투플들이라 계속 바뀌어요(동적, 외연). 협업할 때는 이 스키마를 먼저 합의하고 코딩을 시작해요.

비유로 보면 — 스키마는 엑셀의 머리글 줄(틀), 인스턴스는 지금 입력돼 있는 내용이에요. 오늘 저장한 내용과 내일 저장한 내용은 달라도, 머리글은 그대로죠.
시험엔 이렇게

차수 = 속성 수(정적), 카디널리티 = 투플 수(동적). 스키마 = 구조(정적), 인스턴스 = 특정 시점의 투플 집합(동적).

외우는 법: 차 = 차례로 선 열(속성) · 카 = 카운트되는 사람(투플)
바로 확인
속성 5개, 투플 30개인 릴레이션에 학생 3명을 새로 넣었다. 차수와 카디널리티는?
학생(투플)이 늘었으니 카디널리티만 30 → 33. 속성 수인 차수는 5 그대로예요.

똑같은 학생을 두 번 넣으면 안 되는 이유는?

릴레이션의 특성 4가지

릴레이션이 그냥 "표"가 아닌 이유가 여기 있어요. 릴레이션은 수학의 집합이에요. 집합에는 두 가지 규칙이 있죠. 같은 원소는 두 번 못 들어간다, 원소 사이에 순서가 없다. 여기서 특성 4가지가 나와요.

  1. 투플 유일성 — 똑같은 투플이 두 개 있으면 안 돼요. (s001, 김연아, 4)가 두 줄이면, DB가 "어느 걸 고치라는 거지?" 하고 구별을 못 해요.
  2. 투플 무순서성 — 행 순서는 의미가 없어요. 김연아가 첫 줄이든 셋째 줄이든 같은 릴레이션이에요.
  3. 속성 무순서성 — 열 순서도 의미가 없어요. 학번-이름 순이든 이름-학번 순이든 같아요. 값은 순서가 아니라 속성 이름으로 찾으니까요.
  4. 속성 원자성 — 한 칸에는 값 하나만. 취미 칸에 {축구, 야구}처럼 두 개를 넣으면 릴레이션이 아니에요.
교수
순서대로 하고 싶으면 너네들이 정렬을 해. 데이터베이스는 그런 거 신경 안 쓸 거야. 그게 SQL의 ORDER BY예요.9/17 강의 중 (말을 조금 다듬음)

원자성은 교수님 출결 예시로 보면 더 와닿아요. "지각" 칸 하나에 5분 지각인지 10분 지각인지 섞어 넣으면, 나중에 그 값을 봐도 무슨 뜻인지 알 수 없어요. 나눠야 하면 속성을 따로 만들어야 해요.

시험엔 이렇게

릴레이션의 특성 = 투플 유일성 · 투플 무순서성 · 속성 무순서성 · 속성 원자성. 이유: 릴레이션은 집합이기 때문.

외우는 법: 투플은 유일, 둘 다 순서 없고, 속성은 원자
바로 확인
R1과 R2는 투플 순서만 다르고 내용은 완전히 같다. 둘의 관계는?
집합에는 순서가 없으니 같은 릴레이션이에요. 정렬은 사용자가 ORDER BY로 요청하는 거예요.

장면 3

학원생 중에 딱 한 명을 콕 집어내려면 무엇을 봐야 할까?

키 · 후보키 = 유일성 + 최소성

장면 2에서 "투플은 유일해야 한다"고 했죠. 그럼 투플끼리 무엇으로 구별할까요? 그게 키예요. 모든 릴레이션은 키를 최소 하나는 가져요. 키 없이는 릴레이션이 아니에요.

키가 될 자격, 후보키의 조건은 두 가지예요.

  • 유일성 — 그 값으로 모든 투플이 서로 달라야 해요. 단 1%라도 겹칠 수 있으면 탈락.
  • 최소성 — 꼭 필요한 속성만 있어야 해요. 하나를 빼도 여전히 유일하면 군더더기가 있는 거라 탈락.

최소성은 왜 따질까요? SQL은 키로 연산을 하는데, 키 속성이 많을수록 연산이 늘어나서 큰 시스템에선 느려져요. 모르면 "다 키로 지정해!" 하기 쉬운데 그러면 안 된다고 했어요.

교수님 예제: 학원생(이름, 학교이름, 학년, 반, 번호, 폰번호)

어느 조합이 후보키일까요? 직접 판단해 보고 표를 보세요.

후보유일성최소성결론
{폰번호}○ 사람마다 다름○ 속성 1개후보키
{학교이름, 학년, 반, 번호}○ 같은 반에 번호는 안 겹침○ 하나라도 빼면 겹침후보키
{이름, 폰번호}○✗ 이름 빼도 유일슈퍼키 (후보키 ✗)
{이름, 학교이름, 학년, 반}✗ 같은 반 동명이인 가능-키 아님
시험엔 이렇게

후보키 = 투플을 유일하게 식별하는 속성들의 최소 집합. 유일성 + 최소성을 모두 만족해야 한다.

외우는 법: 하나도 안 겹치고(유일) · 하나도 안 남게(최소)
바로 확인
{이름, 폰번호}가 후보키가 될 수 없는 이유는?
유일하긴 하지만 이름이 군더더기라 최소성을 못 지켜요. 속성 여러 개짜리(복합키)도 최소성만 지키면 후보키가 될 수 있어요.

장면 4

슈퍼키, 후보키, 기본키, 대체키. 가족 관계도를 그려 보자

키 포함 관계 · 기본키 선정 기준
  • 슈퍼키 — 유일성만 있으면 돼요. 최소성은 상관없어요. {이름, 폰번호}도 슈퍼키예요.
  • 후보키 — 유일성 + 최소성. 기본키가 될 수 있는 후보들.
  • 기본키 (PK) — 후보키 중에 하나를 골라 대표로 정한 것. 테이블엔 기본키가 하나예요.
  • 대체키 — 기본키로 뽑히지 못한 나머지 후보키. 여러 개일 수 있어요.

기본키는 어떻게 고를까?

후보키가 하나면 그게 바로 기본키. 여러 개면 이 기준으로 골라요.

  1. 잘 안 바뀌는 값 — 학년은 매년, 학과는 전과하면 바뀌니까 ✗
  2. 널(NULL)이 없는 값 — 널은 "아직 값이 안 들어왔다"는 뜻. 기본키는 비면 안 돼요
  3. 속성 개수가 적은 것
  4. 값의 크기가 작은 것 — "한신대학교 AI소프트웨어대학 AI소프트웨어계열…" 같은 긴 문자열 ✗

그래서 학원생 예제에선 폰번호가 기본키로 뽑힐 확률이 높고, {학교이름, 학년, 반, 번호}는 대체키가 돼요. 그리고 지금 들어 있는 데이터만 보고 정하면 안 돼요. 앞으로 들어올 값까지 예측해서 정해야 해요.

시험엔 이렇게

슈퍼키 ⊇ 후보키 ⊇ 기본키. 후보키 = 기본키 + 대체키. 기본키 선정 기준: 안 바뀌고, 널 없고, 속성 적고, 값 작은 것.

외우는 법: 슈 > 후 > 기 + 대 · 기본키는 안 변 · 널 X · 적게 · 작게
✗ 헷갈리는 생각후보키가 더 엄격하니까 슈퍼키를 포함한다
○ 맞는 생각조건이 느슨한 슈퍼키가 더 큰 집합. 모든 후보키는 슈퍼키다
바로 확인
후보키 {학번}, {주민번호}, {이메일} 중 {학번}을 기본키로 정했다. 나머지 둘은?
기본키로 뽑히지 못한 나머지 후보키 = 대체키. 여러 개일 수 있어요.

장면 5

출결 테이블을 따로 만들었다. 학생 테이블과 어떻게 이을까?

외래키 (FK)

학사 정보를 한 테이블에 다 넣으면 너무 커져요. 그래서 출결 정보, 수강 정보는 테이블을 따로 만들어요. 그런데 "이 출결 기록이 어느 학생 거지?"를 알려면 학생 테이블과 연결돼야 하죠. 그 다리가 외래키예요.

수강 테이블의 학번이 학생 테이블의 학번(기본키)을 가리킨다
학생 테이블수강 테이블
학번 (PK), 이름, 학년←학번 (FK), 과목번호, 평가학점

외래키는 다른 릴레이션의 기본키를 참조하는 속성이에요. 외래키 값은 참조하는 기본키 값 중 하나여야 해요. 학생 테이블에 없는 학번이 수강 테이블에 있으면 안 되겠죠. 교수님은 같은 릴레이션 안의 다른 속성을 가리키는 외래키도 있다고 했어요.

교수
키 종류는 엄청 많아요. 근데 여러분들이 사회에 나가서 쓰는 키는 기본키와 외래키, 이 정도만 이해하고 있으면 대부분 해결됩니다. 관계형 데이터베이스에서 가장 중요한 단어는 키예요.9/17 강의 중 (말을 조금 다듬음)
시험엔 이렇게

외래키 = 다른 릴레이션의 기본키를 참조하는 속성 집합. 릴레이션 사이를 잇는 연결 고리.

외우는 법: PK는 신분증, FK는 다른 테이블 신분증을 가리키는 손가락
바로 확인
수강(학번, 과목번호, 평가학점)의 학번이 학생 릴레이션의 학번을 가리킨다. 수강.학번은?
다른 릴레이션의 기본키를 참조하니 외래키예요. 외래키는 슈퍼키·후보키 포함 관계 그림과는 다른 축이에요.

  • 투플 유일성 · 투플 무순서성 · 속성 무순서성 · 속성 원자성
  • 다중 값 {축구, 야구} ✗ · 정렬은 사용자가 ORDER BY

③ 후보키 ★ 판별

  • 후보키 = 유일성 + 최소성
  • 학원생: {폰번호} ○ · {학교, 학년, 반, 번호} ○ · {이름, 폰번호} ✗ 최소성

④ 키 포함 관계 ★ 그리기슈 > 후 > 기 + 대

  • 슈퍼키(유일만) ⊇ 후보키 ⊇ 기본키(1개) · 나머지 = 대체키
  • PK 기준: 안 변 · 널 X · 적게 · 작게 (미래 값까지 고려)

⑤ 외래키

  • 외래키 = 다른 릴레이션의 기본키 참조 → 연결 고리

빈칸 채우기 눌러서 정답 확인

릴레이션의 열은 속성, 행은 투플이다. 속성의 개수를 차수, 투플의 개수를 카디널리티라 한다. 후보키는 유일성과 최소성을 모두 만족해야 하고, 슈퍼키는 유일성만 만족하면 된다. 후보키 중 기본키로 뽑히지 못한 것은 대체키, 다른 릴레이션의 기본키를 참조하는 것은 외래키다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
속성, 투플, 도메인을 한 줄씩?
속성 = 열. 투플 = 행(개체 하나). 도메인 = 속성이 가질 수 있는 값의 집합.
차수와 카디널리티, 어느 쪽이 동적?
카디널리티(투플 수)가 동적. 차수(속성 수)는 정적.
릴레이션 스키마 vs 인스턴스?
스키마 = 구조(머리글), 정적, 내포. 인스턴스 = 특정 시점의 투플 집합, 동적, 외연.
릴레이션의 특성 4가지는?
투플 유일성 · 투플 무순서성 · 속성 무순서성 · 속성 원자성
특성 4가지가 생긴 근본 이유는?
릴레이션이 집합이라서. 집합은 중복 원소가 없고 순서가 없다.
후보키의 두 조건은?
유일성(모든 투플이 다름) + 최소성(꼭 필요한 속성만).
슈퍼키와 후보키의 차이는?
슈퍼키는 유일성만, 후보키는 유일성 + 최소성.
기본키 선정 기준 4가지는?
잘 안 바뀌고, 널이 없고, 속성 수가 적고, 값의 크기가 작은 것.
대체키란?
기본키로 뽑히지 못한 나머지 후보키. 여러 개일 수 있다.
외래키란?
다른 릴레이션의 기본키를 참조하는 속성 집합. 릴레이션 사이의 연결 고리.

    퀴즈 다 풀고 채점하기

    Q1학생(학번, 이름, 주소, 학년, 나이, 성별, 휴대폰번호, 소속학과)에 투플 7개가 있다. 차수와 카디널리티는?

    속성 8개 → 차수 8, 투플 7개 → 카디널리티 7.

    Q2취미 속성에 {축구, 야구}처럼 두 값을 넣었다. 어떤 특성을 위반했나?

    한 칸엔 값 하나만(원자 값). 다중 값이 들어가면 릴레이션이 아니에요.

    Q3키의 포함 관계로 옳은 것은?

    조건이 느슨한 슈퍼키가 가장 크고, 그 안에 후보키, 그중 고른 게 기본키.

    Q4학원생 릴레이션에서 {이름, 학교이름, 학년, 반}이 키가 될 수 없는 이유는?

    단 1%라도 겹칠 수 있으면 유일성을 못 지켜요. 키 자격 자체가 없어요.

    Q5다음 중 기본키로 가장 부적합한 것은?

    학년은 매년, 학과는 전과하면 바뀌어요. 기본키는 잘 안 바뀌어야 해요.

    Q6학년 도메인을 {1, 2, 3, 4}로 정했는데 5를 입력하면?

    도메인은 속성이 가질 수 있는 값의 범위. 벗어나면 입력이 거부돼요.

    Q7수강 테이블의 학번이 학생 테이블의 학번(기본키)을 참조한다. 수강.학번은?

    다른 릴레이션의 기본키를 참조하는 속성 = 외래키.

    내 말로 설명하기 친구한테 말하듯이

    릴레이션에서 투플은 왜 유일해야 하고, 그게 "키"와 어떻게 연결되는지 설명해 보세요.

    릴레이션은 집합이라서 똑같은 원소(투플)를 두 번 가질 수 없어요. 실제로도 똑같은 줄이 두 개 있으면 DB가 어느 걸 찾거나 고치라는 건지 구별을 못 해요. 그래서 투플마다 서로 구별되는 값이 있어야 하고, 그 구별 수단이 키예요. 유일하게 구별만 되면 슈퍼키, 꼭 필요한 속성만 남기면 후보키, 그중 대표로 하나 고른 게 기본키예요. 기본키를 정해 두면 투플 유일성이 자연스럽게 지켜져요.
    더 알아두면 좋은 것 시험 비중 낮음

    관계형 데이터 모델의 3요소

    데이터 모델은 구조 · 연산 · 제약조건으로 이뤄져요. 관계형에서는 각각 릴레이션 · 관계 대수 · 무결성 제약조건이에요.

    왜 SQL보다 개념을 먼저 배울까

    SQL 명령은 AI나 검색으로 금방 만들 수 있어요. 하지만 도메인을 왜 정하고 기본키를 왜 정하는지 모르면 결과가 맞는지 판단할 수 없어요. 교수님은 앞으로 면접에서도 "SQL 짜 봐"보다 개념을 물어볼 거라고 했어요.

    유일한 값이 마땅치 않을 때

    개발자는 1, 2, 3… 일련번호를 붙이거나, 저장 시각 정보로 값을 만들어 넣어요. 저장한 그 순간은 다시 오지 않으니까 유일하죠.
