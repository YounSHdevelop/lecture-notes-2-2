장면 1

내 중간고사 80점은 데이터일까, 정보일까?

데이터 · 정보 · 가공 처리

출석, 중간 80, 기말 90, 리포트 95… 이걸 다 합쳐서 "A+"가 나왔다

점수 하나하나와 "A+"라는 결과. 둘 다 숫자·글자인데 무엇이 다를까요?

데이터는 현실에서 관찰하거나 수집한 그대로의 값이에요. 출석 횟수, 중간고사 80점, 기말 90점처럼 아무것도 손대지 않은 사실이죠. 가공 전이라서 로우 데이터(raw data)라고도 불러요.

정보는 그 데이터를 가공해서 의미를 붙인 결과예요. 점수들을 합산하고 "95점 이상이니까 A+"라고 판정하는 순간, 이건 학점을 정하는 데 쓰는 정보가 됩니다.

비유로 보면 — 레고 블록이 데이터, 그 블록을 열심히 조립해서 완성한 로봇이 정보예요. 블록은 많이 쌓여 있어도 그냥 블록이지만, 조립(가공)을 거치면 쓸모 있는 무언가가 됩니다.
교수
쉽게 설명하면 데이터를 내 것으로 만들어서 획득하는 것, 그게 정보라고 보시면 될 것 같습니다.9/3 강의 중 (말을 조금 다듬음)

여기서 말하는 "가공 처리"는 거창한 게 아니에요. 조건 검색, 정렬, 사칙연산 같은 간단한 것부터 복잡한 통계 처리까지 전부 포함됩니다. 숫자 3,000개를 그래프 한 장으로 그리는 것도 가공이에요.

그리고 하나 더. 데이터는 현실에서 비교적 쉽게 얻지만, 정보는 정보 시스템을 거치는 특별한 노력이 있어야 얻어져요.

시험엔 이렇게

데이터 = 관찰·수집된 그대로의 객관적 사실. 정보 = 데이터를 가공 처리해 의사 결정에 쓰도록 만든 결과.

외우는 법: 그대로면 데이터, 손대면 정보
✗ 이렇게 쓰면 틀려요"현실 세계에서 수집된 그대로의 값을 정보라 한다"
○ 맞게 쓰기그대로의 값은 데이터. 정보는 데이터를 처리해서 얻은 결과.
바로 확인
편의점 POS기에 찍힌 "오늘 삼각김밥 판매 기록 120건"을 모아 "점심엔 참치마요가 제일 잘 팔린다"고 정리했다. 정리한 결론은?
판매 기록 120건 하나하나는 그대로의 값이니 데이터. 그걸 모아 비교·정리해서 발주 같은 의사 결정에 쓸 수 있게 만든 결론은 정보예요.

시험에 "정보 시스템 구조를 그려라"가 나오면?

I = P(D) · 연쇄 흐름

장면 1의 내용을 그림 하나로 만든 게 정보 시스템 구조예요. 들어가는 건 D(Data), 가운데서 일하는 건 P(Process, 가공 처리), 나오는 건 I(Information). 식으로 쓰면 I = P(D)입니다. "정보는 데이터를 처리한 것"을 그대로 수식으로 쓴 거예요.

그림에서 제일 놓치기 쉬운 게 되돌아가는 점선이에요. 한 시스템이 만든 정보는 다른 사람이나 다른 시스템한테는 다시 입력 데이터가 됩니다. 그래서 같은 것이 관점에 따라 데이터도 되고 정보도 돼요. 이렇게 이어지면 I = P(P(P(D)))처럼 계속 겹쳐 씁니다.

예를 들어 학과 사무실이 만든 "학생별 평점"은 학과 입장에선 정보지만, 장학금 시스템 입장에선 장학생을 고르기 위한 입력 데이터예요.

교수님은 옛날과 지금의 차이도 짚었어요. 예전 파일 시스템 시절엔 데이터 하나가 처리 하나로 가는 1:1이었다면, 지금은 여러 데이터를 모아 정보 하나를 만드는 M:1이에요.

시험엔 이렇게

정보 시스템 구조 = 데이터(D) → 가공 처리(P) → 정보(I), I = P(D). 생성된 정보는 다른 시스템의 입력 데이터가 된다.

외우는 법: D · P · I 세 칸 + 돌아오는 화살표 하나
바로 확인
I = P(D)에서 P는 무엇일까?
P는 Process, 데이터를 정보로 바꿔 주는 가공 처리예요. 판단은 장면 4에서 나오는 맨 꼭대기 단계고, 저장은 DB의 역할입니다.

그래서 데이터베이스는 이 그림 어디에 있는데?

정보 시스템 · 데이터베이스의 역할

우리 학교 출결 관리 시스템은 어떻게 돌아갈까?

교수님이 직접 든 예시예요. 출석 체크부터 "결석 3회 경고"까지 따라가 봅시다.

  1. 수집 — 학생이 SQL을 직접 칠 수는 없으니까 웹페이지나 센서로 출석을 체크해요.
  2. 저장 — 체크된 기록이 데이터베이스에 쌓여요.
  3. 가공 — 쌓인 기록을 학생별로 세고 비교해요.
  4. 정보 — "이 학생 결석 3회" 같은 출결 정보가 나와요.

이 전체 흐름을 굴리는 소프트웨어가 정보 시스템이에요. 조직에 필요한 데이터를 수집·저장해 두었다가, 처리·가공해서 의사 결정에 필요한 정보를 만들어 주는 체계죠.

그리고 그 안에서 가공 전 데이터와 가공 후 정보를 담아 두고 필요할 때 꺼내 주는 저장소가 바로 데이터베이스예요. 저장소가 없으면 가공할 재료도, 결과를 둘 곳도 없으니 시스템이 돌아가지 않아요. 우리가 하루 종일 쓰는 휴대폰 앱 안에도 데이터베이스가 엄청 많이 들어 있습니다.

시험엔 이렇게

정보 시스템 = 데이터를 수집·저장했다가 처리·가공해 의사 결정용 정보를 만드는 소프트웨어 체계. 그 안의 저장·제공 담당이 데이터베이스.

외우는 법: 수집 → 저장 → 가공 → 정보, 저장 칸이 DB
바로 확인
출결 시스템 예시에서 "웹페이지·센서"가 맡은 역할은?
웹페이지·센서는 수집 통로예요. 저장소는 데이터베이스. 이 둘을 헷갈리게 내는 보기가 자주 나와요.

아이디어는 좋은데 왜 개발하면 망할까?

데이터 → 정보 → 지식 → 지혜 → 판단

교수님이 "이 그림을 굉장히 좋아한다"고 한 계단이에요. 아래부터 하나씩 쌓아 올라갑니다.

  • 데이터 — "학교 1층에 편의점, 카페, 식당이 있다", "매점 아침밥이 천 원". 그냥 사실이에요.
  • 정보 — 그 데이터를 가공한 결과. (장면 1)
  • 지식 — 정보를 내 것으로 만들어 쌓은 것. 야구 규칙을 모르면 타자가 뛰어가도 "뭐 하는 거야?"지만, 규칙을 알면 "홈런이구나!"가 보여요. 이건 직접 공부한 사람만 가질 수 있어요.
  • 지혜 — 쌓인 지식을 융합해서 새 연결을 찾는 것. "시장을 조사해 봤더니 이걸 예측하는 시스템이 없네?" 같은 발견이에요.
  • 판단 — AI 시대에 맨 위에 붙은 단계. 결국 의사 결정을 내리는 것. 인공지능은 데이터를 수집·처리·저장해서 인식·판단·행동을 돕는 역할이에요.
교수
아이디어는 좋아. 지혜는 좋아. 그런데 지식이 없어. 그 상태로 개발했어. 망하는 거예요. 지식이 있어야 코딩이 되고, 서비스를 만들 수 있고, 기술 개발도 분석도 마케팅도 됩니다.9/3 강의 중 (말을 조금 다듬음)

그래서 이 계단은 아래부터 쌓아야 해요. 지혜(아이디어)만 위에 떠 있고 지식이 비어 있으면 구현이 안 됩니다. 2학년인 지금은 데이터와 지식을 쌓는 시기라는 게 교수님 얘기였어요.

시험엔 이렇게

데이터 → 정보 → 지식 → 지혜 → 판단(의사 결정). 지식 없는 지혜로는 개발이 안 된다.

외우는 법: 데 · 정 · 지 · 지 · 판 (지가 두 번: 지식이 먼저, 지혜가 나중)

빈칸 채우기 눌러서 정답 확인

데이터는 현실 세계에서 관찰·수집의 결과로 나타난 객관적 사실이고, 정보는 데이터에 의미를 부여하거나 가공 처리를 해서 의사 결정에 쓰도록 만든 결과물이다. 이를 식으로 쓰면 I = P(D)이다. 생성된 정보는 다른 시스템의 입력 데이터가 된다. 정보 시스템 안에서 데이터를 저장했다가 제공하는 것은 데이터베이스다. 위계는 데이터 → 정보 → 지식 → 지혜 → 판단 순이다.

데이터의 정의는?
현실 세계에서 관찰·수집의 결과로 나타난 객관적 사실. 획득한 그대로의 값.
정보의 정의는?
데이터에 의미를 부여하거나 가공 처리해서 의사 결정에 쓰도록 조직한 결과물.
"가공 처리"에 들어가는 것은?
조건 검색·정렬·사칙연산 같은 간단한 것부터 복잡한 통계 처리까지 전부.
I = P(D)의 각 글자는?
I 정보, P 가공 처리, D 데이터.
I = P(P(P(D)))는 무슨 뜻?

정보 시스템이란?
데이터를 수집·저장했다가 처리·가공해서 의사 결정에 필요한 정보를 만드는 소프트웨어 체계.
정보 시스템 안에서 DB의 역할은?
가공 전 데이터와 가공 후 정보를 저장했다가 필요할 때 제공하는 저장소.
위계 5단계는?
데이터 → 정보 → 지식 → 지혜 → 판단 (데·정·지·지·판)
지식과 지혜의 차이는?
지식 = 정보를 내 것으로 쌓은 것. 지혜 = 지식을 융합해 새 연결을 찾는 것.
