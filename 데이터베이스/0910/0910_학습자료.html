장면 1

친구 주소를 적어 둔 파일 뭉치, 이건 DB일까 DBMS일까?

DB · DBMS · DBS

폴더 하나에 친구들 주소를 적은 파일을 잔뜩 넣어 뒀다고 해 봐요. 이 파일 뭉치 자체가 DB(데이터베이스), 즉 저장소예요.

그런데 이 파일은 누구나 열어서 고칠 수 있어요. 실수로 지우거나, 몰래 바꾸거나, 오류로 깨질 수 있죠. 그래서 파일 앞에 관리자 소프트웨어를 세워 둬요. "요청 받고 → 인증하고 → 허락하고 → 검증하고 → 백업까지" 대신해 주는 프로그램. 이게 DBMS(데이터베이스 관리 시스템)예요. 우리가 아는 Oracle, MySQL, MariaDB, PostgreSQL, MongoDB는 엄밀히 말하면 다 DBMS예요.

그리고 저장소(DB)와 관리자(DBMS)를 합쳐서 하나의 체계로 부를 때 DBS(데이터베이스 시스템)라고 해요.

교수
데이터는 신뢰성이 중요해요. 그리고 무결성, 내가 한 번 저장한 데이터는 소멸될 때까지 절대 변형되면 안 된다. DBMS가 생긴 이유는 딱 하나밖에 없어요. 데이터베이스가 오염되거나 불법으로 삭제되거나 오류가 나지 않게 잘 보완해 주는 거예요.9/10 강의 중 (말을 조금 다듬음)
시험엔 이렇게

DB = 저장소. DBMS = DB를 관리하는 소프트웨어. DBS = DB + DBMS를 모두 포함하는 개념.

은행 창구 직원, 앱 개발자, DB 관리자. 셋은 DB를 어떻게 쓸까?

사용자 3유형
  • 일반 사용자 — 둘로 나뉘어요. 초급은 DB가 있는지도 모르고 화면(UI)만 써요. 은행 앱으로 잔액 조회하는 우리 같은 사람이요. 중급은 기본 지식이 있어서 SQL로 직접 조회해요.
  • 응용 프로그래머 — C, Java, JSP, PHP 같은 언어로 프로그램을 만들고, 그 코드 안에 SQL을 넣어서 DB를 다뤄요. 보통 SQL만 따로 쓰지 않고 프로그램 코드 안에 넣어 씁니다.
  • DBA (데이터베이스 관리자) — DB를 기획·구축·운영·통제하는 슈퍼 사용자. 모든 권한과 최종 책임을 가져요. 보안 정책, 백업·회복, 성능 감시까지 다 해요.
교수
지금까지는 응용 프로그래머가 훨씬 더 인기가 많았어요. 그런데 AI 활용에서 데이터가 가장 중요해지니까, 앞으로는 데이터베이스 관리자 쪽을 하고 싶다는 질문을 많이 받을 것 같습니다.9/10 강의 중 (말을 조금 다듬음)
시험엔 이렇게

DB 사용자 = 일반 사용자(초급·중급) · 응용 프로그래머 · DBA(슈퍼 사용자, 모든 권한과 최종 책임)

장면 3

과제 표지 테이블 만들기, 학번 고치기, 조장 권한 주기. 각각 무슨 언어?

데이터 언어: DDL · DML · DCL (+ TCL)

사용자도, 프로그램도 DB에 직접 닿을 수 없어요. 반드시 DBMS한테 부탁해야 하죠. 그 부탁을 전달하는 말이 데이터 언어, 곧 SQL이에요. 목적에 따라 셋으로 나눠요. 교수님이 든 "과제 제출" 예시로 보면 바로 이해돼요.

① DDL (정의어) — 틀을 만든다

과제를 내려면 먼저 표지 테이블이 필요하죠. 과제명, 학과명, 학번, 이름, 담당 교수 칸이 있는 틀. 이렇게 테이블·열·제약 조건 같은 구조를 만들고 바꾸고 지우는 게 DDL이에요. "학번은 중요한 키로 정하고, 이름은 30자를 넘지 않게" 같은 제한도 DDL로 걸어요.

DDL 대표 명령어CREATE  -- 만들기
ALTER   -- 구조 바꾸기
DROP    -- 지우기

② DML (조작어) — 안에 든 값을 다룬다

틀이 생겼으니 학번, 이름, 과제명을 넣어야 하죠. 그런데 학번을 20001111로 잘못 넣었어요. 20001122로 고쳐요. 이렇게 데이터 값을 조회·삽입·수정·삭제하는 게 DML이에요. 주로 일반 사용자가 써요.

DML 대표 명령어SELECT  -- 조회
INSERT  -- 삽입
UPDATE  -- 수정
DELETE  -- 삭제

③ DCL (제어어) — 권한을 준다

팀 프로젝트에서 조장을 뽑았어요. 회의록 테이블은 조장만 수정할 수 있게 하고 싶어요. 나중에 조장이 바뀌면 권한을 다시 뺏어야 하고요. 이렇게 권한·보안을 제어하는 게 DCL이에요.

DCL 대표 명령어GRANT        -- 권한 주기
REVOKE       -- 권한 뺏기
CREATE USER  -- 사용자 계정 만들기 (CREATE로 시작해도 DCL!)

TCL은? 이해만 하고 넘어가요

"수강 신청 끝났으니 전교생 신청을 한 번에 막아라"처럼 여러 작업을 하나로 묶어 실행하거나 취소하는 게 트랜잭션 제어(TCL)예요. COMMIT(확정) · ROLLBACK(되돌리기) · SAVEPOINT(중간 저장). 교수님이 시험에는 안 낸다고 했어요. 교재에서는 COMMIT·ROLLBACK을 DCL에 넣기도 해요.

사용자주로 쓰는 언어
일반 사용자DML
응용 프로그래머DDL · DML (DCL 빼고)
DBADDL · DML · DCL 전부 — DCL은 DBA만
시험엔 이렇게

DDL = 구조 정의(CREATE·ALTER·DROP). DML = 데이터 조작(SELECT·INSERT·UPDATE·DELETE). DCL = 제어·권한(GRANT·REVOKE). DCL은 DBA만 쓴다.

외우는 법: 틀은 DDL · 값은 DML · 권한은 DCL
✗ 자주 틀리는 것테이블에 열 하나 추가하는 것도 "데이터를 조작"하니까 DML
○ 맞게 구별열 추가는 구조(틀)를 바꾸는 것 → DDL의 ALTER. 값을 바꾸는 UPDATE와 다름
바로 확인
학번을 20001111로 잘못 넣어서 20001122로 고쳤다. 어떤 언어의 어떤 명령어?
구조가 아니라 안에 든 값을 고친 거라 DML의 UPDATE. ALTER는 테이블 구조를 바꿀 때 써요.

엑셀은 클릭하면 열리는데, DB는 왜 이렇게 여러 단계를 거칠까?

DBMS 기능 · DBMS 구성 요소 · DB 서버

엑셀 파일은 더블클릭하면 바로 열리죠. DB는 달라요. 요청 → 인증 → 허락 → 검증 → 실행 → 백업. 번거로워 보여도 이 과정 덕분에 데이터가 정확하고 안전하게 지켜져요.

DBMS의 필수 기능 3가지

  • 정의 기능 — 데이터 구조를 정의 (DDL과 연결)
  • 조작 기능 — 데이터를 검색·삽입·수정·삭제 (DML과 연결)
  • 제어 기능 — 정확하고 안전하게! 동시성 제어, 무결성 유지, 보안·권한, 그리고 장애가 나면 회복. 교수님이 DBMS의 가장 큰 기능이라고 강조했어요.

DBMS 안을 들여다보면 (시험 그리기)

  • 프리컴파일러PHP 같은 프로그램 코드가 들어오면, 그 안에서 SQL 부분만 뽑아서 먼저 해석해 줘요.
  • 데이터 사전데이터 파일이 수십 개니까, "어떤 데이터가 어디에 어떤 형태로 있는지"를 사전처럼 적어 둔 곳. 데이터에 대한 정보예요.

웬만한 관계형 DBMS는 다 이 구조를 갖고 있어요. 그리고 이 전체가 돌아가는 컴퓨터가 DB 서버예요. 클라이언트가 접속해서 인증받고 수행하는 클라이언트/서버 환경이죠. 예전엔 비싼 전용 서버가 필요했지만, 지금은 일반 PC나 클라우드로도 충분해서 우리도 각자 노트북에 MySQL을 깔아 실습할 수 있어요.

시험엔 이렇게

DBMS 필수 기능 = 정의 · 조작 · 제어. 가장 중요한 건 제어(정확·안전, 동시성·무결성, 장애 시 회복).

외우는 법: 정 · 조 · 제 → 제어가 왕
바로 확인
여러 사용자가 동시에 접근해도 데이터를 정확하게 유지하고, 장애가 나면 백업으로 회복하는 기능은?
동시성·무결성·보안·회복은 전부 제어 기능이에요.

장면 5

데이터를 어떤 모양으로 쌓을까? 데이터 모델 5종

계층형 · 네트워크형 · 관계형 · 객체 지향형 · 객체 관계형

데이터 모델은 DB 구조를 표현하는 개념 틀(프레임워크)이에요. "데이터를 어떤 모양으로 쌓을까"를 정하는 설계도죠. 한 번 구축하면 바꾸기가 정말 힘들어서 처음에 잘 골라야 해요. DBMS를 분류하는 가장 중요한 기준이기도 해요.

  1. 계층형 — 회사 조직도 같은 트리. 맨 위 루트(학사 정보 시스템) 아래에 출결, LMS가 달려요. 부모 하나에 자식 여러 개(1:N)라 이해하기 쉽고 구축도 쉬워요. 대신 새 관계가 생기면 트리를 새로 만들어야 해요.
  2. 네트워크형 — 계층형의 단점을 보완해서 M:N을 허용해요. 학생 1·2·3이 과목 A·B·C를 여러 개씩 고를 수 있죠. 유연하지만 연결이 복잡해서 유지 관리가 힘들어요.
  3. 관계형 — 우리가 배울 것! 행과 열로 된 테이블에 데이터를 담고, 키로 테이블끼리 연결해요. 가장 많이 써요.
  4. 객체 지향형 — 객체 지향 언어의 개념을 가져와서 데이터를 객체 단위로 다뤄요.
  5. 객체 관계형 — 관계형과 객체 지향형을 섞은 절충형. 요즘 핫해요.

관계형 예시: 김학생이 어느 랩실에 배정됐는지 저장하고 싶다

학생 테이블에서 이름은 바뀔 수 있지만 학번은 절대 바뀌면 안 되는 키(기본키)예요. 랩실 배정 테이블을 하나 더 만들고, 거기서 학생의 학번을 참조하면 두 테이블이 연결돼요.

모델구조관계 표현한 줄 특징
계층형트리 (1:N)포인터쉽지만 새 관계마다 트리 새로
네트워크형네트워크 (M:N)포인터유연하지만 복잡
관계형테이블 (행·열)키가장 많이 씀
객체 지향형객체객체 식별자클래스·상속 개념
객체 관계형관계형 + 객체키 + 객체절충형, 요즘 주목
시험엔 이렇게

데이터 모델 = DB 구조를 명세하는 개념 틀. 계층형(트리 1:N) → 네트워크형(M:N) → 관계형(테이블·키) → 객체 지향형 → 객체 관계형

외우는 법: 계 · 네 · 관 · 객 · 객관 (나무 → 그물 → 표 → 객체 → 섞기)
바로 확인
학생 테이블의 학번을 랩실 배정 테이블에서 참조해 두 테이블을 연결했다. 어떤 모델?
테이블 + 키로 연결하면 관계형이에요. 계층형·네트워크형은 포인터로 연결해요.

① DB · DBMS · DBS ★

  • DBMS 존재 이유 = 데이터 신뢰성 · 무결성 보호

② 사용자 3유형

  • 일반 사용자(초급: UI만 / 중급: SQL) · 응용 프로그래머(코드 속 SQL) · DBA(슈퍼 사용자)

③ 데이터 언어 = SQL ★틀 · 값 · 권한

  • DDL 정의 = CREATE · ALTER · DROP (구조)
  • DML 조작 = SELECT · INSERT · UPDATE · DELETE (값)
  • DCL 제어 = GRANT · REVOKE · CREATE USER (권한) → DBA만
  • TCL(COMMIT · ROLLBACK · SAVEPOINT) 이해만, 시험 ✗

④ DBMS ★ 그리기정·조·제

  • 필수 기능 = 정의 · 조작 · 제어(가장 중요)
  • 컴파일러(DDL · DML) → 질의 처리기 → 런타임 처리기 → 트랜잭션 관리자 → 저장 데이터 관리자 → 데이터 사전 + 데이터 파일
  • DB 서버 = 클라이언트/서버 환경, 지금은 PC·클라우드도 OK

⑤ 데이터 모델 5 계·네·관·객·객관

  • 계층형(트리 1:N) → 네트워크형(M:N) → 관계형(테이블·키) → 객체 지향형 → 객체 관계형(절충)

빈칸 채우기 눌러서 정답 확인

DB를 관리하는 소프트웨어는 DBMS이고, DB와 DBMS를 모두 포함하는 개념은 DBS다. 구조를 정의하는 언어는 DDL, 데이터를 조작하는 언어는 DML, 권한을 제어하는 언어는 DCL이다. 권한을 주는 명령은 GRANT, 뺏는 명령은 REVOKE다. DBMS의 필수 기능 중 가장 중요한 것은 제어 기능이며, 관계형 모델은 테이블의 키로 관계를 표현한다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
DB, DBMS, DBS를 한 줄씩?
DB = 저장소. DBMS = DB를 관리하는 소프트웨어. DBS = DB + DBMS.
DBMS가 생긴 이유는?
데이터의 신뢰성과 무결성을 지키기 위해 (오염·불법 삭제·오류 방지).
일반 사용자 초급과 중급의 차이는?
초급은 DB 존재를 모르고 UI만 사용. 중급은 SQL로 직접 요청.
DBA란?
DB를 기획·구축·운영·통제하는 슈퍼 사용자. 모든 권한과 최종 책임.
DDL의 목적과 명령어는?
DB 구조(테이블·열·제약 조건) 정의. CREATE · ALTER · DROP.
DML의 목적과 명령어는?
데이터 값 조작. SELECT · INSERT · UPDATE · DELETE.
DCL의 목적과 명령어는?
권한·보안 제어. GRANT · REVOKE · CREATE USER. DBA만 쓴다.
TCL은 시험에 나오나?
안 나온다 (교수님). COMMIT · ROLLBACK · SAVEPOINT, 여러 작업을 하나로 묶어 실행·취소.
DBMS 필수 기능 3가지와 가장 중요한 것은?
정의 · 조작 · 제어. 가장 중요한 것은 제어.
데이터 사전이란?
데이터에 대한 정보(어떤 데이터가 어디에 어떤 형태로 있는지)를 저장한 곳.
데이터 모델 5종은?
계층형 · 네트워크형 · 관계형 · 객체 지향형 · 객체 관계형
관계형 모델은 관계를 무엇으로 표현하나?
테이블의 키 (학번 같은 기본키를 다른 테이블에서 참조).

    퀴즈 다 풀고 채점하기

    Q1데이터베이스와 데이터베이스 관리 시스템을 모두 포함하는 개념은?

    DBS = DB + DBMS. DBA는 사람, DDL은 언어예요.

    Q2"학생 테이블을 만들고, 학번을 키로 정하고, 이름은 30자를 넘지 않게 제한한다." 이 작업의 언어는?

    테이블·열·제약 조건 같은 구조(틀)를 만드는 건 DDL(CREATE).

    Q3팀 프로젝트에서 조장에게만 회의록 테이블 수정 권한을 주는 명령은?

    권한 부여 = DCL의 GRANT. 뺏을 땐 REVOKE.

    Q4"CREATE USER"로 새 사용자 계정을 만들었다. 어느 언어로 분류할까?

    CREATE로 시작해도 사용자 계정·권한을 다루면 DCL이에요. 함정으로 잘 나와요.

    Q5DCL을 쓸 수 있는 사용자는?

    DCL은 DBA만. 응용 프로그래머는 DDL·DML, 일반 사용자는 주로 DML.

    Q6프로그램 코드 안에서 SQL 부분만 뽑아 먼저 해석하는 DBMS 구성 요소는?

    PHP 같은 코드에서 SQL만 뽑아 컴파일하는 게 프리컴파일러예요.

    Q7트리 구조를 네트워크로 바꿔 M:N 관계를 쉽게 표현하지만 복잡해서 유지 관리가 힘든 모델은?

    계층형(1:N)의 한계를 넘은 게 네트워크형(M:N). 대신 복잡해요.

    내 말로 설명하기 친구한테 말하듯이

    "과제 제출" 상황 하나로 DDL · DML · DCL을 모두 설명해 보세요.

    과제를 내려면 먼저 과제명·학과·학번·이름·담당 교수 칸이 있는 표지 테이블이라는 틀을 만들어야 해요. 이게 DDL(CREATE)이에요. 그 틀에 내 학번과 이름을 넣고(INSERT), 학번을 잘못 넣었으면 고치는(UPDATE) 건 DML이에요. 팀 과제라면 회의록 테이블을 조장만 수정할 수 있게 권한을 주는(GRANT) 게 DCL이고, 이건 DBA만 할 수 있어요.
    더 알아두면 좋은 것 시험 비중 낮음

    DBA의 역할 10가지

    구성 요소 선정, DB 구조 정의, 물리적 저장 구조와 접근 방법 결정, 무결성 제약 조건 정의, 보안·접근 권한 정책, 백업·회복 기법 정의, 시스템 DB 관리, 성능 감시·분석, DB 재구성, 관련 의견 조정과 분쟁 해결. 학번처럼 "절대 바꾸면 안 되는 키"를 지정하는 것도 DBA예요.

    표준 SQL과 확장 SQL

    Oracle에서 되는 명령이 MariaDB에서 안 되기도 해요. DBMS마다 확장된 SQL이 있어서예요. 수업은 대부분 표준 SQL을 배워요.
