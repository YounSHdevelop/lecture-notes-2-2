로그인한 나를 서버가 알아보게 하는 세 가지 방법 (면접 단골)

Stateless 문제 · Cookie · Session · Token(JWT)

HTTP는 Stateless라 로그인 여부, 사용자 ID, 장바구니, 권한, 개인화 설정 같은 상태를 따로 유지해야 해요. 방법은 세 가지예요. 아이디가 hanshin인 사람이 로그인했다고 해 볼게요.

서버에 저장없음 (헤더에서 값 읽음)Session Store A7K9 → hanshin없음 (서명만 검증)
전송Request Header에 자동 포함Cookie 헤더로 ID 전송Authorization: Bearer …

틀린 생각세션은 서버에 있으니 브라우저에는 아무것도 없다

시험엔 이렇게

Cookie는 브라우저에 작은 데이터를 저장해 Request Header에 자동 포함한다(용량 · 보안 제한). Session은 실제 사용자 상태를 서버에 저장하고 브라우저엔 Session ID만 두어 서버가 ID로 사용자를 식별한다. Token은 인증 정보를 Token(대표적으로 JWT)으로 표현해 Request마다 서버에 전달하며 REST API · SPA에서 많이 쓴다.

바로 확인
로그인 후 브라우저 쿠키엔 sid=A7K9만 있고, 사용자 정보는 서버 저장소에 있다. 어떤 방식?
상태는 서버, 브라우저엔 ID만 = 세션.

HTTPS의 S를 실제로 해 주는 TLS는 무슨 일을 할까?

TLS 3요소 · SSL과의 관계 · 개발자 도구 Network 탭

HTTP 통신 자체엔 암호화가 없어서, 네트워크 구간에서 데이터가 노출되면 중요한 정보가 새요. 여기에 TLS(Transport Layer Security, 전송 계층 보안)를 적용한 게 HTTPS예요. TLS가 해 주는 건 세 가지예요.

기능뜻
암호화 (Encryption)대칭키 · 비대칭키를 조합해 제3자가 가로채도 내용을 못 읽게
무결성 (Integrity)통신 중 데이터가 변조 · 손실되지 않게
인증 (Authentication)접속한 서버(클라이언트)의 신원이 믿을 만한지 확인 (인증서)

SSL(Secure Sockets Layer)은 TLS의 구버전이에요. SSL의 보안 취약점을 보완해 업그레이드한 표준이 TLS. 그래서 "SSL 인증서"라는 이름만 남아 있어요. 서버에 인증서가 없으면 HTTPS 통신 자체가 안 돼요.

직접 확인: 크롬 F12 → Network 탭. Name · Status · Type · Size · Time이 보이고, 항목을 누르면 Request URL · Method · 헤더 · 페이로드 · 응답까지 볼 수 있어요. 404가 어디서 났는지, 어느 요청이 느린지 찾을 때 써요.

시험엔 이렇게

TLS는 인터넷에서 주고받는 데이터를 보호하는 보안 통신 프로토콜로 암호화(Encryption) · 무결성(Integrity) · 인증(Authentication)을 제공한다. SSL은 TLS의 구버전이다.

외우는 법: 암 · 무 · 인 — 가로채도 못 읽고 · 못 바꾸고 · 누군지 확인
바로 확인
TLS가 제공하는 기능이 아닌 것은?
TLS는 암 · 무 · 인. 압축은 아니에요.

장면 3

JS가 페이지 안을 바꾸는 통로, 브라우저를 바꾸는 통로

DOM · BOM · window 계층

JS는 브라우저가 주는 Web API(객체 모델)를 통해서만 페이지와 브라우저를 조작할 수 있어요. 통로는 두 개예요.

  • DOM(Document Object Model) — HTML 문서를 객체 기반 Tree로 표현한 것. 브라우저가 HTML을 파싱해 DOM Tree를 만들고, 각 요소는 Node가 돼요. JS는 DOM으로 요소를 찾고, 내용 · 속성 · 스타일 · 구조를 바꾸고, 요소를 생성 · 삭제하고, 이벤트를 처리해요.
  • BOM(Browser Object Model) — 브라우저 자체를 제어하는 객체 모음. 표준화된 하나의 Tree라기보다 여러 객체의 집합이고, 최상위가 window예요. location(현재 URL) · history(방문 기록) · navigator(브라우저 환경) · screen(화면 정보).

예를 들어 "뒤로가기 했다가 돌아오면 입력 내용이 남아 있는" 기능은 history(BOM)를 써요.

시험엔 이렇게

DOM은 HTML 문서를 객체 기반 Tree 구조로 표현하며 중심 객체는 document로, JS는 이를 통해 Element를 접근 · 조작한다(UI 변경). BOM은 브라우저 환경과 기능에 접근하기 위한 객체 집합으로 window 아래 location · history · navigator · screen이 있다.

외우는 법: DOM은 안(페이지) · BOM은 밖(브라우저) / window 아래 document만 DOM
바로 확인
현재 페이지의 URL을 읽으려면 어떤 객체? 어느 모델?
URL = location, window 아래 BOM.

글씨가 빨개졌는데, 바뀐 건 DOM일까 CSSOM일까?

CSSOM · 렌더링 파이프라인 · DOM 조작 실습 · 리렌더링

CSSOM(CSS Object Model)은 브라우저가 CSS를 해석해서 만든 스타일 정보의 객체 구조예요(Selector · Property · Value). DOM이 "무엇을 보여 줄까"라면 CSSOM은 "어떻게 보여 줄까"예요. 둘이 합쳐져서 화면이 돼요.

실습: 콘솔에 세 줄

F12 → Console (CSS엔 .active { color: red; font-weight: bold; }가 있음)const title = document.querySelector("#main_text");   // 요소 찾기
title.textContent = "Hello JavaScript";            // 글자 바꾸기
title.classList.add("active");                      // class 추가 → 빨갛고 굵게

글씨가 빨개졌으니 CSSOM이 바뀐 걸까요? 교수님이 "그대로겠지? 그대로겠지?" 하고 되물었죠. CSSOM은 그대로예요. CSS 규칙을 새로 만든 게 아니잖아요. 바뀐 건 DOM이에요. <h1 id="main_text">가 <h1 id="main_text" class="active">가 됐고, Render Tree가 CSSOM에서 .active 규칙을 찾아서 적용한 뒤 Layout · Paint를 다시 한 거예요. 이게 리렌더링이고, 새로고침 없이 화면이 바뀌는 이 개념이 React의 핵심이에요.

시험엔 이렇게

CSSOM은 CSS의 Selector와 Style Rule을 객체 구조로 표현한 것이며, DOM과 CSSOM이 결합되어 Render Tree를 만들고 Layout → Paint로 화면을 그린다. JS로 class를 추가하면 DOM이 변경되고 CSSOM은 그대로이며, 일치하는 CSS 규칙이 적용되어 다시 렌더링된다.

외우는 법: DOM은 무엇 · CSSOM은 어떻게 / DOM은 바뀌고 · CSSOM은 조회만 / 합(Render Tree) · 재(Layout) · 칠(Paint)
바로 확인
title.classList.add("active") 실행 후 바뀐 것은?
CSS 규칙은 원래 있었어요. DOM만 변경 → CSSOM 조회 → 리렌더링.

2015년에 나온 JS를 왜 "모던"이라고 부를까? 그리고 var는 왜 쓰지 말래?

Modern JS(ES6) · 타입 · Dynamic Typing · var / let / const · Scope

Modern JavaScript는 ES6(ES2015) 이후 추가된 문법을 적극 쓰는 JS예요. ES2015 = ES6 = ECMAScript2015 = ECMAScript6(연도 표기 vs 버전 표기). 더 간결하고 읽기 쉬운 코드, 함수형 스타일, Module 분리, 개선된 비동기 처리가 특징이고 React · Vue · Next.js의 기반이에요.

타입은 Primitive(String, Number, Boolean, null, undefined)와 Object(Object, Array, Function). JS는 Dynamic Typing이라 선언할 때 타입을 안 쓰고 엔진이 실행 중에 판단해요. 편하지만 age === 20에 문자열 "20"이 들어오면 조건이 틀어지죠. 그래서 나중에 TypeScript가 나와요(9주차 이후).

Scope는 변수 · 함수에 접근할 수 있는 유효 범위예요(Global · Function · Block). 이름이 같아도 Scope가 다르면 다른 변수고, JS는 코드가 작성된 위치로 Scope를 정해요(Lexical Scope).

실행 결과는?const globalValue = 10;
function example() {
  const localValue = 20;
  console.log(globalValue, localValue);   // 10 20
}
example();
console.log(localValue);   // ReferenceError: localValue is not defined

함수 안에선 바깥 globalValue도, 같은 블록의 localValue도 보여요. 하지만 함수 밖에선 localValue가 다른 Scope라 못 찾아요.

시험엔 이렇게

Modern JS는 ES6(2015) 이후 문법을 활용한다. var보다 let · const를 권장하며 let · const는 Block Scope를 갖고 재선언이 불가하다(const는 재할당도 불가). JS는 Lexical Scope를 기반으로 변수를 탐색한다.

외우는 법: const 기본 · let 변신 · var 금지
바로 확인
if (true) { let x = 1; } console.log(x);의 결과는?
let은 Block Scope. 중괄호 밖에서 x는 없어요. (var였다면 1)

+ 기호 범벅 문자열과 긴 function을 한 줄로

Template Literals · Arrow Functions
Template Literal — 백틱 + ${ }const message = "Hello " + name + "!";   // 기존
const message = `Hello ${name}!`;        // Modern — 간결, 여러 줄도 OK

Arrow Functionfunction add(a, b) { return a + b; }     // 기존
const add = (a, b) => { return a + b; };  // 화살표
const add = (a, b) => a + b;            // 한 줄이면 { }와 return 생략
const double = x => x * 2;              // 매개변수 하나면 ( )도 생략

React에서는 화살표 함수가 거의 표준이에요(onClick={() => …}). 단, 괄호 생략은 매개변수가 하나일 때만. 그리고 화살표 함수는 자기 this가 없다는 특징이 있는데, 그건 3주차(9/17)에 나와요.

Modern JS 키워드는 가독성 · 명확성 · 재사용성. 다음엔 Object · Array · Module · 비동기로 확장해요.

시험엔 이렇게

Template Literal(`Hello ${name}`)은 문자열 조합을 간결하게 하고 변수 삽입 · 여러 줄 문자열이 가능하다. Arrow Function((a, b) => a + b)은 함수를 간결하게 작성하며, 본문이 한 줄이면 중괄호와 return을, 매개변수가 하나면 괄호를 생략할 수 있다.

외우는 법: 문자열은 백틱에 ${} · 한 줄이면 중괄호 빼고 · 하나면 괄호 빼고
바로 확인
const name = "Kim"; const age = 20; console.log(`${name}은 ${age + 1}살`);의 출력은?
${ } 안은 JS 식으로 계산돼요. 20 + 1 = 21.

렌더링 파이프라인 순서는?
HTML → DOM, CSS → CSSOM → Render Tree → Layout → Paint → Composite.
classList.add("active")로 바뀌는 것은?
DOM만. CSSOM은 그대로, Render Tree가 .active 규칙을 찾아 적용 → Layout · Paint(리렌더링).
var 대신 let · const를 쓰는 이유는?
var는 Function Scope + 재선언 가능이라 추적이 어려움. let · const는 Block Scope + 재선언 불가.
화살표 함수 축약 규칙 2가지는?
본문 한 줄이면 중괄호 · return 생략, 매개변수 하나면 괄호 생략.
