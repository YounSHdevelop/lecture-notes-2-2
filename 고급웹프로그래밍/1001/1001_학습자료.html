Vite로 만든 React 프로젝트, 폴더마다 뭐가 들어 있지?

node_modules · public · src · package.json · npm install · npm run dev

지난 시간에 npm create vite@latest로 프로젝트를 만들었죠. 열어 보면 어떤 앱을 만들든 거의 같은 구조가 나와요. 교수님 말로 "이게 React의 기본 구조"예요.

폴더 · 파일들어 있는 것
node_modulesnpm으로 설치된 JavaScript 패키지(모듈)들
public정적 파일 (favicon 같은 아이콘). 없는 경우도 있음
src진짜 코드: JSX(컴포넌트)와 CSS. 보통 App.jsx ↔ App.css처럼 1:1
package.json어떤 패키지가 필요한지 정리한 목록
index.htmlReact가 그림을 그릴 빈 도화지 <div id="root">

그래서 Git에 올렸다가 다른 자리에서 clone해 오면 npm install 한 번이면 package.json을 보고 모듈을 다시 다 받아 와요. 교수님이 실습 때 Git에서 받아 온 코드를 바로 돌렸더니 "모듈이 없다(Module not found)" 오류가 났는데, npm install 하니까 해결됐죠.

실행은 터미널에서 npm run dev. 그러면 localhost 주소를 알려 줘요. 빌드하기 전까지는 이렇게 개발 서버로 확인해요.

시험엔 이렇게

node_modules = 설치된 패키지, public = 정적 파일, src = JSX · CSS 코드, package.json = 필요한 패키지 목록. clone 후 npm install로 패키지를 설치하고, npm run dev로 개발 서버를 실행한다.

외우는 법: 받고(install) · 돌리고(run dev)

HTML엔 div 하나뿐인데 화면은 어떻게 다 그려질까?

main.jsx · createRoot · #root · render · App
main.jsximport { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

getElementById('root') — index.html에 있는 <div id="root">를 DOM에서 찾아요.

createRoot — 거기를 뿌리(root)로 삼아요. 컴포넌트도 DOM도 트리라서, 뿌리 하나만 있으면 그 밑을 타고 타고 내려가며 그릴 수 있거든요.

.render(<App />) — 이 한 줄로 루트 밑 컴포넌트 트리 전체를 그려요. 시작점은 App.

그러니까 App.jsx의 return 안을 싹 비우고 원하는 태그나 다른 컴포넌트를 넣으면, 순서대로 화면에 그려지는 거예요. 장면 1의 index.html이 "빈 도화지"였던 이유가 이거예요.

시험엔 이렇게

main.jsx는 createRoot(document.getElementById('root'))로 index.html의 root 요소를 루트로 만들고, render(<App />)로 최상위 컴포넌트 App부터 컴포넌트 트리를 그린다.

외우는 법: 도화지(#root) → 뿌리(createRoot) → 그려(render) → App부터
바로 확인
index.html의 <div id="root">를 <div id="app">로 바꾸고 main.jsx는 그대로 두면?
main.jsx는 id가 'root'인 요소를 찾아요. 이름이 다르면 그릴 곳이 없어요.

카드 3장을 그렸는데 전부 "김민수"가 나왔다

Step 1 컴포넌트 재사용 · Step 2 Props · 구조 분해 할당

Step 1 프롬프트: "학생 이름 · 학과 · 학년을 보여 주는 StudentCard를 만들고 App.jsx에서 3번 렌더링해 줘. 아직 Props와 State는 쓰지 마."

AI가 "딸깍" 하고 <article> 안에 h2 · p · p로 된 StudentCard를 만들어 줬어요. 그런데 App에 3번 놓으니 김민수 · 컴퓨터공학과 · 2학년이 3장 똑같이 나와요. 값이 컴포넌트 안에 박혀 있으니까요. 붕어빵 틀은 하나인데 속재료를 못 바꾸는 상태죠.

그래서 Step 2: 이름 · 학과 · 학년을 Props로 받도록 바꿔요. Props는 그 컴포넌트를 호출하는 쪽(부모)이 넘겨줘요. 생긴 건 HTML 속성처럼요.

App.jsx — 부모가 넘김<StudentCard name="김민수" major="컴퓨터공학과" grade={2} />
<StudentCard name="이서연" major="경영학과" grade={3} />
<StudentCard name="박지훈" major="디자인학과" grade={1} />

StudentCard.jsx — 자식이 받음export default function StudentCard({ name, major, grade }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>학과: {major}</p>
      <p>학년: {grade}학년</p>
    </article>
  );
}

받는 쪽의 { name, major, grade }가 구조 분해 할당이에요. 원래는 props라는 객체 하나로 들어오는데, 그걸 바로 풀어서 변수처럼 쓰는 문법이에요. 숫자는 grade={2}처럼 중괄호로 넘긴다는 것도 봐 두세요.

장면 4

카드 하나에 좋아요를 누르면 다른 카드 숫자도 올라갈까?

Step 3 useState · handleLike · prev => prev + 1 · 독립된 State
StudentCard.jsx — Step 3import { useState } from 'react';

export default function StudentCard({ name, major, grade }) {
  const [likes, setLikes] = useState(0);   // 카드마다 자기 likes, 초깃값 0

  function handleLike() {
    setLikes((prev) => prev + 1);   // 이전 값 기준으로 1 증가 → 리렌더링
  }

  return (
    <article>
      <h2>{name}</h2>
      <button type="button" onClick={handleLike}>좋아요 {likes}</button>
    </article>
  );
}

읽는 순서대로 가 볼게요. 버튼 클릭 → onClick이 handleLike 호출 → setLikes가 이전 값에 1을 더해 State 변경 → 리렌더링 → 새 JSX 계산 → 버튼 숫자가 바뀜.

그리고 State는 카드마다 따로예요. 같은 틀로 찍었어도 각 카드가 자기 likes를 들고 있어서, 김민수 카드를 눌러도 이서연 카드 숫자는 그대로예요.

코드가 사람마다 달랐던 두 군데

  • prev => prev + 1 vs likes + 1 — 둘 다 1씩 오르긴 해요. prev 방식은 기존 State를 직접 안 건드리고 이전 값을 받아 쓰는 방식이라 더 안전해요(왜 안전한지는 10/6에 제대로 나와요). 교수님 말로 유료 모델은 prev, 무료 모델은 likes + 1이 나올 확률이 높았대요.
  • 함수를 따로 뺐나(handleLike) vs onClick 안에 바로 썼나 — 나중에 "좋아요 누르면 아이콘 바뀌는 애니메이션"처럼 할 일이 늘 수 있으니, 함수로 분리하는 게 유지보수에 좋아요.
시험엔 이렇게

각 StudentCard는 useState(0)로 자신만의 likes State를 가지며 서로 독립적이다. 클릭 → handleLike → setLikes(prev => prev + 1) → State 변경 → Re-render → 화면의 좋아요 수 갱신.

외우는 법: 틀은 같아도 State는 각자
바로 확인
카드 3장 중 김민수 카드의 좋아요를 2번, 이서연 카드를 1번 눌렀다. 박지훈 카드의 숫자는?
State는 카드마다 독립. 박지훈 카드는 안 눌렀으니 초깃값 0 그대로예요.

장면 5

좋아요를 다시 누르면 취소되게 하려면?

Mission · 토글 · 수정 모드 · AI 코딩 도구 쓰는 법

교수님이 프롬프트 없이 준 미션이 두 개예요. AI를 써도 되지만 코드를 분석하는 게 목적이에요.

  1. 좋아요 토글 — 다시 누르면 취소
  2. 학과 / 학년 수정 — 수정 버튼을 누르면 텍스트 박스로 바뀌고, 적용하기를 누르면 값이 바뀌며 리렌더링

둘 다 핵심은 "지금 어떤 상태인지를 State로 하나 더 들고 있는 것"이에요. 예를 들어 토글은 이렇게 풀 수 있어요.

토글 풀이 예시 (한 가지 방법)const [liked, setLiked] = useState(false);   // 눌렀는지 여부

function handleLike() {
  setLiked(prev => !prev);   // true ↔ false 뒤집기
}

<button onClick={handleLike}>{liked ? "좋아요 취소" : "좋아요"} {liked ? 1 : 0}</button>

수정 기능도 같은 생각이에요. isEditing State가 true면 input을, false면 글자를 보여 주고, 적용하기를 누르면 major · grade State를 바꾸고 isEditing을 false로.

교수님의 AI 코딩 팁

  • 코드를 짤 땐 추론(reasoning)을 낮게, 아이디어 · 프롬프트를 짤 땐 높게. "extra high 쓸 필요 없다. 돈만 날린다."
  • 프롬프트에 주석을 달라고 꼭 넣기. 안 그러면 나중에 코드를 이해 못 해요.
  • 마지막에 "왜 Props가 필요한가?"처럼 개념을 설명하게 시키기.
  • 코드는 GitHub에 올려 두기 (실습 PC 쓰는 사람은 특히).
시험엔 이렇게

화면이 바뀌어야 하는 조건(눌렀는지, 수정 중인지)은 State로 관리한다. true/false 토글은 setState(prev => !prev), 화면 분기는 삼항 연산자 조건 ? A : B로 표현한다.

외우는 법: 바뀌는 모드도 State · 뒤집기는 !prev
바로 확인
liked가 false인 상태에서 setLiked(prev => !prev)를 2번 실행(클릭 2번)하면 liked는?
false → true → false. 두 번 뒤집으면 제자리예요.

    Q4좋아요 버튼(초깃값 0)을 3번 클릭한 뒤 버튼 글자는? <button onClick={handleLike}>좋아요 {likes}</button>, handleLike는 setLikes(prev => prev + 1)

    클릭마다 이전 값 + 1 → 1, 2, 3. 중괄호 안 변수는 값으로 찍혀요.

    Q5카드 A의 좋아요만 5번 눌렀다. 카드 B(같은 StudentCard)의 likes는?

    State는 컴포넌트 인스턴스마다 독립이에요.

    Q6liked 초깃값 false, 클릭마다 setLiked(prev => !prev). 3번 클릭 후 {liked ? "취소" : "좋아요"}의 출력은?

    false → true → false → true. liked가 true라 "취소".

    Q7교수님이 말한 AI 코딩 도구 사용법으로 옳은 것은?

    코드는 낮은 추론으로, 주석을 달게 하고, 반드시 분석해요.

    내 말로 설명하기 실행 결과 서술 대비

    "StudentCard의 좋아요 버튼을 클릭했을 때 화면 숫자가 바뀌기까지의 과정을 Props · State · Re-render로 설명해 보세요."

    App이 StudentCard에 name · major · grade를 Props로 넘기고, StudentCard는 구조 분해 할당으로 받아 화면에 보여 줘요. 좋아요 수는 각 카드가 useState(0)로 만든 자기만의 likes State예요. 버튼을 클릭하면 onClick에 연결된 handleLike가 실행되고, setLikes(prev => prev + 1)로 State가 1 늘어요. State가 바뀌면 React가 그 컴포넌트를 다시 실행(Re-render)해서 새 JSX를 계산하고, 바뀐 숫자만 실제 화면에 반영해요. 다른 카드의 State는 독립이라 그대로예요.
