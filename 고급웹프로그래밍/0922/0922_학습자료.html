5초짜리 작업 하나에 화면 전체가 얼어붙는 이유

싱글 스레드 · 콜스택 · 동기 · Blocking

JavaScript는 싱글 스레드예요. 스레드는 작업을 처리해 주는 일꾼이라고 생각하면 되는데, 그게 하나뿐이에요. 그래서 함수들은 콜스택이라는 한 공간에 쌓였다가 하나씩 차례로 실행돼요.

문제는 세상엔 바로 안 끝나는 일이 많다는 거예요. 서버 응답을 기다리는 네트워크 통신, 몇 초 세는 타이머, 사용자가 언제 누를지 모르는 버튼 클릭… 이걸 동기(앞 작업이 끝나야 다음 작업)로 처리하면 기다리는 동안 다른 일을 못 해요.

더 큰 문제는 화면을 그리는 일도 같은 스레드에서 한다는 거예요. 교수님 예시처럼 아무리 잘 짜도 5초쯤 걸리는 longTask가 있으면, 그 5초 동안 이렇게 돼요. 이게 Blocking이에요.

Blocking 중에 멈추는 것 (자료 p.7)
① 다음 JS 코드 실행   ② 버튼 클릭 이벤트 처리   ③ 화면 업데이트   ④ 애니메이션 → 사용자는 페이지가 멈췄다고 느낌

동기 vs 비동기, 시간 차이

작업 4개를 동기로 하면 걸린 시간이 계속 더해져서 교수님 자료 예시로 28초까지 가요. 비동기로 동시에 진행하면 가장 긴 작업 하나(약 10초)만큼이면 4개가 다 끝나요.

동기 (Synchronous)코드 순서 = 실행 순서라 흐름은 이해하기 쉽다. 대신 오래 걸리는 작업이 끼면 전부 멈춤
비동기 · Non-blockingJS 스레드는 기다리지 않고 다른 작업을 계속, 작업이 끝나면 Callback으로 결과 처리
교수님 비유 — 비동기의 콜백은 부재중 전화 같은 거예요. 전화를 못 받아도 내 할 일 하다가, 찍혀 있으면 그때 다시 거는 거죠. "끝나고 나서 다시 알려 주는 것"이에요.
시험엔 이렇게

JS는 싱글 스레드(콜스택 1개)라 오래 걸리는 동기 작업이 있으면 Blocking이 발생해 코드 실행 · 이벤트 처리 · 화면 업데이트 · 애니메이션이 모두 멈춘다. Non-blocking에서는 JS 스레드가 다른 작업을 계속하고, 작업 완료 후 Callback으로 결과를 처리한다.

일꾼이 하나인데 어떻게 동시에 여러 일을 하지?

브라우저 멀티 스레드 · Web API 7가지

답은 JS가 직접 안 한다는 거예요. "싱글 스레드"는 JS 엔진 기준이고, 브라우저 자체는 여러 스레드를 써요(Single Thread ≠ Browser Has Only One Thread). 그래서 타이머 · 네트워크처럼 기다리는 일은 브라우저에 맡기고(Web API), JS는 다음 코드를 계속 실행해요. 브라우저가 일을 끝내면 결과(콜백)를 돌려줘요.

전부 브라우저가 제공하지만 JS로 호출해요. JS 엔진 자체 기능과 브라우저 기능을 구분하는 게 포인트예요. 교수님은 회사에서 WebSocket을 많이 썼다고 했어요. C++로 짠 AI 서버에 웹소켓으로 직접 연결하게 해서 빠르게 결과를 받게 했다고요.

시험엔 이렇게

JS 코드 실행은 하나의 Main Thread에서 이뤄지지만 브라우저 전체가 하나의 Thread만 쓰는 것은 아니다. Network · Timer · Rendering 등은 브라우저가 처리하며, JS는 Web API(Timer, DOM, Fetch, Event, Geolocation, WebSocket, Storage)를 통해 이를 사용한다.

장면 3

A, B, C, D 중 뭐가 먼저 찍힐까? (시험 단골)

태스크 큐 · 이벤트 루프 · 마이크로태스크 · 매크로태스크

이 코드의 출력 순서를 먼저 맞혀 보세요. (자료 p.24)

console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");

브라우저가 일을 끝낸 콜백은 바로 실행되지 않고 태스크 큐에 줄을 서요. 그리고 이벤트 루프가 계속 지켜보다가 콜스택이 비면 큐에서 꺼내 콜스택으로 옮겨 줘요. 교수님 자료 표현으로 "Event Loop는 JS 비동기 프로그래밍에서 가장 중요한 개념"이에요.

그런데 큐가 두 종류예요. 여기서 순서가 갈려요.

  • 마이크로태스크 — Promise의 then · catch · finally 콜백. "현재 JS 작업이 끝난 직후 우선 처리"하고, 큐가 빌 때까지 전부 처리해요.
  • 매크로태스크 — setTimeout · setInterval, 사용자 입력 이벤트 콜백, MessageChannel, 최초 <script> 실행. "브라우저가 처리할 하나의 큰 작업 단위". 마이크로가 다 비어야 하나 꺼내요.

그래서 답은 A → D → C → B. setTimeout을 0ms로 줘도 마지막인 이유가 이거예요. 그리고 자료 p.16에 있듯이 setTimeout(fn, 3000)은 3초 동안 JS를 멈추는 코드가 아니에요. "최소 3초 이후, 콜스택이 비었을 때 실행할 수 있도록 등록"하는 거라 3000ms는 정확한 시각이 아니라 최소 대기 시간이에요.

시험엔 이렇게

이벤트 루프는 콜스택이 비었는지 확인하고, 태스크 큐의 콜백을 꺼내 콜스택으로 옮긴다. 실행 우선순위는 동기 코드 → 마이크로태스크(Promise, 큐가 빌 때까지 전부) → 매크로태스크(setTimeout 등). setTimeout의 delay는 최소 대기 시간이다.

콜백 안에 콜백 안에 콜백… 이걸 어떻게 펴지?

Callback · 콜백 지옥 · Promise 3상태 · then / catch / finally

Callback은 실행할 함수를 다른 함수에 넘겨서, 작업이 끝나면 부르게 하는 방식이에요. 그런데 "로그인 끝나면 프로필, 프로필 끝나면 글, 글 끝나면 댓글…"을 콜백으로만 하면 안으로 계속 파고들어요.

Callback Hell (자료 p.19)login(user, () => {
  loadProfile(() => {
    loadPosts(() => {
      loadComments(() => { /* ... */ });
    });
  });
});

이게 콜백 지옥이에요. 교수님 말로 "가독성 당연히 떨어지고, 에러 처리 힘들고, 흐름 파악 · 유지 보수 문제가 많다"고 했죠.

그래서 나온 게 Promise예요. 비동기 작업이 최종적으로 성공했는지 실패했는지, 그리고 그 결과값을 나타내는 객체예요. 상태는 셋뿐이에요.

상태뜻이어지는 메서드

Fulfilled성공then (fulfilled · rejected 콜백 처리)

구조가 try · catch · finally랑 똑같죠. 순차 비동기를 안으로 파고들지 않고 아래로 줄줄이 이어 쓰는 게 핵심이에요.

시험엔 이렇게

Promise는 비동기 작업의 최종 완료 또는 실패와 그 결과값을 나타내는 객체로, Pending · Fulfilled · Rejected 세 상태를 가진다. then(후속 처리) · catch(에러 처리) · finally(항상 실행) 체이닝으로 Callback 중첩을 줄인다.

class가 Prototype의 포장지였다면, async는 뭘 포장했을까?

async / await · try / catch

지난 시간에 class가 Prototype을 쓰기 쉽게 감싼 문법이라고 했죠. 교수님이 "기억나는 사람?" 하고 물어본 그거예요. async / await도 똑같아요. Promise를 동기 코드처럼 쓰게 감싼 문법이에요.

async / await + try / catchasync function loadUser() {
  try {
    const response = await fetch("/api/user");  // 응답 올 때까지 이 함수만 대기
    const data = await response.json();          // response가 와야 json() 가능
    console.log(data);
  } catch (error) {                                // .catch()와 같은 목적
    console.error(error);
  }
}
  • async 함수는 항상 Promise를 반환해요. 그래서 바깥에서 then · catch를 붙일 수 있어요.
  • await는 Promise가 끝날 때까지 그 async 함수의 진행만 멈춰요. JS 스레드 전체가 Blocking되는 게 아니라서 화면은 계속 돌아가요.
  • 에러는 try-catch로. Promise의 .catch()보다 읽기 쉬운 경우가 많아요.
틀린 생각await를 쓰면 프로그램 전체가 멈춘다
맞는 생각await는 해당 async 함수의 진행만 멈춘다. 다른 코드 · 화면은 계속
시험엔 이렇게

async / await는 Promise를 동기 코드처럼 작성하게 해 주는 문법이다. async 함수는 항상 Promise를 반환하고, await는 Promise가 완료될 때까지 해당 함수의 진행만 일시 중지한다(JS 전체 Thread를 Blocking하지 않음). 에러는 try-catch로 처리한다.

외우는 법: class는 Prototype 포장 · async는 Promise 포장
바로 확인
async function f() { return 1; }에서 f()가 반환하는 것은?
async 함수는 항상 Promise를 반환해요. 그래서 f().then(v => …)로 1을 받아요.

서버가 404를 줬는데 왜 catch로 안 갈까?

Fetch API · Response Object · HTTP Error · GET / POST · Sequential vs Parallel · Promise.all

이 부분(자료 p.30~42)은 강의실 대신 온라인 강의로 대체된 범위예요. 그래도 강의자료에 있으니 시험 범위예요.

Fetch API는 브라우저에서 HTTP Request를 보내는 API예요. Promise를 반환하고 비동기로 동작해서, REST API와 데이터를 주고받을 때 많이 써요.

Response Object (자료 p.35)const response = await fetch(url);
// fetch 결과는 바로 JSON이 아니라 Response 객체!
response.status    // 200, 404, 500 …
response.ok        // 성공(200번대)이면 true
response.headers
await response.json();   // body를 JSON으로 (text(), blob()도 있음)

404 · 500은 자동으로 reject되지 않는다

HTTP Error Handling (자료 p.36)const response = await fetch(url);
if (!response.ok) {
  throw new Error(`HTTP Error: ${response.status}`);
}

서버가 404, 500을 돌려줘도 Promise 자체는 잘 동작한 거라 reject되지 않아요(통신은 성공했으니까요). 그래서 response.ok를 직접 확인하고 에러를 던져야 catch로 가요.

GET과 POST

GET — 조회 (기본값)const users = await (await fetch("/api/users")).json();

POST — 데이터 보내기await fetch("/api/users", {
  method: "POST",                                  // HTTP Method 지정
  headers: { "Content-Type": "application/json" },  // 데이터 형식 알림
  body: JSON.stringify({ name: "Kim", age: 20 })     // JS 객체 → JSON 문자열
});

Promise 보조 메서드: Promise.all()은 모두 성공해야 성공, Promise.allSettled()는 성공 · 실패 결과를 모두 확인. 그 밖에 race(), any()도 있어요.

시험엔 이렇게

Fetch API는 HTTP Request를 비동기로 보내고 Promise를 반환하며, 결과는 Response Object라 json() 등으로 변환해 쓴다. fetch는 404 · 500이어도 자동 reject되지 않으므로 response.ok로 확인한다. 의존성이 있으면 Sequential(await 순서대로), 독립적이면 Promise.all로 Parallel 처리한다.

404여도 Promise는 reject되지 않아요. 그래서 OK 404. 에러로 처리하려면 response.ok를 확인해 throw.

빈칸 채우기 눌러서 정답 확인

JavaScript는 싱글 스레드라 콜스택이 하나다. 오래 걸리는 작업은 브라우저의 Web API가 처리하고, 끝난 콜백은 태스크 큐에 들어간다. 이벤트 루프는 콜스택이 비면 큐의 콜백을 옮긴다. Promise는 마이크로태스크, setTimeout은 매크로태스크이며 앞의 것이 먼저 실행된다. async 함수는 항상 Promise를 반환한다. fetch의 결과는 Response 객체이며, 404여도 reject되지 않아 response.ok로 확인한다.

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
Blocking이 일어나면 멈추는 것 4가지는?
다음 JS 코드 실행, 클릭 등 이벤트 처리, 화면 업데이트, 애니메이션.
싱글 스레드인 JS가 비동기를 하는 방법은?
비동기 작업은 브라우저가 Web API로 처리하고, 결과를 Callback으로 돌려준다.
이벤트 루프의 역할 3단계는?
Call Stack이 비었는지 확인 → Queue에서 실행 가능한 Callback 꺼냄 → Call Stack으로 옮김.
매크로태스크 예시는?
setTimeout, setInterval, 사용자 입력 이벤트 callback, MessageChannel, 최초 <script> 실행.
마이크로태스크 예시와 특징은?
Promise(then/catch/finally). 현재 작업 직후 우선 처리, 큐가 빌 때까지 전부 처리한 뒤 매크로.
setTimeout(fn, 3000)의 3000ms의 의미는?
3초 동안 JS를 멈추는 게 아니라, 최소 3초 후 콜스택이 비었을 때 실행되도록 등록. 최소 대기 시간.
Promise의 3상태와 후속 메서드는?
Pending · Fulfilled · Rejected / then(후속) · catch(에러) · finally(항상).
async / await 핵심은?
async 함수는 항상 Promise 반환. await는 Promise 완료까지 해당 함수만 멈춤(전체 Thread X). 에러는 try-catch.
fetch 결과를 데이터로 쓰려면?
결과는 Response Object. await response.json()(또는 text, blob)으로 변환.
fetch에서 404 · 500 처리는?
Promise가 자동 reject되지 않음 → if (!response.ok) throw new Error(...)로 직접 처리.
Sequential vs Parallel Async는?
의존성 있으면 await로 순서대로(합산 시간), 독립이면 Promise.all로 병렬(가장 긴 시간).
Web API 7가지는?
Timer, DOM, Fetch, Event, Geolocation, WebSocket, Storage. (타 · 돔 · 페 · 이 · 지 · 웹 · 스)

    퀴즈 출력 순서 · 실행 결과 위주

    Q1log("Start"); setTimeout(()=>log("Timeout"),0); log("End");의 출력은?

    0ms여도 setTimeout 콜백은 매크로 큐로 가서 콜스택이 빈 뒤에 실행돼요. (자료 p.20)

    Q2log("Start"); Promise.resolve().then(()=>log("Promise")); log("End");의 출력은?

    then 콜백도 비동기(마이크로) → 동기 코드가 다 끝난 뒤. (자료 p.23)

    Q3setTimeout(()=>log("Timeout"),0); Promise.resolve().then(()=>log("Promise 1")).then(()=>log("Promise 2")); Promise.resolve().then(()=>log("Promise 3"));의 출력은?

    처음엔 Promise 1, 3만 마이크로 큐에. Promise 2는 1이 끝나야 들어가요. 마이크로를 빌 때까지 전부(1 → 3 → 2) 처리한 뒤 매크로 Timeout. (자료 p.26)

    Q4setTimeout(fn, 3000) 바로 뒤에 5초 걸리는 동기 작업이 있다. fn은 언제 실행되나?

    3000ms는 최소 대기 시간. 콜스택이 비어야 실행돼요.

    Q5다음 중 매크로태스크가 아닌 것은?

    Promise 후속 콜백은 마이크로태스크.

    Q6async 함수에 대한 설명으로 옳은 것은?

    async/await는 Promise 포장 문법. await는 그 함수만 멈춰요.

    Q7fetch로 서버에 데이터를 POST할 때 JS 객체를 보내는 올바른 방법은?

    JS 객체 → JSON 문자열(stringify). parse는 반대 방향.

    Q8서로 독립적인 loadUsers(), loadPosts()(각 1초)를 가장 빨리 끝내는 코드는?

    독립 작업은 병렬(Parallel) → 약 1초. 2번은 순차라 약 2초.

    내 말로 설명하기 서술형 대비

    "setTimeout(…, 0)과 Promise.then 중 무엇이 먼저 실행되며 왜 그런지 설명해 보세요."

    JS는 싱글 스레드라 콜스택이 하나뿐이에요. setTimeout과 Promise는 비동기라 콜스택에서 바로 실행되지 않고, 끝난 콜백이 태스크 큐에서 기다려요. 큐는 두 종류로, setTimeout 콜백은 매크로태스크 큐, Promise.then 콜백은 마이크로태스크 큐에 들어가요. 이벤트 루프는 콜스택이 비면 마이크로 큐를 빌 때까지 전부 처리한 뒤 매크로 태스크를 꺼내요. 그래서 0ms라도 Promise.then이 먼저 실행돼요. 우선순위는 동기 → 마이크로 → 매크로.
