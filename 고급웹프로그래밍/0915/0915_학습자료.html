함수를 부를 때마다 JS는 작은 작업 공간을 하나씩 만든다

Execution Context · Global / Function Context · Call Stack(LIFO)

Execution Context(실행 컨텍스트)는 JS 코드가 실행되는 환경이에요. 변수, 함수, Scope, this 같은 실행 정보를 여기에 저장해 두고 써요. 두 종류가 있어요.

  • Global Execution Context — 프로그램이 시작되면 가장 먼저 하나 만들어져서 끝까지 유지돼요. 전역 변수와 함수를 관리하고, 브라우저에선 전역 객체 window가 있어요.
  • Function Execution Context — 함수가 호출될 때마다 새로 만들어져요. 매개변수, 지역 변수, 내부 함수를 관리하고, 실행이 끝나면 사라져요. 같은 함수를 여러 번 부르면 그때마다 새로, 재귀 호출도 각각 독립적으로 생겨요.

이 컨텍스트들이 쌓이는 곳이 Call Stack이에요. 함수 호출 순서를 관리하는 자료구조로, 호출되면 위에 Push, 끝나면 Pop. 가장 마지막에 호출된 함수가 가장 먼저 끝나는 LIFO(Last In, First Out) 구조예요. JS는 이 콜스택을 하나만 써요(4주차 싱글 스레드와 연결!).

add(10, 20)을 부르면function add(a, b) {
  const result = a + b;
  return result;
}
add(10, 20);
// 호출 → add의 Context 생성(Push) → result 계산 → return → Context 제거(Pop)
시험엔 이렇게

Execution Context는 JS 코드가 실행되는 환경으로 변수 · 함수 · Scope · this 정보를 관리한다. 프로그램 시작 시 Global Execution Context가 생성되고, 함수가 호출될 때마다 Function Execution Context가 Call Stack에 추가되며 종료되면 제거된다. Call Stack은 LIFO 구조다.

외우는 법: 부르면 쌓고(Push) · 끝나면 뺀다(Pop) · 늦게 온 게 먼저 나간다(LIFO)
바로 확인
main()이 a()를 부르고, a()가 b()를 불렀다. 가장 먼저 Call Stack에서 빠지는 것은?
LIFO. 마지막에 들어간 b가 가장 먼저 끝나고 빠져요.

Global · Function · Block Scope · Lexical Scope

Scope는 변수 · 함수에 접근할 수 있는 유효 범위예요. Scope 밖의 변수엔 직접 접근 못 하고, 선언 위치에 따라 범위가 정해져요. 세 가지가 있어요.

Global Scope — 편하지만 위험

자료 p.11 · 실행 결과는?let discountRate = 0.1;   // 전역 상태
function calculatePrice(price) {
  return price * (1 - discountRate);
}
function startEvent() {
  discountRate = 0.3;     // 다른 함수가 전역을 바꿈
}
console.log(calculatePrice(10000));   // 9000
startEvent();
console.log(calculatePrice(10000));   // 7000

같은 인수를 넣었는데 결과가 달라졌죠. 전역 변수는 어디서나 접근할 수 있어서, 누가 언제 바꿨는지 추적하기 어렵고 이름 충돌과 의존성도 커져요. 그래서 현대 JS는 전역 상태를 줄이라고 해요.

Function Scope와 Block Scope

Function ScopeBlock Scope
범위함수 안{ } 안 (if · for · while 등)
대표var (Block을 무시하고 함수 단위)let, const
예function f(){ var m = "Hi"; } console.log(m); // Errorif(true){ let x = 1; } console.log(x); // Error

Lexical Scope — 어디서 "정의"됐냐가 기준

JS는 Lexical Scope예요. 함수가 어디서 호출됐는지가 아니라 어디서 정의됐는지로 Scope가 정해져요. 그래서 안쪽 함수는 자기를 감싼 바깥 함수의 변수에 접근할 수 있어요. 이게 장면 6 Closure의 기본 원리예요.

시험엔 이렇게

Scope는 변수 · 함수에 접근할 수 있는 유효 범위로 Global · Function · Block이 있다. 전역 변수는 변경 원인 추적이 어려워 줄이는 것이 권장된다. var는 Function Scope, let · const는 Block Scope를 가진다. JS는 함수가 정의된 위치로 Scope를 정하는 Lexical Scope를 쓴다.

외우는 법: 전역은 모두의 것이라 아무도 책임 안 진다 / var는 함수 단위 · let · const는 중괄호 단위 / 태어난 곳이 기준(Lexical)
바로 확인
if (true) { var a = 1; } console.log(a);의 결과는?
var는 Block Scope를 무시해서 if 밖에서도 보여요. let이었다면 ReferenceError.

변수를 못 찾으면 어디까지 찾아 올라갈까?

Scope Chain · ReferenceError · Variable Shadowing
자료 p.16const university = "한국대학교";        // 전역 스코프
function outer() {
  const department = "컴퓨터공학과";     // outer 스코프
  function inner() {
    const student = "김학생";           // inner 스코프
    console.log(student);      // 현재 스코프에서 찾음
    console.log(department);   // outer에서 찾음
    console.log(university);   // 전역에서 찾음
  }
  inner();
}
outer();

현재 Scope에서 변수를 못 찾으면 바깥 Scope로 한 칸씩 올라가며 찾아요. 이게 Scope Chain이에요. inner → outer → 전역 순서. 찾으면 거기서 멈추고, 전역까지 갔는데도 없으면 ReferenceError. 그리고 바깥에서 안쪽으로는 못 찾아요(역방향 ✗). outer에서 student를 찍으면 에러예요.

같은 이름이면? — Shadowing

자료 p.17 · 출력은?const name = "Global";
function example() {
  const name = "Local";
  console.log(name);   // Local
}
example();

안쪽 Scope에서 바깥과 같은 이름으로 선언하면 안쪽 변수가 바깥 변수를 가려요. 이게 Shadowing. 가장 가까운 변수가 먼저 쓰이니까요. 너무 많이 쓰면 읽기 어려워져요.

시험엔 이렇게

Scope Chain은 현재 Scope에서 변수를 찾지 못하면 상위 Scope를 순차적으로 탐색하는 구조이며, Global까지 없으면 ReferenceError가 발생한다. 안쪽 → 바깥 방향만 가능하다. Shadowing은 내부 Scope의 같은 이름 변수가 외부 변수를 가리는 현상이다.

외우는 법: 가까운 데부터 · 밖으로만 · 끝까지 없으면 에러 / 안에서 같은 이름이면 안쪽이 이긴다
바로 확인
let x = 1; function f() { let x = 2; function g() { console.log(x); } g(); } f();의 출력은?
g에 x 없음 → 한 칸 위 f의 x(2)에서 찾고 멈춤. 전역 1까지 안 가요.

var는 undefined, let은 에러, function은 정상 실행. 왜 셋이 다를까?

Hoisting · var Hoisting · TDZ · Function Hoisting

JS는 코드를 실행하기 전에 변수와 함수의 선언 정보를 먼저 처리해요(장면 1의 실행 환경을 먼저 구성하는 거죠). 그래서 선언이 코드 맨 위로 끌어올려진 것처럼 보이는데, 이걸 Hoisting이라고 해요. 진짜로 코드가 이동하는 건 아니에요. 그리고 선언 방식마다 결과가 달라요.

① var — 자료 p.19console.log(value);   // undefined (에러 아님!)
var value = 10;
// 개념적으로는 이렇게 동작:  var value;  console.log(value);  value = 10;

② let / const — 자료 p.20console.log(value);   // ReferenceError
let value = 10;

③ function 선언 — 자료 p.21hello();              // Hello (정상 실행)
function hello() { console.log("Hello"); }
선언 방식선언문 실행 전 상태선언문 이전에 접근하면
var선언 O · undefined로 초기화undefined
let, const선언 O · 초기화 안 됨 (TDZ)ReferenceError
function 선언함수 객체까지 초기화호출 가능

let · const도 선언 정보는 미리 처리되지만, 선언문에 도달하기 전까지는 접근 금지예요. 그 구간이 TDZ(Temporal Dead Zone). 선언 전에 변수를 써서 생기는 실수를 줄이려는 장치예요. 그래서 let · const가 var보다 안전해요.

시험엔 이렇게

Hoisting은 변수 · 함수 선언이 코드 실행 전에 처리되어 선언문보다 앞에서도 영향을 받는 현상이다(코드가 실제로 이동하지 않음). 선언 전 접근 시 var는 undefined, let · const는 TDZ로 인해 ReferenceError, Function Declaration은 함수 전체가 Hoisting되어 호출 가능하다.

외우는 법: var는 빈 상자(undefined) · let은 잠긴 상자(TDZ 에러) · function은 꽉 찬 상자(호출 OK)
바로 확인
console.log(n); var n = 5; console.log(n);의 두 출력은?
선언만 먼저 처리돼서 첫 줄은 undefined, 할당 후엔 5.

똑같은 add 함수인데, 위에서 부르면 어떤 건 되고 어떤 건 안 된다

Function Declaration · Function Expression · Arrow Function
세 가지 add — 자료 p.23function add(a, b) { return a + b; }          // Function Declaration
const add = function(a, b) { return a + b; };  // Function Expression
const add = (a, b) => a + b;                   // Arrow Function (표현식 형태)
  • Function Declaration — 함수 전체가 Hoisting돼서 선언문보다 먼저 호출해도 돼요.
  • Function Expression — 함수를 변수에 담은 것이라 그 변수의 Hoisting 규칙을 따라요. const면 TDZ → 선언 전에 부르면 ReferenceError.
  • Arrow Function — 역시 변수에 할당하는 함수라 선언 전에 호출할 수 없어요.
실행 결과는?sayHi();                          // ReferenceError (TDZ)
const sayHi = () => console.log("hi");

현대 JS에선 상황에 따라 Declaration과 Arrow Function을 같이 써요. React에서도 컴포넌트는 function 선언, 이벤트 핸들러는 화살표 함수를 자주 봐요.

시험엔 이렇게

Function Declaration은 함수 자체가 Hoisting되어 선언 전 호출이 가능하고, Function Expression과 Arrow Function은 변수의 Hoisting 규칙을 따르므로 선언 이후에만 사용할 수 있다.

외우는 법: function으로 시작하면 먼저 불러도 OK · 변수에 담았으면 변수 규칙
바로 확인
선언문보다 위에서 호출해도 정상 실행되는 것은?
Function Declaration만 함수 전체가 Hoisting돼요.

함수는 끝났는데 count는 어떻게 1, 2, 3 하고 계속 올라갈까?

Closure · 일급 객체 · Private State (정보 은닉)

Closure는 함수가 자신이 정의된 바깥 Scope의 변수를 기억하는 특성이에요. 바깥 함수 실행이 끝난 뒤에도 안쪽 함수는 그 변수에 계속 접근할 수 있어요. 함수와 그 주변 환경(Lexical Environment)이 같이 묶여 유지된다고 보면 돼요. 장면 2의 Lexical Scope가 원리예요.

Closure Sample — 자료 p.27function createCounter() {
  let count = 0;
  return function() {   // 안쪽 함수를 돌려줌
    count++;
    return count;
  };
}
const counter = createCounter();   // createCounter는 여기서 끝(Pop)
counter();   // 1
counter();   // 2
counter();   // 3

자료의 퀴즈: counter에 저장된 건 뭘까? 숫자 0이 아니라 함수(function() { count++; return count; })예요. createCounter는 끝나서 콜스택에서 빠졌지만, 돌려받은 안쪽 함수가 count가 있는 바깥 환경을 계속 붙잡고 있어서 호출할 때마다 1, 2, 3이 나와요.

Closure는 JS만의 개념은 아니고, 함수를 일급 객체로 다루는 언어의 특성이에요. 일급 객체란 함수의 인자로 넘기고, 반환값이 되고, 변수에 대입하고, 비교할 수 있는 것(1960년 크리스토퍼 스트래치의 정의).

Closure로 비밀 금고 만들기 — Private State

자료 p.29function createAccount() {
  let balance = 0;                  // 밖에서 직접 접근 불가
  return {
    deposit(amount) {
      if (!Number.isFinite(amount) || amount <= 0) return;   // 유효한 양수만
      balance += amount;
    },
    getBalance() { return balance; }
  };
}
const account = createAccount();
account.deposit(1000);
account.deposit(500);
console.log(account.getBalance());   // 1500
console.log(account.balance);        // undefined — 반환 객체의 속성이 아님

balance는 createAccount의 지역 변수라 밖에서 직접 못 건드려요. 공개된 deposit · getBalance만 Closure로 같은 balance에 접근하니, deposit의 검증 규칙을 거쳐야만 바꿀 수 있어요. 정보 은닉(캡슐화)이죠. Class가 나오기 전 JS에서 많이 쓰던 패턴이고, Event Handler · Callback · React Hook에서도 계속 쓰여요.

시험엔 이렇게

Closure는 함수가 자신의 외부 Scope 변수를 기억하는 특성으로, 외부 함수가 종료된 후에도 내부 함수가 외부 변수에 접근할 수 있다. Closure를 이용하면 외부에서 직접 접근할 수 없는 Private State를 만들어 특정 함수로만 상태를 읽고 수정하게 제한할 수 있다.

외우는 법: Closure = 가방 멘 함수 (태어난 곳의 변수를 가방에 넣고 다닌다) / counter에 든 건 숫자가 아니라 함수
바로 확인
const c1 = createCounter(); const c2 = createCounter(); c1(); c1(); c2(); — 마지막 c2()의 반환값은?
createCounter를 부를 때마다 새 count가 생겨요. c2는 자기 count라 1.

  • inner → outer → 전역 · 없으면 ReferenceError · 역방향 ✗
  • Shadowing = 안쪽 같은 이름이 바깥을 가림

④ Hoisting ★빈 상자 · 잠긴 상자 · 꽉 찬 상자

  • 선언 정보 먼저 처리(코드 이동 ✗)
  • var → undefined · let/const → TDZ · ReferenceError · function 선언 → 호출 가능
  • Expression · Arrow = 변수 규칙 → 선언 전 호출 ✗

⑤ Closure ★가방 멘 함수

  • = 외부 Scope 변수를 기억 · 외부 함수 종료 후에도 접근
  • createCounter → counter에 든 것 = 함수 · 1, 2, 3 · Private State(balance)

빈칸 채우기 눌러서 정답 확인

함수가 호출될 때마다 새로운 Execution Context가 Call Stack에 추가되며, Call Stack은 LIFO 구조다. 현재 Scope에서 변수를 못 찾으면 상위 Scope로 올라가는데 이를 Scope Chain이라 한다. 선언 전에 var 변수에 접근하면 undefined, let 변수에 접근하면 ReferenceError가 나며 이 구간을 TDZ라 한다. 함수가 외부 Scope의 변수를 기억하는 특성을 Closure라 한다.

플래시카드 알면 →, 모르면 ←

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
Execution Context란?
JS 코드가 실행되는 환경. 변수 · 함수 · Scope · this 정보를 관리. Global 1개 + 함수 호출마다 Function Context.
Call Stack의 구조는?
함수 호출 순서를 관리하는 LIFO 자료구조. 호출 시 Push, 종료 시 Pop. JS는 하나만 사용.
전역 변수를 줄여야 하는 이유는?
여러 곳에서 접근 · 변경 가능해 변경 원인 추적이 어렵고 이름 충돌 · 의존성이 커진다.
var와 let · const의 Scope 차이는?
var = Function Scope(Block 무시). let · const = Block Scope.
Lexical Scope란?
함수가 호출된 곳이 아니라 정의된 곳을 기준으로 Scope가 결정되는 방식. Closure의 기본 원리.
Scope Chain이란?
현재 Scope에 없으면 상위 Scope로 순차 탐색. Global까지 없으면 ReferenceError. 안 → 밖 방향만.
Shadowing이란?
내부 Scope에서 외부와 같은 이름으로 선언해 내부 변수가 외부 변수를 가리는 현상.
Hoisting이란?
선언이 코드 실행 전에 처리되어 선언문보다 앞에서도 영향을 받는 현상. 코드가 실제로 이동하지는 않음.
선언 전 접근: var · let/const · function은?
var → undefined. let/const → ReferenceError(TDZ). function 선언 → 호출 가능.
TDZ란?
Temporal Dead Zone. let · const가 선언문에 도달하기 전 접근할 수 없는 구간. 접근 시 ReferenceError.
Closure란?
함수가 외부 Scope 변수를 기억하는 특성. 외부 함수 종료 후에도 내부 함수가 접근 가능.
Closure로 Private State를 만드는 법은?
지역 변수(balance)를 두고 그것에 접근하는 함수들만 반환. 외부에선 직접 접근 불가(account.balance → undefined).

    퀴즈 실행 결과 문제 위주

    Q1console.log(a); var a = 3;의 출력은?

    var는 선언 O · undefined로 초기화된 상태.

    Q2console.log(b); let b = 3;의 결과는?

    let은 TDZ → 선언 전 접근 시 ReferenceError.

    Q3greet(); function greet() { console.log("hi"); }의 결과는?

    Function Declaration은 함수 전체가 Hoisting.

    Q4const name = "Global"; function ex() { const name = "Local"; console.log(name); } ex(); console.log(name);의 두 출력은?

    함수 안은 Shadowing으로 Local, 밖에선 전역 Global.

    Q5discountRate 예제에서 calculatePrice(10000) → startEvent() → calculatePrice(10000)의 출력은?

    startEvent가 전역 discountRate를 0.1 → 0.3으로 바꿔서.

    Q6const counter = createCounter(); counter(); counter(); 후 console.log(counter());의 출력은?

    Closure로 같은 count를 기억 → 1, 2, 3번째 호출이 3.

    Q7createAccount 예제에서 account.deposit(-100); console.log(account.getBalance()); (처음 상태)의 출력은?

    양수만 입금하는 검증에 걸려 return. balance는 0 그대로.

    Q8add(1, 2); const add = (a, b) => a + b;의 결과는?

    Arrow Function은 const 변수 규칙 → TDZ.

    내 말로 설명하기 주관식 대비

    "createCounter 예제에서 createCounter()가 이미 끝났는데도 counter()를 부를 때마다 1, 2, 3이 나오는 이유를 설명해 보세요."

    createCounter()를 호출하면 count가 0으로 초기화되고, count를 1 올려 반환하는 안쪽 함수가 반환돼요. counter에는 숫자가 아니라 이 안쪽 함수가 저장돼요. createCounter의 실행은 끝나서 Call Stack에서 빠지지만, JS는 Lexical Scope라 안쪽 함수는 자신이 정의된 바깥 환경(count가 있는 곳)을 기억하고 계속 접근할 수 있어요. 이게 Closure예요. 그래서 counter()를 부를 때마다 같은 count가 1씩 늘어나 1, 2, 3이 나와요. 외부에서는 count에 직접 접근할 수 없으니 정보 은닉에도 쓰여요.
