자세히: 9/8 페이지 · 9/10 페이지
Summary (2주차 자료 p.47)

외우는 법: 찾고(DNS) · 잇고(TCP/TLS) · 묻고(Request) · 받고(Response) · 그린다(Render) / DNS는 브 · 오 · 리

자세히: 9/22 페이지

JS는 Single Thread로 실행되고, 오래 걸리는 작업은 Browser Web API가 처리한다. Event Loop가 Callback 실행 시점을 관리한다. Promise는 비동기 작업의 상태와 결과를 표현하고, async/await로 Promise 코드를 간결하게 쓴다. Browser는 다양한 Web API를 제공하며 Timer와 Event도 비동기 구조를 쓴다. Fetch API로 HTTP Request를 수행하고 Response를 JSON 등으로 변환해 사용한다.

6주차 State Snapshot과 useEffect — 실행 결과가 제일 헷갈리는 곳

Summary (6주차 자료 p.25 · p.48)

Event Handler와 Effect의 역할을 구분하고, Effect는 외부 시스템 동기화가 필요할 때만.

7주차 React 아키텍처와 useReducer — 시험 범위의 끝

자세히: 10/13 페이지 · MVC · MVVM은 시험에 안 나옴
  • One-way data flow : 데이터는 부모 → 자식으로 Props(읽기 전용)를 통해, 이벤트는 부모가 내려 준 콜백 Props를 자식이 호출해 위로.
  • Lifting State Up : 여러 자식이 쓰는 state를 공통 부모로. state는 쓰는 곳에 최대한 가깝게.
  • 커스텀 훅 : 반복되는 state · effect 로직을 묶어 재사용(useWindowWidth). UI가 아닌 로직 재사용, 이름은 use~.
  • 서비스 레이어 : API 호출을 별도 JS 파일로 분리 → 재사용성 · 테스트 용이성.
  • UI State / Server State : 모달 · 토글 · 입력처럼 화면 안의 상태 / 서버에서 온 데이터(API로 갱신, 무결성).
  • useReducer : [state, dispatch] = useReducer(reducer, 초기값). UI는 dispatch(action), reducer는 (state, action) → 새 state(기존 state 수정 X).

① 2주차 Browser 찾고(DNS) · 잇고(TCP) · 묻고(Request) · 받고(Response) · 그린다(Render)

  • 주소창에 URL을 치면: DNS로 도메인을 IP로 바꾸고(브라우저 캐시 → OS 캐시 → 리졸버 순으로 찾음) → TCP/TLS로 서버와 연결 → Request를 보내고 → Response를 받아서 → Render Tree → Layout → Paint 순으로 화면에 그려요.
  • GET은 보낼 데이터를 URL에 붙이고, POST는 요청 Body에 담아요. HTTPS = HTTP + TLS(암호화). HTTP는 이전 요청을 기억 못 해서(Stateless) 로그인 상태 유지를 위해 쿠키 · 세션(세션 ID) · 토큰(JWT)을 써요.

② 2주차 DOM · JS DOM은 무엇 · CSSOM은 어떻게 · BOM은 브라우저 밖 환경

  • HTML로 만든 DOM과 CSS로 만든 CSSOM이 합쳐져서 Render Tree가 돼요. classList.add로 클래스를 붙이면 바뀌는 건 DOM뿐이고, CSSOM은 그대로예요(Render Tree가 그 클래스 규칙을 찾아 다시 그림). BOM은 window 아래 location · history · navigator 같은 브라우저 객체들.
  • let · const는 { } 블록 안에서만 살아요(Block Scope). 문자열 안에 변수를 넣을 땐 `${x}`, 짧은 함수는 (a, b) => a + b처럼 화살표 함수로 써요.

③ 3주차 ★var 빈 상자 · let 잠긴 상자 · function 꽉 찬 상자 / 원시는 값, 참조는 주소

  • 선언 전에 변수를 쓰면(호이스팅): var는 undefined, let은 ReferenceError(TDZ, 선언 전 접근 금지 구간), function 선언은 미리 호출해도 잘 돌아가요. 카운터를 클로저로 만들어 세 번 부르면 1, 2, 3(값이 기억됨).
  • this는 함수를 정의한 곳이 아니라 어떻게 호출했는지로 정해지고, 화살표 함수는 자기 this 없이 바깥 this를 써요. 객체를 다른 변수에 대입하면 값이 아니라 주소가 복사돼서 한쪽을 고치면 다른 쪽도 바뀌어요. class는 Prototype을 보기 좋게 포장한 문법이에요.

④ 4주차 ★동 · 마 · 매 = 동기 → 마이크로태스크 → 매크로태스크

  • 실행 순서는 동기 코드 → 마이크로태스크(Promise) → 매크로태스크(setTimeout). 그래서 console.log A · setTimeout B · Promise C · log D는 A D C B. Promise 1 · 3이 먼저 큐에 들어가고 2는 1이 끝나야 들어가서 Promise 1 → 3 → 2 → Timeout. setTimeout의 delay는 "정확히 그때"가 아니라 최소 대기 시간이에요.
  • async 함수는 무엇을 return하든 항상 Promise를 돌려줘요. fetch는 404가 와도 reject되지 않으니(네트워크 오류일 때만 reject) response.ok로 직접 확인해야 해요.

⑤ 5주차 붕어빵 = 틀(Component) · 속재료(Props) · 지금 상태(State)

  • Props는 부모가 자식에게 내려주는 값, State는 컴포넌트가 스스로 가진 값이에요. React는 Virtual DOM으로 바뀌기 전과 후를 비교해서 바뀐 곳만 실제 DOM에 반영해요(대신 메모리를 더 씀).

⑥ 6주차 ★사진(Snapshot)이면 2 · 릴레이(prev)면 4 / 배열 없으면 매번 · 빈 배열이면 처음만

  • State는 렌더링 순간 찍힌 사진(Snapshot)이라, count가 1일 때 setCount(count + 1)을 세 번 불러도 셋 다 1 + 1이라 결과는 2예요. 이어서 더하려면 prev => prev + 1처럼 이전 값을 받아 쓰면 4. 객체 · 배열 State는 원본을 고치지 말고 {...user}처럼 복사해서 새로 만들어요. 여러 컴포넌트가 같은 State를 써야 하면 공통 부모로 올려요(Lifting State Up).
  • useEffect의 두 번째 인자: 없으면 렌더링마다, [ ]면 처음(Mount) 한 번만, [x]면 x가 바뀔 때마다 실행. 타이머는 Cleanup(return 안에서 clearInterval)으로 정리해요. Effect 안에서 자기 의존값을 바꾸면 무한 루프가 나고, 버튼 눌러 초기화하는 일은 Effect가 아니라 Event Handler에서 해요.

빈칸 채우기 눌러서 정답 확인

HTTPS는 HTTP에 TLS를 결합한 것이다. HTTP는 Stateless라 로그인 유지에 쿠키 · 세션 · 토큰이 필요하다. 선언 전 var 접근은 undefined, let 접근은 ReferenceError다. 이벤트 루프는 동기 → 마이크로태스크 → 매크로태스크 순으로 처리한다. React는 Virtual DOM을 비교해 바뀐 부분만 반영한다. 같은 렌더에서 State는 Snapshot이라 연속 업데이트는 Functional Update를 쓴다. useEffect의 두 번째 인자가 []이면 Mount 때만 실행된다.

플래시카드 면접 단골 + Summary

키보드: Space 뒤집기 · → 알아요 · ← 모르겠어요
URL 입력부터 화면까지 순서는?
DNS Lookup → TCP/TLS 연결 → HTTP Request → Resource 반환 → Parsing · JS 실행 → Render Tree → Layout → Paint → Composite.
GET vs POST는?
GET: URL ?key=value, 공유 · 테스트 쉬움, 노출. POST: Body, 비노출, 직접 접근 어려움. 상황에 맞게.
HTTP vs HTTPS는?
HTTPS = HTTP + TLS → 암호화 + 서버 인증서 검증. TLS = 암호화 · 무결성 · 인증.
쿠키 · 세션 · 토큰은?
쿠키: 브라우저에 데이터. 세션: 서버에 상태 + 브라우저엔 Session ID. 토큰: JWT를 Authorization 헤더로.
classList.add 시 바뀌는 것은?
DOM만. CSSOM은 그대로, Render Tree가 규칙을 찾아 다시 그림.
Hoisting 3가지 결과는?
var → undefined, let/const → ReferenceError(TDZ), function 선언 → 호출 가능.
Closure란?
함수가 외부 Scope 변수를 기억하는 특성. 외부 함수 종료 후에도 접근. Private State에 활용.
this 결정 규칙은?
호출 방식: 단독 · 일반 함수 → window, 메서드 → 호출한 객체, new → 새 객체, 화살표 → 바깥 this.
Call by Value vs Reference는?
원시 타입은 값 복사, 객체는 힙 주소 복사 → 한쪽을 바꾸면 같이 바뀜. 객체 ===는 주소 비교.
이벤트 루프 우선순위는?
동기(콜스택) → 마이크로태스크(Promise, 전부) → 매크로태스크(setTimeout 등).
async / await 핵심은?
async는 항상 Promise 반환, await는 그 함수만 멈춤. 에러는 try-catch.
Virtual DOM은?
UI를 JS 객체로 메모리에 표현 → State 변경 시 새 결과 계산 → 비교 → 필요한 DOM만 변경. 메모리↑.
State == Snapshot의 결과 예시는?
count 1에서 setCount(count+1) ×3 → 2. prev => prev+1 ×3 → 4.
객체 State 변경법은?
setUser({ ...user, age: 21 }) — Spread(얕은 복사)로 새 객체를 만들어 교체(Immutable Update).
useEffect Dependency 3종은?
없음 → 매 Render 이후. [] → Mount 1회. [value] → Mount 후 + value 변경 시.

    내 말로 설명하기 주관식 필기 대비

    "React에서 버튼 클릭으로 setState를 호출했을 때부터 화면이 바뀌기까지를 State · Re-render · Virtual DOM으로 설명해 보세요."

    버튼의 onClick 이벤트 핸들러에서 setState(Setter)를 호출하면 React가 새 State 값을 반영할 준비를 하고 해당 컴포넌트 함수를 다시 실행해요(Re-render). 이때 State는 렌더링 시점의 Snapshot이라 setter를 부른 그 줄에서 바로 값이 바뀌지 않고 다음 렌더링에서 새 값이 쓰여요. Render 단계에서 새 JSX(새 Virtual DOM)를 계산해 이전 Virtual DOM과 비교하고, Commit 단계에서 바뀐 부분만 실제 DOM에 반영하면 브라우저가 Layout · Paint로 화면을 다시 그려요. 실제 DOM 전체를 다시 만들지 않아서 빠르고 깜빡임이 적지만, UI 복사본을 메모리에 들고 있어 메모리를 더 써요.
