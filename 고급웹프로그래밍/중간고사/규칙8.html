선언하기 전에 쓰면 undefined일까, 오류일까?

Hoisting · var · let · const · function · 3주차 (0915)

JS는 코드를 돌리기 전에 선언만 먼저 훑어 둬요. 이게 Hoisting이에요. 그런데 상자마다 상태가 달라요. var는 빈 상자라 꺼내면 undefined, let · const는 잠긴 상자라 꺼내면 ReferenceError(TDZ), function 선언은 이미 다 채워진 상자라 위에서 불러도 그냥 실행돼요.

예제 · 출력을 먼저 맞혀 보세요console.log(a);
var a = 1;
// → undefined (선언만 위로, 값은 제자리)

console.log(b);
let b = 2;
// → ReferenceError (TDZ)

hi();
function hi() { console.log("hi"); }
// → hi (함수 선언은 통째로 위로)
규칙

선언 전에 쓰면 var는 undefined, let · const는 ReferenceError(TDZ), function 선언은 정상 호출. 함수 표현식 · 화살표 함수는 변수 규칙을 따른다.

외우는 법: var 빈 상자 · let 잠긴 상자 · function 꽉 찬 상자
바로 확인
hey(); const hey = () => console.log("hey"); 결과는?
화살표 함수는 const 변수에 담긴 거라 변수 규칙을 따라요. const는 잠긴 상자 → ReferenceError. function 선언이었다면 hey가 찍혔을 거예요.
바로 확인
function g() { console.log(v); var v = 3; } g(); 결과는?
함수 안에서도 똑같아요. var v의 선언만 함수 맨 위로 올라가고 = 3은 제자리라 undefined.

규칙 2

함수가 끝났는데 변수가 왜 아직 살아 있지?

Scope Chain · Shadowing · Closure · 3주차 (0915)

변수를 찾을 때는 안에서 밖으로만 찾아요(Scope Chain). 안쪽에 같은 이름이 있으면 그게 이겨요(Shadowing). 그리고 함수는 태어난 곳의 변수를 가방에 넣고 다녀요. 바깥 함수가 끝나도 그 변수가 살아 있는 게 Closure예요. 함수를 새로 만들 때마다 가방도 새것이에요.

예제 · 카운터 두 개function makeCounter() {
  let count = 0;
  return () => ++count;
}
const c1 = makeCounter();
const c2 = makeCounter();
c1(); c1();
console.log(c1(), c2());
// → 3 1
// c1, c2는 가방(count)을 따로 가짐
규칙

변수는 안쪽 Scope부터 바깥으로 찾는다(같은 이름이면 안쪽이 가린다). Closure는 바깥 함수가 끝난 뒤에도 그 변수를 기억하고, 만들 때마다 따로 기억한다.

외우는 법: 찾기는 안 → 밖 / Closure = 가방 멘 함수
바로 확인
let x = 1; function f() { let x = 2; console.log(x); } f(); console.log(x);
f 안에서는 안쪽 x(2)가 바깥 x를 가려요(Shadowing). 밖에서는 바깥 x 그대로 1. → 2 1.
바로 확인
위 makeCounter로 c1(); c2(); c2(); console.log(c1()); (c1, c2 새로 만든 상태)
c2를 몇 번 부르든 c1의 가방과는 상관없어요. c1은 두 번째 호출이라 2.

규칙 3

this는 도대체 누구를 가리킬까?

this 바인딩 · 메서드 · 화살표 함수 · new · 3주차 (0917)

this는 함수를 어떻게 불렀는지로 정해져요. obj.a()처럼 점 앞에 객체가 있으면 그 객체, 점 없이 혼자 부르면 window, new로 부르면 새로 만든 객체예요. 화살표 함수는 자기 this가 없어서 바깥의 this를 그대로 써요. 객체 안에 화살표를 써도 바깥은 window예요.

예제 · 브라우저 기준var who = "window";
const obj = {
  who: "obj",
  a() { console.log(this.who); },
  b: () => console.log(this.who),
};
obj.a();
// → obj (점 앞 = obj)
obj.b();
// → window (화살표 = 바깥)
규칙

this는 호출 방식으로 정해진다: 혼자 호출하면 window, 메서드로 호출하면 점 앞의 객체, new면 새 객체, 화살표 함수는 바깥 this(Lexical this).

외우는 법: 점 앞이 this · 점 없으면 window · new면 새것 · 화살표는 바깥
바로 확인
위 코드에서 const f = obj.a; f(); 결과는? (브라우저)
함수를 꺼내서 점 없이 불렀어요. 정의된 곳이 obj여도 this는 부른 방식이 정해요 → window의 who = "window".
바로 확인
const o = { v: 1, show() { return this.v; } };
const p = { v: 2, show: o.show };
console.log(p.show());
같은 함수라도 p.show()로 불렀으니 점 앞은 p → 2.

규칙 4

복사본을 고쳤는데 원본까지 바뀐다고?

값 복사 · 주소 복사 · Spread · 얕은 복사 · 3주차 (0917) · 6주차 (1006)

숫자 · 문자 같은 기본 타입은 값이 복사돼요. 그런데 객체 · 배열은 주소가 복사돼요. 그래서 q = p는 같은 집 주소를 하나 더 적은 거라, q로 고치면 p도 바뀌어요. {...p}(Spread)는 새 집을 짓는 거라 원본이 안 바뀌어요. 단, 겉 한 겹만 새로 지어요(얕은 복사).

예제let a = 1; let b = a; b = 2;
console.log(a);   // → 1

const p = { age: 20 };
const q = p;  q.age = 30;
console.log(p.age);   // → 30

const r = { ...p };  r.age = 99;
console.log(p.age);   // → 30
규칙

기본 타입은 값 복사, 객체 · 배열은 주소 복사(같은 객체를 공유). Spread(...)는 새 객체를 만들지만 얕은 복사라 안쪽 객체는 공유한다. 객체 ===는 주소를 비교한다.

외우는 법: = 은 주소 한 장 더 · ... 은 새 집(겉만)
바로 확인
console.log({ x: 1 } === { x: 1 });
내용이 같아도 객체 두 개를 따로 만들었으니 주소가 달라요 → false. "이름은 둘 다 홍길동, 주소는 다르다."
바로 확인
const u = { info: { age: 1 } };
const c = { ...u }; c.info.age = 5;
console.log(u.info.age);
Spread는 겉 한 겹만 새로 만들어요. 안쪽 info 객체는 주소가 그대로 복사돼서 공유 → 5.

규칙 5

setTimeout 0초인데 왜 맨 마지막에 찍힐까?

이벤트 루프 · 동기 → 마이크로 → 매크로 · 4주차 (0922)

교수님이 "시험 문제에 나오기 딱 좋겠죠"라고 한 부분이에요. 순서는 딱 하나만 기억하면 돼요. 동기 코드를 위에서부터 전부 실행하고, 그다음 마이크로태스크(Promise의 then, await 다음 줄)를 전부, 마지막에 매크로태스크(setTimeout)를 실행해요. setTimeout의 0초는 "최소 0초 기다려라"라는 뜻이라 줄을 서야 해요.

예제console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve()
  .then(() => console.log(3));
console.log(4);
// → 1 4 3 2
// 동기(1, 4) → 마이크로(3) → 매크로(2)
규칙

실행 순서는 동기 코드 → 마이크로태스크(Promise, 큐가 빌 때까지 전부) → 매크로태스크(setTimeout). await는 그 함수만 멈추고, 나머지 코드는 계속 실행된다.

외우는 법: 동 · 마 · 매 — 약속(Promise)이 타이머보다 먼저
바로 확인
async function f() {
  console.log("A"); await null; console.log("B");
}
f(); console.log("C");
f를 부르면 A는 바로(동기) 찍혀요. await에서 f만 멈추고 밖으로 나와 C를 찍고, B는 마이크로태스크로 나중에 → A C B.
바로 확인
setTimeout(() => log("x"), 100);
setTimeout(() => log("y"), 0);
log("z");
동기 z가 먼저. 타이머 둘 중엔 기다리는 시간이 짧은 y(0)가 먼저, x(100)가 나중 → z y x.

규칙 6

setCount를 3번 불렀는데 왜 1만 올라갈까?

State Snapshot · Functional Update · 6주차 (1006)

State는 그 렌더링 순간을 찍은 사진(Snapshot)이에요. 이번 렌더링 안에서는 count가 계속 같은 값이에요. 그래서 setCount(count + 1)을 세 번 불러도 셋 다 "0 + 1 = 1로 해 줘"라는 같은 부탁이에요. 앞의 결과를 이어받으려면 setCount(prev => prev + 1), 함수형 업데이트를 써요. 그리고 setter를 부른 바로 다음 줄에서 count를 찍어도 아직 옛날 값이에요.

예제 · count = 0에서 버튼 클릭setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
console.log(count);
// 콘솔 → 0 (아직 사진 속 값)
// 다음 렌더 count → 1

setCount(prev => prev + 1);  // ×3이면
// 다음 렌더 count → 3
규칙

State는 렌더링 시점의 Snapshot이라 setter를 호출해도 현재 코드의 값은 바뀌지 않는다. 이전 값에 의존하면 setCount(prev => prev + 1) 같은 Functional Update를 쓴다.

외우는 법: count는 사진 · prev는 릴레이 (1에서 +1 ×3: 사진이면 2, 릴레이면 4)
바로 확인
count가 1일 때 setCount(count + 1)을 세 번 호출했다. 다음 렌더의 count는?
셋 다 사진 속 1을 보고 "2로 해 줘" → 2. 함수형이었다면 1→2→3→4.
바로 확인
count가 3일 때 setCount(c => c * 2); setCount(c => c + 1); 다음 렌더의 count는?
둘 다 함수형이라 이어받아요. 3 × 2 = 6, 6 + 1 = 7.

규칙 7

useEffect는 언제, 몇 번 실행될까?

Dependency Array · Cleanup · Mount · Unmount · 6주차 (1008)

useEffect는 화면을 그린 뒤 실행돼요. 언제 다시 실행할지는 두 번째 칸(의존성 배열)이 정해요. 없으면 매번, [ ]이면 처음 한 번(Mount), [n]이면 처음 + n이 바뀔 때. 그리고 Effect가 return하는 함수가 Cleanup인데, 다시 실행하기 직전과 사라질 때(Unmount) 불려요.

예제 · 몇 번 찍힐까useEffect(() => log("A"));
useEffect(() => log("B"), []);
useEffect(() => log("C"), [n]);
// Mount       → A B C
// n 바뀜      → A C
// 다른 State만 → A
규칙

의존성 배열이 없으면 매 Render 후, []이면 Mount 시 1회, [value]면 Mount 시 + value 변경 시 실행된다. Cleanup은 Effect 재실행 전과 Unmount 시 실행되어 Timer 등을 정리한다.

외우는 법: 없으면 매번 · 비면 처음만 · 넣으면 바뀔 때 / return = 소멸자
바로 확인
useEffect(() => log("E"), [a, b]); Mount 후 a가 1번, b가 1번, c가 1번 바뀌었다. E는 몇 번?
Mount 1 + a 1 + b 1 = 3번. c는 배열에 없으니 무시.
바로 확인
useEffect(() => {
  log("start");
  return () => log("stop");
}, [n]);
Mount 후 n이 한 번 바뀌었다. 찍힌 순서는?
Mount에 start. n이 바뀌면 새 Effect 전에 Cleanup(stop) → 다시 start. 컴포넌트가 사라지면 그때 stop이 한 번 더 찍혀요.

규칙 8

dispatch를 몇 번 하면 state는 뭐가 될까?

useReducer · Action · Immutable Update · 7주차 (1013 · 1015)

useReducer는 State 바꾸는 규칙을 reducer 함수 하나에 모아 둔 거예요. 버튼은 dispatch({ type: ... })로 "이 일 해 줘"만 보내고, reducer가 action.type을 보고 새 State를 만들어 반환해요. 모르는 type이면 default에서 state 그대로. 시험에선 dispatch 순서를 주고 마지막 값을 묻는 문제가 딱 좋아요.

예제 · 7주차 자료 p.15 reducerfunction reducer(state, action) {
  switch (action.type) {
    case "INCREMENT":
      return { ...state,
        count: state.count + 1 };
    case "DECREMENT":
      return { ...state,
        count: state.count - 1 };
    default:
      return state;
  }
}
// { count: 0 }에서
// INC, INC, DEC → count 1

장바구니(1015)는 여기에 규칙 세 개만 더해요. 같은 상품을 또 담으면 줄이 아니라 수량 +1, 수량 빼기는 최소 1, 삭제는 filter(그 id만 빼고 남김).

규칙

Reducer는 현재 State와 Action을 받아 새로운 State를 반환한다(직접 수정 금지). UI는 dispatch()로 Action만 전달한다. 단순하면 useState, 변경 규칙이 많으면 useReducer.

외우는 법: 버튼은 부탁(dispatch) · reducer가 새로 만들어 반환 · 모르면 그대로
바로 확인
위 reducer, { count: 0 }에서 INCREMENT, INCREMENT, DECREMENT, "RESET" 순서로 dispatch. count는?
RESET은 case에 없어요 → default로 state 그대로. 0 → 1 → 2 → 1 → 1.
바로 확인
장바구니: Keyboard(50,000) 담기 → Mouse(30,000) 담기 → Keyboard 담기. 총 금액은?
Keyboard는 두 번째에 수량 2가 돼요. 50,000 × 2 + 30,000 = 130,000원.

  • dispatch(action) → reducer → 새 State 반환 / 모르는 type = 그대로
  • 장바구니 : 또 담으면 수량 +1 · 최소 1 · 삭제는 filter

빈칸 채우기 눌러서 정답 확인

선언 전에 var 변수를 쓰면 undefined, let 변수를 쓰면 ReferenceError가 난다. 메서드로 부르면 this는 점 앞의 객체이고, 화살표 함수의 this는 바깥의 this다. 객체를 =로 넣으면 주소가 복사된다. 실행 순서는 동기 → 마이크로태스크 → 매크로태스크다. 이전 값에 의존하는 State 변경은 Functional Update를 쓴다. 의존성 배열이 [ ]이면 Effect는 Mount 시 1회 실행된다.

URL을 치면 일어나는 순서는?
DNS Lookup → TCP/TLS 연결 → HTTP 요청 → 리소스 반환 → 렌더링. DNS 조회는 브라우저 캐시 → OS 캐시 → Resolver(브 · 오 · 리).
Request · Response 구성은?
Request = Method · URL · Header · Body / Response = Status Code · Header · Body.
상태 코드 2xx · 3xx · 4xx · 5xx는?
성공 · Redirect · Client Error(내 탓, 404) · Server Error(서버 탓, 500).
Cookie · Session · Token 차이는?
Cookie = 브라우저에 작은 데이터 / Session = 서버에 상태, 브라우저엔 ID만 / Token(JWT) = 요청마다 보내는 증명서.
TLS가 제공하는 3가지는?
암호화 · 무결성 · 인증 (암 · 무 · 인). SSL은 TLS의 구버전.
DOM과 BOM의 차이는?
DOM = HTML 문서를 Tree로(document) / BOM = 브라우저 기능(window 아래 location · history · navigator · screen).
화면이 그려지는 순서는?
DOM + CSSOM → Render Tree → Layout → Paint (합 · 재 · 칠).
Promise의 3가지 상태는?
Pending(기다림) · Fulfilled(성공) · Rejected(실패). then · catch · finally.
fetch가 404 · 500을 받으면?
reject되지 않는다. response.ok(false)로 확인해야 한다.
명령형 UI와 선언형 UI는?
명령형 = DOM을 어떻게 바꿀지 직접 명령 / 선언형(React) = 상태에 따라 UI가 무엇인지 선언.
Props와 State의 차이는?
Props = 부모가 자식에게 주는 데이터(아래로, 자식이 못 바꿈) / State = 컴포넌트 안에서 바뀌는 데이터, 바뀌면 리렌더링.
Virtual DOM이란?
UI를 JS 객체로 메모리에 두고, 새로 계산해 이전과 비교한 뒤 바뀐 곳만 실제 DOM에 반영. 빠르지만 메모리를 더 씀.
Render 단계와 Commit 단계는?
Render = 새 UI 계산 / Commit = 실제 DOM에 반영.
Component Lifecycle 3단계는?
Mount(태어남) → Update(변함) → Unmount(사라짐).
Lifting State Up이란?
여러 컴포넌트가 같이 쓰는 State를 공통 부모로 올리고 Props로 내려 주는 것. 자식 이벤트는 콜백 Props로 올라온다.
useState와 useReducer는 언제 쓰나?
단순하면 useState(Toggle · Input · Counter), 변경 규칙이 많으면 useReducer(Form · Cart · Todo).

    섞어 풀기 8개 규칙 무작위 · 채점까지

    Q1log("a"); setTimeout(() => log("b")); Promise.resolve().then(() => log("c")).then(() => log("d")); log("e");

    동기 a e → 마이크로 c, 이어진 then d까지 큐가 빌 때까지 전부 → 매크로 b. (규칙 5)

    Q2function outer() { let n = 10; return () => { n = n + 5; return n; }; } const g = outer(); g(); console.log(g());

    같은 g라 같은 가방(n). 10 → 15 → 20. (규칙 2)

    Q3const arr = [1, 2]; const arr2 = [...arr]; arr2.push(3); console.log(arr.length, arr2.length);

    Spread로 새 배열을 만들었으니 arr2에 넣어도 arr는 그대로 → 2 3. arr2 = arr였다면 3 3. (규칙 4)

    Q4const x = 1; x = 2; 를 실행하면?

    let · const는 재선언 불가, const는 재할당도 불가(2주차 Modern JS). 실행하면 TypeError.

    Q5async function f() { return 1; } f().then(v => log(v)); log(2);

    async 함수는 항상 Promise를 반환하고, then은 마이크로태스크라 동기 2가 먼저 → 2 1. (규칙 5)

    Q6count가 5일 때 버튼 핸들러에서 setCount(count + 1); console.log(count); 콘솔에 찍히는 값은?

    이번 렌더링의 count는 사진 속 5 그대로. 6은 다음 렌더에서 보여요. (규칙 6)

    Q7useEffect(() => log("E"), []); Mount 후 다른 State가 바뀌어 3번 리렌더링됐다. E는 몇 번?

    [ ]는 Mount 때 한 번만 → 1번. (규칙 7)

    Q8장바구니에 Mouse ×1만 있다. DECREASE_QUANTITY(Mouse) → INCREASE_QUANTITY(Mouse) 순서로 dispatch. Mouse 수량은?

    최소 수량 1이라 빼기를 해도 1 그대로, 그다음 +1 → 2. (규칙 8)

    Q9var who = "window"; const o = { who: "o", hi: () => console.log(this.who) }; o.hi(); (브라우저)

    점 앞에 o가 있어도 화살표 함수는 자기 this가 없어서 바깥(window)의 who → "window". (규칙 3)

    Q10Reducer 안에서 state.count++; return state;라고 쓰면 안 되는 이유는?

    Reducer는 새 State를 만들어 반환해야 해요(Immutable Update). return { ...state, count: state.count + 1 }. (규칙 8)

    내 말로 설명하기 주관식 개념 대비

    console.log(1); setTimeout(() => console.log(2), 0); Promise.resolve().then(() => console.log(3)); console.log(4);의 출력이 1 4 3 2인 이유를 설명해 보세요.

    JS는 싱글 스레드라 먼저 동기 코드를 위에서부터 실행해서 1과 4를 찍어요. setTimeout의 콜백은 Web API(Timer)를 거쳐 매크로태스크 큐에, Promise의 then 콜백은 마이크로태스크 큐에 들어가요. 콜스택이 비면 이벤트 루프가 마이크로태스크를 먼저 전부 꺼내 실행하니 3이 찍히고, 그다음 매크로태스크인 setTimeout 콜백이 실행돼 2가 찍혀요. setTimeout의 0은 최소 대기 시간이라 바로 실행된다는 뜻이 아니에요.
